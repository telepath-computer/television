# Internal rendering

`<calendar-week>` generates named light-DOM chrome so CSS authors have stable
targets without asking agents to write the structure manually.

Agents author only:

- `<calendar-week start-date days [start-hour]>`
- `<calendar-event title start end [all-day]>`

Everything below is generated by the week itself.

## Section wrappers

| Element | Contents | Purpose |
|---------|----------|---------|
| `<calendar-headers>` | One `<calendar-day date>` per visible day | Sticky headers strip |
| `<calendar-allday>` | One `<calendar-cell date>` per visible day plus routed all-day events | All-day band |
| `<calendar-grid>` | `<calendar-time-axis>`, one `<calendar-column date>` per visible day, routed timed events, `.now-line`, `.start-hour-marker` | Timed hour grid |

## Per-day chrome

Each visible day gets these CSS targets:

- `<calendar-headers> > <calendar-day date="YYYY-MM-DD">`
- `<calendar-allday> > <calendar-cell date="YYYY-MM-DD">`
- `<calendar-grid> > <calendar-column date="YYYY-MM-DD">`

Each of those elements receives `--day-index` (1-based) so CSS can place them
relative to the generated range.

## Event routing

Valid authored events are reparented into one generated section:

- Timed events move into `<calendar-grid>`
- All-day events move into `<calendar-allday>`

The event element itself uses `display: contents`; the visible block is its
generated `.event-block` child. Placement variables differ by mode:

- Timed: `--day-index`, `--y-start`, `--y-end`
- All-day: `--day-start`, `--day-span`

Invalid events keep no `.event-block` and therefore render nothing.

## Now-line

When today's local date is within the visible range, `<calendar-grid>` gets a
`.now-line` element with:

- `--day-index`
- `--y-fraction`

No now-line is rendered outside the visible range.
