# Checklist template

The Checklist template makes an artifact that is a single list of things to tick off, laid out like a sheet of paper. Each story on this page is one state of its page; its markup and styles are the spec for that state. This page states the behaviour the stories cannot show.

<Canvas of={Stories.WithItems} />

## A new checklist

A new artifact from the template has the title "Checklist" and no items. The add field has the keyboard focus, so a person can start typing straight away.

<Canvas of={Stories.New} />

## The title

The title is edited in place: clicking it puts the caret in it, and the text saves as the person types. Return in the title adds a new, empty item at the top of the list and puts the caret in it, so typing a title and pressing Return goes straight to the first item. An empty item left without text is removed, as below. A title cleared to nothing shows "Untitled" in muted text until something is typed.

<Canvas of={Stories.Untitled} />

## Adding an item

Typing in the add field and pressing Return adds the text as a new item at the end of the list, not done, and clears the field, which keeps the focus for the next item. Return on an empty field does nothing.

<Canvas of={Stories.Adding} />

## Items

Clicking the box ticks or unticks an item. A done item stays where it is, its text muted and struck through. Clicking an item's text edits it in place, saving as the person types. Return in an item adds a new, empty item directly below it and puts the caret there, so a list can be typed one line after another. An item whose text is cleared and then left is removed.

<Canvas of={Stories.EditingItem} />

Each item's remove button appears when the pointer is over the item or it is being edited, and removes the item. Long items wrap, with the box beside their first line.

<Canvas of={Stories.LongItems} />

## Changes from elsewhere

The page updates live when an agent or another viewer changes the checklist. Changes to the title and to other items show at once.

While a person is editing an item, their screen keeps showing their own text, whatever arrives for that item. Their text saves as they type, so when two writers change the same item, the last one wins; when the person leaves the item, it shows the stored value. If the item is removed elsewhere while they edit it, it stays on their screen: typing on, or leaving it with text, writes it back whole, with its place and done state, so the later edit wins. Left empty, it stays removed.

## Read-only

When the page can only read its store, as through a read-only share link, the title and items are shown as text, the boxes cannot be ticked, and there is no add field or remove button. The page switches between editable and read-only as its access changes, and is read-only while it has no access at all, as after the share link it was opened through is revoked, keeping what it last showed.

<Canvas of={Stories.ReadOnly} />

## Saving

Changes save as the person makes them, through the artifact's store. While the page cannot reach its server, it is read-only, as below, keeping what it shows, with "Reconnecting…" in muted text at the top of the sheet; it becomes editable again by itself once it reconnects. If a save is refused, that change goes back to the stored value and "Couldn't save that change." shows in the same place for a few seconds.
