# Desktop connect links: implementation plan

The result is a single connect-link workflow: the CLI supplies links, the desktop app accepts one link and remembers the connection, and connection dialogs explain recovery without asking for a separate token.

This plan builds on the specs at `358e6802` and the proofs independently approved in round two at `b7f3e899`. The approved spec deltas include the [connection states explainer](../../../specs/arch/explainer-connection-states.md); the latest wording clarifies that the desktop drag strip appears while no shell is rendered. The [proposal](./proposal.md) records intent, [task record](./task.md) records the method and deferred obligations, and [proof derivation](./proof-derivation.md) records the coverage decisions. This revision is ready for independent plan review; implementation follows plan convergence. The supervisor coordinates independent review.

## Approach and slice boundaries

Keep the CLI, served application's connection owner, and desktop main process as their respective lifecycle owners. Share presentation and stylesheet sources where their dependencies allow it. The desktop identity-check retry loop and the served application's websocket session remain distinct mechanisms.

Three slices separate the CLI process boundary, served-app state and shared presentation, and the packaged desktop lifecycle. Slice 1 is independent of the UI work. Slice 2 supplies the controls and modal presentation used by slice 3. Keeping local rendering, main-process persistence/cancellation, preload IPC and navigation together in slice 3 lets its real-Electron tests prove the whole lifecycle. Each slice receives whole-slice independent review, followed by integrated review under [Planning and slices](../../../specs/spec-workflow.md#planning-and-slices).

The converged proofs determine the tests, their boundaries, mocks and forfeits. The allocations below locate their implementation work; they do not re-derive the assertions. Where a shared assertion spans slices, its completion point is explicit. File names locate the current implementation and tests; implementation may change those boundaries when that makes the result simpler.

The imported UI frames supply the visual design. The setup card uses frame chrome around static content, with no artifact runtime, and its two steps have no tracked current step. The task imports no product, architecture or testing obligations from prerelease PR #387.

## Slice 1 — CLI connect links and startup output

**Deliverable.** `tv links` prints the running server's links, one per line. All CLI link output uses OSC-8 only when its output stream reports `isTTY === true`; captured output contains plain URLs.

**Implementation.** Start in `packages/cli/src/index.ts`, its `CLIEnvironment`, and the existing shared client and connect-URL helpers. Follow [product CLI](../../../specs/product/cli.md#connect-links) and [the client boundary](../../../specs/arch/cli/index.md#client-boundary):

- Register `links` in parsing and help. Reuse home/config/token and client-port resolution. Contact localhost, then use the running server's health-reported addresses and bound port for the output.
- Follow health with authenticated and unauthenticated requests through the existing client, using a read-only operation such as display-state retrieval. Determine token inclusion from those responses even if config has changed since startup. Complete validation before printing links; failures use the specified exit status and stderr with no partial link output.
- Add optional `isTTY` to the output type and route `links`, foreground startup and persisted startup through the same formatter. Startup keeps its headings; `links` prints only links.
- Reconcile the administrator guide with the resulting commands and current-link recovery. Its already-edited installation, upgrade, Docker, SSH and Mac/browser paths remain subject to content review under [the guide spec](../../../specs/arch/cli/admin-guide.md#testing).

## Slice 2 — Served-app connection states and shared presentation

**Deliverable.** Browser and desktop-served pages show one appropriate modal while Television cannot use its server, retain an established shell and live artifacts through an outage, and recover using links. Shared controls and presentation are ready for the desktop local page.

**Implementation.** Start in `packages/web/src/services/server-connection.ts`, `server-connection-owner.ts`, `application-service.ts`, and the application-state, app and system-modal views. The [app's connection rules](../../../specs/ui/app/index.md#connection-states) and [system modal](../../../specs/ui/app/system-modal/index.md) own the behavior; transport internals remain under the [channel-state carve-out](../../../specs/arch/channel-state/index.md#code-governed-carve-out).

- Count completed unreachable reconnect attempts at their owner, once per attempt. The initial drop is not a retry; success resets the count. Keep the existing backoff. Auth and gate answers take effect immediately; rejected credentials stop retries and are cleared in a browser.
- Preserve a displayed upgrade gate until reload, including through later auth rejection. It can be connected while preventing use of the server, so transport-disconnected state alone cannot select the modal.
- Keep the same shell and artifact documents mounted through Disconnected, the third failed reconnect's Can't connect with server state, and recovery. Extend the current `hasApplicationShell` treatment to include post-session error. First-connect failure, authorization and gate presentations have no shell.
- Replace the modal token form with the frame/content's `browser`, `desktop` and `local` guidance. Only local unauthorized/error presentations receive the destructive Disconnect callback. Keep ordinary dialog dismissal separate from connection dialogs' state-driven removal.
- Compose the 36px desktop drag strip when the modal has no shell behind it, on the local page or a served page. A retained shell, including one with a collapsed sidebar, uses its own drag areas. Account for native dialog top-layer hit testing; slice 3 supplies both real-Electron strip crossings.
- Deliver the large button/input styles and `--line-control-lg` through web foundation and live canonical v2, updating v2's vocabulary fixture and built author guidance. Frozen v1 stays byte-identical. Extend the shared Copy helper's size composition for setup's standard button size.
- Implement the browser external-page placeholder's Mac-only copy. Replace the token-form description in `packages/skills/skills/television/src/app-shell-reference.md` with the resulting markup. Update the production style copies and mappings for these shared surfaces; production consumes production assets.

## Slice 3 — Packaged setup and desktop connection lifecycle

**Deliverable.** The desktop app shows setup only without a saved connection, accepts one link, shows Connected before navigation, reconnects saved records automatically, and can forget its server from every state.

**Local rendering and packaging.** Start in `packages/desktop/src/connect.html`, `connect-page.ts`, `connect-preload.ts` and `packages/desktop/build.mjs`. Implement [setup](../../../specs/ui/setup/index.md) and the local system-modal contexts using the authored markup and styles. Reuse Copy and modal presentation where imports remain independent of application services; if necessary, share only presentation or compose it locally. The connection spec leaves this choice to implementation.

Package foundation, surface styles, fonts, icons, Clouds and both wallpaper assets for the local `file:` document. Extend the existing build/upload and licensing inventory for the delivered assets. The page carries the application-document marker; its light/dark marker follows the window's effective native appearance. Retain the last server's native appearance input when returning to local setup, while keeping Clouds as the local theme, under [desktop appearance](../../../specs/arch/desktop/appearance.md).

Implement ready, connecting, connected and error from the frame. Copy leaves both steps available; one press selects the whole prompt. Connect and Return submit the link without requiring Copy. Connecting disables submission; failure retains editable input and connects its invalid state to the inline error. The setup background drags the window while the card remains interactive.

**Main-process lifecycle.** Start in `packages/desktop/src/index.ts`, `connect-screen.ts`, the connect URL/error/check modules and `connection-store.ts`, following [connection flow](../../../specs/arch/desktop/connect-flow.md):

- Replace bootstrap/manual-prefill entry with saved versus unsaved entry. Main owns checks, saved state, navigation and disconnect; the local page renders their results. Keep normalization and persistence format, with no inherited token for a tokenless submission. Reword setup's missing/rejected-token messages around the current link.
- Save and navigate only after a successful check. Enable Disconnect as soon as the record is saved. The current connect call resolves after `loadRemote`, so separate successful setup presentation from remote navigation enough to render Connected first. Keep completion tied to the active attempt so a subsequent disconnect cancels navigation. Choose the smallest handoff that meets those outcomes; the proof sets no additional Connected dwell or transition-event mechanism.
- If navigation does wait on a transition event, add a renderer-contract check that reduced motion still completes navigation when that event does not occur, and update the setup proof to describe that evidence. This carries proof-review observation 3: normal-motion Electron acceptance alone does not establish the reduced-motion handoff. The authored reduced-motion styling remains part of conformance in either implementation.
- On saved startup, show Connecting without a setup flash. A `401` shows Access token required and stops attempts; other check failures show Can't connect with server and retry with backoff. Supply the countdown deadline/in-flight status. A gate-requiring valid identity proceeds to the served page, which owns the gate decision.
- Install Disconnect from Server with `CmdOrCtrl+,`, enabled exactly while a valid record exists. Menu and local-button calls use the same operation: invalidate attempts, retries and pending navigation, delete the record, and load setup. Release outstanding work on window close.
- Keep the connection preload operations available on the packaged local page and unavailable on served pages. Product walks prove working local connect/disconnect IPC and absence of those controls remotely.
- Re-enter saved startup on genuine top-level remote load failure, preserving the specified aborted/subframe/local-page exclusions. After saving, a remote load failure is saved-connection recovery.
