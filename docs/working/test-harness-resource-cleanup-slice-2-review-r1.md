## Are the diagnostics as small as the proposal intends?

Yes. One JSON file per surface execution of about 1.6 KB when nothing failed; a kernel excerpt only on failure or incomplete evidence, capped at 64 KiB; 128 KiB per file and 8 MiB per attempt, enforced at write and again at download; no sampler, process inventory, heap snapshot, archive or daemon; samples kept out of the timing stream and console. The one growth beyond the proposal's minimum is that passing surfaces also keep their start/end file (observation below).

## Refinements (none blocking)

1. **Import the provider constant instead of copying it.** `resource-diagnostics.mjs:22` enables diagnostics only when `TV_TEST_TIMING_PROVIDER` equals a literal that `timing-baseline.mjs:8` already exports as `BASELINE_TIMING_PROVIDER`. A renamed worker tier would then switch diagnostics off silently. Importing the constant, or gating on an explicit variable the shard script sets, removes the drift.
2. **The targeted config path assumes a repository-rooted cwd.** The shard script exports `TV_TARGET_CONFIG` as `/workspace/television/<config>`, but the CLI hands the coordinator a config path relative to the surface's `cwd` (`scripts/test/cli.mjs:810-812`). Correct today, because no Vitest surface declares a `cwd`, and the targeted runs in the record exercised it; a package-rooted Vitest surface would get a wrong path. Join with the target cwd, or say the assumption in a comment.
3. **Treat the receipt shape as provisional.** `cleanRecord` already serializes `kind: "recovery"` with the fields the spec names, and the budget contract exercises it, but no recovery data exists yet. Slice 3 should reconcile the shape against what recovery actually knows rather than inherit it.

**Observation.** Sidecars are retained for passing surfaces as well as failing ones. The spec's retention sentence lists the cases that must be retained and does not forbid this; the attempt budget bounds it; and the baseline on a passing run is the context the proposal wanted. Say the choice in the record so the integrated review does not read it as drift.
