1. **Blocking: the timing-event type omits fields that the persisted-data reader requires.** Place: [reporting.md](../../../specs/arch/test-runner/reporting.md), lines 72–99, particularly “other fields and event kinds belong to the writer.” This is the unresolved part of round 1 finding 1.

   The added types describe the fields used to calculate the baseline, but not the complete boundary through which those records must pass. Before calculating anything, `baseline update` calls `validateTimingEvents` on the stored stream ([timing-baseline.mjs](../../../scripts/test/timing-baseline.mjs), lines 68–79). That validator requires a contiguous zero-based `sequence`, matching `runId` values, and a recognized `status` on every event except a process-leak event ([timing-events.mjs](../../../scripts/test/timing-events.mjs), lines 217–229). The new type omits `sequence` and `runId` entirely, omits the shard's `status`, and permits arbitrary strings for other statuses. It also leaves `timingProvider` as any string, although the updater recognizes Blaxel history by the exact value `blaxel-playwright-x64-4vcpu`.

   A stream containing precisely the specified fields cannot pass the current reader. Changing supposedly writer-owned fields can therefore invalidate stored history without changing the declared version-1 contract. These are dependencies of a reader of persisted data, not merely private normalization details. The general compatibility paragraph is useful, but does not tell an implementer which omitted fields participate in that compatibility.

   Extend the small contract with the common event envelope, the required shard status, the accepted status values and the Blaxel timing-provider identity. For example, the behavioral rule can be one sentence: “Every version-1 event carries the same `runId` and a zero-based `sequence` matching its line position; every event except `process-leak` carries a recognized status.” Reflect those fields in the types. Private attempt payloads, hash formulas and the full normalized result model need not return. If the intended simplification is instead to stop requiring this metadata, make that a deliberate change to the reader contract and identify the current implementation mismatch; the comment cannot by itself make an existing reader dependency private.

   I accept the writer's decision to leave the committed `test/timing-baseline.json` format to code. Its reader and the regenerated file change together. That differs from run directories retained across revisions, and does not leave the original finding open on the baseline file itself.

2. **Refinement: best-effort status is still described partly as a matter of when a diagnostic is written.** Place: [reporting.md](../../../specs/arch/test-runner/reporting.md), line 101.

   The distinction between required final reports and optional diagnostics is restored. However, “Additions made afterwards … include … resource probes” places those probes after finalization. The resource section correctly requires a saved observation before surface preparation, and [resource-diagnostics.mjs](../../../scripts/test/resource-diagnostics.mjs) makes that initial observation and its write best-effort too. The later statement that diagnostics never change outcomes prevents a substantive policy conflict, but the chronology is misleading.

Optional diagnostics are best-effort regardless of when they are collected. These include resource probes, workflow metrics and later phase appends. Verify adds its enclosing phases to the summary after the test command finishes.”
