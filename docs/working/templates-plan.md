# Artifact templates implementation plan

The [approved proposal](templates-proposal.md), the [settled specs](../../specs/index.md), the [converged proofs](../../proofs/index.md), and the [Templates popover pilot](../../storybook/spec/templates-popover/templates-popover.mdx) define this work. This plan groups work by the current code's handoffs: `ServerStore` and HTTP routes, package and onboarding builds, CLI dispatch, and the web top bar. Four slices keep each handoff and its tests together.

The proof anchors below name the required assertions. Write those tests with the implementation of their slice. Use [the canonical test runner](../../specs/arch/test-runner/test-runner.md) to select a file or surface while iterating; widen only after the focused case passes, as [testing policy](../../specs/arch/testing-policy.md#Test-iteration-discipline) requires. Ordinary server or `tv` runs against this checkout, including test subprocesses, get a fresh absolute `--home` or the equivalent explicit `ServerStore.storagePath`. The narrow exception is the required default-home acceptance: it omits `--home`, sets a fresh temporary `HOME` for each spawned process, and checks the selected home is inside that temporary directory, never the operator's home. Follow the test runner's provider rules for the final gate.

## Slice 1 — Template creation at the server boundary

**Scope.** Add the installed-folder validator and fresh scanner, authenticated list, create, and thumbnail routes, and the shared client's `templates` methods. Create ordinary path artifacts from copies, with placement and starting data checked before copying. The current `createArtifact` rolls a record back when saving the channel fails; the template path must preserve everything created after copying begins, including a record or store left by an uncertain save, while ordinary creation keeps its existing contract. Report the destination, attempted ID, and failing step. Declare the closed bundled ID tuple `['example']`; emit ordinary artifact telemetry at registration and template-use telemetry only after successful creation, classifying every other ID as `custom`. Validate the closed `source` field at the HTTP boundary with the ordinary `400` and `{ error: string }` response before it can reach telemetry. Implement last-channel replacement and client convergence needed to keep a focused channel available for popover use.

**Specs and proof assertions.** [Template architecture](../../specs/arch/templates/index.md) and [product behavior](../../specs/product/templates.md): `templates-t-package`, `templates-t-scan`, `templates-t-routes`, `templates-t-create-route`, `templates-t-thumbnail-route`, `templates-t-request-validation`, `templates-t-preflight`, `templates-t-copy`, `templates-t-folder-name`, `templates-t-failure`, and `templates-t-uncertain-seed` in [the architecture proof](../../proofs/arch/templates/index.md). [Telemetry types, derivation and emitters](../../specs/arch/telemetry/index.md), [product telemetry](../../specs/product/telemetry.md): `t-template-vocabulary`, `t-template-classify`, `t-template-emit`, `ac-artifact-template`, the no-user-content assertion, `t-channel-replacement-emit`, and `ac-channel` in their mirrored proofs. [Channel state](../../specs/arch/channel-state/index.md), [channels](../../specs/product/channels.md), and [onboarding boot order](../../specs/arch/onboarding/installer.md): `cs-ac-focus-validate`, `cs-ac-first-focus`, `cs-ac-pin-prune`, `cs-ac-focus-successor`, `cs-t-last-delete-projection`, `cs-ac-ambiguous-scopes`, `cs-t-last-delete-recovery`, `ch-ac-delete-selection`, and `t-default-invariant`. The changed app-shell, sidebar, stage, and top-bar lead markup assertions (`ap-ac-markup-smoke`, `sb-ac-markup-smoke`, `st-ac-markup-smoke`, `top-ac-lead-markup`) cover their always-focused-channel poses in this slice. [Resource first-write and uncertainty](../../specs/arch/resources/index.md) and [route isolation](../../specs/arch/artifact-frame/isolation.md) retain their existing `rs-arch-t-first-write`, `rs-arch-t-uncertain-save`, and `iso-t-routes` tests; the template tests above cross those mechanisms for this feature.

**Files.** Add `packages/server/src/templates.ts`, a bundled-template ID declaration, and a focused creation module beside it if that keeps `server-store.ts` readable. Change `packages/server/src/server-store.ts`, `routes.ts`, route schemas, and `server.ts` as needed; `packages/shared/src/client.ts`, `types.ts`, and `index.ts`; `packages/server/src/telemetry/{types,derivation,emitters}.ts` and their tests; and `packages/web/src/services/application-service.ts` for the last-channel projection. Add focused server template scanner, route, creation, and failure tests under `packages/server/test/`. Extend `packages/server/test/{server-store-channels,server-store-bootstrap,display,events,telemetry-acceptance,telemetry-emitters}.test.ts`, `packages/server/src/telemetry/{types,derivation}.test.ts`, `packages/web/test/application-service.test.ts`, `packages/web/test/e2e/{channel-product,channel-crud}.test.ts`, and the app-shell, sidebar, stage, and top-bar markup tests. Update old deletion outcomes in `display.test.ts` and `events.test.ts` in this slice.

**Red → green order.** First make scanner fixtures fail for malformed packages, exact IDs, ordering, and a directory read error; implement one scanner and use it in all three requests. Next write real HTTP tests for auth, malformed request refusal, fresh create lookup, thumbnail bytes, path containment, and absence of CORS headers; add the shared client calls and routes. Then write preflight, copy, placement, naming, durable seed, and each post-copy failure case against a real temporary filesystem. Use the proof's storage adapter only for the uncertain post-rename store save. Write telemetry vocabulary/classification/emission tests. For last-channel behavior, first write HTTP boot and focus-validation tests, then an HTTP/WebSocket deletion-order test, then client projection/recovery and two-browser deletion tests. Add the telemetry assertion that automatic replacement emits no `screen_created`. Implement each path against its focused red case, including updating the old `display.test.ts` and `events.test.ts` expectations. Widen to the owning server, shared type, application-service, and channel browser surfaces.

**Verification and baseline.** All slice-1 template server assertions pass. HTTP boot/focus, WebSocket order, two-browser last-channel deletion, client recovery, and no-`screen_created` telemetry tests pass; existing artifact, resource, and isolation tests still pass. The server accepts authored templates in a temporary home through the shared client. No temporary failing tests are planned. Bundled Example installation, new CLI commands, and the new popover are absent and have no tests yet; slices 2–4 own them. Full verification is deferred to slice 4.

## Slice 2 — Bundled Example, skills, onboarding assets, and package contents

Ship only the `television` agent skill; keep calendar and task browser components in a distinct `onboarding-dist` output for the bake. Update the bake's input root, the `television` skill's template guidance, licensing surface IDs and notices aggregation, and affected packaged-asset tests. Do not change the Storybook pilot.

**Specs and proof assertions.** [Bundled installation](../../specs/arch/templates/bundled-installation.md) and [bundled inventory](../../specs/arch/templates/bundled-templates.md): `templates-install-t-validate`, `templates-install-t-build`, `templates-install-t-state`, `templates-install-t-boot`, `templates-install-t-retry`, `templates-install-t-state-retry`, `templates-bundled-t-inventory` in their [installation](../../proofs/arch/templates/bundled-installation.md) and [content](../../proofs/arch/templates/bundled-templates.md) proofs.
