## Slice judgment

Use three slices, each with tests and implementation reviewed together. Helper ownership and shipped-asset loading can be completed independently of the remote coordinator. Diagnostic capture has a separate native-runner/reporting boundary. Lease acquisition, dispatch registration, recovery, scratch cleanup, pool mutation and result retrieval must remain together: splitting that lifecycle would leave intermediate combinations whose safety is hard to assess.

The order is helper lifetime, diagnostics, then worker lifecycle and live qualification. The last slice uses the earlier diagnostics and helper fixes on real workers, so the remote acceptance runs prove their composition once. Each slice receives independent implementation review, followed by review and full verification of the integrated result. This is one PR; these are review boundaries, not separate releases.

The specs and proofs remain the source of requirements. Paths below identify the current implementation areas, not a fixed inventory of files that may change. No production application behavior, retry default, standard shard count or browser version changes belong here.

## Slice 3 — exclusive worker lifecycle and live qualification

**Result.** One worker remains exclusively owned from acquisition through confirmed process teardown and retained results. Lost renewal permits automatic cleanup before reuse. Scratch and known leftovers are removed only under the reviewed ownership conditions. Pool operations follow that same exclusion. Live qualification proves the whole path, including slice 2's diagnostics.

**Implementation area.** `scripts/run-blaxel-testshards.mjs`, `manage-blaxel-testshards.mjs`, their lease/discovery/dispatch helpers, the existing process owner/audit mechanisms, and the shared/targeted runner paths. Keep acquisition and entry checks usable before checkout; they cannot depend on code in a checkout another run may still own. Preserve the outer shard-attempt token across nested surface owners. A short OS-released guard serializes worker-local ownership changes; it is never held across report downloads.

In `scripts/test/cli.mjs`, forward an explicitly supplied `--lock-ttl-seconds` to the coordinator for the live driver's shortened recovery interval. Add a small contract beside the existing CLI/provider assertions: the explicit option reaches the delegated arguments and is absent by default. The live recovery run proves it arrives at the worker. Ordinary invocations without that option retain the spec's default interval; this does not add worker-timeout forwarding or change retry defaults.

Keep acquisition, renewal, dispatch registration, normal release, interruption and recovery in one lifecycle. Renew through setup, execution, teardown and retrieval; remove shell-exit unlock. Normal release follows confirmed descendants and verified downloads. The one expired-renewal procedure stops attributed owners, audits, records abandoned report loss and only then reuses the worker. Preserve the reviewed legacy behavior and fail-closed cases. Pool deletion refuses valid leases and removes dispatch eligibility before deletion; fresh provisioning publishes eligibility only after successful verification. No new service, caller-attestation system or mixed-version framework is needed.

Give each shard attempt its specified private scratch and `TMPDIR`. Route uploads, plan, askpass and setup sidecars there, finalizing evidence outside it before removal. Pre-run cleanup removes only the two known direct `/tmp` prefixes and non-current attempt directories after the lease and clean owner audit. Preserve unrelated files, links' outside targets, current scratch and caches; reject unsafe roots/mounts. Stop processes before post-run removal and retain evidence/ownership when cleanup is uncertain.

**Red/green and review criteria.** First establish red at the [lease decision and ordering contracts](../../proofs/arch/test-runner/blaxel-testshards.md#Lease, recovery, and scratch), then implement the lifecycle and cross the real Linux guard/registration and filesystem seams. Cover competing acquisition, old-owner mutation, delayed entry, nested tokens, token/PID-start-validated termination, incomplete records, cleanup errors and permitted legacy behavior at their reviewed shapes. The ordinary guard seam restricts its audit to fixture tokens as declared; it supplies no live-provider credit. Replace the existing TTL-only assertions rather than leaving tests that endorse the superseded release behavior. Test pool publication/deletion ordering and discovery of unavailable partial workers with the declared SDK substitutions before the live pool crossing.

Register `experiment:blaxel-harness` and `experiment:blaxel-harness-fixtures`, giving the fixture surface at least two native files. Discharge the [registry selection contract](../../proofs/arch/test-runner/test-registry.md#^registry-t-blaxel-harness-selection): neither surface enters `all`/ordinary CI, the fixture tag selects only fixtures, and the driver never dispatches itself.
