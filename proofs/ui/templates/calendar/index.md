# Calendar template (UI) — proof

Proves [specs/ui/templates/calendar.mdx](../../../../specs/ui/templates/calendar.mdx).

## Coverage model

Browser tests open real Calendar artifacts. One running server per test file serves the bundled template; each test creates its own artifact from the template with an authored starting store value and opens the page directly in a real browser. Writes go through the page's real resource SDK, and one goes through a spawned `tv resource json` command in the [bundled template proof](../../../arch/templates/calendar.md#^templates-calendar-ac-live). No test replaces the store, the SDK, or the page's DOM. Where today and the now line matter, the browser's clock is fixed; this changes only the time the page reads.

The standard CSS-motion override is used except where an assertion says otherwise. It forfeits the [highlight motion](../../../../specs/ui/templates/calendar.mdx#highlight-motion), which three tests cover with CSS motion kept: the lift and the settle, the same change under reduced motion, and an event that loads highlighted. They observe the transitions through transition events and `getAnimations`, never by sampling a frame. They check the durations the prose states; the exact timing curves are the spec stylesheet's, which the page carries byte for byte under the [stylesheet-copy check](../../../arch/templates/calendar.md#^templates-calendar-t-package), so no test restates them. Smoothness and feel are judged by eye in the non-binding motion demo in `storybook/prototypes/`, which no test covers.

The fitting rule for attendee names is a pure function in the page's attendees module. A contract test proves its choices with a fixed text measure; the browser assertion proves that real widths reach it and that a width change refits the line.

The stories in `storybook/spec/templates/calendar/` hold the page's markup and styling. The page carries their stylesheet byte for byte, which the [bundled template proof](../../../arch/templates/calendar.md#^templates-calendar-t-package) checks. Structural comparison of the page against each story waits for [TV-649](../../../../specs/arch/ui/conformance.md#release-exception-for-tv-649); until then, the stories and the page were compared by screenshot at each story's size, and the browser assertions here cover behaviour, not pixel styling.

Two tests route the page's connection through Playwright. To show the page before its data arrives, the connection is held open and never reaches the server; this forfeits data delivery, which every other test exercises. To show a disconnection, connections pass through to the real server until the test closes them and refuses new ones for a while; the page's own SDK then reconnects through the same route to the same server. Stored data the server cannot read is posed by writing an unreadable file into the store while the server restarts; the page reaches the server through the test proxy that follows it across restarts.

## Test hooks

No production test hook is needed. Starting store values, the fixed clock, and window sizes are fixtures.

## Assertions

Each browser assertion is **Acceptance** (real browser → artifact page → running server, real store and SDK; fixtures `packages/web/test/e2e/fixtures/calendar-week.json` and `calendar-day.json`). Each cites `packages/web/test/e2e/template-calendar-real-stack.test.ts`.

- Under [A new calendar](../../../../specs/ui/templates/calendar.mdx#a-new-calendar), a new artifact with the template's starting data shows seven days from Monday of the current week, marks today and the current time, shows no events and no all-day band, and raises no page error. *(policy-grade test: cases tagged `^calendar-ac-new`)* ^calendar-ac-new
- Under the [Week story](../../../../specs/ui/templates/calendar.mdx#calendar-template), the working week shows the month and year with the year set apart, one header per day, each event's title, time, detail and attendees, a short event's start time alone, and all-day events without a time. *(policy-grade test: cases tagged `^calendar-ac-week`)* ^calendar-ac-week
- Under [Layout](../../../../specs/ui/templates/calendar.mdx#layout), the first load scrolls the hours so the hour before the earliest event sits just below the pinned headers; a later change of the days shown keeps the scroll position. *(policy-grade test: cases tagged `^calendar-ac-scroll`)* ^calendar-ac-scroll
- Under [Changes from elsewhere](../../../../specs/ui/templates/calendar.mdx#changes-from-elsewhere), adding, highlighting, changing and removing events keeps the calendar element and other events' blocks as the same nodes, and keeps the scroll position. *(policy-grade test: cases tagged `^calendar-ac-in-place`)* ^calendar-ac-in-place
- Under [Changes from elsewhere](../../../../specs/ui/templates/calendar.mdx#changes-from-elsewhere), changing one event's detail mutates only nodes inside that event: the calendar's sections, every event and every block stay the same nodes, other blocks' markup is unchanged, and the scroll position stays. *(policy-grade test: cases tagged `^calendar-ac-no-redraw`)* ^calendar-ac-no-redraw
- Under the [store contract](../../../../specs/arch/templates/calendar.md#^bundled-artifact-template-calendar-store), events that end before they start, or have a detail, attendee or colour of the wrong type, are not shown, and a valid event written beside them is. *(policy-grade test: cases tagged `^calendar-ac-invalid`)* ^calendar-ac-invalid
- Under the [Short and overlapping events story](../../../../specs/ui/templates/calendar.mdx#layout), two overlapping events sit side by side at equal widths, and an event with no overlap keeps nearly the day's whole width. *(policy-grade test: cases tagged `^calendar-ac-overlap`)* ^calendar-ac-overlap
- Under [Attendees](../../../../specs/ui/templates/calendar.mdx#attendees), at the starting artifact size the working week shows every name, names and a count, and the count alone where each fits, with no name clipped. Widening the window refits a line to every name, and narrowing it refits the line back. *(policy-grade test: cases tagged `^calendar-ac-attendees`)* ^calendar-ac-attendees
- **Contract** (the attendees module's fitting function; a fixed width per character stands in for text measurement, which the browser assertion above exercises for real): Under [Attendees](../../../../specs/ui/templates/calendar.mdx#attendees), the function returns every name when all fit, the most whole names that fit with a count of the rest, or the total count when no name fits, and never part of a name. *(policy-grade test: `packages/server/test/calendar-attendees.test.ts`, cases tagged `^calendar-t-attendees-fit`)* ^calendar-t-attendees-fit
- Under the [One day and Highlighted event stories](../../../../specs/ui/templates/calendar.mdx#highlighted-events), with CSS motion kept, one day has one column and its full weekday name, and under [Highlight motion](../../../../specs/ui/templates/calendar.mdx#highlight-motion) an event that loads highlighted appears raised with no animation running. *(policy-grade test: cases tagged `^calendar-ac-one-day`)* ^calendar-ac-one-day
- Under [Highlight motion](../../../../specs/ui/templates/calendar.mdx#highlight-motion), with CSS motion kept, highlighting an event on screen runs one transform transition on that event alone, lasting 700 milliseconds and leaving it raised; clearing the highlight runs one lasting 450 milliseconds and leaves it flat. With reduced motion, the event switches between flat and raised with no transition and no animation. This is a real-motion assertion. *(policy-grade test: cases tagged `^calendar-ac-highlight-motion`)* ^calendar-ac-highlight-motion`)* ^calendar-ac-highlight-motion
- Under [Layout](../../../../specs/ui/templates/calendar.mdx#layout), one day fills the width at 1440 and 1920 pixels with a raised event inside the calendar; seven days share the width with no sideways scroll at 1100 pixels, keep 100-pixel columns at 400 pixels, and scroll sideways while the hour labels stay in place. *(policy-grade test: cases tagged `^calendar-ac-layout`)* ^calendar-ac-layout
- Under the [Seven days story](../../../../specs/ui/templates/calendar.mdx#layout), with the clock fixed on a Thursday afternoon, today's header is marked and the now line and its time label show. The line stacks over an event it crosses, the faint line across the other days beneath it, and a raised event over the line. *(policy-grade test: cases tagged `^calendar-ac-now`)* ^calendar-ac-now
- Under the [Seven days story](../../../../specs/ui/templates/calendar.mdx#layout), weekend days look like weekdays when five days are shown and are shaded when seven are, in the all-day band as in the hour grid. *(policy-grade test: cases tagged `^calendar-ac-weekend`)* ^calendar-ac-weekend
- Under the [Short and overlapping events story](../../../../specs/ui/templates/calendar.mdx#layout), a title in a narrow block wraps only between words, and a single word wider than its block is clipped with an ellipsis rather than broken. *(policy-grade test: cases tagged `^calendar-ac-title-wrap`)* ^calendar-ac-title-wrap
- Under [Opening a calendar](../../../../specs/ui/templates/calendar.mdx#opening-a-calendar), with the page connection held so the data never arrives, the page shows the month and an empty grid of this week from Monday, with today and the current time marked, no events and no error page. *(policy-grade test: cases tagged `^calendar-ac-opening`)* ^calendar-ac-opening
- Under [Read-only](../../../../specs/ui/templates/calendar.mdx#read-only), opened through a read-only share link, the calendar shows its events and attendees as through its own address. *(policy-grade test: cases tagged `^calendar-ac-read-only`)* ^calendar-ac-read-only
- Under [Disconnection](../../../../specs/ui/templates/calendar.mdx#disconnection), once the page's connection is cut and it is disconnected, a spawned `tv` write changes nothing on the page and no message appears; once it can reconnect, the change shows. *(policy-grade test: cases tagged `^calendar-ac-disconnection`)* ^calendar-ac-disconnection
- Under [Data the page cannot read](../../../../specs/ui/templates/calendar.mdx#data-the-page-cannot-read) and the [whole-value rule](../../../../specs/arch/templates/calendar.md#^bundled-artifact-template-calendar-store), each of these values replaces the calendar with the error page, an alert with the warning icon, title and text: `events` a list, `events` missing, a root that is not an object, and no value. Writing a valid value after each brings the calendar back. *(policy-grade test: cases tagged `^calendar-ac-unreadable`)* ^calendar-ac-unreadable
- Under [Data the page cannot read](../../../../specs/ui/templates/calendar.mdx#data-the-page-cannot-read), with the clock fixed on a Wednesday, a `startDate` that is not a real date shows five days from today, as with no `startDate`, and `days` outside 1 to 7 shows seven days, as with no `days`; writing valid values brings back the days they name, and the error page never shows. *(policy-grade test: cases tagged `^calendar-ac-unreadable-range`)* ^calendar-ac-unreadable-range
- Under [Read-only](../../../../specs/ui/templates/calendar.mdx#read-only), with a page opened through a read-only share link, revoking the link sends the page's store listeners a `no-store` error, observed through a second listener the test adds on the same store, and the page keeps exactly what it showed, with no error page. *(policy-grade test: cases tagged `^calendar-ac-access-lost`)* ^calendar-ac-access-lost
- Under [Data the page cannot read](../../../../specs/ui/templates/calendar.mdx#data-the-page-cannot-read), when the server restarts with the store's file unreadable, the open page shows the error page; when it restarts with the file restored, the page shows the calendar again without being reloaded. *(policy-grade test: cases tagged `^calendar-ac-unavailable`)* ^calendar-ac-unavailable
- Under [Appearance](../../../../specs/ui/templates/calendar.mdx#appearance), the page background matches the calendar's in light and dark, and both the background and the event ink change with the appearance. *(policy-grade test: cases tagged `^calendar-ac-appearance`)* ^calendar-ac-appearance
