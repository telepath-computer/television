# Weather template (UI) — proof

Proves [specs/ui/templates/weather.mdx](../../../specs/ui/templates/weather.mdx).

## Coverage model

Browser acceptance opens Weather artifacts created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox, loads the served resource SDK, reads and writes a real JSON store according to access, and performs its production fetch. No test replaces the DOM, store, SDK, date/time formatter or time-zone database.

Default tests intercept every Open-Meteo request with the captured fixtures declared by the [Weather architecture proof](../../arch/templates/weather.md). This mocks the provider and public network, forfeiting live service behavior to its [opt-in live seam](../../arch/templates/weather.md#^templates-weather-live-provider). It does not replace the page's fetch, CORS handling, response normalization, cache transaction or rendering. Each expected method, URL, query and response, delay or failure is scripted; any unexpected provider or other external request fails.

Most ready-state and conformance setup uses a fresh compatible saved-forecast fixture so the browser reaches deterministic rendering without a provider attempt. This exercises the real saved-cache parser, selection and rendering, but forfeits response normalization to the architecture contracts and fetch/save acceptances. Loading, unavailable, failed refresh, creation, read-only and access cases use the real fetch path with intercepted provider responses.

Time-zone acceptance runs with browser and forecast zones on opposite sides of UTC in both directions, including an `Asia/Kolkata` half-hour zone and an `America/New_York` response spanning the 2026 fallback. One browser uses a non-English locale. Raw provider cases reach daily dates through `utc_offset_seconds`; a compatible saved-cache case supplies a non-hour instant. Expected hour, weekday and date labels are authored literals, never generated with the browser locale or `new Date('YYYY-MM-DD')`.

Most clock cases use Playwright's controlled browser clock, which replaces wall-clock passage and forfeits real scheduler cadence. A rollover case advances that clock while the real page timer and derivation run, proving the page updates within the specified minute. The shared creation/fetch/save walk and its latitude, longitude and units abort passes install the controlled clock before page code. The main walk fixes it within the everyday captures; each abort pass seeds a compatible forecast with `updatedAt` 16 minutes before its fixed clock and holds the refresh that starts. The current-value and age passes use the real browser clock. The provider walk edits only the captured receipt and current instants to make coherent morning and evening copies, then shifts every UNIX timestamp in `current`, `hourly` and `daily` by the same whole number of days rounded down. It runs both a morning capture against an evening browser clock and the reverse, requiring the shifted capture not to be in the future and the retained daily window to start on the current forecast-zone date. The age pass shifts a capture so its saved values remain fresh at the real clock. Relative positions and fixed-offset local midnights stay intact; all other body values and headers remain captured.

The shared forwarding proxy may delay the first real resource result, sever an established connection and refuse reconnection. It changes delivery timing without fabricating resource values, access or recovery. A saved-data-unavailable case keeps that proxy on the browser-facing address while the real server stops, the saved store file becomes unreadable, and the server restarts on the same home. The resource proofs own transport, authorization, durability and reconnection mechanics. Standard CSS-motion disablement forfeits the loading spinner animation only.

One conformance file compares every one of the 25 exported Weather stories with a copied production page. Storybook is built from the same worktree. Comparisons use real Chromium, the complete `.weather-page` root outside the app shell, matching viewport and appearance, completed story setup, deterministic stores and fixed clocks for populated states. Under the testing policy's [UI styling rule](../../../specs/arch/testing-policy.md#^ui-styling-out), this story-by-story comparison is the only Weather appearance evidence. It owns gradients, first-party artwork, white type, typography, spacing, panels, range bars, attribution, shadows, responsive composition and dark appearance. Behavior assertions own selection, requests, live changes, access and recovery and do not inspect styling.

The current stories do not isolate the promise that cloudy, rain, snow and fog remain visually unchanged at night, that thunderstorm remains visually unchanged by day, or that each hourly glyph switches from its own `isDay` value. They also do not establish painting in Firefox or WebKit because the conformance harness uses Chromium. Those are coverage gaps rather than reasons for custom Weather appearance tests; [the working plan](../../../docs/working/weather-plan.md) records them for Rupert.

## Test hooks

No production test hook is required. Starting values, captured provider responses, fixed clocks, locales, time zones and viewport sizes are fixtures or browser configuration.

The provider interception and connection proxy are mocks with the forfeits declared above. Passing Television traffic is unchanged. Browser observation may record requests, store operations, accessibility output and DOM mutations without replacing page handlers or content.

Unless a size is explicitly called a reference-pixel size, browser assertions use the artifact document's CSS viewport. The stage and browser viewport are large enough to contain it without scaling or clipping.

## Time zones and forecast windows

- **Acceptance — provider time zones on both sides of UTC.** Under [medium and large layout](../../../specs/ui/templates/weather.mdx#size), open 760×740 with fixed clocks for two cases. First, run a `de-DE` browser in `America/Los_Angeles` at `2026-10-27T20:00:00Z` and serve `test/fixtures/weather/open-meteo/kolkata-2026-10-27.json`, where the forecast date is 28 October while browser and UTC dates are 27 October. The captured first stored hourly entry after `Now` is the `2 AM` Kolkata cell, daily rows use `Today` for 28 October, and the age line still begins with the English `Updated`. In a separate fresh compatible saved forecast at the same instant, include entries labelled `1 AM`, `1:45 AM`, `2 AM` and `2:30 AM` in Kolkata: both entries in the 1 AM hour are absent, `2 AM` is retained, and `2:30 AM` includes minutes. Second, run a browser in `Pacific/Auckland` at `2026-11-01T02:30:00Z` and serve `test/fixtures/weather/open-meteo/new-york-dst-2026-10-27.json`, where the forecast date is 31 October while browser and UTC dates are 1 November. Its retained daily labels are `Today`, `Sun` and `Mon` for 31 October through 2 November, exercising dates normalized with the response's fixed `utc_offset_seconds` across the offset change. After `Now`, the New York hourly labels begin `11 PM`, `12 AM`, `1 AM`, `1 AM`, `2 AM`; the repeated hour remains. Later labels are literal `en-US` clock times at the forecast zone; weekdays and all other copy remain English under `de-DE`. Expected labels use the ordinary U+0020 before `AM` or `PM`, as the stories and the repository's Chromium do. The architecture contracts own conversion, ordering, duplicates and limits; current-condition values are covered separately. *(policy-grade test: `packages/web/test/e2e/template-weather-real-stack.test.ts`, “formats provider windows in the forecast zone and en-US locale across DST”)* ^weather-ui-ac-time-zones
- **Acceptance — clock rollover while open.** Under [current conditions](../../../specs/ui/templates/weather.mdx#current-conditions) and [Size](../../../specs/ui/templates/weather.mdx#size), open a fresh saved forecast at 760×740 for `Asia/Kolkata` in a browser fixed to `America/Los_Angeles`. Start within one minute of Kolkata midnight, which also crosses the local hour boundary and is not aligned with the browser-local boundary, and keep the advance within the saved forecast's 15-minute freshness window so no provider request is eligible. Focus and scroll the hourly strip before the advance. Without reload or store write, the structural rebuild restores that focus and scroll; the hourly window and labels advance within one minute; the daily window drops the prior date, moves `Today`, and refreshes high and low within one minute; and age reaches its next completed unit within one minute. Clock control forfeits real elapsed scheduler cadence, not the timer callback or derivation. *(policy-grade test: `packages/web/test/e2e/template-weather-real-stack.test.ts`, “updates hourly and daily windows, high and low, and age across forecast-zone rollover”)* ^weather-ui-ac-clock

## Panels, accessibility and attribution

- **Acceptance — forecast semantics, keyboard reach and attribution.** Under [Size](../../../specs/ui/templates/weather.mdx#size) and [Attribution](../../../specs/ui/templates/weather.mdx#attribution), open the exact 760×740 large boundary. Empty hourly or daily windows omit only their corresponding data. The hourly strip is focusable and named `Hourly forecast; scroll for later hours`; real unmodified right-arrow input advances its scroll, while modified arrows remain available to the browser. Hourly cells expose local time, condition and temperature. The daily heading counts displayed rows; rows expose `Today` or weekday, condition, low and high; range bars add no separate accessible meaning. On populated cards, the credit reads `Open-Meteo data · adapted · CC BY 4.0`, links to the provider and licence in new tabs, and receives keyboard focus. Empty, loading, unavailable and unreadable cards have no provider credit or credit links. No external navigation is followed. Across separate visible minute checks, the hourly strip retains focus and scroll, an unfocused strip retains its scroll, and a focused credit link keeps focus. An ordinary age-only minute update changes the existing age node in place; a structural clock change may rebuild and restore the keyed focus and scroll state. An unchanged unavailable status keeps the same DOM node so a live region is not re-announced. Responsive composition, collision avoidance, range-bar styling and focus appearance belong only to story conformance. *(policy-grade tests: `packages/web/test/e2e/template-weather-real-stack.test.ts`, “keeps forecast semantics, focus, scroll, keyboard movement, and credit usable”, “renders loading, empty and all uncached provider failures, then retries”, and “ignores bad caches, rejects unreadable roots, and recovers after real store unavailability”)* ^weather-ui-ac-accessibility

- **Acceptance — provider failure with and without saved weather.** Under [Fetching, saved weather, and failure](../../../specs/ui/templates/weather.mdx#fetching-saved-weather-and-failure), start once with a stale compatible saved forecast and once without a forecast. Fail the scripted refresh in the saved case; it keeps exactly that weather with its unchanged honest age and no error message or store change. In separate uncached passes, serve the exact status, CORS headers and JSON body from `test/fixtures/weather/open-meteo/error-latitude-out-of-range.json` for the exact request made for the configured valid location; return malformed JSON by editing only a success capture's body and retaining its captured status and headers; and abort the network request.
