# Weather template (UI) — proof

Proves [specs/ui/templates/weather.mdx](../../../specs/ui/templates/weather.mdx).

## Coverage model

Browser acceptance opens Weather artifacts created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox, loads the served resource SDK, reads and writes a real JSON store according to access, and performs its production fetch. No test replaces the DOM, store, SDK, date/time formatter or time-zone database.

Default tests intercept every Open-Meteo request with the captured fixtures declared by the [Weather architecture proof](../../arch/templates/weather.md). This mocks the provider and public network, forfeiting live service behavior to its [opt-in live seam](../../arch/templates/weather.md#^templates-weather-live-provider). It does not replace the page's fetch, CORS handling, response normalization, cache transaction or rendering. Each expected method, URL, query and response, delay or failure is scripted; any unexpected provider or other external request fails.

Most ready-state and conformance setup uses a fresh compatible saved-forecast fixture so the browser reaches deterministic rendering without a provider attempt. This exercises the real saved-cache parser, selection and rendering, but forfeits response normalization to the architecture contracts and fetch/save acceptances. Loading, unavailable, failed refresh, creation, read-only and access cases use the real fetch path with intercepted provider responses.

Time-zone acceptance runs with browser and forecast zones on opposite sides of UTC in both directions, including an `Asia/Kolkata` half-hour zone and an `America/New_York` response spanning the 2026 fallback. One browser uses a non-English locale. Raw provider cases reach daily dates through `utc_offset_seconds`; a compatible saved-cache case supplies a non-hour instant. Expected hour, weekday and date labels are authored literals, never generated with the browser locale or `new Date('YYYY-MM-DD')`.

Most clock cases use Playwright's controlled browser clock, which replaces wall-clock passage and forfeits real scheduler cadence. A rollover case advances that clock while the real page timer and derivation run, proving the page updates within the specified minute. The new-Weather and current-values acceptances use the actual browser clock with response values relative to it, establishing that production reads it.

The shared forwarding proxy may delay the first real resource result, sever an established connection and refuse reconnection. It changes delivery timing without fabricating resource values, access or recovery. A saved-data-unavailable case keeps that proxy on the browser-facing address while the real server stops, the saved store file becomes unreadable, and the server restarts on the same home. The resource proofs own transport, authorization, durability and reconnection mechanics. Standard CSS-motion disablement forfeits the loading spinner animation only.

One conformance file compares every one of the 25 exported Weather stories with a copied production page. Storybook is built from the same worktree. Comparisons use real Chromium, the complete `.weather-page` root outside the app shell, matching viewport and appearance, completed story setup, deterministic stores and fixed clocks for populated states. Conformance owns gradients, first-party artwork, white type, typography, spacing, panels, range bars, attribution, shadows and responsive composition; behavior assertions own selection, requests, live changes, access and recovery.

Appearance acceptance selects a real non-default bundled theme and dark appearance. It covers a populated card and all four placeholder states. The phrase “Typography and spacing still use the foundation” supports two readings until Rupert decides whether that means the active theme's foundation font or the default foundation font. The acceptance holds under either reading and does not decide between them; [the working plan](../../../docs/working/weather-plan.md#open-questions-for-rupert) records the question.

## Test hooks

No production test hook is required. Starting values, captured provider responses, fixed clocks, locales, time zones and viewport sizes are fixtures or browser configuration.

The provider interception and connection proxy are mocks with the forfeits declared above. Passing Television traffic is unchanged. Browser observation may record requests, store operations, accessibility output and DOM mutations without replacing page handlers or content.

Unless a size is explicitly called a reference-pixel size, browser assertions use the artifact document's CSS viewport. The stage and browser viewport are large enough to contain it without scaling or clipping.

First, run a `de-DE` browser in `America/Los_Angeles` at `2026-10-27T20:00:00Z` and serve the captured `Asia/Kolkata` response, where the forecast date is 28 October while browser and UTC dates are 27 October. The first stored hourly entry after `Now` is 2 AM Kolkata, and daily rows use `Today` for 28 October. In a separate fresh compatible saved forecast at the same instant, include 1:00 AM, 1:45 AM, 2:00 AM and 2:30 AM Kolkata entries: both 1 AM entries are absent, 2 AM is retained, and 2:30 AM includes minutes. Second, run a browser in `Pacific/Auckland` at `2026-11-01T02:30:00Z` and serve the captured `America/New_York` response spanning fallback, where the forecast date is 31 October while browser and UTC dates are 1 November. Its retained daily rows run from `Today` on 31 October through 2 November, so weekdays and high/low exercise dates normalized with the response's fixed `utc_offset_seconds` across the offset change. The first hourly cell says `Now` and uses current temperature, condition and day/night. Later labels are literal `en-US` clock times at the forecast zone; weekdays and all other copy remain English under `de-DE`. Expected labels are authored literals with the stories' ordinary U+0020 before `AM` or `PM`. The architecture contracts own conversion, ordering, duplicates and limits. *(test to be written)* ^weather-ui-ac-time-zones
- **Acceptance — clock rollover while open.** Under [current conditions](../../../specs/ui/templates/weather.mdx#current-conditions) and [Size](../../../specs/ui/templates/weather.mdx#size), open a fresh saved forecast at 760×740 in an `America/Los_Angeles` browser for `Asia/Kolkata`. - **Acceptance — first result, empty location and first fetch.** Under [Opening and an empty location](../../../specs/ui/templates/weather.mdx#opening-and-an-empty-location), hold the first real store result after the document and SDK load: the page exposes one status region named `Loading weather`. - **Acceptance — provider failure with and without saved weather.** Under [Fetching, saved weather, and failure](../../../specs/ui/templates/weather.mdx#fetching-saved-weather-and-failure), start once with a stale compatible saved forecast and once without a forecast. Fail the scripted provider request. The saved case keeps exactly that weather with its unchanged honest age and no error message or store change. The uncached case becomes a status region named `Forecast unavailable` with the warning icon and specified retry copy. Before 15 minutes, no retry starts; at the next eligible check it returns to loading, and a success restores and saves weather. Provider interception forfeits the live failure to the architecture live seam. *(test to be written)* ^weather-ui-ac-failure
- **Acceptance — read-only, disconnection and revocation.** Under [Changes, access, and disconnection](../../../specs/ui/templates/weather.mdx#changes-access-and-disconnection), open a configured read-only share without a cache. It fetches and displays its own result and scrolling behavior without a store write. For an owner page, sever and refuse the real Television connection after weather appears; the page retains it, and an eligible scripted provider refresh changes the in-memory display without saving. Change configuration through another real client, reconnect and observe the new configuration and forecast. Revoke a share with weather and retain exactly what it showed; no later provider request starts. In separate passes, revoke during the first delayed fetch and revoke after an uncached failure: abort or release the response and advance the retry interval, but the page remains `Loading weather`, no late response appears and no request starts. - **Acceptance — unreadable configuration, bad cache and unavailable store.** Under [Data the page cannot read](../../../specs/ui/templates/weather.mdx#data-the-page-cannot-read), replace valid configuration with malformed configuration through the real API. Separately, configure a valid location with an invalid or incompatible saved `forecast`: the page ignores only the cache, fetches, displays and replaces it on successful save. For store unavailability, keep the forwarding proxy open while stopping the server, make the real saved store bytes unreadable and restart on the same home. The page receives the real unavailable result, shows the same alert and starts no provider request. Repair and restart through the same proxy; weather returns without reload. The connection proxy forfeits only the deliberately unavailable Television path. *(test to be written)* ^weather-ui-ac-invalid
