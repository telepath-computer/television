# Weather template (UI) — proof

Proves [specs/ui/templates/weather.mdx](../../../specs/ui/templates/weather.mdx).

## Coverage model

Browser acceptance opens Weather artifacts created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox, loads the served resource SDK, and reads a real JSON store. Forecast fixtures are written through production HTTP or spawned `tv resource json` commands. No test replaces the DOM, store, SDK, date/time formatter or time-zone database, and the browser is denied external network access.

Time-zone acceptance runs with the browser and forecast on opposite sides of UTC in both directions: a `de-DE` browser in `America/Los_Angeles` displays an `Asia/Kolkata` forecast, and a browser in `Pacific/Auckland` displays an `America/New_York` forecast. Each fixed instant puts the forecast on a calendar date different from both the browser date and the UTC date. Kolkata also makes the forecast clock-hour boundary differ from UTC and browser hour boundaries. Expected hour and weekday strings are literal `en-US` values rather than values generated with the browser locale or `new Date('YYYY-MM-DD')`, so the test cannot repeat either defect it is meant to catch. The architecture proof separately covers offset parsing, stable sorting, limits, duplicates and the repeated hour at daylight-saving fallback.

Most clock cases fix the browser clock, which replaces wall-clock passage and forfeits scheduler timing. A rollover case advances that controlled browser clock through an hour and a forecast-zone midnight while the real page timers and derivation run; it proves the page reacts within the specified minute, not the cadence or jitter of real elapsed time. The new-Weather and current-values acceptances use the actual browser clock with forecast values relative to it, establishing that the production clock reaches the page.

The [shared forwarding proxy](./checklist.md#test-hooks) may delay the first real resource result, sever an established connection and refuse reconnection. It changes delivery timing without fabricating resource values, access or recovery. A saved-data-unavailable case keeps that proxy on the browser-facing address while it stops the real server, damages and later repairs the saved store file, and follows the server across restarts on the same home. These cases establish the page response; the resource proofs own transport, authorization, durability and reconnection mechanics. Standard CSS-motion disablement forfeits the loading spinner animation, which the spec does not promise.

One conformance file compares every exported Weather story with a copied production page served by a running Television server. Storybook is built from the same worktree. Comparisons use real Chromium, the complete `.weather-page` root outside the app shell, matching viewport and appearance, completed story setup, deterministic store values and a fixed clock for every populated state. Conformance owns gradients, artwork, typography, spacing, panels, range bars, shadows and responsive composition; behavior assertions own data selection, live changes, access and recovery.

Appearance acceptance selects a real non-default bundled theme and dark appearance. It covers a populated card and every placeholder state because the single dark conformance story covers only the populated clear-day design. The phrase “Typography and spacing still use the foundation” may mean either the foundation values selected by the active theme or the default foundation values. Nord does not distinguish those readings. The acceptance below holds for both and does not decide between them; [the working plan](../../../docs/working/weather-plan.md#open-questions-for-rupert) records the question for Rupert.

## Test hooks

The server receives the real built resource SDK path allowed by [SDK packaging](../../../specs/arch/resources/sdk.md#^sdk-packaging); production resolves the same bundle from the installed package.

Playwright configures the browser locale and time zone and may control its clock. Production uses the host browser locale, time zone and clock. Locale and time-zone configuration replace no `Intl` logic. Clock control forfeits real wall-clock passage as described above; the page's formatter, selection code and timer callback remain production code. Every populated conformance state fixes the clock to the instant that yields the story labels; this is the same declared exception, not a generated label oracle.

The shared forwarding proxy may hold the first resource result or close and refuse connections. Passing traffic is unchanged. Browser observation may record requests, SDK operations, accessibility output and DOM mutations without replacing page handlers or rendered content.

## Entry and current conditions

Unless stated otherwise, each acceptance uses the real browser/server/store boundary, authored forecast fixtures and no mocks beyond the standard CSS-motion override.

- **Acceptance — new Weather and live forecast.** Under [the empty state](../../../specs/ui/templates/weather.mdx#opening-and-an-empty-forecast) and [changes](../../../specs/ui/templates/weather.mdx#changes-access-and-disconnection), use the actual browser clock and build forecast timestamps relative to it. The created artifact has a 340-by-340 reference-pixel page, transparent frame, `{}` seed and the empty copy, and opening makes no store write. Use a spawned `tv resource json set` command to replace the whole root; place, sky and current conditions update together without reopening. Resize to 760×740 before a second complete replacement, then observe the place, sky, current conditions, hourly panel and daily panel change together. The browser requests no external weather data. The store-operation observations in [the architecture live-store assertion](../../arch/templates/weather.md#^templates-weather-ac-live) belong to this same browser test; [the delivery seam](../../arch/templates/weather.md#^templates-weather-t-delivery) separately proves independent asset delivery. *(test to be written)* ^weather-ui-ac-new
- **Acceptance — current values and age.** Under [Current conditions](../../../specs/ui/templates/weather.mdx#current-conditions), use the actual browser clock with forecast timestamps relative to it and open the 760×740 large layout. A complete forecast shows the place, `Updated` age and selected unit, rounded current temperature, condition name and summary. Cross the browser boundary once for each rendered position—current, hourly, daily low and daily high—with fixtures that collectively include positive and negative halves and a value that would otherwise display as negative zero. The high-and-low line uses only the current forecast-zone date and disappears when that entry is absent. Ages cover now, singular and plural minutes, hours and days, and future clock skew. Current values, high/low and age update in place without a page write. The architecture contracts carry calculation breadth; this assertion proves the values reach the page with the specified English forms. *(test to be written)* ^weather-ui-ac-current

## Time zones and forecast windows

- **Acceptance — forecast time zones on both sides of UTC.** Under [medium and large layout](../../../specs/ui/templates/weather.mdx#size), open the 760×740 large layout and fix the browser clock for two real-browser cases. First, run a `de-DE` browser in `America/Los_Angeles` at `2026-11-04T20:00:00Z` while displaying `Asia/Kolkata`, where the forecast date is 5 November and both the browser and UTC dates are 4 November. Second, run a browser in `Pacific/Auckland` at `2026-11-05T02:00:00Z` while displaying `America/New_York`, where the forecast date is 4 November and both the browser and UTC dates are 5 November. The first hourly cell says `Now` and uses `temperature`, `condition` and `isDay` from `current`. Later labels are literal `en-US` clock times at the forecast `timeZone`: Kolkata fixtures include local-hour entries and a half-hour entry, so the case distinguishes forecast-hour boundaries from UTC and browser boundaries and distinguishes `11 AM` from `11:00 AM`. The expected time labels copy the ordinary U+0020 space before `AM` or `PM` used by the stories. Daily rows use `Today` only for the forecast-zone current date and otherwise literal `en-US` weekdays; English copy remains English under `de-DE`. High and low come from that same date. The expected labels are authored literals, not output from the page's date conversion. Assert the retained first entries and limits selected by [the architecture window contract](../../arch/templates/weather.md#^templates-weather-t-windows), without duplicating all contract permutations. *(test to be written)* ^weather-ui-ac-time-zones
- **Acceptance — clock rollover while open.** Under [current conditions](../../../specs/ui/templates/weather.mdx#current-conditions) and [Size](../../../specs/ui/templates/weather.mdx#size), open the 760×740 large layout and use the declared browser clock control to cross the end of a forecast-zone hour and then the forecast-zone midnight at an instant that is not the browser midnight. Without reloading or writing the store, the hourly window and labels advance within one minute; the daily window drops the prior date, moves `Today`, and refreshes the displayed high and low within one minute; and the age reaches the next completed unit within one minute. Store-operation observation records no page write. The browser zone differs from the forecast zone. Clock control forfeits real wall-clock scheduler timing, not the production timer callback or derivation. *(test to be written)* ^weather-ui-ac-clock

## Size, panels and accessibility

- **Acceptance — responsive composition and panel independence.** Under [Size](../../../specs/ui/templates/weather.mdx#size), resize populated artifacts across 230×230, 280×280, the 340×340 default, 760×300, 400×740, 600×480, 900×600, 700×780 and 760×740. The 760×300 and 400×740 cases pass only one medium threshold and remain small; 900×600 and 700×780 pass only one large threshold and remain medium. At 230×230 and 760×300, element bounds and scroll extents show that a three-character reading, condition artwork, summary and high/low stay inside the card without intersecting. At medium and large sizes, omit the hourly panel when the hourly window contains no stored entries after `Now`; at 760×740, keep a non-empty daily panel in that state. Separately, provide future hours but no daily rows at 760×740 and assert that the card retains the medium current/hourly composition without a reserved lower band. Daily rows fit at the exact large threshold. Add valid eighth and ninth stored dates with extreme temperatures and assert that the retained seven rows and their range bars use only the displayed lows and highs. Conformance owns exact styling and shadow clipping; this acceptance checks thresholds, panel presence, element bounds, scroll extents and collision outcomes. *(test to be written)* ^weather-ui-ac-size
- **Acceptance — forecast semantics and keyboard reach.** Under [Size](../../../specs/ui/templates/weather.mdx#size), open the exact 760×740 large boundary. The hourly strip is focusable and named `Hourly forecast; scroll for later hours`. Send real right-arrow input until the strip scroll offset changes and the final hourly cell intersects the visible strip. Hourly cells expose local time, condition and temperature. A daily panel heading counts its displayed rows, its rows expose `Today` or weekday, condition, low and high, and its visual range bars add no separate accessible meaning. The first and last daily row bounds remain within the daily panel scroll area. *(test to be written)* ^weather-ui-ac-accessibility

## Loading, access and recovery

- **Acceptance — first result and empty value.** Under [Opening and an empty forecast](../../../specs/ui/templates/weather.mdx#opening-and-an-empty-forecast), hold the first real store result after the document and SDK load. The page exposes one status region named `Loading weather`. Release an empty object and observe the empty glyph, heading and agent prompt. Repeat with no store value. Neither state writes or invents data. *(test to be written)* ^weather-ui-ac-loading
- **Acceptance — read-only, disconnection and access loss.** Under [Changes, access, and disconnection](../../../specs/ui/templates/weather.mdx#changes-access-and-disconnection), open a populated read-only share and observe the same forecast and scrolling behavior as the artifact owner, with no writes. Sever and refuse the real connection after a forecast appears; the page retains exactly that forecast without a message. Change the store through another real client, reconnect and observe the new forecast. Revoke access and retain the last forecast. In two separate passes, sever the connection before the first result and revoke the share before the first result; loading remains in each. Store-operation observation records no page write during disconnection, reconnection or revocation. No access state or store result is injected. *(test to be written)* ^weather-ui-ac-access
- **Acceptance — unreadable data and recovery.** Under [Data the page cannot read](../../../specs/ui/templates/weather.mdx#data-the-page-cannot-read), replace a valid root with one malformed complete value through the real API. An alert replaces every forecast panel with the warning icon, heading and specified guidance; the stored value remains unchanged and the page makes no repair write. Repair it and observe recovery without reopening. Repeat from initial load and with `null`; `{}` reaches the empty state instead. [The architecture validity contract](../../arch/templates/weather.md#^templates-weather-t-validity) owns malformed-value breadth. *(test to be written)* ^weather-ui-ac-invalid
- **Acceptance — saved data unavailable.** Under [Data the page cannot read](../../../specs/ui/templates/weather.mdx#data-the-page-cannot-read), keep the forwarding proxy open on the browser-facing address while stopping the server, damaging the real saved store bytes and restarting on the same home. The proxy follows the server across the restart. The open page receives the real unavailable result and shows the same alert, leaving the bytes untouched. Stop, repair and restart again through the same proxy; the forecast returns without a page reload. No storage operation or error response is fabricated. *(test to be written)* ^weather-ui-ac-unavailable
