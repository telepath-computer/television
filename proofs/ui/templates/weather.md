# Weather template (UI) — proof

Proves [specs/ui/templates/weather.mdx](../../../specs/ui/templates/weather.mdx).

## Coverage model

Browser acceptance opens Weather artifacts created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox, loads the served resource SDK, and reads a real JSON store. Forecast fixtures are written through production HTTP or spawned `tv resource json` commands. No test replaces the DOM, store, SDK, date/time formatter or time-zone database, and the browser is denied external network access.

Time-zone acceptance runs with the browser and forecast on opposite sides of UTC in both directions: a browser in `America/Los_Angeles` displays an `Asia/Tokyo` forecast, and a browser in `Pacific/Auckland` displays an `America/New_York` forecast. Fixed instants make expected hours and dates deterministic. Expected weekday strings come from literal calendar-date fixtures rather than `new Date('YYYY-MM-DD')`, so the test cannot repeat the UTC-midnight parsing defect it is meant to catch. The architecture proof separately covers offset parsing, stable sorting, limits, duplicates and the repeated hour at daylight-saving fallback.

Most clock cases fix the browser clock, which replaces wall-clock passage and forfeits scheduler timing. A rollover case advances that controlled browser clock through an hour and a forecast-zone midnight while the real page timers and derivation run; it proves the page reacts to timer delivery, not the cadence or jitter of real elapsed time. Other browser cases load from the actual current clock with relative fixtures, establishing that the production clock reaches the page.

The shared forwarding proxy may delay the first real resource result, sever an established connection and refuse reconnection. It changes delivery timing without fabricating resource values, access or recovery. A saved-data-unavailable case stops the real server, damages and later repairs the saved store file, and restarts on the same home. These cases establish the page response; the resource proofs own transport, authorization, durability and reconnection mechanics. Standard CSS-motion disablement forfeits the loading spinner animation, which the spec does not promise.

One conformance file compares every exported Weather story with a copied production page served by a running Television server. Storybook is built from the same worktree. Comparisons use real Chromium, the complete `.weather-page` root outside the app shell, matching viewport and appearance, completed story setup and deterministic store/time fixtures. Conformance owns gradients, artwork, typography, spacing, panels, range bars, shadows and responsive composition; behavior assertions own data selection, live changes, access and recovery.

## Test hooks

The server receives the real built resource SDK path allowed by [SDK packaging](../../../specs/arch/resources/sdk.md#^sdk-packaging); production resolves the same bundle from the installed package.

Playwright configures the browser time zone and may control its clock. Production uses the host browser time zone and clock. Time-zone configuration replaces no `Intl` logic. Clock control forfeits real wall-clock passage as described above; the page's formatter, selection code and timer callback remain production code.

The shared forwarding proxy may hold the first resource result or close and refuse connections. Passing traffic is unchanged. Browser observation may record requests, SDK operations, accessibility output and DOM mutations without replacing page handlers or rendered content.

## Entry and current conditions

Unless stated otherwise, each acceptance uses the real browser/server/store boundary, authored forecast fixtures and no mocks beyond the standard CSS-motion override.

- **Acceptance — new Weather and live forecast.** Under [the empty state](../../../specs/ui/templates/weather.mdx#opening-and-an-empty-forecast) and [changes](../../../specs/ui/templates/weather.mdx#changes-access-and-disconnection), open Toolbox, observe the supplied Weather icon and choose it. The created artifact has a 340-by-340 reference-pixel page, transparent frame, `{}` seed and the empty copy, and opening makes no store write. Use a spawned `tv resource json set` command to replace the whole root; place, sky, current conditions and applicable panels update together without reopening. A second complete replacement updates them together again. The browser requests no external weather data. [The architecture seam](../../arch/templates/weather.md#^templates-weather-ac-live) carries the store-operation observations and independent asset delivery. *(test to be written)* ^weather-ui-ac-new
- **Acceptance — current values and age.** Under [Current conditions](../../../specs/ui/templates/weather.mdx#current-conditions), a complete forecast shows the place, `Updated` age and selected unit, rounded current temperature, condition name and summary. Table-driven updates cover halves on both sides of zero and values that would round to negative zero. The high-and-low line uses only the current forecast-zone date and disappears when that entry is absent. Ages cover now, singular and plural minutes, hours and days, and future clock skew. Current values, high/low and age update in place without a page write. The architecture contracts carry calculation breadth; this assertion proves the values reach the page with the specified English forms. *(test to be written)* ^weather-ui-ac-current

## Time zones and forecast windows

- **Acceptance — forecast time zones on both sides of UTC.** Under [medium and large layout](../../../specs/ui/templates/weather.mdx#size), run two real-browser cases: `America/Los_Angeles` viewing `Asia/Tokyo`, and `Pacific/Auckland` viewing `America/New_York`. At fixed instants, the first hourly cell says `Now` and uses `temperature`, `condition` and `isDay` from `current`; later labels are `en-US` clock times at the forecast `timeZone`, including minutes for a half-hour entry. Daily rows use `Today` only for the forecast-zone current date and otherwise the fixture's literal `en-US` weekday. High and low come from that same date. Include a date for which parsing `YYYY-MM-DD` as UTC and formatting it in the west-of-UTC browser would produce the previous weekday. The expected labels are literal fixture values, not output from the page's date conversion. Assert the retained first entries and limits selected by [the architecture window contract](../../arch/templates/weather.md#^templates-weather-t-windows), without duplicating all contract permutations. *(test to be written)* ^weather-ui-ac-time-zones
- **Acceptance — clock rollover while open.** Under [current conditions](../../../specs/ui/templates/weather.mdx#current-conditions) and [Size](../../../specs/ui/templates/weather.mdx#size), use the declared browser clock control to cross the end of a forecast-zone hour and then local midnight without reloading or writing the store. The hourly window and its labels advance; the daily window drops the prior date, moves `Today`, and refreshes the displayed high and low; the age advances to the next completed unit. The browser zone differs from the forecast zone. Clock control forfeits wall-clock scheduler timing, not the production timer callback or derivation. *(test to be written)* ^weather-ui-ac-clock

## Size, panels and accessibility

- **Acceptance — responsive composition and panel independence.** Under [Size](../../../specs/ui/templates/weather.mdx#size), resize one populated artifact across 230×230, 280×280, the 340×340 default, 590×230, 600×480 and 760×740. Below either medium threshold only current conditions appear. At 230×230 and 590×230, a three-character reading, condition artwork, summary and high/low stay inside the card without overlap or clipped shadow. Medium shows the horizontally scrollable hourly panel only when at least one stored future entry remains. Large shows the daily panel only when its daily window is nonempty; with no daily rows it retains the medium current/hourly composition instead of a reserved lower band. Daily rows fit at the exact large threshold. Empty hourly and daily arrays remain readable. Conformance owns exact geometry and styling; this acceptance checks threshold selection, panel presence, overflow and collision outcomes. *(test to be written)* ^weather-ui-ac-size
- **Acceptance — forecast semantics and keyboard reach.** Under [Size](../../../specs/ui/templates/weather.mdx#size), the hourly strip is focusable and named `Hourly forecast; scroll for later hours`; real arrow-key input reaches later off-screen entries. Hourly cells expose local time, condition and temperature. A daily panel heading counts its displayed rows, its rows expose `Today` or weekday, condition, low and high, and its visual range bars add no separate accessible meaning. The first and last daily rows remain reachable at the large boundary. *(test to be written)* ^weather-ui-ac-accessibility

## Loading, access and recovery

- **Acceptance — first result and empty value.** Under [Opening and an empty forecast](../../../specs/ui/templates/weather.mdx#opening-and-an-empty-forecast), hold the first real store result after the document and SDK load. The page exposes one status region named `Loading weather`. Release an empty object and observe the empty glyph, heading and agent prompt. Repeat with no store value. Neither state writes or invents data. *(test to be written)* ^weather-ui-ac-loading
- **Acceptance — read-only, disconnection and access loss.** Under [Changes, access, and disconnection](../../../specs/ui/templates/weather.mdx#changes-access-and-disconnection), open a populated read-only share and observe the same forecast and scrolling behavior as the artifact owner, with no writes. Sever and refuse the real connection after a forecast appears; the page retains exactly that forecast without a message. Change the store through another real client, reconnect and observe the new forecast. Revoke access and retain the last forecast. In a separate pass, sever or revoke before the first result arrives: loading remains. No access state or store result is injected. *(test to be written)* ^weather-ui-ac-access
- **Acceptance — unreadable data and recovery.** Under [Data the page cannot read](../../../specs/ui/templates/weather.mdx#data-the-page-cannot-read), replace a valid root with one malformed complete value through the real API. An alert replaces every forecast panel with the warning icon, heading and specified guidance; the stored value remains unchanged and the page makes no repair write. Repair it and observe recovery without reopening. Repeat from initial load and with `null`; `{}` reaches the empty state instead. [The architecture validity contract](../../arch/templates/weather.md#^templates-weather-t-validity) owns malformed-value breadth. *(test to be written)* ^weather-ui-ac-invalid
- **Acceptance — saved data unavailable.** Under [Data the page cannot read](../../../specs/ui/templates/weather.mdx#data-the-page-cannot-read), stop the server, damage the real saved store bytes and restart on the same home. The open page receives the real unavailable result and shows the same alert, leaving the bytes untouched. Stop, repair and restart again; the forecast returns without a page reload. No storage error or response is fabricated. *(test to be written)* ^weather-ui-ac-unavailable
