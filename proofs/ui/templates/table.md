# Table template (UI) — proof

Proves [specs/ui/templates/table.mdx](../../../specs/ui/templates/table.mdx).

## Coverage model

Browser acceptance opens a Table created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox and loads the served resource SDK. Store changes cross real HTTP or WebSocket connections into the real JSON store; administrative reads confirm saves. Fixtures are the bundled seed and authored table values written through production commands or APIs.

Pure contracts exercise selection, navigation and post-structure selection through the production Table selection model. Real Chromium then walks each main pointer, keyboard, menu and structure path once, and owns clipboard, focus, accessibility and scrolling behavior. No browser case substitutes the DOM, SDK, menu element or page markup. Behavior tests use the standard CSS-motion override and forfeit motion. Conformance keeps CSS motion real, injects nothing into either rendered document, and uses the story markup with foundation styles; the stories import no production Table or menu code.

Focus-loss coverage moves between real artifacts and browser pages. It does not claim to reproduce every operating-system application switch.

Fault cases use the forwarding proxy or real saved files declared below. Passing messages are unchanged. Accessibility evidence covers exposed roles, names, positions, selection, focus and status-region update order, not spoken output from every screen reader.

The [Table architecture proof](../../arch/templates/table.md) owns schema, tolerant-reading and ordering breadth, drawn-position identity, write plans and exact operation paths. This proof walks the user paths that consume those contracts. [Resource SDK](../../arch/resources/sdk.md) and [JSON store](../../arch/resources/json-store.md) proofs own transport, rollback, transaction and durability mechanics; the cases here prove the page response.

Conformance compares every exported [Table story](../../../storybook/spec/templates/table/table.stories.ts), including exports not embedded in the MDX page, with production in the same state. It runs against Storybook built from this worktree and the copied Table served by a running server. It compares the complete `.table-page` root at the story viewport and light or dark appearance after deterministic story and production setup. It lets `conform` settle real CSS motion before capture.

## Test hooks

The server receives the real built `sdkDir` allowed by [SDK packaging](../../../specs/arch/resources/sdk.md#^sdk-packaging); production resolves the same bundle from the installed package.

The production Table selection model exposes pure transition functions consumed by the page. Contract tests call those exports with authored display and selection states; no test-only branch or DOM replacement is used.

The shared forwarding proxy may hold initial resource messages, record or hold an ordinary page write or its acknowledgement, hold a transaction attempt, sever a connection and refuse reconnection. Production forwards each message immediately. Held messages remain unchanged, so the controls change timing or reachability without replacing subscription, authorization, writes, acknowledgements, rollback, transactions or reconnect.

For a refused save, selective WebSocket buffering holds the access notification while forwarding the later real write rejection, then releases the notification. The server normally sends access first. This message-order mock forfeits ordinary access ordering to [access acceptance](#^table-ac-access); it replaces neither authorization nor rollback.

Clipboard fixtures use the real browser clipboard. Damaged-file cases stop the server before changing the real saved file and restart it through the existing server harness.

## Entry, display and editing

Unless stated otherwise, each acceptance uses the real browser, copied page, running server, SDK and store described above, with no mocks beyond the CSS-motion override.

- **Acceptance — new Table and first edit.** Under [A new table](../../../specs/ui/templates/table.mdx#a-new-table), choose Table in the real Toolbox and observe the supplied icon. The new artifact uses the shared display defaults, persists exactly `{"columns":{},"rows":{}}`, shows an unfocused four-by-four grid without a header and makes no page write merely by opening. Select B3, type a value and press Return: the commit stores columns A–B and rows 1–3, leaves the other drawn positions unstored, selects B4 and survives reload. Move the installed template out of discovery before reload and another edit to carry [independent delivery](../../arch/templates/table.md#^templates-table-t-assets). *(test to be written)* ^table-ac-new
- **Acceptance — rows, columns and layout.** Under [Rows, columns and cells](../../../specs/ui/templates/table.mdx#rows-columns-and-cells), write ordered columns and rows containing representative string, number, boolean, empty and multiline cells through the API. Display stored entries in order followed by drawn positions up to four, with headers on and off, unnamed headers, blank empty cells, one-line ellipsis and line breaks shown as spaces. There is no search or sort control. With enough wide data, scroll both ways and observe that the header and strips remain with the visible grid. The [architecture contracts](../../arch/templates/table.md#^templates-table-t-model) cover malformed-entry and type breadth; this walk crosses representative values into the page. *(test to be written)* ^table-ac-rows
- **Acceptance — cell and header editing.** Under [Editing cells and headers](../../../specs/ui/templates/table.mdx#editing-cells-and-headers), click a body cell and type to replace its text; separately open existing text with double-click, Return and F2 and observe the caret at the end. While the editor is open, arrow keys move its caret without moving the grid selection, and Shift-Space and Ctrl-Shift-Space type normally instead of selecting an axis. Exercise Return, Shift-Return, Tab and Shift-Tab through header and body cells, including each outer edge, without creating entries at an edge. Click another target to commit before its action; click outside the table control and its open menu to commit and clear selection; leave the artifact by keyboard or move to another artifact or browser page to commit while preserving selection. Escape cancels to the current stored value and keeps the cell selected; a second Escape clears it. Edit a header with the same rules. Preserve pasted line breaks and ordinary field copy, paste, selection and native undo; after commit, the page offers no undo action. *(test to be written)* ^table-ac-editing

## Selection, keyboard and structure

- **Contract — selection and navigation state** (authored displayed axes, selection states and actions → production Table selection model; DOM and SDK absent, no mocks): Under [selection](../../../specs/ui/templates/table.mdx#selecting-cells-rows-and-columns), [keyboard behavior](../../../specs/ui/templates/table.mdx#keyboard-and-assistive-technology), [structure changes](../../../specs/ui/templates/table.mdx#adding-inserting-and-deleting-structure) and [live changes](../../../specs/ui/templates/table.mdx#changes-from-elsewhere), cover body, header, row and column selection; Shift ranges and axis switching; body/header and whole-axis arrow movement; Left and Right doing nothing on a row selection and Up and Down doing nothing on a column selection; range collapse to its anchor before movement; Shift extension and shrinking; Tab movement and edge exit; Shift-Space and Ctrl-Shift-Space; and the other no-op keys for whole-axis selection. A body-cell menu request selects its row, while a header-cell request selects its column. Live reorder follows stored keys; removed, hidden, noncontiguous or changed-identity selections clear as specified. Adding selects the cell at the prior body-cell position on the other axis or the first position; inserting selects one new whole row or column; deleting selects the former position or the new last position; clearing contents leaves selection unchanged. *(policy-grade test: `packages/server/test/table-selection-model.test.ts`, “Table selection model”)* ^table-t-selection-model
- **Acceptance — pointer selection.** Under [Selecting cells, rows and columns](../../../specs/ui/templates/table.mdx#selecting-cells-rows-and-columns), click a body cell, a header cell and each strip. Build one Shift-click row range, then switch to a column selection. Observe the specified cell, related-strip, whole-axis and range treatments. Clicking outside the table control and its open menu clears selection, while moving focus away and back preserves it. Escape closes an open Table menu without clearing selection; with no menu it clears selection and moves focus to the grid, where an arrow selects the first body cell. *(test to be written)* ^table-ac-selection
- **Acceptance — keyboard and accessibility.** Under [Keyboard and assistive technology](../../../specs/ui/templates/table.mdx#keyboard-and-assistive-technology), Tab into a retained selection and into an unselected table, move once between the body and header, select one row and one column with the keyboard, and leave at an outer edge without a trap. Assert the grid, cells, editors, strip buttons and add controls expose the specified roles, names, positions and selection, including an unnamed header. Only the anchor strip item of a range can receive focus; hidden strip items and add controls are absent from the Tab order. Real focus shows the cell or strip focus treatment. The [selection contract](#^table-t-selection-model) carries navigation breadth. *(test to be written)* ^table-ac-keyboard
- **Acceptance — clearing, adding and structure menus.** Under [Clearing contents](../../../specs/ui/templates/table.mdx#clearing-contents) and [Adding, inserting, and deleting structure](../../../specs/ui/templates/table.mdx#adding-inserting-and-deleting-structure), clear one selected cell and one selected column, leaving its name. Use one add control, insert one entry, delete one selection and toggle the header once; the [selection contract](#^table-t-selection-model) carries the symmetric and post-action cases. While editing, right-click a strip item and observe that the edit commits before selection and menu opening. Open a row menu by right-click; from a body cell and a header cell, use Shift-F10 to open the row and column menus, and use the context-menu key on an existing whole-axis selection. Assert canonical menu content, order, danger treatment, the missing Delete item for an all-drawn selection, and a mixed stored/drawn range whose singular or plural Delete label counts only the stored entries. Right-click inside a range retains it, right-click outside selects one item, and Escape dismisses the menu. With an editor open, right-click another body or header cell, then right-click and use both menu keys inside the editor; no Table menu opens, and none of these gestures commits or changes the selection. *(test to be written)* ^table-ac-structure

## Live data and access

- **Acceptance — agent changes and concurrent editing.** Under [Changes from elsewhere](../../../specs/ui/templates/table.mdx#changes-from-elsewhere), use spawned `tv resource json` commands and a second real viewer to edit unrelated cells, names, orders and membership while the first viewer selects or edits. Changes outside the active field appear immediately; the local text and caret survive a change to that field until commit or cancel, and controlled writes settle by real last-write-wins ordering. An unchanged commit makes no write and reveals the latest stored value. Reorder one selected entry and observe that selection follows its key; remove it while its menu is open and observe that both selection and menu close. Open an editor on a cell in a stored row, remove that row through an agent command, and observe the selection and editor close without a write. The [selection contract](#^table-t-selection-model) carries the other live selection transitions. Hiding the header closes its editor. Change the displayed stored count while a person types in a drawn position: the selection clears, the editor closes, the typed text is discarded and no write starts. Separately edit a stored cell while an agent writes another path and confirm both persist. This also executes representative commands taught by the README. *(test to be written)* ^table-ac-live
- **Acceptance — read-only and changed access.** Under [Read-only and access loss](../../../specs/ui/templates/table.mdx#read-only-and-access-loss), open a real read-only share with populated and empty data. Selection and navigation remain; editing, clearing, add controls and menus are unavailable. Agent changes still appear. Upgrade the same link and save, then downgrade while an editor and separately a menu are open: each closes without writing and the last confirmed value remains. Restore write access and save a fresh edit. Revoke the link after readable data has arrived while an editor is open: it closes, and the last table remains read-only. No access state is injected. *(test to be written)* ^table-ac-access

## Loading, disconnection and failures

- **Acceptance — first load.** Under [Opening a table](../../../specs/ui/templates/table.mdx#opening-a-table), hold initial resource messages after the real document and SDK load. The centred activity icon appears with no grid. Sever and refuse the connection before releasing data: the loading state remains and `Reconnecting…` appears in an established status region. Restore the real connection and observe the current table without reload. *(test to be written)* ^table-ac-loading
- **Acceptance — disconnection and reconnect.** Under [Saving and disconnection](../../../specs/ui/templates/table.mdx#saving-and-disconnection), sever an established editable connection and refuse new ones. The last table remains, add controls and menus disappear, new editing is disabled, and `Reconnecting…` appears. An editor already open stays usable; every commit gesture leaves it open, does not write or act on the target, and Escape cancels it while preserving selection. Restore connectivity and commit normally. Then commit a changed edit while the proxy holds its write or acknowledgement, so the SDK still reports it pending, and sever the connection. Assert rollback to the confirmed value and that the page does not reopen the editor with the changed text. After reconnection, accept either documented server outcome for the uncertain write. Repeat over an unreadable page. *(test to be written)* ^table-ac-disconnection
- **Acceptance — refused save and failed transaction.** Under [Saving and disconnection](../../../specs/ui/templates/table.mdx#saving-and-disconnection), hold a real write from a read-write share, downgrade access while buffering its notification, and release the write for real refusal. The affected value rolls back and the established status region says `Couldn't save that change.` before clearing after a few seconds. Restore access and save again. Separately hold an insertion transaction, make the selected keys invalid through an agent write and release it: no insertion persists and the same message appears. Disconnect while the message is visible and observe `Reconnecting…` take precedence. Selective buffering forfeits ordinary access-message order as declared above. *(test to be written)* ^table-ac-save-failure

## Unreadable data and recovery

- **Acceptance — tolerant, unreadable and unavailable data.** Under [Data the page cannot read](../../../specs/ui/templates/table.mdx#data-the-page-cannot-read), show a missing and partial root as the corresponding empty or partial grid without a repair write. Write representative ignored entries and cells and observe the readable remainder. Then replace an axis with a non-object while an editor and separately a menu are open: the alert replaces the table with the specified icon, title and guidance; the editor closes without writing and the menu closes. Repair through the API and observe recovery without reload or replay. Lose all access before the first readable value and observe the same alert. Finally stop the server, damage the real saved bytes, restart to receive `unavailable`, then repair and restart; the page recovers without changing the damaged bytes itself. [Architecture contracts](../../arch/templates/table.md#^templates-table-t-model) cover remaining malformed permutations, and [the write guard](../../arch/templates/table.md#^templates-table-t-invalid-guard) covers suppressed operations. *(test to be written)* ^table-ac-unreadable

- **Acceptance — every spec story conforms.** Under [story output](../../../specs/spec-ui.md#^ui-story-output) and [conformance](../../../specs/spec-ui.md#^ui-conformance-test), generate one comparison for every Table story export and fail when any export lacks a production setup. Store fixtures repeat story args through the real API. Real input reaches selection, focus, editing and open-menu states. Reach resting selections by pointer unless the story shows keyboard focus. Click a body cell before using a strip, because strips are hidden without a selection. Before every capture, move the pointer to unused page space outside the table control and any open menu. Keep CSS motion real, inject nothing into either rendered document, and let `conform` settle animations. The save-failure message-order mock is the declared exception; [access acceptance](#^table-ac-access) covers normal ordering. *(test to be written)* ^table-ac-conformance
