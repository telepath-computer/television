# Table template (UI) — proof

Proves [specs/ui/templates/table.mdx](../../../specs/ui/templates/table.mdx).

## Coverage model

Browser acceptance opens a Table created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox and loads the served resource SDK. Store changes cross real HTTP or WebSocket connections into the real JSON store; administrative reads confirm saves. Fixtures are the bundled seed and authored table values written through production commands or APIs.

Pure contracts exercise selection, navigation and post-structure selection through the production Table selection model. Real Chromium then walks each main pointer, keyboard, menu, resize and structure path once, and owns clipboard, focus, accessibility, scrolling behavior and the geometry needed to prove those behaviors. No browser case substitutes the DOM, SDK, menu element or page markup. Behavior tests do not assert appearance. They use the standard CSS-motion override and forfeit motion. Conformance keeps CSS motion real, injects nothing into either rendered document, and uses independent story markup with foundation styles; the stories import no production Table or menu code.

Focus-loss coverage moves between real artifacts and browser pages. It does not claim to reproduce every operating-system application switch. Fault cases use the forwarding proxy or real saved files declared below. Passing messages are unchanged. Accessibility evidence covers exposed roles, names, positions, selection, focus, descriptions and status updates, not spoken output from every screen reader.

The [Table architecture proof](../../arch/templates/table.md) owns schema, tolerant reading and ordering breadth, drawn-position identity, write plans and exact operation paths. This proof walks the user paths that consume those contracts. [Resource SDK](../../arch/resources/sdk.md) and [JSON store](../../arch/resources/json-store.md) proofs own transport, rollback, transaction and durability mechanics; the cases here prove the page response.

Conformance compares every exported [Table story](../../../storybook/spec/templates/table/table.stories.ts), including exports not embedded in the MDX page, with production in the same state. It runs against Storybook built from this worktree and the copied Table served by a running server. It compares the complete `.table-page` root at the story viewport and light or dark appearance after deterministic story and production setup, letting `conform` settle real CSS motion before capture. It is the only automated owner of Table appearance.

The accepted stories do not currently pose a selected header cell while scrolled, vertical-only or horizontal-only scrolling, a scrolled read-only table, overflowing cell text, a populated non-visible resize announcement, or the Toolbox icon at 20 pixels. This proof does not treat behavior-test pixels or computed styles as substitutes for those missing reference states. Rupert decides whether any needs another story.

## Test hooks

The server receives the real built `sdkDir` allowed by [SDK packaging](../../../specs/arch/resources/sdk.md#^sdk-packaging); production resolves the same bundle from the installed package. The production Table selection model exposes pure transition functions consumed by the page; contract tests call them with authored display and selection states, without a test-only branch or DOM replacement.

The shared forwarding proxy may hold initial resource messages, record or hold an ordinary page write or its acknowledgement, hold a transaction attempt, sever a connection and refuse reconnection. Production forwards each message immediately. Held messages remain unchanged, so the controls change timing or reachability without replacing subscription, authorization, writes, acknowledgements, rollback, transactions or reconnect.

For a refused save, selective WebSocket buffering holds the access notification while forwarding the later real write rejection, then releases the notification. The server normally sends access first. This message-order mock forfeits ordinary access ordering to [access acceptance](#^table-ac-access); it replaces neither authorization nor rollback. Clipboard fixtures use the real browser clipboard. Damaged-file cases stop the server before changing the real saved file and restart it through the existing server harness.
