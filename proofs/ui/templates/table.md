# Table template (UI) — proof

Proves [specs/ui/templates/table.mdx](../../../specs/ui/templates/table.mdx).

## Coverage model

Browser acceptance opens a Table created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox and loads the served resource SDK. Store changes cross real HTTP or WebSocket connections into the real JSON store; administrative reads confirm saves. Fixtures are the bundled seed and authored table values written through production commands or APIs.

Pure contracts exercise selection, navigation and post-structure selection through the production Table selection model. Real Chromium then walks each main pointer, keyboard, menu, resize and structure path once, and owns clipboard, focus, accessibility and scrolling behavior. No browser case substitutes the DOM, SDK, menu element or page markup. Behavior tests use the standard CSS-motion override and forfeit motion. Conformance keeps CSS motion real, injects nothing into either rendered document, and uses independent story markup with foundation styles; the stories import no production Table or menu code.

Focus-loss coverage moves between real artifacts and browser pages. It does not claim to reproduce every operating-system application switch. Fault cases use the forwarding proxy or real saved files declared below. Passing messages are unchanged. Accessibility evidence covers exposed roles, names, positions, selection, focus, descriptions and status updates, not spoken output from every screen reader.

The [Table architecture proof](../../arch/templates/table.md) owns schema, tolerant reading and ordering breadth, drawn-position identity, write plans and exact operation paths. This proof walks the user paths that consume those contracts. [Resource SDK](../../arch/resources/sdk.md) and [JSON store](../../arch/resources/json-store.md) proofs own transport, rollback, transaction and durability mechanics; the cases here prove the page response.

Conformance compares every exported [Table story](../../../storybook/spec/templates/table/table.stories.ts), including exports not embedded in the MDX page, with production in the same state. It runs against Storybook built from this worktree and the copied Table served by a running server. It compares the complete `.table-page` root at the story viewport and light or dark appearance after deterministic story and production setup, letting `conform` settle real CSS motion before capture.

## Test hooks

The server receives the real built `sdkDir` allowed by [SDK packaging](../../../specs/arch/resources/sdk.md#^sdk-packaging); production resolves the same bundle from the installed package. The production Table selection model exposes pure transition functions consumed by the page; contract tests call them with authored display and selection states, without a test-only branch or DOM replacement.

The shared forwarding proxy may hold initial resource messages, record or hold an ordinary page write or its acknowledgement, hold a transaction attempt, sever a connection and refuse reconnection. Production forwards each message immediately. Held messages remain unchanged, so the controls change timing or reachability without replacing subscription, authorization, writes, acknowledgements, rollback, transactions or reconnect.

For a refused save, selective WebSocket buffering holds the access notification while forwarding the later real write rejection, then releases the notification. The server normally sends access first. This message-order mock forfeits ordinary access ordering to [access acceptance](#^table-ac-access); it replaces neither authorization nor rollback. Clipboard fixtures use the real browser clipboard. Damaged-file cases stop the server before changing the real saved file and restart it through the existing server harness.

- **Acceptance — resizing.** Under [Resizing rows and columns](../../../specs/ui/templates/table.mdx#resizing-rows-and-columns), drag an internal and last column divider and an internal and last row divider. - **Acceptance — first load.** Under [Opening a table](../../../specs/ui/templates/table.mdx#opening-a-table), hold initial resource messages after the real document and SDK load. The centred activity icon and ruled top edge align with the blank grid and with a fixture containing fewer than ten rows. Sever and refuse the connection before releasing data: loading remains and `Reconnecting…` appears in the established status region. Restore the real connection and observe the current table without reload. *(real-stack test: `packages/web/test/e2e/template-table-real-stack.test.ts`, “first load keeps one status region through disconnection and recovery”)* ^table-ac-loading
- **Acceptance — disconnection and reconnect.** Under [Saving and disconnection](../../../specs/ui/templates/table.mdx#saving-and-disconnection), sever an established editable connection and refuse new ones. The last table remains; add controls and menus disappear; new editing and resizing are disabled; and `Reconnecting…` appears. An editor already open stays usable. Return, Tab, clicking another target, clicking outside and moving focus out of the artifact make no write, leave the editor open, keep its selection, and neither move nor clear that selection nor act on the target; Escape cancels and keeps the cell selected. A resize in progress ends without writing. Restore connectivity and commit or resize normally. Commit a changed edit while the proxy holds its write or acknowledgement, then disconnect and drop it: assert rollback to the confirmed value, no save-failure message after reconnect, and no reopened editor containing the lost text. In a separate segment, let a renumbering transaction commit, disconnect before its required follow-up write starts, and assert that `Reconnecting…` takes precedence while disconnected, then the established save-failure message appears after reconnection because the follow-up was never sent. Repeat disconnection and recovery over an unreadable page, where the error remains and gains `Reconnecting…` until readable data and the connection return. *(real-stack tests: `packages/web/test/e2e/template-table-real-stack.test.ts`, “disconnection keeps an open editor, blocks commits and rolls back an unacknowledged save”, “resizing reconciles concurrent, access and disconnected changes”, “moving focus to another artifact frame commits and keeps selection”, and “unreadable and unavailable states survive disconnection and recover”)* ^table-ac-disconnection
- **Acceptance — refused save and failed transaction.** Under [Saving and disconnection](../../../specs/ui/templates/table.mdx#saving-and-disconnection), hold a real write from a read-write share, downgrade access while buffering its notification, and release the write for real refusal. Assert that the affected value rolls back and the established status region says `Couldn't save that change.` before clearing after a few seconds; restore access and save again. Exercise an insert and a drawn resize whose renumbering transaction aborts or fails while connected and assert the same message with no deferred write. Exercise held transactions that commit before write access disappears and before the data becomes unreadable; in each case assert that the required follow-up write is suppressed with the same message. A drawn-cell save whose two axes both require renumbering also shows the message. Each message assertion begins after the previous one clears; disconnect while it is visible and assert `Reconnecting…` takes precedence. Selective buffering forfeits ordinary access-message order as declared above. *(real-stack tests: `packages/web/test/e2e/template-table-real-stack.test.ts`, “late descendant writes stay ignored and renumbering retries before deferred writes” and “a refused save and aborted renumbering use the established failure status”)* ^table-ac-save-failure
