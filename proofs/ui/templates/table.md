# Table template (UI) — proof

Proves [specs/ui/templates/table.mdx](../../../specs/ui/templates/table.mdx).

## Coverage model

Browser acceptance opens a Table created through the real template path in a temporary serving home. The copied page runs in the production artifact sandbox and loads the served resource SDK. Store changes cross real HTTP or WebSocket connections into the real JSON store; administrative reads confirm saves. Fixtures are the bundled seed and authored table values written through production commands or APIs.

Pointer, keyboard, context-menu, clipboard, selection, focus and scrolling behavior run in real Chromium. No case substitutes the DOM, SDK, menu element or page markup. Behavior tests use the standard CSS-motion override and forfeit motion. Conformance keeps production and reference styling independent and uses the story markup with foundation styles; the stories import no production Table or menu code.

Focus-loss coverage moves between real artifacts and browser pages. It does not claim to reproduce every operating-system application switch.

Fault cases use the forwarding proxy or real saved files declared below. Passing messages are unchanged. Accessibility evidence covers exposed roles, names, positions, selection, focus and status-region update order, not spoken output from every screen reader.

The [Table architecture proof](../../arch/templates/table.md) owns schema, tolerant-reading and ordering breadth, drawn-position identity, write plans and exact operation paths. This proof walks the user paths that consume those contracts. [Resource SDK](../../arch/resources/sdk.md) and [JSON store](../../arch/resources/json-store.md) proofs own transport, rollback, transaction and durability mechanics; the cases here prove the page response.

Conformance compares every exported [Table story](../../../storybook/spec/templates/table/table.stories.ts), including exports not embedded in the MDX page, with production in the same state. It runs against Storybook built from this worktree and the copied Table served by a running server. It compares the complete `.table-page` root at the story viewport and light or dark appearance after deterministic story and production setup. No production markup or style is added for comparison.

## Test hooks

The server receives the real built `sdkDir` allowed by [SDK packaging](../../../specs/arch/resources/sdk.md#^sdk-packaging); production resolves the same bundle from the installed package.

The shared forwarding proxy may hold initial resource messages, record page writes, hold a transaction attempt, sever a connection and refuse reconnection. Production delivers immediately. The controls change timing or reachability without replacing subscription, authorization, writes, rollback, transactions or reconnect.

For a refused save, selective WebSocket buffering holds the access notification while forwarding the later real write rejection, then releases the notification. The server normally sends access first. This message-order mock forfeits ordinary access ordering to [access acceptance](#^table-ac-access); it replaces neither authorization nor rollback.

Clipboard fixtures use the real browser clipboard. Damaged-file cases stop the server before changing the real saved file and restart it through the existing server harness.

## Entry, display and editing

Unless stated otherwise, each acceptance uses the real browser, copied page, running server, SDK and store described above, with no mocks beyond the CSS-motion override.

- **Acceptance — new Table and first edit.** Under [A new table](../../../specs/ui/templates/table.mdx#a-new-table), choose Table in the real Toolbox and observe the supplied icon. The new artifact uses the shared display defaults, persists exactly `{"columns":{},"rows":{}}`, shows an unfocused four-by-four grid without a header and makes no page write merely by opening. Select B3, type a value and press Return: the commit stores columns A–B and rows 1–3, leaves the other drawn positions unstored, selects B4 and survives reload. Move the installed template out of discovery before reload and another edit to carry [independent delivery](../../arch/templates/table.md#^templates-table-t-assets). *(test to be written)* ^table-ac-new
- **Acceptance — rows, columns and layout.** Under [Rows, columns and cells](../../../specs/ui/templates/table.mdx#rows-columns-and-cells), write ordered columns and rows containing representative string, number, boolean, empty and multiline cells through the API. Display stored entries in order followed by drawn positions up to four, with headers on and off, unnamed headers, blank empty cells, one-line ellipsis and line breaks shown as spaces. There is no search or sort control. With enough wide data, scroll both ways and observe that the header and strips remain with the visible grid. The [architecture contracts](../../arch/templates/table.md#^templates-table-t-model) cover malformed-entry and type breadth; this walk crosses representative values into the page. *(test to be written)* ^table-ac-rows
- **Acceptance — cell and header editing.** Under [Editing cells and headers](../../../specs/ui/templates/table.mdx#editing-cells-and-headers), click a body cell and type to replace its text; separately open existing text with double-click, Return and F2 and observe the caret at the end. Exercise Return, Shift-Return, Tab and Shift-Tab through header and body cells, including each outer edge, without creating entries at an edge. Click another target to commit before its action; click outside the table control and its open menu to commit and clear selection; leave the artifact by keyboard or move to another artifact or browser page to commit while preserving selection. Escape cancels to the current stored value and keeps the cell selected; a second Escape clears it. Edit a header with the same rules. Preserve pasted line breaks and ordinary field copy, paste, selection and native undo; after commit, the page offers no undo action. *(test to be written)* ^table-ac-editing

## Selection, keyboard and structure

- **Acceptance — pointer selection.** Under [Selecting cells, rows and columns](../../../specs/ui/templates/table.mdx#selecting-cells-rows-and-columns), click body and header cells, row numbers and column letters. Observe the corresponding selection, strip visibility, quiet related-axis emphasis, accent treatment only for whole-axis selection and the selected body range. Shift-click extends a contiguous range from its anchor; switching axes starts one selection at the pressed item. Clicking outside the table control and its open menu clears selection, while moving focus away and back preserves it. Escape closes an open Table menu without clearing selection; with no menu it clears selection and moves focus to the grid, where an arrow selects the first body cell. *(test to be written)* ^table-ac-selection
- **Acceptance — keyboard and accessibility.** Under [Keyboard and assistive technology](../../../specs/ui/templates/table.mdx#keyboard-and-assistive-technology), Tab enters the table at the retained selection or first body cell and leaves at the documented edges without a trap. Arrows move body and header cells and whole-axis selections; Shift extends or shrinks a range; Shift-Space and Ctrl-Shift-Space select the current row or column outside an editor and act as ordinary text input inside one. Whole-axis Return, F2, typing and Space do nothing. Hidden strip items and add controls are absent from the Tab order. Assert the grid, cells, editors, strip buttons and add controls expose the specified roles, names, positions and selection, including an unnamed header. Real focus shows the cell or strip focus treatment. *(test to be written)* ^table-ac-keyboard
- **Acceptance — clearing, adding and structure menus.** Under [Clearing contents](../../../specs/ui/templates/table.mdx#clearing-contents) and [Adding, inserting, and deleting structure](../../../specs/ui/templates/table.mdx#adding-inserting-and-deleting-structure), Delete and Backspace clear the selected body cells or header name without deleting structure or a column name selected through the strip. Use both add controls and observe focus in the new row or column at the previous body-cell position, or the first position. Open row and column menus by right-click, context-menu key and Shift-F10; right-click inside a range retains it, outside selects one item, and cell/editor context gestures behave as specified. Assert canonical menu content, order, danger treatment, singular/plural Delete labels, the missing Delete item for an all-drawn selection, header toggling and Escape dismissal. Insert and delete stored and drawn selections, then observe the documented selection position. *(test to be written)* ^table-ac-structure

## Live data and access

- **Acceptance — agent changes and concurrent editing.** Under [Changes from elsewhere](../../../specs/ui/templates/table.mdx#changes-from-elsewhere), use spawned `tv resource json` commands and a second real viewer to edit unrelated cells, names, orders and membership while the first viewer selects or edits. Changes outside the active field appear immediately; the local text and caret survive a change to that field until commit or cancel, and controlled writes settle by real last-write-wins ordering. An unchanged commit makes no write and reveals the latest stored value. A selection follows keys through reorder and clears when a selected entry disappears or stops displaying, or when a range stops being contiguous; its menu or editor closes with it. Hiding the header closes its editor. Change the displayed stored count while a person types in a drawn position: the selection clears, the editor closes, the typed text is discarded and no write starts. Separately edit a stored cell while an agent writes another path and confirm both persist. This also executes representative commands taught by the README. *(test to be written)* ^table-ac-live
- **Acceptance — accepted blank-axis race.** Under [the accepted concurrent race](../../../specs/arch/templates/table.md#drawn-rows-and-columns), hold a page commit that stores drawn entries while a real agent write stores the same positions, then release both without substituting either write. Observe the allowed outcome in which both key sets remain; the page stays readable, displays the stored cells and follows stored order. This proves tolerance of the specified outcome, not every network schedule. *(test to be written)* ^table-ac-drawn-race
- **Acceptance — read-only and changed access.** Under [Read-only and access loss](../../../specs/ui/templates/table.mdx#read-only-and-access-loss), open a real read-only share with populated and empty data. Selection and navigation remain; editing, clearing, add controls and menus are unavailable. Agent changes still appear. Upgrade the same link and save, then downgrade while an editor and separately a menu are open: each closes without writing and the last confirmed value remains. Restore write access and save a fresh edit. Revoke the link after readable data has arrived: the last table remains read-only. No access state is injected. *(test to be written)* ^table-ac-access

## Loading, disconnection and failures

- **Acceptance — first load.** Under [Opening a table](../../../specs/ui/templates/table.mdx#opening-a-table), hold initial resource messages after the real document and SDK load. The centred activity icon appears with no grid. Sever and refuse the connection before releasing data: the loading state remains and `Reconnecting…` appears in an established status region. Restore the real connection and observe the current table without reload. *(test to be written)* ^table-ac-loading
- **Acceptance — disconnection and reconnect.** Under [Saving and disconnection](../../../specs/ui/templates/table.mdx#saving-and-disconnection), sever an established editable connection and refuse new ones. The last table remains, add controls and menus disappear, new editing is disabled, and `Reconnecting…` appears. An editor already open stays usable; every commit gesture leaves it open, does not write or act on the target, and Escape cancels it while preserving selection. Restore connectivity and commit normally. Include a write sent just before severing: if real SDK rollback occurs, the editor does not reopen with that text; the test accepts either documented uncertain server outcome. Repeat over an unreadable page. *(test to be written)* ^table-ac-disconnection
- **Acceptance — refused save and failed transaction.** Under [Saving and disconnection](../../../specs/ui/templates/table.mdx#saving-and-disconnection), hold a real write from a read-write share, downgrade access while buffering its notification, and release the write for real refusal. The affected value rolls back and the established status region says `Couldn't save that change.` before clearing after a few seconds. Restore access and save again. Separately hold an insertion transaction, make the selected keys invalid through an agent write and release it: no insertion persists and the same message appears. Disconnect while the message is visible and observe `Reconnecting…` take precedence. Selective buffering forfeits ordinary access-message order as declared above. *(test to be written)* ^table-ac-save-failure

## Unreadable data and recovery

- **Acceptance — tolerant, unreadable and unavailable data.** Under [Data the page cannot read](../../../specs/ui/templates/table.mdx#data-the-page-cannot-read), show a missing and partial root as the corresponding empty or partial grid without a repair write. Write representative ignored entries and cells and observe the readable remainder. Then replace an axis with a non-object while an editor and separately a menu are open: the alert replaces the table with the specified icon, title and guidance; the editor closes without writing and the menu closes. Repair through the API and observe recovery without reload or replay. Lose all access before the first readable value and observe the same alert. Finally stop the server, damage the real saved bytes, restart to receive `unavailable`, then repair and restart; the page recovers without changing the damaged bytes itself. [Architecture contracts](../../arch/templates/table.md#^templates-table-t-model) cover remaining malformed permutations, and [the write guard](../../arch/templates/table.md#^templates-table-t-invalid-guard) covers suppressed operations. *(test to be written)* ^table-ac-unreadable

- **Acceptance — every spec story conforms.** Under [story output](../../../specs/spec-ui.md#^ui-story-output) and [conformance](../../../specs/spec-ui.md#^ui-conformance-test), generate one comparison for every Table story export and fail when any export lacks a production setup. The save-failure message-order mock is the declared exception; [access acceptance](#^table-ac-access) covers normal ordering. *(test to be written)* ^table-ac-conformance
