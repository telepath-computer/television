# Icon (UI) — proof

Proves [specs/ui/foundation/icons/index.md](../../../../specs/ui/foundation/icons/index.md).

## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below.

The complete manifest is covered by one table-driven contract rather than by one assertion per icon. [The every-name contract](#^ic-ac-markup-smoke) requires the authoritative manifest, the name-to-drawing table in the production `tv-icon` element, and the exact SVG file each manifest entry names to agree.

## Assertions

### Test assertions

The suite samples the icon element's meaningful markup breadth, proves its stylesheet reaches icons in documents and in author-created shadow roots, and proves the spinning state's consequential motion. It does not measure glyph alignment, colour, exact animation duration, or easing ([arch/testing-policy.md#^ui-suite-scope](../../../../specs/arch/testing-policy.md#^ui-suite-scope), [arch/testing-policy.md#^ui-styling-out](../../../../specs/arch/testing-policy.md#^ui-styling-out)). This assertion block is reconciled with the current prose, markup, and [styles.css](../../../../specs/ui/foundation/icons/styles.css), so every assertion below is accurate authority under [the UI-assertion policy](../../../../specs/arch/testing-policy.md#^ui-assertions-unmaintained).

- **Contract** (the authored icon template parsed as document markup and the registered production `tv-icon` constructed without a declarative root in a real browser; every manifest name, its installed SVG source, and the authored icon styles are real fixtures, with no mocks or test hooks): one table-driven markup smoke check proves that every valid name reaches an open shadow root through both the declarative and imperative paths; both hosts have empty light DOM, both roots carry equivalent authored styles and the same glyph, and that glyph is the name's exact installed SVG — *(covered by test: `packages/web/test/e2e/icon.test.ts` “renders every manifest glyph through equivalent declarative and imperative shadow roots”)*. ^ic-ac-markup-smoke
- **Contract** (the registered production `tv-icon` and its carried production stylesheet in a real browser; an unsized icon and one representative named-size icon are authored fixtures mounted in document light DOM and again inside an author-created open shadow root; browser style and layout are real, with no mocks or test hooks): in both tree scopes the unsized icon has a non-zero square bounding box matching its inherited `1em`, and the named-size icon has a non-zero square bounding box matching its computed font size — *(covered by tests: `packages/web/test/e2e/icon.test.ts` “sizes an unsized icon from inherited text in document light DOM”, “sizes a named icon in document light DOM”, “sizes an unsized icon from inherited text inside an author shadow root”, and “sizes a named icon inside an author shadow root”)*. ^ic-ac-tree-scope
- **Contract** (an authored document styled by the fresh production canonical stylesheet in a real browser; unsized, `sm`, `md`, `lg`, and `xl` icons are fixtures; the production element definition is loaded only after the initial boxes are recorded; no mocks or test hooks): each undefined icon's bounding box before `customElements.whenDefined("tv-icon")` equals its bounding box after upgrade — *(covered by test: `packages/web/test/e2e/icon.test.ts` “keeps every canonical icon box stable across definition”)*. ^ic-ac-pre-upgrade-box
- **Seam** (authoritative icon sheet → byte-identical production element stylesheet → canonical builder extraction, crossed through the real repository filesystem and a fresh canonical build; no mocks or test hooks): the default placeholder carries exactly the declarations of `:host`, every named placeholder carries exactly the `font-size` of its corresponding `:host([size])`, and canonical output contains exactly the placeholder set and no other rule from the icon sheet — *(covered by test: `packages/canonical/test/build-canonical.test.ts` “extracts exactly the authoritative pre-upgrade icon rules into canonical document scope”)*. ^ic-t-pre-upgrade-style-seam
- **Contract** (real-motion declaration: animation and transition overrides are absent; the registered production `tv-icon` and its production stylesheet run in a real browser; `spinner` with normal and reduced-motion media preferences is an authored fixture; the normal path synchronizes through the Web Animations API and successive animation-frame signals, and the reduced-motion negative uses the same API as an absence recorder through two animation frames): `spinning` starts one continuously advancing descendant animation under the normal preference, while the reduced-motion preference starts none — *(covered by tests: `packages/web/test/e2e/icon.test.ts` “starts one continuously advancing animation under normal motion preference” and “starts no animation under reduced motion preference”)*. ^ic-ac-spinning

Coverage relationship: [arch/ui/elements.md](../../../../specs/arch/ui/elements.md) owns the public `tv-icon` inputs and shadow-root construction, while [#^ic-ac-markup-smoke](#^ic-ac-markup-smoke) proves their name/glyph handoff and the equivalence of the two construction paths without a second architecture-level resolver assertion, [#^ic-ac-tree-scope](#^ic-ac-tree-scope) proves the browser-visible upgraded sizing outcome, and [#^ic-ac-pre-upgrade-box](#^ic-ac-pre-upgrade-box) proves continuity at definition. [arch/ui/index.md#^ui-t-module-shape](../../../arch/ui/index.md#^ui-t-module-shape) documents custom-element registration and class structure as conventions maintained through code style and engineering review. Composing-surface markup smoke checks own the icon names and size attributes each surface asks for. The four exact pixel steps, inline alignment, `currentColor`, and the one-second linear turn remain authored styling rather than independently measured values; the pre-upgrade assertions prove equality across the loading boundary and production copies.
