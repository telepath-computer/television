*How the production popover's interaction, placement, and lifecycle are proven in Chromium, and presses over window drag regions in the real Electron app.*

# Popover (UI) — proof

Proves [specs/ui/foundation/popover/index.md](../../../../specs/ui/foundation/popover/index.md).

## Coverage model

`packages/web/test/e2e/panel-elements.test.ts` loads the production custom elements and stylesheet in a real Chromium document. Its HTML controls, constrained containers, and event counters are fixtures. Selected focus cases install an authored host listener that prevents a button's pointer press from taking focus, matching the application's convention; browser focus, pointer and keyboard dispatch, layout, mutation observation, and element lifecycle remain real. The current fixture installs no CSS-motion override; authored styles run as written. These assertions observe settled behavior and geometry without claiming motion timing or visual conformance.

The suite observes open state, owned ARIA attributes, actual focus, rendered bounds, and hit testing. It exercises the shared panel implementation used by popovers, menus, and selects. Application commands and persistence belong to composing surfaces; canonical delivery belongs to [canonical](../../../arch/canonical.md).

The cases cover ordinary dismissal, trigger replacement, viewport flipping, constrained scrolling, document stacking, reconnecting, and dynamic panel/viewport dimensions. Polling waits for observable state or settled geometry, rather than inferring coverage from the presence of a test file.

A focused `PanelController` lifecycle contract in a mocked DOM observes shared resource cleanup at the platform boundary. Event registration is recorded with its real AbortSignal; MutationObserver disconnection is observed, and animation-frame scheduling is replaced by a recording scheduler so an outstanding frame is deterministic. This forfeits actual browser scheduling, observation, and input delivery to the browser cases above. It detects missing cleanup directly rather than relying on the absence of visible duplicate input.

Presses over a window drag region are proven once, in the real desktop app against a really-running server ([#^po-ac-drag-overlap](#^po-ac-drag-overlap)), honoring the spec's Testing directive. The press under claim is native: the X server generates it through XTest, so it passes through Electron's drag-region handling as a mouse press does. Playwright page input only opens Settings beforehand, outside the claim. The case is the reported one: with Swiss active, the Settings theme select opens with its **None** option over the navbar. This one select case covers popovers and menus too: the popover stylesheet declares `-webkit-app-region: no-drag` in a single open-state rule shared by all three, on the panel box that holds all panel content, and the [foundation copy check](../../../arch/ui/foundation.md#^ui-t-foundation-copy) holds both of the application's production copies byte-identical to it. This evidence is Linux/X11 only; it supplies no macOS or Windows native-input evidence. Television's side of the crossing has no platform branch, since every platform receives the same declaration, so the [platform-breadth rule](../../../../specs/arch/testing-policy.md#^platform-breadth) orders no platform contract here. Xvfb runs no window manager, and a press needs none, so nothing stands in for one.

## Test hooks

The browser cases need no production test hook. Fixture-owned controls and listeners supply the host context; the lifecycle contract instruments platform boundaries in its test environment.

The drag-region seam runs under the desktop harness's standing `TV_TEST_MODE` gate, where `TV_TEST_DESKTOP_APP_VERSION` supplies the shell version that production reads from `app.getVersion()`. The [desktop upgrade-gate proof](../../../arch/updates/desktop-upgrade-gate.md#^hook-shell-version) owns that hook.

## Assertions

- **Contract** (production popover in Chromium; the fixture supplies buttons and content, with the focus convention above): the [behavior and trigger contracts](../../../../specs/ui/foundation/popover/index.md#behaviour) hold through trigger and `open`-attribute changes: paired ARIA state follows opening/closing, a trigger toggles both ways, closing returns focus only when the panel held it, unrelated non-manual root panels are exclusive, and a manual panel survives other panels opening, outside presses, and Escape. Existing evidence: `panel-elements.test.ts`, “popover attributes, focus, exclusivity and manual dismissal” and “trigger replacement and owner removal leave no stranded panel or ARIA”. ^po-ac-lifecycle
- **Contract** (production popover and menu elements in Chromium; authored parent, sibling, and grandchild triggers and panels are fixtures, with one child panel outside its parent DOM subtree; real pointer and keyboard input and element removal, no mocks or production hooks): [nesting](../../../../specs/ui/foundation/popover/index.md#nesting) follows the nearest open panel containing the trigger. Opening a child preserves its ancestors; a sibling replaces the child branch, and an unrelated root replaces the automatic branch. Clicking an ancestor closes the child while the original control still acts; an action that removes its own child panel keeps the original ancestor boundary, and a panel opened by the original outside action is not dismissed by that same gesture; clicking outside closes the branch without redirecting the press or moving focus away from the target. Escape closes only the deepest eligible panel and returns focus at that boundary. A control that prevents Escape keeps its panel open. Closing or removing a parent closes its descendants even when their DOM is elsewhere or they are manual/select panels; focus never lands in the closed parent. Select and manual exclusions remain covered by the existing lifecycle and select cases. Existing evidence: the nested branch cases in `packages/web/test/e2e/panel-elements.test.ts`. ^po-ac-nesting
- **Contract** (production panels and real layout in Chromium; fixture geometry supplies constrained space): [placement](../../../../specs/ui/foundation/popover/index.md#placement) opens below-left, chooses each axis independently, respects window clearance and scrollable constraints, and follows trigger, panel, and viewport changes while open. Authored `max-height: 600px` caps tall content, available viewport room can lower that cap, short content retains its natural height, and closing restores an authored inline max-height value and priority. The panel keeps its DOM parent and ordinary [document-layer ordering](../../../../specs/ui/foundation/popover/index.md#layer). Existing evidence: “panels retain their parent, follow their trigger and flip at window edges”, “constrained panels scroll, keep window clearance and follow live root theme changes”, “ordinary document layers cover panels in order and reconnecting restores pairing”, and “authored panel height caps survive viewport placement and restore inline priority” in `panel-elements.test.ts`. ^po-ac-placement
- **Contract** (production elements disconnected and reconnected in a real browser): the [element's disconnect contract](../../../../specs/arch/ui/elements.md#tv-popover) clears its trigger's expanded state, removes the open panel without resurrection, and permits normal pairing on reconnect. Existing evidence: “explicit removal does not resurrect an open panel and preserves inline priority on close” and “ordinary document layers cover panels in order and reconnecting restores pairing” in `panel-elements.test.ts`. The browser cases prove visible disconnection and reconnecting; shared resource release is carried by the separate lifecycle contract below. ^po-ac-removal

- **Contract** (production `PanelController.connect()`/`disconnect()` in a mocked DOM; real fixture hosts and recorded event-registration AbortSignals, observed MutationObserver `disconnect`, and a recording animation-frame scheduler): the shared [document-level interaction ownership](../../../../specs/arch/ui/elements.md#tv-popover) honors [cleanup policy](../../../../specs/arch/testing-policy.md#timing-observable-status-cleanup-and-flakiness). Removing one of two connected panels leaves shared resources active; removing the last aborts the signal registered with all document input listeners, disconnects the observer, and cancels the pending animation frame. A later connection creates fresh active resources and releases them when it disconnects. The assertion observes each cleanup operation directly, so an empty old panel set cannot conceal an un-aborted listener or live observer. Covered by `packages/web/test/panel-controller.test.ts`, “retains shared resources until the last disconnect and recreates them on reconnect”. ^po-ac-resource-cleanup

- **Contract** (real canonical elements in Chromium; authored height, grid, flex and image fixtures; no mocks): a 100px host clips 600px content and retains native wheel and programmatic scrolling; grid columns and wrapping flex retain direct-child geometry; a zero-padding image is clipped at rounded corners. The exterior rim follows the host with classic document scrollbars and a translated/scaled ancestor. Covered by the “authored panel” cases and “panel paint follows its box with classic scrollbars and transformed ancestors” in `packages/web/test/e2e/window-edge-rims.test.ts`. ^po-ac-authored-layout

- **Seam** (the open panel's app-region styling in the production app document → Electron's native routing of pointer presses over a window drag region, crossed in the real Electron app against a really-running authenticated Television server by real X11 pointer events that `packages/desktop/test/e2e/x11-pointer-press.py` has the X server generate through XTest; the real bundled theme packages, copied into the server's theme folder and registered through the production refresh, and Swiss selected through the production display API, are fixtures; `launchDesktop({ connectTo })` seeds an isolated saved-connection record, a setup mock that forfeits manual connection entry and persistence to [desktop product connection acceptance](../../../product/desktop-app.md#^desktop-ac-connect-link), and the harness's standing `TV_TEST_DESKTOP_APP_VERSION` mock of `app.getVersion()` forfeits the real version path to [the unhooked shell-version seam](../../../arch/updates/desktop-upgrade-gate.md#^t-shell-version-param), while desktop startup and server-page loading remain real; Settings opens through Playwright page input, as setup outside the claim; no CSS-motion override is installed, and no CSS motion lies on the press path; this case runs only on Linux/X11 and supplies no macOS or Windows native-input evidence): with Swiss active, a native press on the Settings theme trigger, which lies below the navbar, opens the select with its **None** option inside the navbar's band, where the navbar computes `-webkit-app-region: drag` and **None** is the document's hit target. A native press there selects **None**: the server's active theme becomes none and the trigger reads None, satisfying [presses over a drag region](../../../../specs/ui/foundation/popover/index.md#^po-drag-overlap) — *(covered by test: `packages/desktop/test/e2e/popover-header-overlap.test.ts` “a native press on a theme option over the draggable navbar selects it (^po-ac-drag-overlap)”)*. ^po-ac-drag-overlap
