# Select (UI) — proof

Proves [specs/ui/foundation/select/index.md](../../../../specs/ui/foundation/select/index.md).

## Coverage model

`packages/web/test/e2e/panel-elements.test.ts` runs production select and option elements in Chromium. Authored options, labels, container geometry, and change-event counters are fixtures. Real input, focus, layout, and element lifecycle remain on the path; the optional host pointer-focus convention is described in the [popover proof](../popover/index.md). The fixture installs no CSS-motion override; authored styling remains active, and assertions observe settled behavior without claiming motion timing.

Chromium's accessibility tree observes option/listbox semantics; DOM attributes observe selection, highlight, and trigger references. Property writes and event counts distinguish programmatic selection from user commits. The browser cases cover selection and highlight separately, keyboard/pointer input, generated identities, owned trigger semantics, and constrained placement. Test execution is recorded separately from this coverage model.

Shared pairing, dismissal, continuous placement, and document-lifecycle coverage compose with the [popover proof](../popover/index.md) through the same production panel controller. This proof carries select-specific value, keyboard, alignment, and exclusivity behavior. Composing surfaces own persisted values and the effects of changing them. [Settings browser acceptance](../../app/settings/index.md#^settings-ac-browser) composes real pointer commits with the public `value` getter: the production Settings handler reads the selected value and the test observes the resulting confirmed server preference. That existing path is reused rather than ordering a second persisted-value journey.

## Test hooks

No production test hook is required. Fixture event counters observe ordinary `change` events.

## Assertions

- **Contract** (production select in Chromium, authored option sets and value assignments): the [markup and selection rules](../../../../specs/ui/foundation/select/index.md#markup) and [element API](../../../../specs/arch/ui/elements.md#tv-select-tv-option) yield exactly one initial selection, choosing the first option when none is authored; valid `value` writes select without dispatching change, an unknown value leaves selection unchanged, and only a changed user commit dispatches change. Trigger content follows selection while highlight remains separate. Minted panel/option IDs are unique and stable, and trigger references point to them. Replacement/stripped trigger semantics are restored, and disconnect removes owned trigger attributes. Existing evidence: “select reserves width, separates highlight from selection and commits once”, “select restores owned semantics after rerender and keeps minted identities stable”, and “select keys work away from the trigger and typeahead accumulates then resets” in `panel-elements.test.ts`. ^sl-ac-selection
- **Contract** (production select driven by real pointer and keyboard input): the [keyboard and selection contracts](../../../../specs/ui/foundation/select/index.md#keyboard) open without moving focus, consume their keys even when focus is elsewhere, hold arrow navigation at both ends, support Home/End and accumulated/reset typeahead, commit with Enter/Space, and commit then advance on Tab from the trigger. Escape/outside press cancel; a stationary pointer leaves the initial selected highlight alone. Existing evidence: “select reserves width, separates highlight from selection and commits once”, “select opens over its selected row without stationary-pointer or document-scroll changes”, “select keys work away from the trigger and typeahead accumulates then resets”, and “select consumes Tab away from its trigger without committing or advancing focus” in `panel-elements.test.ts`. ^sl-ac-input
- **Contract** (production trigger/panel geometry in Chromium with authored option widths and constrained viewport): the [placement and trigger-sizing contracts](../../../../specs/ui/foundation/select/index.md#placement) reserve the widest-option width, honor an ordinary CSS width override, recompute when options change, open over the selected row when that seat fits, align panel and trigger top edges when it does not fit and room is below, align their bottom edges when opening upward, remain at least trigger-wide, and fit the available window. Existing evidence: “select reserves width, separates highlight from selection and commits once”, “select opens over its selected row without stationary-pointer or document-scroll changes”, “a constrained select reveals the selected row and preserves keyboard scrolling”, “select width follows new options and an ordinary CSS width wins”, and “a select connected inside a hidden wrapper measures when revealed” in `panel-elements.test.ts`. ^sl-ac-placement
- **Contract** (production select nested in a production popover, real input and programmatic opening): [popover exclusivity](../../../../specs/ui/foundation/select/index.md#popover-exclusivity) excludes selects in both directions; nested-select interactions keep the owner open, while ordinary dismissal remains effective. Existing evidence: `panel-elements.test.ts`, “a select inside Settings keeps its popover open and closes with its owner”. ^sl-ac-exclusivity
