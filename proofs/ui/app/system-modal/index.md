## Assertions

### Test assertions

The suite samples the authored modal states and proves the access-token form's own behavior ([arch/testing-policy.md#^ui-suite-scope](../../../../specs/arch/testing-policy.md#^ui-suite-scope)). Styling stays outside the suite: no assertion measures the panel, centering, responsive width, type, tint, or wash ([arch/testing-policy.md#^ui-styling-out](../../../../specs/arch/testing-policy.md#^ui-styling-out)). The DOM is only the instrument used to observe the state and interaction claims below ([arch/testing-policy.md#^ui-dom-instrument](../../../../specs/arch/testing-policy.md#^ui-dom-instrument)).

Shared contract declaration for the assertions below ([arch/testing-policy.md#^declaration-schema](../../../../specs/arch/testing-policy.md#^declaration-schema)): they prove the system-modal view side of the application-service/view handoff defined by [arch/ui/index.md](../../../../specs/arch/ui/index.md). Server addresses, failure messages, selected upgrade instructions, and each authored modal state are fixtures. An implementation-mount hook supplies a fake application service and directly poses state; both are mocks, greenlit here, and forfeit real state selection, precedence, retry, authentication storage, and server behavior to [ui/app/index.md](../../../../specs/ui/app/index.md) and [arch/channel-state/index.md#^cs-connection-carve-out](../../../../specs/arch/channel-state/index.md#^cs-connection-carve-out). The mocked DOM substitutes for native focus, form submission and constraint validation, layout, scrolling, and animation; the assertions therefore claim only rendered markup and view logic after the submit handler receives a value, while real form and server wiring remain with [ui/app/index.md#^ap-ac-signin-first](../index.md#^ap-ac-signin-first) and [arch/channel-state/index.md#^cs-connection-carve-out](../../../../specs/arch/channel-state/index.md#^cs-connection-carve-out). Neither assertion claims styling or motion; the spinner's exact glyph belongs to [ui/foundation/icons/index.md#^ic-ac-markup-smoke](../../foundation/icons/index.md#^ic-ac-markup-smoke), and its turning behavior belongs to [ui/foundation/icons/index.md#^ic-ac-spinning](../../foundation/icons/index.md#^ic-ac-spinning).

- **Contract** (the production system-modal view mounted in the mocked DOM under the shared declaration): one table-driven markup smoke check covers connecting; disconnected with a numbered reattempt and with an attempt in flight; unauthorized before submission and after rejection; error; and needs-upgrade. Each row renders only its selected interrupting surface. Connecting asks for the spinning spinner and shows its title with no supporting line. Both disconnected rows ask for that spinner and show the title with the corresponding reattempt line. Unauthorized shows the locked icon, copy, labeled required password field, and Connect button; its rejected state leaves the field empty, sets aria-invalid="true", links aria-describedby to the tv-error rejection alert, and removes that state and link when a fresh unauthorized state is presented. Error shows the authored title, server address, and supplied failure message. Needs-upgrade routes the supplied instructions into the desktop-upgrade-gate surface rather than wrapping them in the standard interior, and with a desktop update state whose stand-in bridge has reported a version it routes the restart state too, so the gate shows the downloaded-update message and its restart button — *(covered by `packages/web/test/app-root.test.ts` “system modal (^sm-ac-markup-smoke) > renders each selected interrupting surface and no other”)*. ^sm-ac-markup-smoke
- **Contract** (the same production view, mocked DOM, implementation-mount hook, and fake application service; a production-shaped rejection update is injected through that service and forfeits the real authentication round trip as declared above): native prevention of an empty submission before the handler runs is carried as markup by the required field in [#^sm-ac-markup-smoke](#^sm-ac-markup-smoke); when the view's submit handler receives an empty or whitespace-only token it invokes nothing; an entered token invokes the service once; and when the service reports that token rejected, the input clears, the alert appears, and a replacement token can be submitted — *(covered by `packages/web/test/app-root.test.ts` “system-modal token submission (^sm-ac-auth-submit) > refuses blank values, authenticates entered tokens, and clears a rejected token”)*. ^sm-ac-auth-submit

Coverage relationship: [ui/app/index.md](../../../../specs/ui/app/index.md) owns choosing one modal state, sign-in and gate precedence, and whether the shell stays mounted behind the wash. The connection lifecycle retained under [arch/channel-state/index.md#^cs-connection-carve-out](../../../../specs/arch/channel-state/index.md#^cs-connection-carve-out) owns retry timing, authentication against a real server, and leaving error or unauthorized after a successful connection; this surface consumes those outcomes without repeating their full browser/server paths. [ui/app/desktop-upgrade-gate/index.md](../../../../specs/ui/app/desktop-upgrade-gate/index.md) owns the gate's interior, markdown, controls, and scrolling; this row proves only that the needs-upgrade state routes to it. The dialog element row owns generic background inertness and floating-surface dismissal, and the icon element row owns spinner motion.
