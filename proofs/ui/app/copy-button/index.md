# Copy button (UI) — proof

Proves [specs/ui/app/copy-button/index.md](../../../../specs/ui/app/copy-button/index.md).

## Coverage model

The suite retains its existing clipboard, activation, timer, and announcement coverage. The markup contract covers caller-supplied `intent` alongside the copy lifecycle.

## Test hooks


`copyButtonTemplate` accepts optional `CopyButtonDependencies` so tests can supply a `CopyButtonClipboardSink` that records copy attempts and a `CopyButtonScheduler` that controls the confirmation timeout. Production callers omit these dependencies, so the template uses the browser clipboard path and the global timer.

## Assertions

### Test assertions

The suite proves the button's authored states, clipboard crossing, confirmation lifecycle, and exact dwell. It does not measure the no-resize swap or container reflow, which are styling conformance judged in staging and review ([arch/testing-policy.md#^ui-styling-out](../../../../specs/arch/testing-policy.md#^ui-styling-out)).

- **Contract** (the production copy-button template helper as the consumer of caller label, prompt, intent, and copied state, exercised in a mocked DOM; those values are fixtures, direct copied-state posing is a mock that forfeits the transition to [#^cb-ac-confirm](#^cb-ac-confirm), and the mocked DOM forfeits clipboard behavior to [#^cb-ac-clipboard](#^cb-ac-clipboard); no styling or motion claim): one markup smoke table covers idle plain and copied primary-intent rows. Each renders one native small button with the prompt and optional intent reflected exactly, copy/check icons, the caller's idle label, and the fixed Copied confirmation; only the copied row carries the copied mark — *(covered by `packages/web/test/copy-button.test.ts`; “copyButtonTemplate (^cb-ac-markup-smoke)” covers idle plain and copied primary-intent rows)*. ^cb-ac-markup-smoke
- **Seam** (copy-button activation → system clipboard, crossed in a real browser with the production clipboard handler and system clipboard; the primary row wraps `navigator.clipboard.writeText` only to record that the real method ran, without replacing its result; the fallback row removes `navigator.clipboard` — a declared mock of browser capability detection that forfeits only detection, while the real synchronous `execCommand("copy")` path and clipboard readback remain in the test; the standing motion override may run and forfeits only CSS motion, which this assertion does not claim): activating the button places its prompt on the system clipboard through the modern path when available and the fallback path when it is absent — *(covered by inherited tests: `packages/web/test/e2e/copy-button.test.ts` “^cb-copy: clicking the inner button copies the prompt to the system clipboard” and “fallback path (?no-clipboard): execCommand still lands the prompt on the system clipboard”, minimally modified to mount the target production surface and address its native-button root)*. ^cb-ac-clipboard
- **Contract** (the production copy-button activation side of the clipboard seam in a mocked DOM; `navigator.clipboard.writeText` is replaced by a rejecting recorder and `document.execCommand` by a call recorder — both greenlit mocks that forfeit real clipboard behavior to [#^cb-ac-clipboard](#^cb-ac-clipboard)): when the available modern writer rejects, activation calls it exactly once with the prompt, does not invoke the legacy fallback after the gesture, exposes no rejection, and still enters the optimistic copied confirmation — *(covered by `packages/web/test/copy-button.test.ts` “absorbs one rejected modern write without invoking the legacy fallback”)*. ^cb-ac-clipboard-rejection
- **Contract** (production copy-button activation → caller callback in a mocked DOM with an injected clipboard recorder and scheduler, which forfeit clipboard and timer behavior to [#^cb-ac-clipboard](#^cb-ac-clipboard) and [#^cb-ac-confirm](#^cb-ac-confirm)): each button activation invokes the optional `onActivate` callback exactly once after attempting the clipboard write, including repeated activation — *(covered by `packages/web/test/copy-button.test.ts` “invokes the caller activation callback once per copy attempt”)*. ^cb-ac-activate-callback

- **Contract** (the copy-button confirmation state machine in a mocked DOM with an injected fake scheduler and clipboard sink — both greenlit; the scheduler forfeits real timer wiring to [#^cb-ac-confirm](#^cb-ac-confirm), and the sink forfeits the system clipboard to [#^cb-ac-clipboard](#^cb-ac-clipboard); copied-state synchronization advances the scheduler to the named boundary and waits for the composing view's render completion; the states have no animation or transition, so this assertion makes no motion claim): activation announces Copied through a `role="status"`, `aria-live="polite"` region; the button remains copied through 1,399 ms; and the task at 1,400 ms returns it to idle — *(covered by `packages/web/test/copy-button.test.ts` “announces politely and changes back to idle at exactly 1,400 ms”)*. ^cb-ac-dwell

Coverage relationship: [#^cb-ac-markup-smoke](#^cb-ac-markup-smoke) proves the caller-to-button label and prompt inputs that composing surfaces render. [#^cb-ac-clipboard](#^cb-ac-clipboard) proves the two successful real-browser clipboard paths once for every caller, while [#^cb-ac-clipboard-rejection](#^cb-ac-clipboard-rejection) proves the modern writer's rejection branch; [#^cb-ac-activate-callback](#^cb-ac-activate-callback) proves the callback seam once; [#^cb-ac-confirm](#^cb-ac-confirm) and [#^cb-ac-dwell](#^cb-ac-dwell) divide real timer wiring from exact duration. Skill selector proves each fixed callback's telemetry value. Update notification proves prompt presence and its callback's surface-owned telemetry plus close/reopen reset; neither caller repeats clipboard or generic confirmation breadth.

> **Assertion cost.** The three mocked-DOM contracts keep the fake scheduler and rejecting clipboard recorders confined to the claims that need them. Exact dwell earns a separate assertion because the inherited browser case proves only eventual return, while faking time in the whole browser seam would weaken clipboard and timer wiring. One real-browser seam covers both successful clipboard capability paths for every caller; the cheap contract separately covers modern rejection. No composing surface repeats those paths, and the suite does not turn button width, icon alignment, or reflow into permanent geometry checks.
