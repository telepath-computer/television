# Artifact frame (UI) — proof

Proves [specs/ui/app/artifact-frame/index.md](../../../../specs/ui/app/artifact-frame/index.md).

## Coverage model

View contracts use authored artifact/navigation state and recording application-service mocks to prove names, directional controls, the browser demo mode return button and which views show it, menu actions, and deletion confirmation. These contracts exercise `tv-menu` composition and retain action-routing evidence. Independently, a real Frameset/Vite rendering contract proves the authored delete-confirmation frame required by the extended [Testing](../../../../specs/ui/app/artifact-frame/index.md#Testing) guidance, including default and supplied title handling. Missing and unsupported document contracts retain their inherited metadata coverage. Foundation menu and dialog proofs own generic interaction, while product and bridge proofs retain browser, server, navigation, and document-delivery crossings. Menu placement follows the shared popover proof, with no artifact-specific direction assertion.

## Window edge regression

The raster fixtures supply the client-owned sidebar width and integral trigger widths explicitly, so native font metrics do not move the sampled fractional edge. Classic-scrollbar coverage authors a scrollbar width in the fixture; it does not depend on the host's overlay-scrollbar preference.

- **Contract** (production artifact-frame, sidebar and stage views in Chromium; authored light/dark iframe documents and Swiss/None theme fixtures; a stub application service forfeits server persistence and navigation to the product proofs already cited below; browser rasterization, iframe loading, input and CSS remain real): across both appearances and white/dark grounds at DPR1 and DPR2, the inner side highlight follows white .20 source-over paint and the fractional sidebar exterior follows appearance-dependent black paint with half coverage at DPR1 and one device column at DPR2. Actual iframe buttons remain clickable. Independent native border shorthands, separate broad-shadow overrides including `none`, shared rim disabling, and locally computed radii work. Canonical artifact popovers, menus, selects and dialogs consume the same complete paints; controls and focus retain their borders and outlines. Keyboard focus and menu access remain available; inactive production stage frames retain the rim and stay pointer-inert. A narrow viewport is a render smoke check, not mobile support. Implements the bounded raster exception in [Testing](../../../../specs/ui/app/artifact-frame/index.md#Testing). Covered by `packages/web/test/e2e/window-edge-rims.test.ts`. ^af-ui-ac-window-edges

## Assertions

### Test assertions

The suite samples the frame and error page's meaningful authored states and proves the frame's own service callbacks ([arch/testing-policy.md#^ui-suite-scope](../../../../specs/arch/testing-policy.md#^ui-suite-scope)). Except for the bounded edge regression below, styling remains outside the suite: no assertion measures the radii, truncation, menu position, colour, or other visual adherence ([arch/testing-policy.md#^ui-styling-out](../../../../specs/arch/testing-policy.md#^ui-styling-out)). DOM state is the observation instrument, never a blanket coverage claim ([arch/testing-policy.md#^ui-dom-instrument](../../../../specs/arch/testing-policy.md#^ui-dom-instrument)).

- **Contract** (the production artifact-frame view as the consumer side of application and navigation state, exercised in a mocked DOM; artifact IDs, sources, titles, full-screen mode, and directional capabilities are authored fixtures; an implementation-mount hook supplies fake application and navigation services and directly poses their state — mocks that forfeit production state derivation and browser interaction to the interaction contract and product assertions below; the mocked DOM also forfeits document loading and layout; no styling or motion claim): one table-driven markup smoke check renders two sibling frames and the no-history, history-tail, history-middle, history-home, full-screen, and delete-confirmation states. Each frame has an artifact name, the same title on its document, and a menu trigger paired with its own `tv-menu`. Pairing identifies the correct frame independently of the panel mounting location. The no-history state has no direction controls; every history state has both controls and the divider, with Back and Forward enabled exactly from `can_back` and `can_forward`. The ordinary and full-screen menus carry their respective full-screen action, then a separator and destructive Delete; the confirmation names the artifact with Cancel before destructive Delete. A return state renders the artifact icon inside a button named by [content.yml#return_aria_label](../../../../specs/ui/app/artifact-frame/content.yml#return_aria_label) and no direction controls or divider, even while directional capabilities are posed; every other state renders the icon outside any button — `packages/web/test/artifact-view.test.ts` (“artifact-frame view rendering dispatcher > renders frame chrome states and named confirmation (^af-ui-ac-frame-markup)”); the return state is covered by `packages/web/test/artifact-view.test.ts` (“browser demo mode artifact frame > renders the return state with the icon in a button and no direction controls (^af-ui-ac-frame-markup)”). ^af-ui-ac-frame-markup
- **Contract** ([the named-artifact promise for the delete-confirmation frame](../../../../specs/ui/app/artifact-frame/index.md#Markup-and-styling), compiled and rendered through the installed Frameset Vite plugin; the omitted title and supplied ordinary and HTML-sensitive artifact titles are authored fixtures; no mocks and no forfeits): the omitted title renders the `Roadmap` sample default; supplied titles render in the exact question copy, with HTML-sensitive characters entity-escaped so the title remains text; the literal `{{ title }}` is absent; and the existing explanatory paragraph, Cancel action, and destructive Delete action remain exact and ordered — *(covered by test: `test/repo/artifact-delete-reference-frame.test.ts`, “artifact delete reference frame > renders the named confirmation with exact copy (^af-ui-ac-delete-reference-render)”)*. ^af-ui-ac-delete-reference-render
- **Contract** (the production artifact-frame view as the consumer side of the handoff from the application and navigation services, exercised in the same mocked DOM with the implementation-mount hook and recording fake service above; those mocks forfeit real service, history, stage, server, production menu-element, and native dialog behavior to [product/artifact-navigation.md#^ac-back](../../../product/artifact-navigation.md#^ac-back), [product/artifact-navigation.md#^ac-forward](../../../product/artifact-navigation.md#^ac-forward), [product/artifacts.md#^af-ac-delete](../../../product/artifacts.md#^af-ac-delete), and [ui/app/stage/index.md#^st-ac-fullscreen](../stage/index.md#^st-ac-fullscreen)): Back and Forward each call only their matching navigation action; Make full-screen requests entry to the frame's full-screen mode and Exit full-screen requests exit from that same mode; double-clicking the title bar requests a toggle, while double-clicking any of its buttons never does; Delete presents the named confirmation, Cancel closes it without a delete call, and confirming calls delete once; pressing the return button assigns the artifact's own URL as the frame's `src` (the real load is walked by [product/artifacts.md#^af-ac-demo-return](../../../product/artifacts.md#^af-ac-demo-return)) and, like every frame control under the surface's Testing directive, requests no navigation or application operation — `packages/web/test/artifact-view.test.ts` (“artifact-frame view rendering dispatcher > routes frame controls through navigation and application operations without replacing the host (^af-ui-ac-frame-actions)”); the return button is covered by `packages/web/test/artifact-view.test.ts` (“browser demo mode artifact frame > assigns the artifact's own URL as the frame src when return is pressed (^af-ui-ac-frame-actions)”). ^af-ui-ac-frame-actions
- **Contract** (the production artifact-frame view deriving its return state, exercised in the same mocked DOM; authored external page, shared, path, Markdown, and non-web URL artifacts are fixtures; the implementation-mount hook supplies a fake application service whose demo-mode flag and desktop-app mode are posed directly — mocks that forfeit the real server flag and its delivery to [product/artifacts.md#^af-ac-demo-mode](../../../product/artifacts.md#^af-ac-demo-mode)): across demo mode on and off, browser and desktop app, and each artifact kind, the artifact icon is a button only for the external page artifact in a browser with demo mode on — `packages/web/test/artifact-view.test.ts` (“browser demo mode artifact frame > makes the artifact icon a button only for an external page artifact in a browser under demo mode (^af-ui-ac-return-scope)”). ^af-ui-ac-return-scope
- **Contract** (the production missing-artifact renderer as the consumer side of host-supplied metadata, exercised in a mocked DOM; the host reply is injected directly and the fixed document structure is an authored fixture, forfeiting real iframe and webview delivery to [arch/artifact-frame/artifact-bridge.md#^ab-ac-missing-browser-seam](../../../arch/artifact-frame/artifact-bridge.md#^ab-ac-missing-browser-seam) and [arch/artifact-frame/artifact-bridge.md#^ab-ac-missing-electron-seam](../../../arch/artifact-frame/artifact-bridge.md#^ab-ac-missing-electron-seam)): without metadata it renders the fixed missing title, description, and recovery copy and no path; with metadata it uses the artifact name as the document title and exposes the exact path as text, never interpreted markup — *(covered by inherited tests: both cases in `packages/web/src/views/artifact-missing/main.test.ts` “artifact-missing renderMissingArtifact”)*. ^af-ui-ac-missing-state
- **Contract** (the production URL-unsupported renderer as the consumer side of the host target reply, exercised in a mocked DOM; the reply is injected directly and the fixed document structure is an authored fixture, forfeiting real iframe delivery and browser opening to [arch/artifact-frame/artifact-bridge.md#^ab-ac-url-target-seam](../../../arch/artifact-frame/artifact-bridge.md#^ab-ac-url-target-seam)): no target hides the address block while leaving the desktop-app section visible; an HTTP or HTTPS target renders that exact value as a safe new-tab link; and a non-web or invalid target renders the exact value as plain text with no link or click guidance — *(covered by inherited tests: all three cases in `packages/web/src/views/url-unsupported/main.test.ts` “url-unsupported renderTarget”, with the first case minimally table-driven across HTTP and HTTPS)*. ^af-ui-ac-url-state

Coverage relationship: the product spec owns the real-browser/server deletion spine at [product/artifacts.md#^af-ac-delete](../../../product/artifacts.md#^af-ac-delete); the title's visible and accessible names are this spec's own claim. Product navigation owns the browser and Electron Back/Forward outcomes; its assertions are cited above rather than repeated as a second component matrix. The [menu proof](../../foundation/menu/index.md) and [dialog proof](../dialog/index.md) own generic opening, focus movement, dismissal, backdrop, and background inertness. The [popover proof](../../foundation/popover/index.md) owns shared below/left placement, per-axis flipping, and unclipped presentation; this surface adds no placement exception. The stage owns full-screen geometry and real motion at [ui/app/stage/index.md#^st-ac-fullscreen](../stage/index.md#^st-ac-fullscreen). Frame-core routing owns the iframe/webview choice and status-page mechanism ([arch/artifact-frame/index.md#^frame-core-carve-out](../../../../specs/arch/artifact-frame/index.md#^frame-core-carve-out)), while the bridge owns the real metadata/target handoffs. These crossings compose with the two view contracts; this row orders no duplicate acceptance path.
