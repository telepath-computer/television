## Coverage model

The transparent state follows the [Storybook stories](../../../../storybook/spec/artifact-frame/artifact-frame.stories.ts) and [behavior prose](../../../../specs/ui/app/artifact-frame/transparency.mdx). A cheap view contract checks true or absent record values against the rendered state. Real-browser contracts mount production frames and drive pointer, keyboard, and the production menu, keeping CSS motion real to prove the frost-layer and title-bar fades, delayed hiding, unchanged document size, and reduced-motion behavior. The menu contract mounts the production stage with its resize handles and observes rendered placement and real hit targets, so an open attribute or keyboard-only activation cannot stand in for a reachable menu. The [stage resize-state contract](../stage/index.md#^st-ac-frame-resizing) drives handle hover and captured drags through the production stage to prove that they also reveal and retain the frost and bar. Their application-service mock forfeits persistence and delivery to [the product transparency walk](../../../product/artifacts.md#^af-ac-transparent).

Production is reviewed by screenshot against `Opaque`, `TransparentAtRest`, and `TransparentHovered`. Handle hover and live dragging are compared with the same `TransparentHovered` state in [the stage proof](../stage/index.md#transparent-resize-state); the native border and both edge paints stay hidden throughout. Review checks frost on the clip and title-bar `::before` layers beneath positioned content, with no backdrop filter on a menu ancestor or added stacking context that traps the menu beneath stage handles. Transparent background, native border, outline, shadow, edge paints, document corners, and frost tint/blur are styling judgments; no automatic stylesheet-copy or conformance check is added for this Storybook state, under [the migration boundary](../../../../specs/spec-migration.md#under-spec-authority). Existing checks for the rest of the frame remain active, including the bounded raster regression on opaque frames. The hover demonstration and `data-hovered` are story posing, not required production test hooks.

The [frame proof](./index.md) owns ordinary frame content, actions and the opaque window-edge regression. These assertions retain their existing test evidence; moving the spec does not add a conformance suite under the migration boundary above.

## Test hooks

The existing implementation-mount hook can supply authored artifact/navigation state and a recording application service; production gets those from its connected application services. Its mocked-DOM use forfeits native layout and input to the browser contracts; its browser use forfeits server state and transport to the product proofs. Real-motion tests use the shared motion-helper opt-out, and browser reduced-motion emulation supplies the user preference that production reads through its media query.
