# Toolbox — proof

Proves [specs/ui/app/toolbox.mdx](../../../specs/ui/app/toolbox.mdx).

## Coverage model

A Chromium conformance file compares every imported spec story with the production surface in the same state, viewport, theme and appearance.
It uses shipped markup/styles without test additions and fails if any story is missing; no permitted-difference list is allowed.
This MDX surface follows story conformance, not the conformance for retained frame/template contracts.
Conformance and cheap state contracts may substitute the item/cache service with authored scans and icon bytes; that mock forfeits discovery and transport to [template architecture](../../arch/templates/index.md), directory-read failure through the caches into the UI to [directory-failure acceptance](#^toolbox-ac-directory-error), and creation to [product creation](../../product/templates.md).
A real browser proves search focus, grid keys, pointer highlighting, active-cell semantics and scrolling; those mechanisms are never replaced by a mocked DOM. Browser-generated input drives every key assertion except input-method composition: because Playwright cannot drive a composition sequence, that case dispatches a synthetic keydown carrying `isComposing` at the real field. It proves only that the production listener passes the event through, forfeiting browser generation and delivery of composition events.
Product creation acceptance proves successful copy/URL activation and placement once, shared with this proof rather than duplicated.
Real-browser failure walks use filesystem obstructions; only a failed focus request uses a declared transport abort.
[The shared popover proof](../foundation/popover/index.md) owns generic toggling, dismissal, exclusivity and focus return; this proof checks Toolbox composition and trailing-edge placement.
[The app cache proof](../../arch/templates/index.md#^templates-t-app-cache) owns load/retry/reconnect and icon response ordering; the browser cache seam proves its real transport.
A default-icon contract checks Unicode and stable palette selection without a browser; image decoding and fallback require a real browser.
Shortcut breadth uses a platform-input contract and one real host crossing in browser and Electron; there is no implied Windows acceptance run.
The standing CSS-motion override forfeits motion only. No Toolbox assertion depends on CSS animation.
Behavior and every story are covered by the tests cited below. The conformance harness gives both pages the same 640×800 canvas and padded outer mount; it does not alter the Toolbox's shipped markup or styles.

## Test hooks

- A production Toolbox mount may accept an item/cache service and action callback; conformance and consumer contracts may supply authored items/errors, pending loads and recording actions. Production supplies its connection-owned template cache and creation action. This hook substitutes services, never markup, styles or browser input.
- The shortcut predicate may receive a platform value in contract tests; production obtains the current app platform. This forfeits platform detection to the real host seam below.
- Browser routes may hold/fail the startup list, an icon request or the focus request where explicitly declared. These mocks forfeit the corresponding transport outcome to [template transport](../../arch/templates/index.md#^templates-t-app-cache-seam) and [successful focus](../../product/templates.md#^templates-ac-ui-create).
- The input-method composition case dispatches a synthetic keydown carrying `isComposing` at the real search field. It proves production listener pass-through but forfeits browser generation and delivery of composition events; every other browser key assertion uses Playwright keyboard input.
- Electron uses [the existing app-URL fixture hook](../../../specs/arch/desktop/e2e-harness.md#^desktop-e2e-fixture-hook) to load the supplied app URL directly, bypassing saved-connection lookup and the connect screen. This setup substitution keeps the shortcut check focused on real host keyboard delivery. It forfeits connection entry and saved startup to the existing [desktop connect, remember and disconnect acceptance](../../product/desktop-app.md#^desktop-ac-connect-link).

## Consumer contracts

- **Contract** (item/query/highlight state → production grid model; authored records, no DOM or service needed): under [search](../../../specs/ui/app/toolbox.mdx#^toolbox-search), [vertical grid navigation](../../../specs/ui/app/toolbox.mdx#^toolbox-grid-navigation) and [highlight behavior](../../../specs/ui/app/toolbox.mdx#^toolbox-highlight), trim queries and match names only, case-insensitively in discovery order. Nonempty input highlights the first match; clearing removes the highlight. On list updates retain the query and matching highlighted ID, otherwise clear the highlight, without activation. Down from no highlight highlights the first tile; Up from no highlight leaves it clear. Up and Down move by three, with Up from the first row clearing the highlight and Down without a tile below highlighting the last tile. Unmodified Left and Right move in reading order and stop at the first and last tiles; neither creates a highlight from none. *(policy-grade test: `packages/web/test/toolbox-state.test.ts`, “matches trimmed names in discovery order and navigates the three-column grid”)* ^toolbox-t-search-state
- **Contract** (ID/name → production default-icon value; Unicode fixtures, no mocks): under [default icons](../../../specs/ui/app/toolbox.mdx#^artifact-template-default-icon), use the first Unicode code point with locale-free uppercase and the exact ordered nine-token palette/hash, including non-BMP IDs/names and 32-bit wrap. Same ID yields the same token across theme changes. Text remains text. *(policy-grade tests: `packages/web/test/toolbox-state.test.ts`, “uses Unicode code points and the ordered palette with unsigned 32-bit wrapping”)* ^toolbox-t-default-icon
- **Contract** (keyboard event/platform → shortcut decision; controlled platform input, real detection forfeited below): under [the shortcut](../../../specs/ui/app/toolbox.mdx#^toolbox-shortcut), Meta+K on macOS and Ctrl+K elsewhere toggle Toolbox; the wrong platform modifier does not claim that shortcut. ## Real browser and desktop behavior

- **Acceptance** (real browser → running server and template files; no mocks except CSS-motion disablement): under [opening](../../../specs/ui/app/toolbox.mdx#^toolbox-opening), [searching](../../../specs/ui/app/toolbox.mdx#searching) and [icons](../../../specs/ui/app/toolbox.mdx#^toolbox-icons), the navbar trigger, tooltip, popover and grid are named “Toolbox”; the trigger precedes Settings, and opening clears and focuses search with no highlight. The field is named “Search toolbox” with the specified placeholder and has `role="combobox"`, `aria-haspopup="grid"`, `aria-autocomplete="list"`, `aria-expanded="true"` and `aria-controls` naming the rendered Toolbox grid while cells are visible. Looking up that value yields the element with `role="grid"`; it contains three `role="gridcell"` elements in each complete `role="row"`, plus an incomplete final row without placeholders. Cells are named only by the full item name, `aria-selected` follows the highlight, descriptions are absent, default icons are decorative, and the input owns focus and `aria-activedescendant`. No visible tiles means no controlled grid or active cell and `aria-expanded="false"`. Escape restores focus to the trigger; the trigger and host shortcut toggle the panel, and outside input dismisses it. The shared popover proof owns the general focus-restoration rule. At the trailing edge the panel aligns to fit. Share setup with product UI creation. *(policy-grade test: `packages/web/test/e2e/toolbox-acceptance.test.ts`, “Toolbox opens, dismisses and toggles with the host keyboard shortcut”)* ^toolbox-ac-open
- **Contract** (production surface in a real browser with the declared item-service mock; real Playwright input except the declared composition seam): under [search](../../../specs/ui/app/toolbox.mdx#^toolbox-search), [vertical grid navigation](../../../specs/ui/app/toolbox.mdx#^toolbox-grid-navigation) and [highlight behavior](../../../specs/ui/app/toolbox.mdx#^toolbox-highlight), typing, filtering, clearing, four-direction grid navigation, pointer movement and list updates produce the state-contract outcomes while input focus stays put. Unmodified Left and Right move the text cursor normally with no highlight and move in reading order while a tile is highlighted. Up and Down pass through when no tiles are visible. Modified arrow keys retain normal text-field behavior. Real key presses drive modifier and endpoint cases, with a capture-phase listener recording whether production consumed each event. Because Playwright cannot drive input-method composition, a synthetic keydown carrying `isComposing` at the real field proves only that the production listener passes each arrow through; it forfeits browser generation and delivery of composition events. An unmodified vertical or horizontal endpoint key is consumed while tiles are visible. Pointer movement changes the highlight without scrolling; keyboard, search and list-update changes keep the highlighted tile fully visible between the top of the scrolling area and the floating footer. Under [grid layout](../../../specs/ui/app/toolbox.mdx#^toolbox-grid-layout), the first row starts below the search field with a gap, and that gap scrolls away as tiles pass directly under the field. Under [footer layout](../../../specs/ui/app/toolbox.mdx#^toolbox-footer), the search field stays fixed; the footer is the scrolling area's last child, stays at the bottom, lets the last row scroll fully above it and overlaps tiles. Moving within the footer over a different underlying tile does not move the highlight, and clicking there does not activate the tile. A wheel over the footer scrolls the grid. In Chromium launched with classic scroll bars enabled, the footer and its top rule stop before the scroll-bar gutter and the bar remains usable. Text selection and browser dragging are suppressed for tiles, names and default icons; [the browser icon seam](#^toolbox-t-icon-browser) covers supplied images. Return without highlight and Escape activate nothing. Service discovery and action execution are forfeited to the real product walk. *(policy-grade tests: `packages/web/test/e2e/toolbox.test.ts`, “real search, grid keys, pointer, updates and scrolling preserve input focus”, “keyboard and search reveal highlights at both scrolling edges”, and “real scroll bar remains usable beside the sticky footer”)* ^toolbox-t-browser-input
