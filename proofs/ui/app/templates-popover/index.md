# Templates popover (UI) — proof

Proves [specs/ui/app/templates-popover.mdx](../../../../specs/ui/app/templates-popover.mdx).

The spec embeds [Storybook stories](../../../../storybook/spec/templates-popover/templates-popover.stories.ts) and states the behavior those stories cannot show.

## Coverage model

Browser tests drive the production popover with a real pointer and keyboard against a running server and authored template folders. They cross the real scan, client, and creation path for success, pre-copy refusal, and failure after registration. For a scan-wide read failure, a regular file replaces the templates directory after serving boot. For a post-registration failure, a template with `data.json` meets a regular file at `<home>/resources` during its first store write; the browser observes the partial tab delivered by the server. For a focus-request failure after successful creation, the browser aborts only `POST /display/focus`; that case forfeits server focus behavior, which the successful creation case exercises. The standard CSS-motion override may be used; it forfeits motion, which these assertions do not claim. No test substitutes a mocked DOM, template registry, or creation service. The [product proof](../../../product/templates.md) owns the lasting artifact and store outcomes; this proof observes the popover's behavior at the point of use. [The foundation popover proof](../../foundation/popover/index.md) owns generic trigger toggle, placement, and light dismissal.

The stories exported by the popover's story module show closed and open, highlighted and pressed tiles, search and no match, empty and error states, missing image, long content, and scrolling with many templates. Production styles are derived by hand from `storybook/spec/templates-popover/styles.css` and checked against the stories by eye, as the [Templates popover spec](../../../../specs/ui/app/templates-popover.mdx) requires. No automated stylesheet-copy or conformance check applies to this pilot in this change, and this proof orders none. Browser assertions cover behavior and accessible state, not pixel styling. The tile crop, card dimensions, truncation, and pressed tint are checked by eye.

## Test hooks

No production test hook is needed; temporary template folders and browser state are fixtures.

## Assertions

- **Acceptance** (real browser → Templates trigger → running server and real scan; valid and invalid folders, and the post-boot directory obstruction declared above; no mocks beyond the motion override): Under [opening and image behavior](../../../../specs/ui/app/templates-popover.mdx#opening), each opening rescans, focuses an empty search field with no highlighted tile, shows valid tiles in scan order with names and images or placeholders, requests thumbnail bytes through the authenticated shared client only for entries with `hasThumbnail: true`, and lists invalid folders and their errors below the grid. The trigger is named and titled “Templates”; the search is a combobox controlling the listbox, each tile has one option identity, and decorative images have empty alt text and are nondraggable. An empty directory, only errors, an unreadable directory, and no search matches show their respective messages. Errors remain visible while searching. *(policy-grade test: `packages/web/test/e2e/skill-selector.test.ts`, cases tagged `^templates-ui-ac-open`)* ^templates-ui-ac-open
- **Acceptance** (real browser keyboard and pointer → production popover; a multi-column grid of templates with names and descriptions; no mocks beyond the motion override): Under [search and highlight behavior](../../../../specs/ui/app/templates-popover.mdx#the-highlight), case-insensitive search matches either field in usual order; typing highlights the first match and clearing removes the highlight. Left and Right move to the previous and next tile; Up and Down move to the tile above and below, with edge stops. From no highlight, any arrow highlights the first tile. Focus stays in the search field, which announces the active tile while there is a grid and no active tile when the grid is absent. Pointer movement changes the highlight; tiles cannot be dragged and their images and names cannot be text-selected. Return with no highlight creates nothing. *(policy-grade test: `packages/web/test/e2e/skill-selector.test.ts`, cases tagged `^templates-ui-ac-search`)* ^templates-ui-ac-search
- **Acceptance** (real browser click or Return → authenticated create request → running server; selected tab and empty-channel fixtures; the focus-failure case aborts only its focus request, forfeiting server focus behavior): Under [the specified behavior](../../../../specs/ui/app/templates-popover.mdx#creating-an-artifact), the activated tile creates in the focused channel after the selected tab, or as the only page when empty, focuses the new page, and closes the popover. Observing the unmodified create request verifies that the production popover sends `source: "ui"` under [the telemetry source rule](../../../../specs/product/telemetry.md#^artifact-template-telemetry). Removing the tile’s template folder after the opening scan but before activation makes the fresh create scan fail through the real filesystem. The popover then closes without displaying an error; focus and the selected tab stay as they were. If creation succeeds but the focus request fails, the new artifact exists while focus and the selected tab remain unchanged. Return with no highlight creates nothing, and Escape closes without creating. *(policy-grade test: `packages/web/test/e2e/skill-selector.test.ts`, cases tagged `^templates-ui-ac-create`)* ^templates-ui-ac-create
- **Acceptance** (real browser click → authenticated create request → running server and real filesystem; a selected tab and authored template with valid `data.json`, no mocks beyond the motion override): Under [failed creation](../../../../specs/ui/app/templates-popover.mdx#creating-an-artifact), place a regular file at `<home>/resources` after serving boot so the template seed fails after the server copies and registers the artifact. Observe focus and selected-tab state from the click until the failed request settles, including after the resulting partial tab is delivered and rendered. The popover closes without displaying an error; focus and the selected tab stay as they were, and the partial artifact is never selected or focused. *(policy-grade test: `packages/web/test/e2e/skill-selector.test.ts`, cases tagged `^templates-ui-ac-post-copy-failure`)* ^templates-ui-ac-post-copy-failure
