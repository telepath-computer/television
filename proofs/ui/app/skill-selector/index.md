# Skill selector (UI) — proof

Proves [specs/ui/app/skill-selector/index.md](../../../../specs/ui/app/skill-selector/index.md).

## Coverage model

The production composition uses `tv-popover`. The contracts below exercise the production composition through its unit and browser fixtures.

## Test hooks


`SkillSelectorTelemetrySignalSender` is the optional input through which the selector reports its fixed click event and property. Tests may supply a recording implementation to observe that mapping. The production navbar supplies the current `ServerConnection`; when no sender is supplied, telemetry reporting is a no-op and the copy button still performs its copy and confirmation behavior.

## Assertions

### Test assertions

- **Contract** (the production skill-selector view as the consumer of this surface's fixed content, exercised in a mocked DOM; the four imported thumbnail URLs are fixtures generated by the production asset path, and the mocked DOM forfeits popover and clipboard behavior to [ui/foundation/popover/index.md](../../foundation/popover/index.md) and [ui/app/copy-button/index.md#^cb-ac-clipboard](../copy-button/index.md#^cb-ac-clipboard); no application service, interaction mock, styling measurement, or motion claim): one markup smoke check renders the trigger followed by the panel. The trigger carries the fixed accessible copy and skills icon; the non-manual `tv-popover` names the button through `trigger` and contains the fixed heading and intro, and exactly the Calendar, Table, Tasks, and Markdown cards in that order. Each card carries its decorative thumbnail, exact name and description, and one composed copy button handed the shared label and that card's exact prompt, trailing space included — *covered by `packages/web/test/skill-selector.test.ts`*. ^ss-ac-markup-smoke
- **Seam** (real browser pointer input → composed copy-button activation callback → recording signal sender; the sender replaces websocket delivery, validation, and server capture, which compose through [arch/telemetry/client-signals.md#^tel-t-signal-sender](../../../arch/telemetry/client-signals.md#^tel-t-signal-sender) and [arch/telemetry/client-signals.md#^t-signal-forwarding](../../../arch/telemetry/client-signals.md#^t-signal-forwarding); clipboard is stubbed only to keep the browser fixture deterministic and forfeits clipboard success to [ui/app/copy-button/index.md#^cb-ac-clipboard](../copy-button/index.md#^cb-ac-clipboard)): pressing each fixed card's Copy prompt button sends exactly one `artifact_skill_prompt_copy_clicked` signal with its fixed skill key and no prompt text, and pressing one again sends one more — *covered by `packages/web/test/e2e/skill-selector.test.ts`*. ^ss-ac-telemetry

Coverage relationship: the trigger–panel pairing above composes with [ui/foundation/popover/index.md](../../foundation/popover/index.md) for toggle, focus, outside-press, and Escape behavior. The exact prompt handed to each composed button composes with [ui/app/copy-button/index.md#^cb-ac-clipboard](../copy-button/index.md#^cb-ac-clipboard) and [ui/app/copy-button/index.md#^cb-ac-confirm](../copy-button/index.md#^cb-ac-confirm) for copy and confirmation. The telemetry seam covers only the selector-owned fixed event/key mapping; the generic sender and server forwarding remain the telemetry transport's assertions. The top-bar row owns this surface's placement and mountedness inside the controls cluster.

> **Assertion cost.** The mocked-DOM rendering covers fixed content, order, references, asset placement, and prompt wiring. The focused browser seam covers the one selector-owned interactive outcome: a real click maps each fixed card to its content-free telemetry signal. Generic clipboard behavior remains covered by the copy button; generic popover coverage is established by that element; thumbnail crops, panel size, card grid, truncation, and button placement remain staging and review concerns.
