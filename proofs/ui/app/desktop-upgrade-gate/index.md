## Assertions

### Test assertions

The suite samples the component's salient markup and fixed fallback content, then proves the browser mechanics that make it a blocking, scrollable instructions surface ([arch/testing-policy.md#^ui-suite-scope](../../../../specs/arch/testing-policy.md#^ui-suite-scope)). It does not compare whole rendered HTML, measure panel geometry or overflow styling, or repeat the update architecture and product gate walks ([arch/testing-policy.md#^ui-styling-out](../../../../specs/arch/testing-policy.md#^ui-styling-out)). The DOM is the observation instrument for the claims below, not a blanket test subject ([arch/testing-policy.md#^ui-dom-instrument](../../../../specs/arch/testing-policy.md#^ui-dom-instrument)).

- **Contract** (the production `.desktop-upgrade-gate` view as the consumer side of the instruction-state-to-rendered-surface handoff, exercised in a mocked DOM; channel instructions, the no-channel fallback state and a desktop update state on a stand-in bridge that has reported a version are authored fixtures; the mocked DOM is a declared mock that forfeits native dialog, keyboard, pointer, link, and scrolling behavior to [#^dug-ac-blocking-interaction](#^dug-ac-blocking-interaction), [ui/app/dialog/index.md#^dg-ac-modal-behaviour](../dialog/index.md#^dg-ac-modal-behaviour), and [arch/updates/desktop-upgrade-gate.md#^updates-t-gate-render](../../../arch/updates/desktop-upgrade-gate.md#^updates-t-gate-render); no styling or motion claim): one table-driven salient-markup check covers channel instructions, the built-in fallback, and the downloaded-update message ready to restart and restarting. Each state renders one dialog overlay containing one open dialog and one message body, with that body composed exactly once. The channel state contains its supplied heading, prose, link, and command but no built-in copy. The fallback state is the authored fallback rendered, including its download link. Neither adds a button, button role, form control, dismiss affordance, or copy affordance. The downloaded-update states are the authored message rendered, followed by one primary restart button and no other control; the button carries the authored `restart_to_update` label, and in the restarting state the authored `restarting` label and is disabled — *covered by `packages/web/test/desktop-upgrade-gate.markup.test.ts` “renders each message as the only dialog body, with the restart button only for a downloaded update”*. ^dug-ac-markup-smoke
- **Contract** (the production `.desktop-upgrade-gate` view mounted directly in a real browser with a desktop update state on a stand-in bridge that has reported a version and records restart requests — a declared mock forfeiting real IPC to [product acceptance](../../../product/update-notifications.md#^ac-gate-downloaded-update); pointer input is real): pressing **Restart to update** requests the restart exactly once, the gate stays presented, and the button then reads **Restarting…** and is disabled — *covered by `packages/web/test/e2e/desktop-upgrade-gate.spec.ts` “the restart button requests the restart once (^dug-ac-restart)”*. ^dug-ac-restart
- **Contract** (the production `.desktop-upgrade-gate` view mounted directly in a real browser with overlong channel instructions as an authored fixture; direct presentation is a declared mock of application state selection and composition, forfeiting the boot decision, system-modal routing, and instruction selection to [arch/updates/desktop-upgrade-gate.md#^t-gate-boot-barrier](../../../arch/updates/desktop-upgrade-gate.md#^t-gate-boot-barrier), [ui/app/system-modal/index.md#^sm-ac-markup-smoke](../system-modal/index.md#^sm-ac-markup-smoke), and [arch/updates/desktop-upgrade-gate.md#^t-gate-instructions](../../../arch/updates/desktop-upgrade-gate.md#^t-gate-instructions); native dialog cancellation, keyboard input, pointer hit testing, and scrolling are real and form the assertion's spine; no test hook or CSS-motion override runs, so smooth scrolling and script-driven motion remain real; backdrop/Escape recorders begin before input and retain geometry-classified backdrop presses, native cancel and prevention state, native close, and open/modal presentation state through two animation frames; scroll recorders begin before wheel input, wait for the instructions body's scroll event and stable animation-frame position samples, and retain window, document, overlay, and dialog scroll events and offsets through that settled sample): pressing the backdrop or Escape does not withdraw the gate; wheel input inside overflowing instructions scrolls that body, while the backdrop and page do not move — *covered by `packages/web/test/e2e/desktop-upgrade-gate.spec.ts` “blocks dismissal and confines wheel scrolling to long instructions”*. ^dug-ac-blocking-interaction

Coverage relationship: [arch/updates/desktop-upgrade-gate.md#^t-gate-instructions](../../../arch/updates/desktop-upgrade-gate.md#^t-gate-instructions) owns message selection, [arch/updates/desktop-upgrade-gate.md#^t-gate-screen](../../../arch/updates/desktop-upgrade-gate.md#^t-gate-screen) owns the switch to the downloaded-update message and what the restart calls, and [arch/updates/desktop-upgrade-gate.md#^updates-t-gate-render](../../../arch/updates/desktop-upgrade-gate.md#^updates-t-gate-render) owns the real-browser crossing from selected markdown through the standard pipeline to DOM, including external-link behavior. [ui/app/system-modal/index.md#^sm-ac-markup-smoke](../system-modal/index.md#^sm-ac-markup-smoke) owns routing the needs-upgrade state to this surface.
