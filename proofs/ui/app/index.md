## Coverage model

The connection states describe Television being unable to use its server, including a connected app halted at the gate. Their contracts cover selection and failed-attempt counting with substituted connection sources and clocks. They forfeit real transport, authentication and recovery to the browser acceptances below. Those use a running server, real token rejection at boot and after an established session, and an outage long enough to reach the third failed reconnect. They honor the spec's real-browser and retained-node directives. The first-connection error uses the same unreachable-result and retry handoff as outage recovery; the state and markup contracts cover its no-prior-session selection and bare background without another browser walk. The [system-modal proof](./system-modal/index.md) owns contents and non-dismissal; [desktop product coverage](../../product/desktop-app.md) owns the separate packaged local-page lifecycle.

The shell markup contract samples every meaningful application state and requires the permanent `#foreground-overlay` in every row. A second contract composes the production shell view with the theme-resource owner under a mocked DOM to cover the optional frames' exact body order, IDs, sandbox, inertness, focus exclusion, and accessibility attributes across independently enabled and jointly enabled states. The theme registry and iframe documents are posed fixtures at that contract; this forfeits real registry lookup and iframe behavior to [theme delivery](../../arch/themes/delivery.md#^theme-delivery-t-frame-browser) and the [product browser spine](../../product/themes-and-appearance.md#^theme-ac-sandboxed-frames).

Real-browser hit continuity, focus restoration, top-layer precedence, matching host and frame-document schemes, and transparent frame composition belong to [theme delivery](../../arch/themes/delivery.md#^theme-delivery-t-frame-appearance-browser) and the [product frame-appearance spine](../../product/themes-and-appearance.md#^theme-ac-frame-appearance).

## Test hooks


`TelevisionAppOptions.onRenderComplete` is the optional production callback for observing when the connected app view has rendered a selected `ApplicationState.kind`. The production entry point supplies it to notify callbacks registered through the [`window.__telepath` test seam](../../arch/channel-state/index.md#Test hooks); when no test has registered a callback, the notification has no effect on application state or rendering.

Connection assertions may observe the production owner and render-complete signal through [the existing `window.__telepath` seam](../../arch/channel-state/index.md#^cs-telepath-test-seam). Server lifecycle control and real event-socket termination create outages; tests do not set application state on acceptance paths. Stored token values are browser-storage fixtures. The gate uses the [version hooks](../../arch/updates/desktop-upgrade-gate.md#test-hooks); they replace advertised versions, not gate decisions.

The browser's native `Animation` named `sidebar-collapse-boundary` is observed and its timeline paused/advanced for motion conformance. Production normally advances that timeline itself. Tests keep the production pose calculation, animation-frame callbacks, DOM application, and browser layout intact; this introduces no production-only testing setter.
