# Update notification (UI) — proof

Proves [specs/ui/app/update-notification/index.md](../../../../specs/ui/app/update-notification/index.md).

## Coverage model

The production composition uses `tv-popover`. The contracts below exercise the production composition through its unit and browser fixtures.

## Assertions

### Test assertions

The suite samples the notice's authored markup and proves the closing and confirmation behavior this surface adds around the foundation popover ([arch/testing-policy.md#^ui-suite-scope](../../../../specs/arch/testing-policy.md#^ui-suite-scope)). It does not measure the bell, panel, or button styling, including the no-resize swap ([arch/testing-policy.md#^ui-styling-out](../../../../specs/arch/testing-policy.md#^ui-styling-out)); DOM state is only the instrument for the behavior below ([arch/testing-policy.md#^ui-dom-instrument](../../../../specs/arch/testing-policy.md#^ui-dom-instrument)).

> **Assertion cost.** Popover presentation has no motion, and the generic copied swap is immediate state followed by a timer, not an animation; this row orders no real-motion assertion. The interaction browser contracts share one mount, and selection coverage extends the two existing rendering cases without adding a journey. Panel open-state mutations and render completion settle closing paths; the no-auto-hide and outside-press recorders protect their negatives. The confirmation contract narrows to the only behavior composition adds: clearing stale state across close/reopen. One mocked-DOM table proves the prompt/label handoff without repeating generic copy/check internals. Panel dimensions, colors, button width, and reflow remain staging and review concerns. The assertion inventory stays bounded to the surface's composition.
