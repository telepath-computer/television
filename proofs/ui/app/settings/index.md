# Settings (UI) — proof

Proves [specs/ui/app/settings/index.md](../../../../specs/ui/app/settings/index.md).

## Coverage model

The production composition uses `tv-popover` and, for Settings, `tv-select`. The contracts below exercise the production composition through its unit and browser fixtures.

A production-view contract uses authored registry and confirmed-display snapshots behind an application-service mock. It proves conditional main-page consent markup, exact copy, accessible checked state, immediate service calls, pending confirmation, event convergence, and readable failure without paying for transport. Enabled iframe-only, disabled main-page, unflagged, and incomplete-snapshot fixtures prove that sandboxed declarations never expose a consent control. The mock forfeits display persistence and event delivery to [theme architecture](../../../arch/themes/index.md#^themes-t-javascript-consent-state).

A real Chromium acceptance drives the production Settings popover against a running server and real package folders through HTTP and websocket connections. It covers main-enabled, disabled-main, unflagged-main, iframe-only, and ordinary active themes, another authenticated client, a genuine failed write, and the browser's native switch and production popover behaviour without replacing those paths. Its reload portion proves one open Settings surface returns once after the application document is replaced; [the product reset acceptance](../../../product/themes-and-appearance.md#^theme-ac-executable-reset) carries the broader two-document reset outcome.

The browser checks the toggle's labelled switch semantics and rounded-track geometry. Exact spacing, colors, and motion remain staging-review judgments, along with the rest of the panel's interior styling.
