# Markdown editor color and table interactions (UI) — proof

Proves [specs/ui/markdown-editor/index.md](../../../specs/ui/markdown-editor/index.md).

## Coverage model

The color authority is a stylesheet-only surface. Its production crossing is split at the named handoffs below: authoritative copy, entry-module delivery, built output and template-page order. The checks read real repository files and run the real Vite builder without mocks or test hooks. They do not claim that a browser applies each declaration or that the resulting colors are visually successful.

Exact styling remains stylesheet authority under the [UI testing policy](../../../specs/arch/testing-policy.md#^ui-styling-out). Under [frame and template conformance](../../../specs/arch/ui/conformance.md), implementation and visual review judge the complete [color-state promise](../../../specs/ui/markdown-editor/index.md#^md-editor-color-states) across representative light, dark, and themed appearances. The themed set includes a purpose-built light-primary contrast theme so the active outside table-header handle exercises `--color-primary-text` against a light `--color-primary` fill. The same judgment covers the rendered and source-reveal states, retained CodeMirror focus geometry, task controls, and the table’s open menu. The opt-in browser fixture at `packages/view-markdown/test/e2e/visual-review.spec.ts` makes those exact poses reproducible and can write screenshots plus a computed-style inventory for human inspection. Its checks establish only that the requested interaction states were reached; they do not turn visual success into an automated color, screenshot, or selector assertion. Existing browser probes for cursor and earlier marker token mappings remain regression evidence, but they do not substitute for that review or enumerate the stylesheet.

The real-browser [artifact-color acceptance](../../arch/themes/delivery.md#^theme-delivery-t-artifact-colors) proves that canonical and active-theme values reach a built Markdown document and update live. This proof composes with that delivery evidence rather than repeating theme selection or native `color-scheme` coverage. Server-rendered read-only Markdown remains outside this proof and has no parity assertion against the editor sheet.

The narrow table-interaction buffer adopts existing Chromium browser tests as inherited evidence for link gestures and code literals. Table-edge navigation has a policy-grade browser contract that covers both outcomes: leaving a table with text around it, and keeping the caret in the edge cell where the table starts or ends the document. These tests run the real widget and editor, with captured host messages and window.open rather than real parent navigation. They establish interaction outcomes without extending color conformance or claiming a complete Markdown-editor UI specification.

## Test hooks

Table cases observe the root editor through `window.__cmView`, which the Markdown file view exposes in development and production for its established browser and Electron tests. They substitute `window.__televisionContentBridge` for host-message capture and replace `window.open` to record requested destinations. Production uses the real editor, host bridge, and browser context creation.

## Assertions

### Test assertions

- **Seam** (authoritative `specs/ui/markdown-editor/styles.css` → committed `packages/view-markdown/src/colors.css` copy through the real repository filesystem; no mocks or test hooks): to prove the copy leg of the spec's [production crossing](../../../specs/ui/markdown-editor/index.md#^md-editor-color-crossing), the crossing registry discovers this standalone UI source and the committed package copy is byte-identical. *(covered by test: `packages/web/test/foundation-copy.test.ts`, “application foundation production crossing (^ui-t-foundation-copy)”)*. ^md-editor-t-stylesheet-copy

- **Contract** (real Markdown entry modules and production style-route registry; no mocks or test hooks): to prove the source-delivery leg of the [production crossing](../../../specs/ui/markdown-editor/index.md#^md-editor-color-crossing), the Markdown file view and packaged Markdown editor entry modules reach their implementation-owned layout sheets and authoritative colour copy, and the route inventory contains those document styles. *(policy-grade test: `test/repo/ui-style-delivery.test.ts`, “reachable stylesheet and style-adoption routes match the explicit expected routes”)*. ^md-editor-t-entry-delivery

- **Seam** (the two real Markdown entry modules → fresh production Markdown file-view output and the committed packaged Markdown editor stylesheet checked against fresh output; no mocks or test hooks): to prove the ordered build leg of the [production crossing](../../../specs/ui/markdown-editor/index.md#^md-editor-color-crossing), the file-view entry imports the page layout, editor layout, and authoritative colour copy in that order, and its built output preserves the order; the packaged Markdown editor entry and committed `editor.css` put the editor layout before the colour copy. The packaged Markdown editor side relies on the [licensing build seam](../../arch/licensing.md#^licensing-t-markdown-editor-build) to keep the committed stylesheet equal to fresh output; the [packaged Markdown editor build seam](../../arch/templates/document.md#^templates-document-t-editor-build) checks the remaining output shape. *(policy-grade test: `packages/view-markdown/test/e2e/appearance.spec.ts`, “ships the authoritative colour sheet after each implementation layout”)*. ^md-editor-t-build-order

- **Contract** (real bundled-template HTML; no mocks or test hooks): to prove the page-delivery leg of the [production crossing](../../../specs/ui/markdown-editor/index.md#^md-editor-color-crossing), the template loads canonical v2, its packaged `editor.css`, and then its local page layout. This is the same stylesheet-order clause and adapted server-package test cited by the [packaged Markdown editor-files assertion](../../arch/templates/document.md#^templates-document-t-editor-files). *(policy-grade test: `packages/server/test/document-template.test.ts`, “ships and loads its packaged Markdown editor”)*. ^md-editor-t-template-order

- **Inherited browser contract:** to prove [table interactions](../../../specs/ui/markdown-editor/index.md#^md-table-interactions), real Chromium editor/widget DOM renders table links as labels, keeps code literals literal, routes plain/modifier clicks like prose links, and retains cell editing on Alt-click. The host content bridge and window.open are replaced to capture messages and destinations; actual parent navigation and browser-context creation are forfeited. The [table-source proof](../../arch/artifact-frame/markdown-tables-buffer.md#^mt-t-passive-source) carries emitted-save/source preservation, and [edge navigation](#^md-table-t-edge-navigation) carries the edge keys — *(covered by inherited tests: `packages/view-markdown/test/e2e/links.spec.ts`, “table links render and use the same navigation and editing gestures”)*. ^md-table-t-interactions

- **Contract** (Markdown view's table keyboard navigation, loaded from its Vite source server in Chromium with real keyboard input, root editor, table widget, and source mapper; the `window.__televisionContentBridge` hook delivers the authored fixtures and captures update-content messages): to prove [table-edge navigation](../../../specs/ui/markdown-editor/index.md#^md-table-interactions), Tab from the last cell, Shift-Tab from the first cell, and Enter from the last row each leave a table that has text before and after it: no cell editor remains, the root editor holds focus, and its caret lies outside the table on the side the key moved toward. In a document that is only a table, the same keys keep the caret in the edge cell: that cell's editor keeps focus, the root editor never receives focus, and the root caret stays within the cell's source text. In both documents the source and cell count stay unchanged and no update-content message is emitted. The bridge mock forfeits delivery through a real parent frame and persistence, which this buffer leaves outside its authority — *(covered by tests: `packages/view-markdown/test/e2e/table-source-preservation.spec.ts`, “edge keys leave a table with surrounding text without changing source or saving” and “edge keys at document edges keep the caret in the edge cell without changing source or saving”)*. ^md-table-t-edge-navigation
