# Setup screen — proof

Proves [specs/ui/setup/index.md](../../../specs/ui/setup/index.md).

## Coverage model

A renderer contract covers the four authored states and the local connection handoff. It replaces the connection bridge and clipboard sink, proving what setup sends and renders, not IPC, authentication or the system clipboard. [Desktop product acceptance](../../product/desktop-app.md#^desktop-ac-connect-link) crosses the packaged page, preload, main process, server and served interface; [setup failure acceptance](../../product/desktop-app.md#^desktop-ac-setup-errors) proves inline recovery. The product success walk uses real CSS motion to observe Connected before navigation, including the reduced-motion path, without introducing an additional dwell requirement.

The shared [Copy proof](../app/copy-button/index.md) owns clipboard success, fallback, confirmation and its timer for all callers. Setup proves the prompt supplied to that control and that copying does not advance or disable either step. An Electron seam proves native prompt selection. Drag coverage uses the existing X11 harness and explicitly forfeits the host window manager; it does not treat a computed CSS property as movement evidence.

The card is static content using the frame's look. Its contract checks that it creates no artifact document or controls; setup requires no artifact runtime. Geometry, colours and Clouds styling stay with UI conformance and review. [Desktop asset delivery](../../arch/desktop/connect-flow.md#^desktop-t-local-assets) and [appearance](../../arch/desktop/appearance.md#^desktop-appearance-t-local) prove delivery and mode selection. General markup-comparison automation remains deferred under [TV-649](../../../specs/arch/ui/conformance.md#release-exception-for-tv-649); active stylesheet and functional evidence still applies.

## Test hooks

Electron assertions use the [user-data and version hooks](../../arch/desktop/connect-flow.md#test-hooks); the renderer contract supplies a recording local bridge at its dependency boundary, where production receives the packaged preload bridge.

The Copy dependency seam is declared by [the Copy proof](../app/copy-button/index.md#test-hooks); setup contracts may use its recording clipboard sink, forfeiting the clipboard to that proof.

## Assertions

- **Contract — states and submission.** Mount the production setup renderer in a mocked DOM with link/error fixtures and a recording bridge whose promises the test resolves or rejects. These mocks forfeit native submission and the real lifecycle to the product walks named above. Under [States](../../../specs/ui/setup/index.md#states) and [the frame](../../../specs/ui/setup/setup.frame), ready has the prompt and an empty, labeled, required link field; Copy requests standard size, the field `data-size="lg"`, and Connect `size="lg"`. Connecting disables the field and Connect and requests the spinner. Connected presents the check and Connected content with the steps inert. Error keeps the full link editable and connects its invalid marker to the supplied error paragraph in place of the hint. The card has its title but no artifact document, menu or navigation controls. At the [submission boundary](../../../specs/ui/setup/index.md#interaction), empty input submits nothing, a nonempty link can be submitted without copying first, and a failed attempt can be corrected and resubmitted; retry leaves the error treatment for the connecting state. *(test to be written)* ^setup-t-states
- **Contract — Copy composition.** Use the production renderer with the same mocked DOM/bridge and the Copy recording sink. Under [Interaction](../../../specs/ui/setup/index.md#interaction), activating Copy supplies exactly the frame's prompt, including its guide URL, while keeping the entered link, connection state, and both steps' availability unchanged. Clipboard and confirmation mechanics remain with [Copy coverage](../app/copy-button/index.md#^cb-ac-clipboard). *(test to be written)* ^setup-t-copy
- **Seam — prompt selection.** Cross a real pointer press on the packaged prompt into Chromium's native selection in Electron, using empty isolated user data and no selection or renderer mocks. Under [Interaction](../../../specs/ui/setup/index.md#interaction), one press selects the whole prompt without submitting or changing screen state. *(test to be written)* ^setup-t-select
- **Seam — setup dragging.** Cross native pointer input on the packaged setup background into Electron's native move request and `BrowserWindow` movement. Use the Linux/X11 driver declared by [sidebar dragging](../app/sidebar/index.md#^sb-ac-titlebar-drag): it substitutes the window manager's response to `_NET_WM_MOVERESIZE`, leaving host-window-manager and macOS behavior outside this automated assertion; Electron hit testing and window bounds remain real. Under [Interaction](../../../specs/ui/setup/index.md#interaction), dragging the background moves the window, while input inside the card selects/edits or activates a control without moving it. Observe move events and bounds after native pointer release. *(test to be written)* ^setup-t-drag

The product [connection walk](../../product/desktop-app.md#^desktop-ac-connect-link) supplies real-motion proof of [Connected before the served page](../../../specs/ui/setup/index.md#states). It observes the production transition and a rendered Connected presentation before navigation, using animation/frame and navigation signals rather than sleeps. The reduced-motion row reaches the same presentation and navigation without waiting for a transition event that does not occur. ^setup-t-connected
