*How the promises in Themes and appearance are proven.*

# Themes and appearance — proof

Proves [specs/product/themes-and-appearance.md](../../specs/product/themes-and-appearance.md).

## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below.

The executable-theme browser spine uses two connected application documents in one real Chromium session against a running production server. Real package fixtures drive main-enabled, unflagged, iframe-enabled, syntax-error, and uncaught-exception paths through Settings, persisted display state, the three public script routes, the production application resource owner, two real iframe boundaries, and an artifact document. Theme-owned markers, execution counters, package assets, and frame messages make absence before main consent, main execution in both application documents, automatic sandbox execution, repeat execution, document-lifetime effects, reload reset, classic-script-relative URL resolution, and frame replacement observable without a test hook or mock. Browser error events and ordinary application controls establish failure isolation.

That walk keeps the active package selected while an unrelated file changes, its root disappears and returns, the server reconnects, and the built server restarts. It distinguishes main-script reruns from appearance changes, which preserve the main include while replacing enabled frame documents, and from empty script responses. Its reset portion withdraws consent and selects both another theme and `None` while a main include is active, observes both connected documents reload under confirmed destination state, and gives only one document an open Settings popover so one-shot restoration and marker consumption are observable. Package and route breadth remain cheaper in [theme architecture](../arch/themes/index.md#^themes-t-javascript-package) and [theme delivery](../arch/themes/delivery.md#^theme-delivery-t-script-route); Settings presentation and failure recovery live in [the Settings proof](../ui/app/settings/index.md#^settings-ac-javascript-consent).

The sandbox slice uses real background and foreground frames from the active package. It observes the opaque-origin boundary, protected stacking, replacement and removal, all five pointer messages across the application and a bridge-capable artifact, unchanged clicks in both documents, focus restoration, the production document-layer Settings popover and browser-top-layer modal controls, and contained script failures in Chromium. Its appearance case drives a real effective change, records removal before replacement, observes the new root markers and script startup state, compares the host and document schemes, and samples rendered probes behind otherwise transparent frames; computed transparent backgrounds alone would not exercise the browser's iframe canvas composition. Deterministic declaration, lookup-failure, stale-result, and event permutations stay at the theme-delivery contract so the acceptance walk need not multiply expensive browser scenarios. Bridgeless documents, nested frames, possible content interference, and Electron raw/plugin gaps remain outside acceptance by explicit reference to the [artifact bridge's known limits](../../specs/arch/artifact-frame/artifact-bridge.md#known-limits-and-non-goals), not as omitted product assertions.

A separate real-Electron acceptance grants main consent through the application's Settings surface, observes main and frame execution only in the application renderer, and uses another client to drive reset and replacement events. It proves that the artifact webview remains theme-script-free while its ordinary pointer input reaches both theme frames without suppressing its click, the renderer receives no added Node integration, main opt-out and theme changes reload the application document under confirmed state, and frame-only replacement does not. It uses only the desktop harness's shell-version hook, whose installed-version-provenance forfeit remains owned by desktop upgrade-gate coverage.

The active-package stylesheet spine extends the existing Chromium persistence walk, so it pays for no additional browser startup. A real active package imports a nested stylesheet while the application and one live-canonical HTML artifact expose computed-style probes. The test edits only that nested file, moves the complete package away, and restores it at the same path while the browser stays connected to the running product server. It observes changed, baseline, and restored presentation plus the server-confirmed theme ID; it invokes neither registry refresh nor another selection and uses no mocks or test hooks.

That one walk honors the active-package testing directive. Operation breadth, debounce, watcher recovery, owner cleanup, and domain-event separation are carried by [theme architecture](../arch/themes/index.md#^themes-t-active-package-watch); exact missing-root route responses and validators are carried by [theme delivery](../arch/themes/delivery.md#^theme-delivery-t-route-recovery); and the shared file/folder mechanism is carried by [reload and navigation](../arch/artifact-frame/reload-navigation.md#^rn-ac-shared-watcher-recovery).

A Firefox acceptance drives a fixed-dark-to-light selection through real Settings after a Markdown editor is ready. It observes the shell and same loaded editor converge without losing the document or contents. The same browser walk supplies the request-level evidence required by [theme delivery](../arch/themes/delivery.md#^theme-delivery-t-markdown-refresh-firefox); the canonical wrapper's query permutations remain at that architecture proof's cheaper HTTP seam.

The appearance browser spine uses one adaptive and one fixed package in the existing Chromium persistence walk. Real Settings changes and a built-server restart keep the application, Television-managed artifact, URL artifact, foundation styling, and both sandboxed frames on the production path. It walks the adaptive choices once for breadth, then holds the fixed theme under an opposing stored preference and returns to adaptive so persistence and delayed effect are user-visible without multiplying browser launches.

The corresponding real-Electron spine shares the desktop acceptance at [desktop appearance](../arch/desktop/appearance.md#^desktop-appearance-t-electron). It keeps `nativeTheme`, an existing Television-managed webview, and a third-party URL webview real, proving both the fixed result and application of the latest preference after returning to adaptive. Architecture contracts carry normalization, display/event production, and renderer permutations; the product assertions pay for the browser and desktop principal paths once.

The bundled-theme acceptance starts the built CLI against separate real temporary [Television homes](../../specs/product/cli.md#^cli-home) for fresh installation and a below-minimum Clouds upgrade. The upgrade fixture carries prior package bytes, extra content, an active Clouds selection, exact-ID JavaScript consent, and completed bundled-theme state. The walk observes the hidden byte-identical backup, complete packaged replacement, preserved selection and consent, and a registry with no backup entry or error. Installer decision and failure breadth remain at [bundled installation](../arch/themes/bundled-installation.md); this acceptance pays only for the two principal built-product paths.

`tv themes-path` prints the directory the server scans for installed themes when it is given the server's home. [The CLI contract](../arch/cli/index.md#^cli-themes-path-contract) proves it prints `<home>/themes`, and [the CLI/server seam](../arch/cli/index.md#^cli-themes-path-server-seam) writes a package after boot into the directory `tv --home <home> themes-path` prints, then refreshes and selects it through the real server. No browser walk repeats that handoff.

The Settings acceptance checks that a fresh installation offers None plus the themes in [the bundled inventory](../../specs/ui/themes/bundled.yml). Preservation of packages removed from the bundled set is covered at the cheaper [real-filesystem installation contract](../arch/themes/bundled-installation.md#^bundled-t-retired-package).

Clouds' association with Television 1.3 composes with [product versioning's release identity](./versioning.md#^versioning-ac-release-identity); theme manifests keep their independent package versions and are never used as Television release evidence.
