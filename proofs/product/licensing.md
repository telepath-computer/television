*How Television's licensing promises are proven where users receive them: the license gate over the real tree, the packed CLI tarball, the desktop upload directory, the served browser notices, and Electron's license files in the installed desktop app.*

# Licensing — proof

Proves [specs/product/licensing.md](../../specs/product/licensing.md).

## Coverage model

The assertions below are the spine paths. Their breadth — per-package permutations, notices formatting, override handling, per-bundle inventory mechanics — is proven by the contract and seam assertions in the [architecture proof](../arch/licensing.md).

The license gate runs over the real tree in the standard suites, after real builds of the CLI and the desktop app, and its failure exit is walked as a spawned process against an authored package tree. The CLI package is accepted in the real tarball `npm pack` produces. The desktop app is accepted in an upload directory generated by the real desktop build script, which is what ToDesktop builds the app from. The built app is inspected only by the desktop product's recorded real-Mac run, which [finds Electron's license files inside it](./desktop-app.md#^desktop-ac-electron-license-files). No test observes that ToDesktop carries the upload directory's `LICENSE` and notices into the app, or that the packages it installs keep their own license files; the spec relies on ToDesktop building the app from that directory and installing whole packages. The browser notices are fetched from a running server. One acceptance reads every generated notices file together, from the real artifacts, for the reader, existence and ignored-package promises.

The [resource SDK](../../specs/arch/resources/sdk.md) is a surface because its push-key generator is adapted from the Firebase JavaScript SDK. Its notices are accepted where users receive them: served by a running server next to the module, and in the packed CLI tarball, beside the module and in the umbrella notices. [The SDK build contract](../arch/resources/sdk.md#^sdk-t-build) reads esbuild's metafile and fails if any input is not first-party, so a package bundled into the SDK cannot pass unnoticed. The adapted file's attribution comment is accepted in the committed source file, which the public repository delivers, beside the root notices. The `television` skill's `resources.md` is first-party instructions like its other guidance and orders nothing.

The root `LICENSE` is authored legal text. Review checks that it carries the [specified trademark statement](../../specs/product/licensing.md#television-is-mit) verbatim after the MIT text, separated by a blank line; no test checks that wording. The CLI-tarball and desktop-upload assertions prove that the whole root file, whatever it contains, reaches the tarball and the upload directory byte-for-byte.

A bundled theme's attribution is proven on the real packed CLI tarball: the Nord stylesheet's opening comment, the notices file in the Nord folder, and Nord's entry in the package notices. The tarball is where that acceptance stops. The copy from the packaged folder into a user's data directory is carried by the bundled-theme installation proof, which compares every theme file byte-for-byte through the builds and installation. The README's link to the upstream license is authored prose judged in review, and no test covers it.

## Assertions

Test shapes follow the [testing-policy.md](../../specs/arch/testing-policy.md) declaration schema.

- **Acceptance — gate passes on the real tree.** Boundary: the license gate run inside the standard suite, over the surface inventories produced by the suite's real pre-build of both products, the CLI and the desktop app (the enforcement path itself — wiring owned by [arch/licensing.md](../../specs/arch/licensing.md)). Asserts the gate passes on the tree as it stands, enumerating every checked surface — proving the shipped inventory, config, and committed source-surface notices are actually in a passing state, not just that the machinery can fail. No mocks. ^licensing-ac-gate-passes
- **Acceptance — gate failure exit.** Boundary: the gate as a spawned process. Against a fixture dependency tree containing a shipped dependency with a disallowed license, asserts the gate exits nonzero and names the offending package. Fixture: an authored minimal package tree; declared here because the real tree (rightly) contains no violation to observe. ^licensing-ac-gate-fails
- **Acceptance — published CLI package.** Boundary: the real package artifact — build the CLI workspace and pack it with `npm pack`, then inspect the tarball. Asserts the tarball contains a `LICENSE` byte-identical to the repository root `LICENSE`, and a third-party notices file carrying at least one known entry from **every input class**: the CLI bundle (`express`), the web bundle (`dompurify`, shown under its elected Apache-2.0), a bundled view (a CodeMirror package), a skill bundle (`@rupertsworld/event-target`), and the vendored assets (Hind, Phosphor, the Nord color palette) — plus the **complete notice text** of at least one package whose notice is config-resolved rather than read from a license file (`cookie-signature`, whose MIT grant lives only in its README). Spot entries per class rather than "every package," because each class entry proves its whole collection seam is wired; per-package completeness is the generator contract's job in [arch/licensing.md](../../specs/arch/licensing.md). No mocks; the built tree is the fixture. ^licensing-ac-cli-tarball
- **Acceptance — desktop upload directory.** Boundary: an [upload directory](../../specs/arch/desktop/distribution.md#^desktop-dist-upload) generated by the real desktop build script after a real desktop build, stopped before the ToDesktop build by [the build script's test hook](../arch/desktop/distribution.md#test-hooks). Asserts the directory contains a `LICENSE` byte-identical to the repository root `LICENSE`, and contains `dist/THIRD-PARTY-NOTICES.txt` exactly when the desktop build produced entries, which today it does ([a file where there is something to declare](../../specs/product/licensing.md#^licensing-notices-when)), with the bytes that build wrote. It contains the local renderer’s bundled packages and the Hind, Phosphor, Tailwind and both Clouds photo attributions, establishing the [desktop theme-material promise](../../specs/product/licensing.md#^licensing-theme-material) on the delivered directory. This is the desktop's [upload-directory check](../../specs/arch/licensing.md#^licensing-upload-assertions). No mocks; the built tree is the fixture — *(covered by test: `test/node/licensing.test.ts` “desktop upload directory carries the project license, and notices exactly when entries exist”)*. ^licensing-ac-desktop-upload
- **Acceptance — Electron's license files in the installed app.** The [aggregate condition](../../specs/product/licensing.md#^licensing-electron-aggregate) is accepted in the built Mac app by the desktop product's license-file check, which an agent runs on the build's Mac zip and which finds Electron's `LICENSE.electron.txt` and `LICENSES.chromium.html` in its `Contents/Resources` ([Electron's license files](./desktop-app.md#^desktop-ac-electron-license-files)). ^licensing-ac-desktop-install
- **Acceptance — browser surface.** Boundary: a really-running Television server and a real HTTP client. Fetches the notices at their stable URL next to the client bundle and asserts real entries: a bundled package under its elected license (`dompurify` as Apache-2.0) and the vendored Hind and Phosphor records — proving the served file is the generator's merged output, not a raw bundler inventory that cannot know about assets or elections. No mocks. ^licensing-ac-web-notices
- **Acceptance — every shipped notices file reads for its audience.** Boundary: every notices file Television generates, collected from the real artifacts — the committed repository-root file, the packed CLI tarball, the desktop upload directory and its Clouds folder, each built view and skill directory that has one, the resource SDK's directory in the tarball, each bundled theme folder that owes one, and the files the running server serves next to the browser bundle and next to the resource SDK. The theme folders are selected from the asset manifest's records, never by looking for the file, so a folder missing the file it owes fails. The set is also asserted to be the right one: a notices file exists at each of those locations whose surface has entries, and at none of the others ([the existence rule](../../specs/product/licensing.md#^licensing-notices-when)). For each one, asserts that it names no ignored package in any form (no entry, no heading, no status line) and that it follows [the reader rule](../../specs/product/licensing.md#^licensing-notices-audience) throughout: the header names the product and what the file is, and nowhere in the file — header or entry — does an internal identifier, a configuration key, or a term of this project's own machinery appear. Composing both properties over the real files is what makes them true of what users receive, rather than only of a generator fixture — *(covered by test: `test/node/licensing.test.ts` “every real artifact has notices exactly where entries exist, and every file is written for readers”)*. ^licensing-ac-ignored-silent
- **Acceptance — a bundled theme's attribution ships with it.** Boundary: the real packed CLI tarball, the same artifact as the published-CLI acceptance. For Nord, the theme whose asset record exists today, asserts [the theme rule](../../specs/product/licensing.md#^licensing-theme-material) on what a user receives: `dist/themes/nord/theme.css` opens with a comment carrying Nord's address, its copyright line, its license name, and the notices filename; `dist/themes/nord/THIRD-PARTY-NOTICES.txt` carries the complete Nord license text; and the tarball's umbrella notices list the Nord color palette. The copy from that packaged folder into a user's data directory is forfeited here and carried by [the bundled-theme package-copy and lifecycle assertions](../arch/themes/bundled-installation.md#^bundled-t-package-copy), which prove the complete folder is copied byte-for-byte. The README's fixed-revision link is authored prose judged in review and orders no test. No mocks; the built tree is the fixture — *(covered by `test/node/licensing.test.ts` “CLI tarball ships the Nord theme with its attribution”)*. ^licensing-ac-theme-attribution
- **Acceptance — adapted code carries its attribution.** Boundary: the committed source file and repository-root notices, the real packed CLI tarball (the same artifact as the published-CLI acceptance), and a really-running Television server given the built SDK, fetched with a real HTTP client. Asserts [the adapted-code rule](../../specs/product/licensing.md#^licensing-adapted-code) on what users receive: `packages/shared/src/resources/push-keys.ts` opens with a comment naming the Firebase JavaScript SDK and its address, carrying `Copyright 2017 Google LLC` and the Apache License 2.0 notice, and stating that Television modified the file; and the root notices, the tarball's umbrella notices, the tarball's `dist/sdk/v1/THIRD-PARTY-NOTICES.txt`, and the notices the server serves at `/sdk/v1/THIRD-PARTY-NOTICES.txt` each list the Firebase JavaScript SDK under Apache-2.0 with Google's copyright line and the complete Apache License 2.0 text. No mocks; the built tree is the fixture — *(covered by test: `test/node/licensing.test.ts` “code adapted from the Firebase JavaScript SDK carries its attribution wherever it ships”)*. ^licensing-ac-adapted-code
- **Acceptance — manifest coverage.** Boundary: the manifest check run as a spawned process. Asserts it exits nonzero when any workspace manifest omits `"license": "MIT"`, and zero on the real tree. ^licensing-ac-manifests
