*How the promises in CLI are proven.*

# CLI — proof

Proves [specs/product/cli.md](../../specs/product/cli.md).

## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below.

Spawned tests give every `tv` process that uses an installation a temporary [Television home](../../specs/product/cli.md#^cli-home) with `--home`. The exceptions are the default-home and legacy-variable acceptances, which run without `--home` and substitute the operating-system home directory through `HOME`. No test reads or writes the default home or `~/.tv-home` of the user running it, which honors the spec's home testing directive. The spine walks these home and config paths through built processes:

- a server and its client commands agreeing through one home: its token, its config file, and its port;
- `tv config set` writing the config file that the next `tv serve` reads;
- default-home selection with and without `~/.tv-home`, and `--home` taking precedence over the file;
- an invalid config file stopping `tv serve` before it binds;
- authentication on by default for foreground and persisted serving;
- a client finding a persisted service through its home's nonzero config port;
- a retired option refused with the upgrade guidance, and an earlier release's service definition still starting a server;
- a legacy environment variable warned about and ignored.

An existing storage directory serves as a home without moving files because a home has the same layout; the [onboarding](./onboarding/onboarding-channels.md#^ac-legacy-upgrade) and [bundled-theme](./themes-and-appearance.md#^theme-ac-bundled-upgrade) upgrade acceptances boot built servers over pre-existing homes and observe their data reused in place.

The [transitional service path](../../specs/product/cli.md#^cli-retired-service-compat) is proven at the process boundary: its acceptance starts the built CLI with the arguments and environment that an earlier release's service definition stores, with port `0` in place of the stored port. The daemon acceptance suite proves that a real service manager runs a stored command and environment, and the path depends on nothing else from the service manager, so the two compose and the suite has no case for this temporary path.

The breadth of home resolution, the config reader and writer, `tv config` parsing, the client-port rule, retired options, and ignored legacy variables is proven by contract tests in [the CLI architecture proof](../arch/cli/index.md), which crosses the config-port and home handoffs once more at real seams.

Television never writes `~/.tv-home`; that promise orders no separate test because it has no write path. Only the home resolver touches `.tv-home`, and it only reads it. The server receives settings read at startup; [links acceptance](#^cli-ac-links) observes link output after config edits to catch accidentally using the file instead of those running settings. The [invalid-config acceptance](#^cli-ac-invalid-config) does check that `tv serve` leaves the file it read unchanged.

The CLI's selected-theme application reference composes with [theme delivery](../arch/themes/delivery.md#^theme-delivery-t-visible-app) for visible browser selection, clearing, and live edits; CLI [command contracts](../arch/cli/index.md#^2b573706) own argument mapping and [real CLI/server coverage](../arch/cli/index.md#^bd409c7e) owns the handoff. This reference correction adds no duplicate browser or CLI journey.

The [theme-registry scanner contract](../arch/themes/index.md#^themes-t-scan) proves that dot-prefixed folders never enter a completed snapshot. The CLI command contract reports only an exact matching registry error and the real CLI/server seam covers the ordinary missing-theme response. Those clean handoffs compose to the product distinction between an invalid discovered folder and no discovered match; no dot-folder-specific spawned CLI journey is required.

Connect-link acceptance proves live-server token decisions and the command's success, refusal and unreachable exits through built processes. [CLI architecture](../arch/cli/index.md#^cli-links-contract) carries address, option and token-file breadth. The [shared-formatter contract](../arch/cli/index.md#^cli-osc8-visible) covers links and both startup callers, including terminal inputs; process acceptance crosses real piped stdout. The existing [persisted-install walk](#^cli-ac-persist-home-install) crosses plain piped output in its designated-host suite; no additional daemon installation journey is needed.

## Test hooks

The connect-link walks add no production hooks: they use the built executable, real process streams, isolated homes and ordinary config/token files.

## Assertions

### Acceptance criteria: CLI spine

The CLI acceptance boundary is a spawned `tv` process receiving real argument tokens and reporting its real exit code, stdout, and stderr. These tests use temporary homes, config files, token, content, and skills-directory fixtures. A foreground server follows [the test-runner recipe for spawned `tv serve`](../../specs/arch/test-runner/test-runner.md#Test infrastructure addresses): its home's config file sets port `0`, the server and every client command receive that home with `--home`, the server publishes its acquired port through startup output, and client commands pass that port with `--port`. Unless an assertion says otherwise, the config file sets only `port`, so the server runs with its default authentication. Every assertion labeled **Acceptance** below replaces no production mechanism.

The single dispatch seam is **argument tokens → command dispatch → command action**. Commander parses the process arguments and hands the resulting values to one registered action. Each implemented principal outcome below has one spawned acceptance test; the in-process contract tests in [arch/cli/index.md](../../specs/arch/cli/index.md) cover command and option variations through that same dispatcher, while the named seam tests there prove the real server, filesystem, and build handoffs. Both direct-install acceptances use the production packaged collection; the stale-cleanup path begins with the retired directory present in its real temporary destination. Interactive installer delegation retains its owned exception.

#### Owned exception: interactive external installer

`tv skills install -i` is an explicit exception to the acceptance-test requirement. The external installer can prompt and writes to agent skill directories selected outside Television's control; running it as part of the Television suite could mutate a developer's real agent configuration. The CLI architecture spec therefore pins the delegated subprocess arguments with a contract test at the injected installer boundary and claims no real crossing of the external installer seam.

### Connect-link acceptance

The spawned-process boundary and home isolation declared above apply. Use a real server and real stdout pipes, with no client, stream, network or filesystem mocks.

- **Acceptance — links from the running server.** Under [connect links](../../specs/product/cli.md#^cli-links), spawn built `tv links` for a running token-requiring server. It exits `0`, leaves stderr empty and prints exactly one plain connect link per health-reported listener on the bound port, each with the home's token and no heading or escape sequence. Edit config auth to false without restarting: links remain token-bearing and usable for an authenticated read.
