*How the downloaded desktop app's promises are proven: continuous real-Electron tests, and checks of an unreleased ToDesktop build, run by agents or by a person on a real Mac, before a change to the app's behavior reaches `main`.*

# Desktop application — proof

Proves [specs/product/desktop-app.md](../../specs/product/desktop-app.md).

## Coverage model

The desktop application has continuous evidence from `e2e:desktop`, which launches the repository's desktop package in real Electron and crosses the production main process, `BrowserWindow` and webview behavior with no Electron mocks. It runs wherever the test runner runs, which in CI is Linux. The [harness smoke seam](../arch/desktop/e2e-harness.md#^desktop-t-e2e-smoke) is its minimum launch path, and the rest of the surface supplies behavior breadth. It runs the Electron that npm installs, so it proves neither that the Mac app installs or starts nor anything ToDesktop does.

The downloaded app is proven by the real-host checks that the spec declares an exception to the testing policy: Television has no macOS CI environment, and only ToDesktop's build service signs and notarizes the app. They are not automated tests. [The rule](../../specs/product/desktop-app.md#^desktop-checks-before-main) has a change to the app's behavior pass the checks it needs on an unreleased build before it reaches `main`, and the pull request records each run. An Electron major-version change ([runtime operations](../../specs/arch/desktop/runtime.md#operations)) and a change to the build's electron-builder release ([ToDesktop build operations](../../specs/arch/desktop/distribution.md#operations)) are among the changes the checks list. The assertions below are the checks. They use the real built app and ToDesktop's builds and downloads; the manual ones also use the real installer, operating system, Dock, application menu and filesystem. The earlier app's saved connection is a fixture. ToDesktop's simulated update is the runtime's own mode, not a Television test hook; it stands in for a real download, and it restarts the app without installing anything. Real-Electron evidence does not replace the checks.

The implementation pull request ran the three Mac checks on two builds it released in Television's own app, 1.4.0 and 1.4.1, before any published guide gave the download link, and records those runs.

The architecture proofs carry the breadth. The [desktop root](../arch/desktop/index.md) proves the window title, icon and About-panel values Television supplies to Electron, and that naming the app fixes where its data lives; the Mac install check is where those reach the native Dock, menu, About panel and saved connection. The [ToDesktop build proof](../arch/desktop/distribution.md) proves, with automated tests, what the upload directory and configuration contain. The Mac install check observes what the built app makes of them: the effect of the product name, the installed bundle's identifier, its version fields and macOS's assessment of its signature, which the operator reads by hand on the real Mac and records with the run. No check starts the built app with `ELECTRON_RUN_AS_NODE` set, so the effect of the `runAsNode` fuse setting is not observed; the [configuration contract](../arch/desktop/distribution.md#^desktop-dist-t-config) shows that the configuration sets it.

The implementation pull request also records a run of `npm run verify -- local` on a supported Mac, the evidence [preflight](../../specs/arch/test-runner/preflight.md#Testing) requires from a real macOS host.

Some promises order no test ([spec purposes](../../specs/arch/testing-policy.md#^spec-purposes)). That no build exists for any computer but an Apple Silicon Mac, and that the download link keeps its address across releases, follow from the build target chosen in the ToDesktop dashboard and from ToDesktop's hosting, which no Television test observes. That wording about the desktop app names the Mac where it names a platform ([^desktop-mac-wording](../../specs/product/desktop-app.md#^desktop-mac-wording)) is copy, which review checks. That the administrator guide gives the user the link and the installation steps is guide content, which [the guide's spec](../../specs/arch/cli/admin-guide.md#Testing) leaves to review. That the checks run before a change reaches `main` is a procedure that review keeps, and which checks a change needs is the judgment of its author and reviewers; no test decides either. The npm package's deprecation message and its installable published versions are npm registry state, which no repository test observes. The private desktop workspace, proven by the [ToDesktop build proof](../arch/desktop/distribution.md#^desktop-dist-t-workspace), is what keeps npm from publishing a new version of it.

## Assertions

- **Acceptance — Mac install** (boundary: a signed, unreleased build of the candidate commit, a [candidate build](../../specs/arch/desktop/distribution.md#^desktop-dist-candidate-builds) or a signed [test build](../../specs/arch/desktop/distribution.md#^desktop-dist-test-builds), its DMG downloaded from its ToDesktop build page, installed on a [supported real Mac](../../specs/product/desktop-app.md#^desktop-product-support) where an earlier desktop app has saved a connection, and opened from Applications): macOS opens the app without a warning, so it accepts the signature and notarization; the Dock and the application menu show Television; the About panel shows the exact release version with no separate build number; and the app opens with the earlier app's saved connection. The operator also reads the installed bundle by hand and records the output: `spctl --assess --type execute` accepts it with the source `Notarized Developer ID`, its `CFBundleIdentifier` is `computer.telepath.television`, and its `CFBundleShortVersionString` and `CFBundleVersion` are both the release version, which is what operating-system metadata inspectors show. This proves [installation from the download link](../../specs/product/desktop-app.md#^desktop-install-download), [Television identity](../../specs/product/desktop-app.md#^desktop-product-identity), [saved data](../../specs/product/desktop-app.md#^desktop-saved-data) and the [About version](../../specs/product/desktop-app.md#^desktop-about-version). — *(manual; run before a change that needs it reaches `main`; recorded by the implementation pull request)*. ^desktop-ac-mac-install
- **Acceptance — Electron's license files** (boundary: the same build's Mac zip, unzipped): the app's `Contents/Resources` folder contains Electron's `LICENSE.electron.txt` and `LICENSES.chromium.html`, the files [licensing's upstream-aggregate condition](../../specs/product/licensing.md#^licensing-electron-aggregate) requires to reach users — *(agent-run; run before a change that needs it reaches `main`; the implementation pull request recorded a run on the installed app)*. ^desktop-ac-electron-license-files
- **Acceptance — updates** (boundary: the installed build from the Mac install check, opened on a real Mac with ToDesktop's simulated update, `--runtime-simulate-updates=update-available`, and connected to a real server run from the same code): the app presents the [desktop self-update notice](../../specs/product/update-notifications.md#^desktop-self-update) with the simulated version, and pressing **Restart to update** quits the app and opens it again. For a change to the gate, the app connected to a server that gates it shows the downloaded update and **Restart to update** on the gate screen. The simulated update stands in for downloading a real release, and its restart installs nothing. Downloading and installing a real release are the runtime's, which ToDesktop's smoke tests exercise before a build is released ([releases](../../specs/arch/desktop/distribution.md#^desktop-dist-release)). This walks [desktop app updates](../../specs/product/update-notifications.md#^desktop-self-update) in the built app — *(manual; run before a change that needs it reaches `main`)*. ^desktop-ac-updates
- **Acceptance — bridge and IPC** (boundary: the installed build, connected to a real server run from the same code on a real Mac): each changed operation of the native bridge, or message between the app and the page or its artifact views, does what it provides when used through the part of the interface that calls it. This observes in the built app what the operations' architecture proofs show in the real Electron app of a development run — *(manual; run before a change that needs it reaches `main`)*. ^desktop-ac-bridge
