*How Television's release versions are proven where users receive them: the packed CLI package and the desktop upload directory built from the same commit, the built `tv` process and running server, update details, and the native About panel in the desktop product's Mac install check.*

# Product versioning — proof

Proves [specs/product/versioning.md](../../specs/product/versioning.md).

## Coverage model

Release identity is accepted at the two boundaries the spec's Testing section names. One test packs the CLI/server package with real `npm pack` and generates the desktop upload directory with the real build script from the same worktree, then compares the packed manifest's version, the upload directory's generated manifest version and its ToDesktop configuration's `buildVersion` with the release the repository declares. The upload directory is what ToDesktop builds the app from, so this is the last point before ToDesktop at which Television can check the version a desktop release carries. That the built app reports it is observed by the desktop product's [Mac install check](./desktop-app.md#^desktop-ac-mac-install), which runs before a change that needs it reaches `main`. That check reads the exact release version in the About panel, and its recorded readings of the installed bundle's version fields show what operating-system metadata inspectors report. Source-manifest synchronization remains [architecture evidence](../arch/updates/index.md#^updates-t-package-lockstep).

A desktop release made by the build workflow carries its Television release's version because the workflow builds a commit that carries that release's version and code, which the [ToDesktop build proof](../arch/desktop/distribution.md) leaves to review and first use, and because the upload directory takes its version from that commit's workspace manifest, which the acceptance below proves.

That some Television releases get no desktop release is the maintainers' choice and orders no test ([spec purposes](../../specs/arch/testing-policy.md#^spec-purposes)). The version of the [first desktop release](../../specs/arch/desktop/distribution.md#^desktop-dist-first-release) orders no test either; review checks it.

Exact CLI release versions share the spawned built-process paths owned by [basic CLI version acceptance](./cli.md#^cli-ac-help-version), [developer-version acceptance](./cli.md#^cli-ac-developer-version), and [CLI status acceptance](./cli.md#^cli-ac-status-version). Each reads the expected release version independently from the actual built package manifest. Developer-version acceptance reads the expected Git commit independently and proves that its labeled annotation remains separate from the release version. The status path observes only the release version through the running server's health endpoint. The macOS About version is observed by the Mac install check cited above, with the exact application version and empty build-version field supplied to Electron covered by [desktop architecture](../arch/desktop/index.md#^desktop-t-about-version). These are shared evidence, not duplicate process or application launches.

The exact version in Television-authored update details is covered by [update-notification acceptance](./update-notifications.md#^ac-toast-release-label). Package specifiers, server health and event protocols, release-version build stamps, and comparisons retain the same triples under [updates architecture](../arch/updates/index.md#^updates-t-version-model). Telemetry keeps the exact value through the [server emitter](../arch/telemetry/emitters.md#^t-config-attached) and [real Electron client](../arch/telemetry/client.md#^t-clientid-scope) paths. [CLI architecture](../arch/cli/index.md#^cli-status-version-pass-through) proves that status copies the available health version unchanged. Theme and canonical authoring guidance uses that exact status value as metadata without translation.

The **Television 1.3** release-line association composes the product's `1.3.1` release identity with the packaged bundled-theme path in [themes and appearance](./themes-and-appearance.md#^theme-ac-bundled). The durable artifact assertion below follows the actual candidate version because the publish workflow may advance its patch. Theme package versions remain outside Television release identity.

The acceptance uses one test hook, the build script's option that stops before the ToDesktop build ([ToDesktop build test hooks](../arch/desktop/distribution.md#test-hooks)). It replaces no production mechanism.
