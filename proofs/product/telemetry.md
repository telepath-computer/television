*How the promises in Telemetry are proven.*

# Telemetry — proof

Proves [specs/product/telemetry.md](../../specs/product/telemetry.md).

## Coverage model

Lifecycle, actions, controls, and sessions use the harnesses declared below, with real server state, HTTP, websocket, and filesystem boundaries. A recording sink replaces delivery only; the live PostHog suite proves that final boundary. Browser and Electron spines prove genuine engagement produces activity. The theme/appearance extension exercises the server's committed settings through real HTTP and websocket inputs; it composes with those client spines because the client activity signal carries no settings. Pure classifier tests cover declaration and consent combinations, while server seams cover boot, refresh, suppression, and re-enablement. Serialized event assertions include person properties and reject user-authored names, consent lists, and script data. This honors the owning spec's real-behavior and complete-event testing directives without repeating the browser execution tests: the measured feature is configured use, not script execution.

The README, privacy notice, administrator guide, and bundled skill are checked by content review against the spec’s disclosure instructions. Review checks README placement before commands, usable links, environment opt-out before first use, persistent opt-out against a running server, `tv status`, purpose, data categories and identifiers, privacy exclusions, PostHog destination, agreement with the four rules, and the ToDesktop statement. No wording tests are ordered for these document surfaces; notice coverage combines compiled skills installation with real source server and persisted-parent seams below. The latter model the bake and rely on the compiled case for its connection to the shared four-rule decision. No production-eligible real host service is installed.

The release/default and developer-marker product behavior is proven through [compiled skills-install acceptance](../arch/telemetry/sink.md#^ac-compiled-telemetry); source server routing seams model the baked marker rather than promoting a build through a runtime variable. The [transport request contract](../arch/telemetry/sink.md#^t-transport-privacy) composes with live event/person queries for the IP/GeoIP guarantee. Provider settings and historical cleanup remain operator actions, not an assertion that code can erase existing data.

The disable directive is exercised through authenticated HTTP with the default buffer, using intercepted fetch; live delivery on a developer host is covered by the manual suite. Persisted marker lookup composes the daemon environment boundary with real marker checks in a distinct operating-system home on every runtime creation, plus the compiled action acceptance.

## Test hooks

Source-run telemetry fixtures pass authored environment objects rather than inheriting the runner’s environment, and explicitly use `TV_TELEMETRY_TEST=1` to open the gate; recording sinks do not route requests. Suppression rows omit that flag where they exercise development suppression. Production-routing source tests model the baked constant and intercept `fetch`; compiled acceptance validates the real baked gate.

`ServerOptions.telemetry.sink` accepts a recording sink; production uses the PostHog sink. Existing browser and Electron harness hooks are declared by the client proofs cited below. Theme and appearance inputs are real temporary theme packages and persisted server settings, not mocked classifiers or stores.

## Assertions

### Test assertions

The product assertions compose four declared harnesses:

- The **server seam harness** drives a really-running `Server` and real `ServerStore` through HTTP, websocket, restart, or direct committed store mutations over a temporary home and authored content. A recording telemetry sink replaces PostHog, so the claim ends at the built event handed to delivery; [arch/telemetry/sink.md#^t-posthog-lands](../arch/telemetry/sink.md#^t-posthog-lands) crosses the real analytics boundary.
- The **client seam harnesses** drive a real browser or the real Electron app against a running server with temporary browser profiles, Electron user data, and server data. They use the same recording sink and therefore forfeit PostHog only; client storage, DOM engagement, HTTP, websocket, server session logic, and event construction remain real.
- The **PostHog harness** uses the real transport and sandbox PostHog project, unique identities, real server HTTP/websocket clients, and the declared read-key preflight. Its persisted-daemon variant registers a uniquely named real user service and has only the substitutions stated at [#^ac-persist-auth-install](#^ac-persist-auth-install).
- The **CLI harnesses** are owned and declared by [arch/cli/index.md](../../specs/arch/cli/index.md). Product assertions below name whether they use an in-process action/server seam or a spawned built process. Their recording sink forfeits only analytics delivery.

Citations identify implemented coverage; inherited assertions retain their standing evidence grade. Context and analytical goals elsewhere in this spec inform engineering and review without creating a sentence-by-sentence test inventory ([arch/testing-policy.md#^spec-purposes](../../specs/arch/testing-policy.md#^spec-purposes)).

#### Identity and server lifecycle

- **Seam** (fresh/existing server data → lifecycle capture in the server seam harness): the first serving boot mints one stable telemetry-user GUID and emits `server_installed` once; later boots do not reinstall, and missing telemetry state on existing served data is adoption rather than install. - **Acceptance** (outer boundary: a spawned source CLI with real argv → real `Daemon.install()` → host service manager → daemon server → sandbox PostHog): fresh persisted service installation from a temporary home lands `server_installed` in both cases: without authentication, where the parent creates no token and the daemon creates the storage, and with authentication, where the parent creates the token and empty storage directories before it installs the service. The driver replaces daemon construction only to choose a test-scoped service name and source-CLI arguments, forfeiting production CLI packaging and daemon configuration but no token path, config read, state classifier, server, telemetry runtime, transport, or PostHog query. The temporary homes and the test service are fixtures; cleanup uses real `tv stop` — *covered by the two `packages/server/test/telemetry-posthog.integration.test.ts` cases under “persisted daemon fresh-install classification”*. ^ac-persist-auth-install
- **Acceptance** (same harness): each of those installs starts from a home whose config file is written before the first serving boot, and `server_installed` still lands, so a config file does not count as served data. The unauthenticated home's config file sets `"auth": false`; the authenticated home's has no `auth` key, so authentication is on by default. - **Seam** (server boot → lifecycle capture): an existing directory with no recorded telemetry version or an older version emits `server_upgraded` and advances `lastVersion`; a same-version restart and downgrade emit only `server_started`, with downgrade still writing the running version — *(covered by inherited tests: `packages/server/test/telemetry-lifecycle.test.ts` “emits install once, start on each boot, and upgrade with old/new versions” and the boot-derivation cases cited by [arch/telemetry/identity.md#^t-boot-derivation](../arch/telemetry/identity.md#^t-boot-derivation))*. ^ac-upgrade
- **Seam** (server boot → event and person-property payload): install sets `pre_telemetry: false`; adoption sets `pre_telemetry: true` on the upgrade and person; later upgrades do not change it — *(covered by inherited tests: `packages/server/test/telemetry-lifecycle.test.ts` “emits install once, start on each boot, and upgrade with old/new versions” and “emits upgrade, not install, when an existing data dir has no telemetry version”; real person-state delivery is [arch/telemetry/sink.md#^tel-t-posthog-person](../arch/telemetry/sink.md#^tel-t-posthog-person))*. ^ac-pre-telemetry
- **Seam** (server config snapshot → built lifecycle/activity events): `server_started` carries and `$set`s version and the full config, `server_upgraded` carries new and optional old version, and `session_activity` carries current version; the sandbox saga confirms current person state — *(covered by inherited tests: `packages/server/test/telemetry-lifecycle.test.ts` “reports daemon launch mode in the server_started config payload” and “attaches config and version to server_started as event properties and $set person properties”, `packages/server/test/telemetry-event-stream.test.ts` “emits a content-free session_activity event from an activity signal”, and [arch/telemetry/sink.md#^tel-t-posthog-saga](../arch/telemetry/sink.md#^tel-t-posthog-saga))*. ^ac-server-props
