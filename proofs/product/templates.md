# Artifact templates — proof

Proves [specs/product/templates.md](../../specs/product/templates.md).

## Coverage model

The CLI walk starts a real server in a temporary home, lists folders through a spawned `tv` process, and creates an artifact from a template through that process. A real browser walk opens the Templates popover and creates in its focused channel. Both use authored template folders as fixtures, with real files, HTTP, storage, and browser behavior. Neither replaces a production mechanism. The browser may use the standard CSS-motion override; it forfeits motion, which this spec does not promise.

These walks prove the principal success and refusal outcomes people and agents see. [Template architecture](../arch/templates/index.md) covers validation, copying, placement, seed failures, and folder naming across their variations. [CLI](./cli.md) covers argument parsing and output. [The popover UI proof](../ui/app/skill-selector/index.md) covers its search, highlight, and dismissal. [Bundled installation](../arch/templates/bundled-installation.md) covers preservation and replacement at boot. Ordinary path-artifact deletion and store recovery remain with [artifacts](./artifacts.md) and [resources](./resources/resources.md).

## Test hooks

No production test hook is needed; temporary homes and template folders are input fixtures.

## Assertions

- **Acceptance** (spawned built `tv` with real argv → running server and temporary home; authored valid and invalid template folders; no mocks): Under [the specified behavior](../../specs/product/templates.md#finding-and-using-an-artifact-template), `tv templates list` reports a newly added valid template and a malformed folder with its error; after repairing that folder, the next list reports it as valid without restarting the server. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-discovery`)* ^templates-ac-discovery
- **Acceptance** (spawned built `tv` → real HTTP and filesystem; a template with `README.md`, supporting files, and `data.json`; no mocks): Under [the specified behavior](../../specs/product/templates.md#^artifact-template-result), `tv create-artifact --channel <channel-id> --template <id> --title <title> --no-focus` returns an ordinary artifact ID and copied path, applies the chosen title, leaves the template untouched, and makes the seeded value readable through the artifact's own store. Editing the copy does not change the template. After a spawned `tv update-artifact --id <id> --title <new-title>`, a fresh real-server read reports the new title and the same registered copied path. Deleting the artifact leaves its copied folder and store on disk. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-cli-create`)* ^templates-ac-cli-create
- **Acceptance** (real browser → running server, authenticated client and temporary home; an existing selected tab and authored template folder; no mocks beyond the CSS-motion override): Under [the specified behavior](../../specs/product/templates.md#^artifact-template-popover), opening Templates discovers the folder, using its tile creates and focuses an ordinary page immediately to the right of the selected tab in the focused channel, and the copied page loads. In a separate empty channel, creation establishes its only page. *(policy-grade test: `packages/web/test/e2e/skill-selector.test.ts`, cases tagged `^templates-ac-ui-create`)* ^templates-ac-ui-create
- **Acceptance** (spawned built `tv` → running server; an invalid template folder and valid channel; no mocks): Under [the specified behavior](../../specs/product/templates.md#finding-and-using-an-artifact-template), creation by that ID reports the scan error and creates no artifact; after the folder is removed, the same request reports that the ID was not found. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-cli-refusal`)* ^templates-ac-cli-refusal
- **Acceptance** (spawned built `tv` → running server and a template with starting data; real filesystem obstruction, no mocks): Under [the failed-copying outcome](../../specs/product/templates.md#^artifact-template-data) and [CLI error output](../../specs/product/cli.md#^cli-create-artifact-template), after serving boot the test makes `<home>/resources` a regular file so the first store write cannot create its directory. `tv create-artifact --channel <channel-id> --template <id> --no-focus` copies and registers the artifact, then exits `1` with no creation-success lines. Its error names the copied destination, generated ID, and unconfirmed store step. The copied folder and registered artifact remain for inspection, and the source template is unchanged. The [architecture failure cases](../arch/templates/index.md#^templates-t-failure) own other failing steps. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-cli-post-copy-failure`)* ^templates-ac-cli-post-copy-failure
