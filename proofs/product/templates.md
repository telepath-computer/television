# Artifact templates — proof

Proves [specs/product/templates.md](../../specs/product/templates.md).

## Coverage model

The CLI walk starts a real server in a temporary home, lists folders through a spawned `tv` process, and creates an artifact from a template through that process. A real browser walk opens the Templates popover and creates in its focused channel. Both use authored template folders as fixtures, with real files, HTTP, storage, and browser behavior. Neither replaces a production mechanism. The browser may use the standard CSS-motion override; it forfeits motion, which this spec does not promise.

These walks prove the principal success and refusal outcomes people and agents see. [Template architecture](../arch/templates/index.md) covers validation, copying, placement, seed failures, and folder naming across their variations. [CLI](./cli.md) covers argument parsing and output. [The popover UI proof](../ui/app/templates-popover/index.md) covers its search, highlight, and dismissal. [Bundled installation](../arch/templates/bundled-installation.md) covers preservation and replacement at boot. The [inventory proof](../arch/templates/bundled-templates.md) owns manifest identity and versions; the [Checklist](../arch/templates/checklist.md) and [Sticky note](../arch/templates/sticky-note.md) architecture proofs own their display options and store contracts. Their creation walks extend the popover journey through each shipped seed, starting display, first edit, and saved result: [Checklist](../ui/templates/checklist/index.md#^checklist-ui-ac-new) and [Sticky note](../ui/templates/sticky-note/index.md#^sticky-note-ui-ac-new) have real-stack evidence. These shared walks accept [the bundled-template promise](../../specs/product/templates.md#^artifact-template-bundled) without a second product-level browser suite. Ordinary path-artifact deletion and store recovery remain with [artifacts](./artifacts.md) and [resources](./resources/resources.md).

The CLI template walk also exercises a manifest's starting display values through a real command and server. The browser walk uses a second manifest with no CLI overrides and observes the resulting page. [The scanner contract](../arch/templates/index.md#^templates-t-display-scan) checks manifest fields and errors; existing [list](#^templates-ac-discovery) and [popover](../ui/app/templates-popover/index.md#^templates-ui-ac-open) walks expose those errors. [The template creation contract](../arch/templates/index.md#^templates-t-display-resolution) covers per-field precedence and defaults. These contracts use real folders and server code, and the two product walks cross the CLI and browser boundaries without a separate browser test for each value. The browser's standard CSS-motion override forfeits motion only; neither walk substitutes creation, storage, or page rendering.

The display walks also cover transparency: the CLI explicitly disables a template default and reads metadata with no transparency field, while the popover creates an enabled artifact without supplying display overrides. The CLI walk then changes the created artifact and edits the template to prove that later template edits do not control the copy. [Template architecture](../arch/templates/index.md#^templates-t-transparent-resolution) carries boolean precedence, default, seed-write, and restart breadth. [Product artifacts](./artifacts.md#^af-ac-transparent) proves the shared frame outcome in browser and desktop, and the frame UI proof owns hover and motion. The transparency assertions below can extend the existing display walks; they do not require a second size/full-screen test suite.

## Test hooks

No production test hook is needed; temporary homes and template folders are input fixtures.

## Assertions

- **Acceptance** (spawned built `tv` with real argv → running server and temporary home; authored valid and invalid template folders; no mocks): Under [the specified behavior](../../specs/product/templates.md#finding-and-using-an-artifact-template), `tv templates list` reports a newly added valid template and a malformed folder with its error; after repairing that folder, the next list reports it as valid without restarting the server. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-discovery`)* ^templates-ac-discovery
- **Acceptance** (spawned built `tv` → real HTTP and filesystem; a template with `README.md`, supporting files, and `data.json`; no mocks): Under [the specified behavior](../../specs/product/templates.md#^artifact-template-result), `tv create-artifact --channel <channel-id> --template <id> --title <title> --no-focus` returns an ordinary artifact ID and copied path, applies the chosen title, leaves the template untouched, and makes the seeded value readable through the artifact's own store. Editing the copy does not change the template. After a spawned `tv update-artifact --id <id> --title <new-title>`, a fresh real-server read reports the new title and the same registered copied path. Deleting the artifact leaves its copied folder and store on disk. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-cli-create`)* ^templates-ac-cli-create
- **Acceptance** (spawned built `tv` with real argv → running server and temporary home; authored valid template manifest with `display`, no mocks or test hooks): Under [display precedence](../../specs/product/templates.md#^artifact-template-display-options), a template declares width, height, and `fullScreen: true`; `tv create-artifact --template` supplies a different `--width` and `--no-full-screen`. The command succeeds, and a real channel read shows its page using the command width, template height, and `full_screen: false`. After the manifest is edited, the created artifact keeps those saved values. *(policy-grade test: `test/node/cli-acceptance.test.ts` “lets a template creation option override only its own display value”)* ^templates-ac-display-cli
- **Acceptance** (real browser → running server, authenticated client and temporary home; an existing selected tab and authored template folder; no mocks beyond the CSS-motion override): Under [the specified behavior](../../specs/product/templates.md#^artifact-template-popover), opening Templates discovers the folder, using its tile creates and focuses an ordinary page immediately to the right of the selected tab in the focused channel, and the copied page loads. In a separate empty channel, creation establishes its only page. *(policy-grade test: `packages/web/test/e2e/skill-selector.test.ts`, cases tagged `^templates-ac-ui-create`)* ^templates-ac-ui-create
- **Acceptance** (real browser → running server and temporary home; authored valid template manifest with a partial `display`, no mocks except the standard CSS-motion override, which forfeits motion): Under [popover display defaults](../../specs/product/templates.md#^artifact-template-display-options), choosing the template in the Templates popover sends a creation request with no `display` field and creates a page with its declared width and full-screen state and the shared default height. The test observes the real outgoing request without intercepting or replacing it; [the stage proof](../ui/app/stage/index.md#^st-ac-fullscreen) covers leaving full-screen without losing that size. *(policy-grade test: `packages/web/test/e2e/skill-selector.test.ts` “Templates popover uses manifest display and shared defaults without sending display”)* ^templates-ac-display-ui
- **Acceptance** (spawned built `tv` → running server; an invalid template folder and valid channel; no mocks): Under [the specified behavior](../../specs/product/templates.md#finding-and-using-an-artifact-template), creation by that ID reports the scan error and creates no artifact; after the folder is removed, the same request reports that the ID was not found. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-cli-refusal`)* ^templates-ac-cli-refusal
- **Acceptance** (spawned built `tv` → running server and a template with starting data; real filesystem obstruction, no mocks): Under [the failed-copying outcome](../../specs/product/templates.md#^artifact-template-data) and [CLI error output](../../specs/product/cli.md#^cli-create-artifact-template), after serving boot the test makes `<home>/resources` a regular file so the first store write cannot create its directory. `tv create-artifact --channel <channel-id> --template <id> --no-focus` copies and registers the artifact, then exits `1` with no creation-success lines. Its error names the copied destination, generated ID, and unconfirmed store step. The copied folder and registered artifact remain for inspection, and the source template is unchanged. The [architecture failure cases](../arch/templates/index.md#^templates-t-failure) own other failing steps. *(policy-grade test: `test/node/cli-acceptance.test.ts`, cases tagged `^templates-ac-cli-post-copy-failure`)* ^templates-ac-cli-post-copy-failure

## Transparency defaults

- **Acceptance** (spawned built `tv` → authenticated running server and real temporary home; a valid template with `display.transparent: true` and other display values; no mocks or hooks): under [display precedence and independence](../../specs/product/templates.md#^artifact-template-display-options), `tv create-artifact --template` with `--no-transparent` creates an opaque artifact while retaining the other independently selected display values; a spawned `tv get-artifact` shows no `transparent` field, as required by [the stored transparency rule](../../specs/arch/artifacts/index.md#^ar-transparent). Change that artifact with `tv update-artifact --transparent`, then edit the template to declare false: fresh artifact reads still report true and its saved page values are unchanged. This extends [the existing CLI display walk](#^templates-ac-display-cli) and proves both the explicit-false override and later independent changes. *(policy-grade test: `test/node/cli-acceptance.test.ts`, “lets a template creation option override only its own display value”)* ^templates-ac-transparent-cli
- **Acceptance** (real browser → production Templates popover → authenticated running server and temporary home; template with a partial `display` containing `transparent: true`, no mocks except the standing CSS-motion override): under [popover display resolution](../../specs/product/templates.md#^artifact-template-display-options), selecting the tile creates and focuses an artifact whose document loads in the transparent frame, with the title bar hidden at rest. The observed, unmodified outgoing request omits `display`; real metadata reads show top-level `transparent: true` and independently resolved page values. This extends [the existing popover display walk](#^templates-ac-display-ui); fade timing is forfeited to [the frame UI proof](../ui/app/artifact-frame/transparency/index.md#^af-ui-ac-transparent-hover). Covered by `packages/web/test/e2e/skill-selector.test.ts`, “Templates popover creates a focused transparent frame from manifest defaults without sending display (^templates-ac-transparent-ui)”. ^templates-ac-transparent-ui
