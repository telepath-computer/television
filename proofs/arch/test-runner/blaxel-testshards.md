# Blaxel Test Shards — proof

Proves [specs/arch/test-runner/blaxel-testshards.md](../../../specs/arch/test-runner/blaxel-testshards.md).

## Coverage model

The host marker’s provider-selection behavior and one-file local limit are covered by [the runner marker proof](test-runner.md#^t-blaxel-host-marker) and [local admission proof](test-runner.md#^t-runner-file-admission). The setup sentence directs callers to those rules rather than defining a second marker mechanism. The runner’s [live remote handoff](test-runner.md#^t-runner-remote-handoff) adds native-entrypoint and retry-policy evidence on the real planned and targeted paths; this proof retains ownership of Blaxel transport, leasing, and setup. The corporate credential location is setup information checked by human review, not a new token-source mechanism. The existing token-source assertions remain unchanged; no test reads the vault or asserts its item name.

Lease decisions and failure ordering are checked cheaply at the worker/coordinator contracts. Real Linux processes and files cross the guard, owner-registration, and deletion seams. These tests do not claim Blaxel transport coverage.

The live acceptances below enter through the canonical CLI on a dedicated pool: normal retrieval, refusal while another coordinator holds the worker, recovery after coordinator death, and pool creation/deletion. They share a small committed fixture selection and fresh workers rather than repeating a full suite for every failure permutation. Both planned and targeted execution paths are crossed. Resource retention composes with [reporting's diagnostics assertions](reporting.md#Resource diagnostics); helper teardown belongs to [the testing-policy proof](../testing-policy.md#Worker-owned builds).

The spec's [testing guidance](../../../specs/arch/test-runner/blaxel-testshards.md#testing-guidance) require real API/transport, fresh provisioning, and observed Node/Chromium temporary paths. Private workers and bounded disposable processes supply those observations; no deliberately exhausted host or shared-pool contamination is needed. The live driver and its native fixtures live in `experiment:blaxel-harness` and `experiment:blaxel-harness-fixtures`, excluded from `all` and ordinary CI by their experiment kind. Mocks below forfeit those crossings to the named live assertions. The live driver shares these observations within one fresh private pool; focused contracts carry uncommon failure permutations without repeating paid-service runs.

The lease contracts and filesystem seams run only on Linux because their production helpers inspect procfs and mount records. This does not establish macOS worker support. `test/repo/blaxel-stale-owner-audit.test.ts` checks diagnostic construction and coordinator ordering on every host. Its live diagnostic cases require Linux procfs and run only on Linux; they establish no macOS backend coverage. `test/repo/test-runner-provider.test.ts` exercises shell activation ordering with an authored nvm replacement in a shell isolated from host startup files. That contract check does not install nvm or establish real worker activation.

Repository selection composes several pieces across clean seams. A contract test proves URL conversion. A seam test runs real Git against a temporary checkout's `origin` to prove selection, and a process-boundary test runs the real coordinator to prove that an unusable selection stops it before dispatch. A further seam test executes the worker's generated `checkout` script under real `bash` and Git against two local bare repositories with shared history, proving that one persistent checkout moves between repositories in both directions without re-cloning or deleting ignored dependency files. That test reaches the repositories through local paths, so it forfeits GitHub HTTPS transport and token authentication. The coordinator's use of the selector and the generated script is a source assertion. The live runs that the spec's [testing guidance](../../../specs/arch/test-runner/blaxel-testshards.md#testing-guidance) orders for a repository-selection change carry the GitHub transport, token, and real worker handoff: they run from checkouts of two repositories on the same pool, including workers whose checkout last served the other repository. When the two runs' commits have identical dependency declarations, those workers' logs must show no clone and a `deps` cache hit, which is the live evidence that switching repositories keeps installed dependencies. A focused test runs the worker's generated `deps` script after real checkouts of both repositories, with a stand-in `npm`. It proves that the cache decision follows the dependency declarations and ignores which repository supplied them.

Pool discovery also has a contract test that runs the shared discovery helper used by the pool manager and coordinator with the installed Blaxel SDK against a loopback HTTP server returning authored paginated sandbox responses. The SDK builds requests and handles pages through its native-fetch path over loopback HTTP. This proves page traversal, label filtering and deployed-only filtering; production HTTP/2 transport, real authentication and service compatibility are covered by live evidence: a read-only multi-page listing and the required live Blaxel run.

## Test hooks


`readBlaxelGithubToken` accepts `cwd` (the directory containing `.blaxel-gh-token`) and `env` (the environment source), so tests can control token precedence without changing process-wide state. The coordinator uses the process defaults.

`acquireShardLeases` accepts `acquire` (one lease attempt), `transferShardInputs` accepts `write` (one sandbox-file upload), and `finishInterruptedRun` accepts `preserveReport` (the initial interrupted report write), `releaseLeases` (remote process and lease cleanup), and `finalizeReport` (the final interrupted report write). Tests may supply recording or failing callbacks to isolate scheduling, ordering, and failure handling. Under the testing policy's [mocking policy](../../../specs/arch/testing-policy.md#Mocking policy), these replacements earn no coverage of the Blaxel API, sandbox file upload, or remote cleanup.

`resolveBlaxelRepositoryUrl` accepts `cwd`, the checkout whose `origin` it reads; the coordinator uses the process working directory. `blaxelCheckoutScript` accepts `root`, the checkout directory the generated script manages; the coordinator uses the worker's `/workspace/television`. `blaxelDependencyScript` accepts `cacheDir`, the directory holding dependency markers; the coordinator uses the worker's `/cache/blaxel-testshards`. The generated `deps` script reads `TV_TEST_DEPS_CACHE_STATUS_FILE`, where tests and the worker both read the hit-or-miss outcome.

The SDK reads `BL_API_URL`, `BL_API_KEY`, and `BL_WORKSPACE`; the discovery contract test supplies a loopback API and fixture credentials in an isolated working directory and home, with an explicit child environment that preserves the test owner token and disables SDK telemetry and HTTP/2. Production uses the configured Blaxel API and credentials.

The worker lock and temporary-cleanup helpers accept filesystem roots for disposable seam fixtures; production uses the specified worker paths. The lease fixture supplies `auditPids`, its explicit process set, before procfs inspection. Production supplies no process set and enumerates the whole worker. This substitutes enumeration only and forfeits whole-worker coverage to the live acceptance; identity/token reads and signal revalidation remain real. Their decision layer accepts a clock, owner-audit/signal operations, and filesystem probes for contract failure injection; production uses worker time, procfs, signals, and the filesystem.

A coordinator milestone hook, enabled only by `TV_TEST_RUNNER_SELFTEST`, can wait on a fixture-controlled rendezvous immediately before report download while renewal continues; ordinary runs do not wait. It changes scheduling, not lease state, process results, or report bytes. Live recovery uses the existing `--lock-ttl-seconds` override to shorten the abandonment wait, not a fake clock or altered retry budget.

`retainAttemptEvidence` accepts the lease’s SDK filesystem and a coordinator download directory. The prepared-but-undispatched contract substitutes reads backed by real fixture files; worker inventory creation, teardown and local writes remain real. Production reads the worker results tree through the installed SDK.

Pool-management contract tests may supply recording/failing SDK operations; ordinary pool commands use the installed SDK. These substitutions forfeit provider behavior to the live pool acceptance below.

### Pool mutation

- **Contract — publication and deletion ordering.** The pool manager uses authored sandbox states and recording/failing SDK operations. Under [Pool](../../../specs/arch/test-runner/blaxel-testshards.md#Pool) and [pool operations](../../../specs/arch/test-runner/blaxel-testshards.md#Older runners and pool operations), it publishes eligibility only after successful provisioning/verification, refuses to refill partial pools, refuses deletion of valid leases, and unpublishes before deleting an idle or expired worker.
