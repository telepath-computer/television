*How the promises in Blaxel Test Shards are proven.*

# Blaxel Test Shards — proof

Proves [specs/arch/test-runner/blaxel-testshards.md](../../../specs/arch/test-runner/blaxel-testshards.md).

## Coverage model

The host marker’s provider-selection behavior is covered by [the runner proof](test-runner.md#^t-blaxel-host-marker). The corporate credential location is setup information checked by human review, not a new token-source mechanism. The existing token-source assertions remain unchanged; no test reads the vault or asserts its item name.

Coverage declarations are carried inside the migrated assertion blocks below.

`test/repo/blaxel-stale-owner-audit.test.ts` checks diagnostic construction and coordinator ordering on every host. Its live diagnostic cases require Linux procfs and run only on Linux; they establish no macOS backend coverage. `test/repo/test-runner-provider.test.ts` exercises shell activation ordering with an authored nvm replacement in a shell isolated from host startup files. That contract check does not install nvm or establish real worker activation.

Repository selection composes several pieces across clean seams. A contract test proves URL conversion. A seam test runs real Git against a temporary checkout's `origin` to prove selection, and a process-boundary test runs the real coordinator to prove that an unusable selection stops it before dispatch. A further seam test executes the worker's generated `checkout` script under real `bash` and Git against two local bare repositories with shared history, proving that one persistent checkout moves between repositories in both directions without re-cloning or deleting ignored dependency files. That test reaches the repositories through local paths, so it forfeits GitHub HTTPS transport and token authentication. The coordinator's use of the selector and the generated script is a source assertion. The live runs that the spec's [Testing](../../../specs/arch/test-runner/blaxel-testshards.md#Testing) directive orders for a repository-selection change carry the GitHub transport, token, and real worker handoff: they run from checkouts of two repositories on the same pool, including workers whose checkout last served the other repository. When the two runs' commits have identical dependency declarations, those workers' logs must show no clone and a `deps` cache hit, which is the live evidence that switching repositories keeps installed dependencies. A focused test runs the worker's generated `deps` script after real checkouts of both repositories, with a stand-in `npm`. It proves that the cache decision follows the dependency declarations and ignores which repository supplied them.

Pool discovery also has a contract test that runs the shared discovery helper used by the pool manager and coordinator with the installed Blaxel SDK against a loopback HTTP server returning authored paginated sandbox responses. The SDK builds requests and handles pages through its native-fetch path over loopback HTTP. This proves page traversal, label filtering and deployed-only filtering; production HTTP/2 transport, real authentication and service compatibility are covered by live evidence: a read-only multi-page listing and the required live Blaxel run.

## Test hooks


`readBlaxelGithubToken` accepts `cwd` (the directory containing `.blaxel-gh-token`) and `env` (the environment source), so tests can control token precedence without changing process-wide state. The coordinator uses the process defaults.

`acquireShardLeases` accepts `acquire` (one lease attempt), `transferShardInputs` accepts `write` (one sandbox-file upload), and `finishInterruptedRun` accepts `preserveReport` (the initial interrupted report write), `releaseLeases` (remote process and lease cleanup), and `finalizeReport` (the final interrupted report write). Tests may supply recording or failing callbacks to isolate scheduling, ordering, and failure handling. Under the testing policy's [mocking policy](../../../specs/arch/testing-policy.md#Mocking policy), these replacements earn no coverage of the Blaxel API, sandbox file upload, or remote cleanup.

`resolveBlaxelRepositoryUrl` accepts `cwd`, the checkout whose `origin` it reads; the coordinator uses the process working directory. `blaxelCheckoutScript` accepts `root`, the checkout directory the generated script manages; the coordinator uses the worker's `/workspace/television`. `blaxelDependencyScript` accepts `cacheDir`, the directory holding dependency markers; the coordinator uses the worker's `/cache/blaxel-testshards`. The generated `deps` script reads `TV_TEST_DEPS_CACHE_STATUS_FILE`, where tests and the worker both read the hit-or-miss outcome.

The SDK reads `BL_API_URL`, `BL_API_KEY`, and `BL_WORKSPACE`; the discovery contract test supplies a loopback API and fixture credentials in an isolated working directory and home, with an explicit child environment that preserves the test owner token and disables SDK telemetry and HTTP/2. Production uses the configured Blaxel API and credentials.

## Assertions

### Test assertions

- Pool discovery includes matching workers on later API pages and excludes workers with other project, purpose, pool, or architecture labels, as required by the spec's [Pool](../../../specs/arch/test-runner/blaxel-testshards.md#Pool) contract. **Contract:** the consumer is the shared discovery helper and installed SDK, called in a child process; the service is the HTTP mock described above. The helper collects the unfiltered listing before filtering locally. Both the manager mode (all matching workers) and coordinator mode (only matching `DEPLOYED` workers) must traverse all pages, including an earlier page containing no matching workers. A page-fetch failure rejects discovery rather than returning a partial pool. Fixture sandbox records omit a region so discovery needs no data-plane connection. (policy-grade test: `test/repo/blaxel-pool-discovery.test.ts`) ^blaxel-pool-pagination

The repository-selection assertions:

- **Contract — URL conversion.** `githubRepositoryHttpsUrl` converts GitHub HTTPS URLs with or without `.git` or a trailing slash, HTTPS URLs carrying embedded credentials, `git@github.com:<owner>/<repository>` URLs, and `ssh://git@github.com/` URLs to `https://github.com/<owner>/<repository>.git`, as the spec's [Repository](../../../specs/arch/test-runner/blaxel-testshards.md#Repository) section requires. No converted URL contains the embedded credential, and a rejection diagnostic never repeats it, including for userinfo containing `@`, a scp-style `user:secret@host:path` remote, or a malformed scheme separator. It rejects URLs on other hosts, local paths and `file:` URLs, and GitHub URLs that do not name exactly an owner and a repository. (policy-grade test: `test/repo/blaxel-repository.test.ts` “converts GitHub remote URLs to credential-free HTTPS repository URLs”) ^blaxel-repo-url-conversion
- **Seam — selection from the checkout.** Real Git runs in a temporary repository; no part of Git is replaced. With `origin` set to an SSH GitHub URL and no explicit URL, `resolveBlaxelRepositoryUrl` returns that repository's HTTPS URL. A credential-bearing explicit URL is converted and selected even when `origin` is a non-GitHub URL, which is not consulted. A non-GitHub `origin` with no explicit URL fails, as does a repository with no `origin`. This proves the selection rules in the spec's [Repository](../../../specs/arch/test-runner/blaxel-testshards.md#Repository) section. (policy-grade test: `test/repo/blaxel-repository.test.ts` “selects the repository from the checkout's origin unless --repo-url is given”) ^blaxel-repo-origin-selection
- **Acceptance — rejection before dispatch.** The real coordinator runs as a child process with real argv in a temporary Git repository whose `origin` is not on GitHub. The fixtures are that repository and a placeholder token in `BLAXEL_TV_GH_TOKEN`, so the run gets past the token check without a real credential. The coordinator exits `2` with the conversion diagnostic and creates no output directory, so it wrote no request and contacted no worker. This proves the spec's [Repository](../../../specs/arch/test-runner/blaxel-testshards.md#Repository) promise that an unusable selection fails before dispatch. (policy-grade test: `test/repo/blaxel-repository.test.ts` “stops the coordinator before dispatch when origin is not a GitHub repository”) ^blaxel-repo-reject-before-dispatch
- **Seam — one checkout moves between repositories.** The handoff is from the coordinator's generated `checkout` script to Git on a worker, crossed with real `bash` and Git. The fixtures are two local bare repositories that share a base commit, each with commits the other lacks, reached through local paths instead of GitHub HTTPS (forfeit above). Running the script for repository A, then B, then A again on one checkout root clones only the first time. The B run fetches a commit only B holds. The final A run fetches an A-only commit created after the first clone, so neither switch can succeed from objects the checkout already has. A sentinel inside `.git` and an ignored `node_modules` sentinel both survive every switch. After each run, `HEAD` is the requested commit and `origin` points at that run's repository. This proves the checkout behavior in the spec's [Repository](../../../specs/arch/test-runner/blaxel-testshards.md#Repository) section and the [Shard lifecycle](../../../specs/arch/test-runner/blaxel-testshards.md#Shard lifecycle) `checkout` step. (policy-grade test: `test/repo/blaxel-repository.test.ts` “moves one persistent checkout between repositories without re-cloning or deleting ignored dependencies”) ^blaxel-repo-checkout-switch
- **Contract — dependency reuse across repositories.** The generated `checkout` and `deps` scripts run under real `bash`, Git, and `sha256sum` on one checkout root, using the two-repository fixtures above. A stand-in `npm` on `PATH` replaces `npm ci`: it records each call and creates `node_modules`. This forfeits real installation, which the live runs carry. The first `deps` run is a miss and calls `npm`. A second run is a hit. After the checkout moves to the other repository's commit with identical declarations, `deps` is still a hit and calls nothing. After it moves to a commit that changes `package-lock.json`, `deps` is a miss and calls `npm` again. This proves [Dependency-hash caching](../../../specs/arch/test-runner/blaxel-testshards.md#Dependency-hash caching) and the dependency-reuse promise in [Repository](../../../specs/arch/test-runner/blaxel-testshards.md#Repository). (policy-grade test: `test/repo/blaxel-repository.test.ts` “reuses installed dependencies across repositories until their declarations change”) ^blaxel-repo-deps-reuse
- **Contract — coordinator wiring (source).** The coordinator selects its repository through `resolveBlaxelRepositoryUrl` with the `--repo-url` option, carries no hard-coded repository URL, builds the worker's `checkout` step from `blaxelCheckoutScript` with the selected URL and resolved commit, and builds its `deps` step from `blaxelDependencyScript`. The live runs above carry the real handoff. This supports the spec's [Repository](../../../specs/arch/test-runner/blaxel-testshards.md#Repository) section and its [Options](../../../specs/arch/test-runner/blaxel-testshards.md#Options) default for `--repo-url`. (policy-grade test: `test/repo/blaxel-repository.test.ts` “selects the coordinator repository and worker checkout through the shared repository module”) ^blaxel-repo-coordinator-wiring

The remaining coverage lives in `test/repo/test-runner-provider.test.ts`.

- The canonical recommended shard count is 36, and the pool default remains 72 workers using `blaxel/playwright-chromium:latest`, 8192 MB, and the existing labels and naming scheme.
- Pool-manager source assertions require pinned nvm `v0.40.3`, `.nvmrc` selection, fresh-worker provisioning before architecture verification, and no alternate image or size defaults.
- Coordinator source assertions require nvm activation after checkout and before dependency/test work, and the generated `deps` script includes `.nvmrc` and the root manifest in its dependency cache identity.
- The `electron-repair` source assertion requires Electron's own installer with the worker-local archive cache and rejects a separate `@electron/get`, unzip, or runtime-deletion path.
- `classifyBlaxelShardStatus` returns `infra-failed` for a setup-step failure before `test-run`, an absent summary, an unconfirmed worker exit, or a summary that declares `infra-failed`; it returns `failed` for a failed summary or a passed summary contradicted by a known nonzero exit, and `passed` only for a passing summary with exit `0`.
- `normalizeBlaxelSurfaces` normalizes a passing Blaxel report into the surface's `NormalizedSurfaceResult` ([sharded-execution.md](../../../specs/arch/test-runner/sharded-execution.md)), including repository-relative conversion of absolute worker-native paths.
- A targeted command runs under the generic surface supervisor with the selected surface owner token, and a failed target still writes a shard summary instead of being retried as infrastructure.
- Provider summaries and normalized run events preserve each shard's restore/wake, checkout, dependency cache outcome, readiness, surface compute, and report-download phases without parsing human logs.
- The normal-lease acquisition scheduler never exceeds its concurrency bound, attempts each requested shard exactly once, and preserves input order in its outcomes. A partial batch writes a provider report containing acquired-but-not-run, unavailable, and thrown-error shard outcomes before releasing every partial success.
- Signal shutdown writes completed, running, and pending shard outcomes before lease cleanup; a report-write failure does not suppress cleanup.
- Unconfirmed ordinary execution cleanup orders named stop, owner-token reaping, confirmed zero-owner state, then lock release; failed owner confirmation retains the lease until TTL. Completed and undispatched paths do not run descendant cleanup.
- A stale-owner setup failure records the contaminated sandbox and its lifecycle evidence, excludes that sandbox from subsequent attempts, and permits a configured infrastructure retry only on a distinct sandbox that independently passes lease acquisition and owner audit.

**Boundary gaps — stated honestly per [testing-policy.md](../../../specs/arch/testing-policy.md):** the classifier, normalization, bounded acquisition scheduler, and provisioning/activation/cache command shapes are covered without calling Blaxel. The scheduler test uses an injected acquisition callback and therefore does not cross the Blaxel API boundary. The code-only checks cannot prove nvm installation, selected Node/npm versions, or cache behavior inside the base image. After review, deleting and recreating `poc` and running an operator-approved targeted shard provide that seam evidence along with the real coordinator path: leasing sandboxes, lock protocol, architecture validation, checkout/runtime/dependency setup, streaming logs, and result download. There is no recorded-fixture stand-in for that external boundary today. Repository switching on real workers has no committed test; the live runs from two repositories' checkouts described in the coverage model provide that evidence for a repository-selection change.
