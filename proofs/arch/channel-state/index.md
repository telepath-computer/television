# Channel and client state (architecture) — proof

Proves [specs/arch/channel-state/index.md](../../../specs/arch/channel-state/index.md).

## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below.

The inventory's active-theme row delegates field and selection semantics to [theme architecture](../themes/index.md); [theme delivery](../themes/delivery.md) proves their application to browser documents. Channel-state assertions below retain their narrower focus/pin preservation and migration responsibilities without duplicating theme behavior coverage.

The channel-sidebar width and collapsed state are client-only preferences and order no server-state assertions. Separate contract tests exercise each production preference owner against a recording storage substitute. This mock makes key use, encoding, malformed and absent reads, separation between the two preferences, and failed writes cheap and deterministic, but forfeits the real browser-storage handoff. [Resize acceptance](../../ui/app/index.md#^ap-ac-sidebar-resize) crosses the width handoff with real `localStorage`; [collapse acceptance](../../ui/app/index.md#^ap-ac-sidebar-collapse) crosses the collapsed-state handoff and proves the reload landing and preserved width. The width spec resolves an exact half-pixel tie upward; the storage assertion covers values strictly below and above the tie, and an exact-tie assertion is not ordered under the coverage-returns rule — the rounding path is proven around the tie, and the tie itself is neither plausible nor consequential enough to buy its own permanent test.

The [connection carve-out](../../../specs/arch/channel-state/index.md#^cs-connection-carve-out) leaves socket management and backoff under code authority. The [app proof](../../ui/app/index.md#^ap-ac-retry-count) owns visible retry escalation, auth/gate priority and shell continuity; its real-browser outage walk composes with this proof's reconnect-convergence coverage. Renaming the auth presentation orders no channel-state test.

## Test hooks


`window.__telepath` is a production seam for e2e tests. It exposes the running `ServerConnectionOwner` (`connectionOwner`) and application service (`applicationService`) instances, for observing state and for driving application-state operations through their public methods, and a shared `renderCompleteCallbacks` set that a test's init script may register into before the module runs. It replaces no production mechanism, and tests never substitute either instance. ^cs-telepath-test-seam

## Assertions

### Test assertions

Coverage relationship ([arch/testing-policy.md#^declaration-schema](../../../specs/arch/testing-policy.md#^declaration-schema)): the user-visible sync spine — pinning, reordering, renaming, and focus reflected across two live clients, and per-browser page selection staying local — is proven by [channels.md](../../../specs/product/channels.md) and [tab-pages.md](../../../specs/product/tab-pages.md) and is not repeated here. The browser-persisted channel-sidebar width and collapsed state are carried by the storage contracts below and the app-shell acceptances named in the coverage model, not by the server-state suite. The whole server-upgrade walk, including the display conversion this spec defines, is [arch/layout/migration.md#^mig-ac-full-upgrade](../layout/migration.md#^mig-ac-full-upgrade); this spec proves the conversion rules in isolation. Context in the state inventory and the code-governed boundaries informs implementation and review without creating a sentence-by-sentence test list ([arch/testing-policy.md#^spec-purposes](../../../specs/arch/testing-policy.md#^spec-purposes)). The browser acceptance assertions use the standing motion-disablement carve-out from the testing policy and forfeit motion, which none of their promises involve; their “no additional mocks” declarations apply to every other mechanism.
