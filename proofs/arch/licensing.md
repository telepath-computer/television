*How the licensing machinery is proven: generator, gate and loader contracts over authored inputs, and seams through every real shipping build, the suite's inventory handoff and the committed asset manifest.*

# Licensing architecture — proof

Proves [specs/arch/licensing.md](../../specs/arch/licensing.md).

## Coverage model

Contract tests drive the generator and gate with authored inventories, editor licensing records, manifests, configs, package trees, and expected output; those fixtures replace bundler discovery only for permutation breadth. Production seams run every shipping esbuild and Vite build plus the checked Markdown template editor build, persist or verify their real inventories and records, aggregate notices, and inspect the real committed asset manifest. The suite handoff then proves those inputs reach the ordinary licensing gate.

Folder notices are proven at the contract tier: fixture manifests drive the generator's folder output, the loader's `noticesFolder` validation, and the gate's staleness rule, and the real tree's committed Nord folder file is held current by the product's real-tree gate acceptance. The real-asset seam reads `scripts/licenses/assets.json` directly. It checks the three wallpaper identities, the allowlist including `LicenseRef-Unsplash`, Tokyo Night Apache text, all three photo attributions and license terms, and source/CLI/folder coverage using the existing notice-generation and staleness checks. It also checks the Tailwind component in Clouds and the live/frozen foundation paths and surfaces. Attribution comments in Clouds and the live foundation stylesheets identify Tailwind and its supplied copyright. Generated source and Clouds folder notices contain the complete recorded MIT text once, even though several records share it. Frozen payload bytes are not edited. Its path-membership checks keep the source inventory aligned with the frozen v1 font and component bundle plus the live copies, while notice and build assertions prove those records reach the declared surfaces. Product acceptance owns the user-facing source, browser, CLI tarball and desktop upload-directory outcomes; the desktop's [upload-directory check](../../specs/arch/licensing.md#^licensing-upload-assertions) is [its acceptance](../product/licensing.md#^licensing-ac-desktop-upload). [Where Electron's license files sit](../../specs/arch/licensing.md#^licensing-electron-built-app) is checked in the built Mac app by the desktop product's [recorded real-Mac run](../product/desktop-app.md#^desktop-ac-electron-license-files).

The [Sticky note font seam](#^licensing-t-sticky-note-font) extends asset coverage to the story font and the independently packaged copy. Existing loader/generator contracts cover folder validity, complete notice rendering and staleness. The source-notices regeneration test folds all source records into the root file; the folder-regeneration test includes both Sticky note folders in its fixed expected list. The font record checks cover both copies and their complete OFL notices. Whether the use respects the font-only OFL policy and reserved-name terms is review under [product licensing](../../specs/product/licensing.md#^licensing-ofl-fonts-only), not a new license-classification mechanism. The Markdown editor seam separately proves the checked record's real packages and matched vendored assets; the generator and gate contracts prove how that record reproduces the template and root notices without rebuilding the editor.

## Assertions

Shapes per the [testing-policy.md](../../specs/arch/testing-policy.md) declaration schema. The spine acceptance tests — including the real-tree gate pass, the per-input-class CLI tarball entries, the desktop upload directory, and the served browser notices — are owned by the [product proof](../product/licensing.md#assertions); the assertions here are the breadth behind them. The clean seam this composition leans on: the generator and gate consume the same persisted inputs (the [inventory root](../../specs/arch/licensing.md#^licensing-inventory-root)'s per-surface inventories, the committed Markdown template editor record, config, and asset manifest) through one loading path.

- **Contract — generator.** Fixture metafiles, bundle-module lists, and package trees in, notices text out. Covers: input-path → containing-package mapping (including scoped and nested packages); [the ignored filter](../../specs/arch/licensing.md#^licensing-ignored-filter) — a fixture package matched by an exact pattern and one matched by a `@scope/*` pattern each leave no inventory record and no notices text, and a fixture whose every package is ignored yields no file at all ([existence rule](../../specs/arch/licensing.md#^licensing-notices-existence)), while one retaining a single handled package still yields a well-formed file; the [notice-resolution rules](../../specs/arch/licensing.md#^licensing-notice-resolution) — license-file case, config-`notices` case (a `cookie-signature`-shaped fixture: MIT declared, no license file, config-supplied text), and the **failure** when neither resolves; reproduction of a synthetic Apache package's `NOTICE` file; election application; vendored-asset folding per surface (including `onboarding:*` and `source`), including a component missing its notice text, one missing its license, and one naming an ignored package each failing the build; the [content rule](../../specs/arch/licensing.md#^licensing-notices-header) — the rendered file names the product and what the file is, contains no config `id` and none of this spec's field names as labels, and renders an asset-sourced and a bundler-sourced entry in the same shape, so neither betrays its origin; entry naming — a package-identity entry carries its name and version, a component without package identity carries its own `name`, and one with neither package identity nor a name is rejected; an asset naming an undeclared surface is rejected, and a plugin is rejected when constructed with an undeclared or non-inventory surface; [one entry per item](../../specs/arch/licensing.md#^licensing-entry-once) — the same name and version arriving from both an inventory and the asset manifest renders once, and a disagreement between them about license or notice text fails the build; [record dedupe](../../specs/arch/licensing.md#^licensing-record-dedupe) — combining inventories where one record carries a license file and the other does not keeps the one that does; deterministic output ordering; [folder notices](../../specs/arch/licensing.md#^licensing-folder-notices) — an asset naming a `noticesFolder` yields a `THIRD-PARTY-NOTICES.txt` in that folder rendered from its components under the same content rule, two assets naming one folder share one file, an asset without the field yields no folder file, and the loader rejects a `noticesFolder` that is absolute, escapes the repository, is missing, or is not a folder. The bundlers are absent — the fixtures are authored data, declared here. ^licensing-t-generator-contract
- **Contract — Markdown template editor record and notices.** The real Markdown file view and template Vite configs are read, and the production licensing plugin, generator, and gate are exercised without Vite or Rollup. Authored `view:markdown` inventory, asset manifest, and emitted-module inputs replace bundler discovery; the test calls `generateBundle` directly with an empty plugin context. It proves the file view selects the one inventory writer; the template selects verification; emitted packages must exist without conflict in that inventory; matched repository-local module paths produce sorted asset IDs whose records cover both `view:markdown` and `source`; package records are sorted by name then version; and neither case writes a second surface inventory or notices. Given that committed-record shape, the generator renders its packages and assets into the template notices and the root notices, with no asset record naming the Markdown folder in `noticesFolder`. The gate reproduces both files from the record and rejects an invalid record, an unknown asset ID, or either stale file. Vite's hook invocation and real module discovery are forfeited to the real-build seam below. *(test to be written)*. ^licensing-t-vite-verification-contract
- **Contract — gate.** Fixture inventories, the Markdown template editor record, and configs in, exit results out. Covers each failure rule in [gate behavior](../../specs/arch/licensing.md#^licensing-gate-behavior): disallowed license, unresolvable notice, election drift (via the recorded `offered` value), dead config entries per category ([dead-entry rules](../../specs/arch/licensing.md#^licensing-dead-entries) — including an entry whose package survives only in `node_modules` as dev tooling), an inventory-producing declaration whose inventory is absent from the root ([forward direction](../../specs/arch/licensing.md#^licensing-declared-forward) — the writer and the plugin refuse the opposite case at its source, so the gate has none to check), an invalid editor record or unknown asset ID, stale root or Markdown template notices reproduced from that record, a [folder notices file](../../specs/arch/licensing.md#^licensing-folder-notices) that is stale and one that is missing, plus the passing case with elections applied. The [declared-dependency scan](../../specs/arch/licensing.md#^licensing-declared-scan) reads the `dependencies` of both the public CLI package and the private desktop workspace: a declared dependency under a disallowed license fails by name, one that is not installed fails, and neither a notice nor its own dependency tree is required or scanned. An ignored package cannot reach the gate, so no ignored package is gated; what the gate contract does cover for that config category is that an ignored pattern matching nothing in the current tree is **not** reported dead ([dead-entry rules](../../specs/arch/licensing.md#^licensing-dead-entries)), since the list is a standing scoping decision rather than a correction to an observed fact. A companion config-loader case proves the pattern grammar: exact and `@scope/*` forms load, and a bare `*`, a partial wildcard, a trailing-slash form, and an empty pattern are each rejected by name. *(test to be written)*. ^licensing-t-gate-contract
- **Seam — esbuild wiring.** Parameterized over **both esbuild products**: a real full CLI build and a real desktop build each persist their surface inventory, proving the metafiles really flow from each `build.mjs` into the generator on the production build path, and each write a notices file where that surface has entries; so does the real resource SDK build, whose `sdk:resources` inventory lists no packages and whose notices beside the module carry the Firebase JavaScript SDK record. The CLI's file carries entries for genuinely bundled packages (`express`); the desktop's carries its actual bundled packages, including `lit-html` from the local renderer, and the shipped Hind, Phosphor, Tailwind and Clouds photo asset records. `electron` and the workspace's declared `dependencies` load from outside the bundle. This exercises the same [existence rule](../../specs/arch/licensing.md#^licensing-notices-existence) from the populated side. Crossed once for real per product; package-level permutations stay in the generator contract tests. ^licensing-t-build-seam
- **Seam — Vite inventories.** Parameterized over **every shipping Vite surface** (`web`, `view:markdown`, `onboarding:calendar`, `onboarding:tasks`): a real `vite build` persists its surface inventory and yields a final per-dist notices file exactly where the surface has entries. The web, markdown, and `onboarding:tasks` inventories each list a genuinely bundled package; `onboarding:calendar`'s framework-free bundle records no packages and emits no notices file. Every dist contains no raw inventory artifact ([no in-dist inventory](../../specs/arch/licensing.md#^licensing-vite-intermediate)), and inline `/*! @license` banners survive minification where present ([legal comments](../../specs/arch/licensing.md#^licensing-legal-comments)) — *(policy-grade tests: `test/node/licensing.test.ts`, cases tagged `^licensing-t-vite-seam`)*. ^licensing-t-vite-seam
- **Seam — Markdown template editor build and notices.** The real Markdown file view build writes the current `view:markdown` inventory, then the real Markdown template editor check runs the production Vite plugin in verification mode over the shared editor source. With no mocks or test hooks, it emits exactly `editor.js` and `editor.css`, compares them with the committed template files, and produces sorted package records and matched asset IDs equal to the committed `template-editor-licenses.json`; no second surface inventory is written. The real record contains every emitted package and the `markdown-table-editor` asset matched from its emitted module path, whose asset record covers both `view:markdown` and `source`. The generator reproduces the committed Markdown template and repository-root notices from that record, so both notices include the emitted packages and matched table asset; the license gate accepts those files. This crosses build discovery, the checked record, notice rendering, and gate consumption once on the production path; permutation failures stay in the record contract above. *(test to be written)*. ^licensing-t-markdown-editor-build
- **Seam — aggregation.** The full CLI build's umbrella notices include entries sourced from the copied-in web inventory and the `onboarding:tasks` component inventory, the baked task artifact retains its notices file, the copied `sdk/v1/` directory retains the SDK's notices file, and the dependency-free calendar component has none; no copied component carries a raw inventory artifact. This proves the [aggregation](../../specs/arch/licensing.md#^licensing-notices-placement) and [component placement](../../specs/arch/licensing.md#^licensing-skill-notices) handoffs are wired — *(policy-grade test: `test/node/licensing.test.ts`, cases tagged `^licensing-t-aggregation-seam`)*. ^licensing-t-aggregation-seam
- **Seam — suite inventory handoff.** On the suite path (the [real-tree acceptance](../product/licensing.md#^licensing-ac-gate-passes)'s boundary), the `e2e:node` pre-build's two real product builds populate an inventory for every [declaration with `producesInventory: true`](../../specs/arch/licensing.md#^licensing-declared-surfaces) in the shared root, and the in-suite gate consumes them, asserted through the gate enumerating the surfaces it checked. This is the crossing the per-build seams cannot prove: the inventories survive their child build processes and reach the gate that enforces them. ^licensing-t-suite-seam
- **Seam — real asset records.** Reads the **real committed `assets.json`** (not a fixture) and asserts that every declared path exists; the Clouds record includes its CSS and wallpaper paths, Tailwind and both photo components, and `cli`/`desktop`/`source`/folder delivery; the Tailwind foundation record covers all live copies and frozen v1 with `web`, `view:markdown`, `desktop` and `source` delivery; Tailwind attribution comments open the Clouds and live foundation stylesheets, and its complete MIT text renders once in root and Clouds folder notices; the Hind record names the frozen v1 font, live v2 canonical font, web font, and foundation-spec font with no deleted v1 source/spec path; the Phosphor record names the live icon source, frozen v1 component bundle, and copied Checklist page, with `cli` delivery and the Checklist folder as its `noticesFolder`; the Calendar icons record names the Calendar attendees module and the Calendar story module, the same Phosphor component, the `cli` and `source` surfaces, and the Calendar folder as its `noticesFolder`, with the Phosphor comment in both files; the Firebase JavaScript SDK record names `packages/shared/src/resources/push-keys.ts`, the `cli`, `sdk:resources` and `source` surfaces, and one Apache-2.0 component whose notice text opens with `Copyright 2017 Google LLC` and carries the complete Apache License 2.0 text, with the file opening with the [attribution comment](../../specs/arch/licensing.md#^licensing-adapted-records); and the Nord record names the UI-spec stylesheet and its production copy, the `cli` and `source` surfaces, and the Nord theme folder as its `noticesFolder`, with both stylesheets opening with the [attribution comment](../../specs/arch/licensing.md#^licensing-theme-records). The Hind and Phosphor records appear in the root notices, CLI umbrella notices, web dist notices and desktop notices; the Phosphor MIT terms also appear in the generated Checklist and Calendar folder notices, which the real source manifest and folder-generation tests hold current; the desktop also attributes the Tailwind foundation and Clouds material it ships, the Nord record in the root notices, CLI umbrella notices, and its committed folder file, and the Firebase JavaScript SDK record in the root notices, CLI umbrella notices and the SDK's notices, proving that the authoritative records exist and flow to every surface they declare — *(covered by `test/repo/licensing-config.test.ts`, “regenerates the committed asset folder notices byte-for-byte” in `test/repo/licensing-generator.test.ts`, and the real build/gate cases in `test/node/licensing.test.ts`)*. ^licensing-t-real-assets-seam
- **Contract — manifest lint.** The extended `check-publishable` manifest rule fails on a fixture workspace manifest lacking `"license": "MIT"` and passes the real tree. ^licensing-t-manifest-contract
