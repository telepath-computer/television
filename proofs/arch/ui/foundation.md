*How the promises in Foundation architecture are proven.*

# Foundation architecture — proof

Proves [specs/arch/ui/foundation.md](../../../specs/arch/ui/foundation.md).

## Coverage model

The distribution seams include the shared native input, error-message, and standalone Markdown-editor stylesheets, inspect authoritative and production repository files, then run fresh live-v2 canonical and web builds. No filesystem, builder, or stylesheet mechanism is mocked. These assertions prove live byte crossings, import order, standalone-document delivery, and the canonical v2 Hind preload URL; they do not claim visual styling adherence. The Markdown editor's own proof adds its fresh-view-build leg to the shared registry and copy checks here. Frozen v1 has no foundation-source crossing and is owned by canonical's committed-payload assertions.

The production token sheets cross through the ordinary `television` builder into `theming.md`. [Theme authoring](../themes/authoring.md#^theme-authoring-t-shipped-guidance) owns the manifest-built document, including the authored reference and token and styling guidance.

The drag-region contract uses jsdom for selector matching and therefore forfeits native-window movement to the sidebar's Electron acceptance path. Canonical's own proof carries artifact-foundation delivery through the server, while this proof owns the application's copied foundation and build output.

## Test hooks

`buildTelevision()` accepts a temporary output directory; vocabulary insertion follows the same path as the ordinary production build.

## Assertions

### Test assertions

The crossing assertion covers the real repository copies and production build. The complete document route set, including the runtime theme sheet, remains [arch/ui/index.md#^ui-t-style-delivery](./index.md#^ui-t-style-delivery)'s.

- **Seam** (the authoritative foundation, element, app-surface, bundled-theme, Markdown-editor, and standalone view-specific assets crossed to their production styles through the real repository filesystem, with app-delivered assets additionally exercised by a fresh production web build; no mocks or test hooks): each CSS and font source in the app-delivered foundation has a byte-identical committed copy under `packages/web/src/foundation/`; every implemented stylesheet or frame style block discovered under `specs/ui/foundation/`, `specs/ui/elements/`, `specs/ui/app/`, `specs/ui/themes/`, and `specs/ui/markdown-editor/` has at least one declared production crossing, while each intentionally uncrossed stylesheet belongs to a spec explicitly marked **specified, not implemented**; Clouds stylesheet and wallpaper bytes cross into `packages/server/assets/themes/clouds/`, not the web bundle; module-sibling stylesheets contain their ordered byte-identical CSS sources or YAML-decoded frame style blocks, bundled-package entries and standalone view-specific style blocks preserve their source bytes, and the complete production foundation imports a copy of every sheet in the authority's order; the app imports only production copies; and the built stylesheet contains the app-document delivery set without any production import from `specs/ui/` — *(covered by test: `packages/web/test/foundation-copy.test.ts` “application foundation production crossing (^ui-t-foundation-copy)”)*. ^ui-t-foundation-copy
- **Contract** (the style-source reader used by the repository crossing seam; literal CSS and frame fixtures, no mocks): standalone CSS keeps its bytes; frame extraction returns only the YAML-decoded `style` value, preserving YAML chomping; frames without a style block contribute no stylesheet; malformed front matter and non-string styles fail rather than disappearing from discovery. This does not establish production conformance; the repository seam above owns that claim — *(covered by `test/repo/ui-style-source.test.ts`)*. ^ui-t-frame-style-source
- **Seam** (production token sheets → ordinary `television` builder → temporary `theming.md`, through real files; no mocks): complete bytes and source labels appear in foundation order, including font and layer tokens and the application catalog — *(covered by `packages/skills/skills/television/src/build.test.ts` “inserts the complete production token sheets in foundation order in the ordinary build”)*. ^ui-t-foundation-theme-guidance-copy
- **Seam** (authoritative Hind bytes → fresh canonical and web production builds, crossed through the real repository filesystem and builders; the canonical stylesheet, byte-identical web font copy, and built shell entry document are real outputs; no mocks or test hooks): the built entry document contains exactly one `link` with `rel="preload"`, `as="font"`, and `crossorigin`; the web and canonical v2 builds derive the same eight-character SHA-256 digest from their byte-identical font copies; and the link's `href` is the exact v2 font URL referenced by the built canonical `styles.css` — *(covered by test: `test/repo/build-config-integrity.test.ts` “the production shell preloads the exact canonical Hind URL”)*. ^ui-t-canonical-font-preload
- **Contract** (production drag-region stylesheet with the Electron runtime absent; jsdom supplies selector matching and therefore forfeits native-window behavior to [ui/app/sidebar/index.md#^sb-ac-titlebar-drag](../../ui/app/sidebar/index.md#^sb-ac-titlebar-drag)): a marked band matches the drag selector, button, input, link, and explicit button descendants match the no-drag selector, and an ordinary span remains draggable — *(covered by the six cases under `packages/web/test/electron-draggable.test.ts` “[electron-draggable] convention”, which read the selectors from the application global stylesheet)*. ^ui-t-electron-drag-region
