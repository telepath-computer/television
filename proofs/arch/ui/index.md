*How the promises in UI architecture are proven.*

# UI architecture — proof

Proves [specs/arch/ui/index.md](../../../specs/arch/ui/index.md).

## Coverage model

Repository contract tests inspect the live production source tree and import graph without mocks or test hooks. The module-shape heuristic catches the direct declaration and registration forms used by the repository, while engineering review remains responsible for equivalent TypeScript forms and complete architectural conformance. Its canonical-entrypoint check applies to live component builds only; canonical's proof owns the frozen v1 JavaScript bytes and public names without claiming they retain the live source shape.

The style-delivery contract records every document-level stylesheet route, including canonical v2 for the Markdown editor and built-in error documents and both Markdown view-specific sheets. A separate static resource-owner contract proves that the app import graph has one owner for its active stylesheet, main script, both sandboxed frame documents, pointer forwarding, and frame-focus guard; it also proves the permanent CSS foreground surface belongs to the app view and that standalone and artifact production sources acquire none of the application-only JavaScript resources. These checks prove source wiring and sole ownership, not manifest and consent gating, browser loading, iframe isolation, pointer behavior, execution, or reload. [Theme delivery](../themes/delivery.md#^theme-delivery-t-app-script-renderer) carries deterministic main-script lifecycle coverage, [sandboxed-frame ownership and lifecycle](../themes/delivery.md#^theme-delivery-t-frame-lifecycle), and [forced reset](../themes/delivery.md#^theme-delivery-t-script-reset); [the product executable-theme acceptance](../../product/themes-and-appearance.md#^theme-ac-executable-browser) carries the real crossings. Fresh-build distribution belongs to the foundation proof, and each UI surface owns its rendered behavior.

The architecture's [theme application scope](../../../specs/arch/ui/index.md#^ui-browser-theme-scope) composes with [theme delivery's visible application seam](../themes/delivery.md#^theme-delivery-t-visible-app) and [product theme acceptance](../../product/themes-and-appearance.md). Static source checks here do not prove visible selection, clearing, or file-edit propagation; the delivery proof cites the two active browser cases that observe those effects.

The channel-sidebar width storage contract is proven where its spec statement lives, in [the channel-state proof](../channel-state/index.md#^ui-t-sidebar-width-storage); this proof orders no assertion for it.

The application platform marker is a behavior of the production entry document rather than a styling assertion. A real-browser seam boots that document with and without the Electron query input and observes the handoff from Electron-context determination to the root attribute. The query parser breadth remains with [desktop upgrade gate detection](../updates/desktop-upgrade-gate.md#^t-electron-detection); this proof crosses the one mapping from that result to the application document. Exact traffic-light spacing remains authored token styling and is not duplicated here.

## Assertions

### Architecture test assertions

Complete module-shape conformance is established through engineering review of the production tree against this architecture and the repository code style. A repository heuristic reads the real production source tree and package metadata without mocks or test hooks, then flags violations expressed in the current direct declaration and registration forms. The heuristic is intentionally bounded: it is not a complete TypeScript parser or source-language convention, and a passing result is not proof that every production view or custom element conforms. Which surfaces decompose into which views, their argument shapes, and client service internals remain implementation choices, while each surface's own contract tests prove its service callbacks and rendered behavior.

- **Heuristic** (bounded repository source signal): for direct forms used by the current tree, flag a `View` subclass outside `packages/web/src/views/`, a missing single exported `view(Class)` wrapper or sibling stylesheet, and direct custom-element registrations that do not match the production element shape. The custom-element signal checks `packages/web/src/elements/`, a local direct `HTMLElement` subclass, an app `tv-` name or a name in canonical v1's permanent public element fixture, a sibling stylesheet, and direct `CustomEvent` construction. The live canonical entrypoint signal follows direct relative imports from `packages/canonical/canonical-components.ts` and requires each reached element module to be one of those `packages/web/src/elements/` modules. It does not inspect frozen bundle internals. Equivalent TypeScript spellings and complete conformance remain engineering-review responsibilities — *(covered by test: `test/repo/ui-module-shape.test.ts` “flags violations expressed in the repository's current direct forms”)*. ^ui-t-module-shape
- **Contract** (static source import graphs from the production web and Markdown-view entries plus the standalone production documents; no mocks or test hooks): the app entry carries the app-document marker, and the document-level stylesheet routes are exactly the production stylesheet set this architecture delivers — the app document's foundation aggregate, global sheet, each reachable view sibling stylesheet, the checkbox-list sibling stylesheet, and the final active-theme link owned by `packages/web/src/theme.ts`; the Markdown entry carries its implementation-owned layout sheet and authoritative color-sheet sibling; the Clouds package is absent from these compiled import graphs; the icon stylesheet ships inside each icon's shadow root instead of through the document-level route; and each standalone production document's canonical v2 stylesheet route is recorded explicitly — *(covered by test: `test/repo/ui-style-delivery.test.ts` “production document style delivery (^ui-t-style-delivery)”)*. ^ui-t-style-delivery
- **Contract** (static production import graphs and source-route inventory for the application, canonical wrappers, artifact proxy, markdown editor, and built-in error documents; no mocks or test hooks): the application graph reaches exactly one active-theme resource owner under `packages/web/src/`; that owner alone constructs the cache-busted stylesheet link, classic `/theme/main.js` include, `iframe-background.js` and `iframe-overlay.js` frame documents, host pointer forwarding, and frame-focus guard. The application view alone supplies permanent `#foreground-overlay`. The Clouds package remains outside the graph, and no artifact or standalone source constructs, imports, or injects any application-only theme script or surface — *(covered by `test/repo/ui-style-delivery.test.ts` “keeps the executable theme resource application-only with one owner”)*. ^ui-t-theme-resources
- **Seam** (the handoff from Electron-context determination to the application-document root marker, crossed by booting the production document and entry module in a real browser against a really-running server; page search parameters are authored fixtures; the standing CSS-motion override is the sole mock and forfeits CSS motion, which this assertion does not claim; no test hook is used): under [the platform-marker contract](../../../specs/arch/ui/index.md#^ui-platform-marker), the document root has exactly `data-platform="electron"` when `?mode=electron` establishes Electron context, and has no `data-platform` attribute when the parameter is absent or carries any other value — *(covered by test: `packages/web/test/e2e/platform-marker.test.ts` “application platform marker (^ui-t-platform-marker)” / “marks only the exact Electron mode on the production document”)*. ^ui-t-platform-marker
Coverage relationships: [lit-view.md](../../../specs/arch/ui/lit-view.md) owns the base view lifecycle, [menu-view.md](../../../specs/arch/ui/menu-view.md) owns menu trigger/panel binding, and [elements.md](../../../specs/arch/ui/elements.md) owns custom-element public APIs.
