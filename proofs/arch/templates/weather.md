# Weather artifact template — proof

Proves [specs/arch/templates/weather.md](../../../specs/arch/templates/weather.md).

## Coverage model

Package contracts read the real bundled manifest, seed, page files, icon and README. The generic [template proof](./index.md) owns schema enforcement at creation, copying, display-option precedence and independent stores. [Bundled installation](./bundled-installation.md) owns build membership and boot replacement. The assertions here establish the Weather values supplied to those shared paths.

Pure contracts exercise the forecast parser and display-window derivation used by the copied page. Authored fixtures cover complete and malformed roots, timestamp offsets and fractional seconds, invalid dates and instants, unknown time zones, condition and unit vocabulary, empty and oversized arrays, stable sorting, duplicate removal, limits, repeated daylight-saving hours, current-date ranges, rounding and elapsed age. The current instant is an explicit input to this logic; production supplies the browser clock. These contracts do not prove browser `Intl` behavior or resource delivery.

A real-browser seam creates the bundled template against a running server, loads its copied files and served resource SDK, and observes a spawned `tv resource json set` replacement on the open page. The page uses its real JSON store and makes no writes. The browser request log must contain no weather-service or other external request. The [Weather UI proof](../../ui/templates/weather.md) owns labels, responsive composition, loading, empty and unreadable presentation, live time-zone behavior, access and recovery. Its conformance assertion owns rendered appearance.

The first-party condition drawings and Toolbox icon need no third-party notice. The warning and spinner supplied by the foundation use Phosphor artwork; [licensing coverage](../licensing.md#^licensing-t-weather-icons) owns the asset record and generated package notice. README meaning also receives review because content checks alone cannot prove that the guidance teaches an agent correctly.

## Test hooks

The forecast derivation accepts a current instant. Production passes the browser clock; contract tests supply fixed instants. This replaces no parsing, time-zone conversion, sorting or display calculation.

The real-browser seam uses the built resource SDK path accepted by the server harness. Production resolves the same bundle from the installed package. Temporary homes, store values and browser request logs are fixtures; no page mechanism is replaced.

## Forecast contracts

- **Contract** (authored roots → production Weather parser; transport and DOM absent, no mocks): Under [the store schema and page checks](../../../specs/arch/templates/weather.md#^bundled-artifact-template-weather-store), classify an absent value and `{}` as empty; accept complete Celsius and Fahrenheit forecasts with every condition, empty arrays, extra fields, more than 24 hours and seven days, explicit positive and negative offsets, `Z`, optional seconds and fractional seconds; and leave inputs unchanged. Reject null, arrays and scalar roots; partial or wrongly typed forecasts; timestamps without an offset; impossible dates or instants; an unrecognized IANA time zone; unknown conditions or units; nonnumeric temperatures; and a daily high below its low. One malformed stored entry makes the complete value unreadable. [Creation-schema coverage](./index.md#^templates-t-preflight) proves that the same manifest schema gates starting and caller data; [UI invalid-data acceptance](../../ui/templates/weather.md#^weather-ui-ac-invalid) crosses page validation into the copied artifact. *(test to be written)* ^templates-weather-t-validity
- **Contract** (parsed forecast, current instant and IANA zone → production display-window derivation; authored fixtures, no mocks): Under [the current-hour and current-date definitions](../../../specs/arch/templates/weather.md#store), parse timestamps as instants regardless of written offset. Stably sort, keep the first duplicate instant or date, discard hours through the current local clock hour and dates before the current local date, then retain the first 23 future hours and first seven remaining dates. Empty arrays remain valid, and extra valid entries do not invalidate the forecast. Cover a daylight-saving fallback in `America/New_York` with distinct `-04:00` and `-05:00` instants that share a clock label, plus zones east and west of UTC. Expected calendar dates are constructed as date fields, never by parsing `YYYY-MM-DD` as a UTC instant. Browser-zone independence belongs to [UI time-zone acceptance](../../ui/templates/weather.md#^weather-ui-ac-time-zones). *(test to be written)* ^templates-weather-t-windows
- **Contract** (parsed forecast and current instant → production current-value derivation; authored fixtures, no mocks): Under [current high/low and elapsed age](../../../specs/arch/templates/weather.md#store), choose high and low only from the retained entry for the current date at `timeZone`, never from an adjacent date, and omit them when that entry is absent. Derive age from `updatedAt` in completed minutes, hours and days, treating less than a minute and future skew as now. Round temperature halves away from zero and normalize negative zero to `0°` without changing stored values. UI acceptance owns the English labels and placement. *(test to be written)* ^templates-weather-t-current-values
