# Weather artifact template — proof

Proves [specs/arch/templates/weather.md](../../../specs/arch/templates/weather.md).

## Coverage model

Package contracts read the real bundled manifest, seed, page files, icon and README. The generic [template proof](./index.md) owns creation-time schema enforcement, copying, display-option precedence and independent stores. [Bundled installation](./bundled-installation.md) owns build membership and boot replacement. The assertions here establish the Weather values supplied to those shared paths.

Pure contracts exercise the configuration and saved-forecast parser, request builder, Open-Meteo response normalizer, request eligibility, forecast selection, cache-transaction updater, display windows, rounding and elapsed age used by the copied page. `test/fixtures/weather/open-meteo/current-success.json` is the ordinary captured success; `kolkata-2026-10-27.json` and `new-york-dst-2026-10-27.json` are immutable, date-pinned time-zone fixtures. Each records the exact request, response status and CORS header alongside the unmodified provider body. Edited copies vary one relevant response field for mapping and failure breadth. Those are fixtures, not replaced page code; the contracts do not claim HTTP, browser CORS, store or rendered-page coverage.

Default browser tests run the copied page in Television's real sandbox against a running server, resource SDK and JSON store. They intercept every `https://api.open-meteo.com/**` request and script its captured response, delay or failure. That interception mocks the provider and public network, forfeiting the live endpoint, current provider response, provider timing and availability. The browser still makes the production fetch and applies real CORS checks to the captured `Access-Control-Allow-Origin` header. An unexpected provider method, URL, query or disposition fails the test, and every other external request is blocked.

One opt-in browser test, excluded from CI and default verification, crosses the real browser-provider seam from Television's opaque-origin sandbox. It proves the live endpoint, current browser CORS path and response acceptance at the time it runs, and may refresh only `current-success.json`. The Kolkata and New York fixtures stay pinned to 27 October 2026. The live test does not prove the provider's terms or limits, future compatibility or availability, or the desktop `Origin` and `Referer` path. The release gate remains human sign-off, not a test result.

The [Weather UI proof](../../ui/templates/weather.md) owns visible labels, responsive composition, placeholder states, access and recovery, attribution and conformance. It shares the primary creation/fetch/save walk with this proof. The first-party condition drawings and Toolbox icon need no third-party notice. The warning and spinner copied from the foundation use Phosphor artwork; [licensing coverage](../licensing.md#^licensing-t-weather-icons) owns the asset record and generated package notice.

## Test hooks

No production test hook is required. Contract tests call the same production parsing, request, normalization and selection modules the page imports.

Playwright may control the browser clock. Production uses the browser clock. Clock control forfeits real elapsed scheduling, not the page's timer callback, request decisions or time-zone calculations.

For the visibility acceptance, an installed Playwright helper defines a configurable `document.visibilityState` value on the real document and dispatches `visibilitychange` after changing it. This mechanism was checked in the repository's Chromium: the document reported `hidden` and then `visible`, and received both events. It mocks native browser Page Visibility delivery and forfeits that browser integration, but it does not replace the page's event handler, request check or scheduler. Automation-created Chromium tab activation did not change `document.visibilityState`, so the proof does not rely on it.

Browser tests intercept the provider at the network boundary as declared above. They use temporary Television homes, real stores and authored configuration or saved-cache fixtures. The opt-in live test removes that interception for the exact provider request only.

- **Contract** (compatible forecast, current instant and IANA zone → production display-window derivation; authored cache fixtures, no mocks): Under [the hourly window](../../../specs/arch/templates/weather.md#^bundled-artifact-template-weather-hourly-window) and [daily window](../../../specs/arch/templates/weather.md#^bundled-artifact-template-weather-daily-window), parse timestamps as instants regardless of written offset. Stably sort, keep the first duplicate instant or date, discard hours through the current local clock hour and dates before the current local date, then retain the first 23 future hours and first seven remaining dates. - **Contract** (compatible forecast and current instant → production current-value derivation; authored fixtures, no mocks): Under [current high/low and elapsed age](../../../specs/arch/templates/weather.md#store) and [UI current conditions](../../../specs/ui/templates/weather.mdx#current-conditions), choose high and low only from the first retained daily entry for the current date at `timeZone`, and omit them when absent. ## Provider request and response

- **Contract** (configured location → production request builder; authored configurations, no mocks): Under [the request form](../../../specs/arch/templates/weather.md#^bundled-artifact-template-weather-request), build a GET to exactly `https://api.open-meteo.com/v1/forecast` with the configured coordinates, requested current/hourly/daily field lists, matching `temperature_unit`, `timeformat=unixtime`, `timezone=auto` and `forecast_days=7`. Place names and saved forecasts never enter the URL. Exercise both unit values, negative and fractional coordinates, and exact query membership independent of parameter order. *(test to be written)* ^templates-weather-t-request
- **Contract** (parsed captured Open-Meteo objects → production response normalizer; captured success fixtures and edited copies, HTTP and JSON parsing absent at the test edge, no mechanism mocks): Under [response success](../../../specs/arch/templates/weather.md#^bundled-artifact-template-weather-response) and [WMO mapping](../../../specs/arch/templates/weather.md#^bundled-artifact-template-weather-wmo), accept only an object with integer `utc_offset_seconds`, complete valid current data and the expected temperature-unit strings. Map every documented WMO code to the specified condition and summary, including slight hail for 96, heavy thunderstorm for 97 and heavy hail for 99; map `is_day` 0 and 1 without inference. A missing `hourly` or `daily` object, a non-array `time` or requested field, incomplete current data, bad units, bad metadata and an unknown current code fail. Within present parallel arrays, drop only entries with a missing, null, non-finite, invalid or unmapped requested value, and drop a daily high below its low; extra values beyond `time` are ignored. Apply the hourly-window ordering, duplicate and eligibility rules at receipt; when more remain, retain exactly the first 24 eligible entries beginning with the first instant after the current hour. Empty normalized lists can still succeed. Stamp `updatedAt` with the supplied receipt instant and requested coordinates and units. A normalized success passes the same forecast checks as saved data. Malformed JSON is caught by the production fetch path before this parsed-object normalizer; [the shared failure acceptance](#^templates-weather-ac-access) owns that browser boundary. *(test to be written)* ^templates-weather-t-response
- **Contract** (captured UNIX-time responses → production normalizer and forecast windows; Node runtime in `TZ=UTC`, no mocks): Under [Open-Meteo time conversion](../../../specs/arch/templates/weather.md#forecast-request-and-mapping), use `test/fixtures/weather/open-meteo/new-york-dst-2026-10-27.json` and `kolkata-2026-10-27.json`. Hourly epoch seconds become instants and use the returned IANA zone only for local display. For the captured New York response spanning the 1 November 2026 fallback, apply its fixed `utc_offset_seconds` to each daily epoch before taking the date: the seven results remain 27 October through 2 November even though converting the last timestamp through `America/New_York` directly would produce 1 November. At `2026-11-01T02:30:00Z`, the New York current date is 31 October and the retained dates cross the offset change through 2 November. Repeat with the Kolkata half-hour offset at `2026-10-27T20:00:00Z`, when the Kolkata current date is 28 October; the captured first eligible hour is `2026-10-27T20:30:00Z`, or 2:00 AM in Kolkata. Expected dates and labels are literal values taken from the captured files and documented offset rule, not from `new Date('YYYY-MM-DD')` or the runtime zone. Feed the normalized results into the production windows and assert the retained dates and hours. *(test to be written)* ^templates-weather-t-provider-time-zones
