# Artifact template architecture — proof

Proves [specs/arch/templates/index.md](../../../specs/arch/templates/index.md).

## Coverage model

Scanner contracts use actual folders in a temporary home and exercise the real validator. A regular file at the templates-directory path causes scan-wide read failures; server cases place it after boot. A sibling folder outside that directory, with a valid manifest, page, and thumbnail, tests whether creation and thumbnail requests use only fresh scan IDs. Separate running-server checks cross list and thumbnail delivery over authenticated HTTP. A creation acceptance crosses HTTP, copying, artifact registration, channel placement, and the first store write with real files. Malformed HTTP requests cross validation and state boundaries; a recording telemetry sink replaces delivery so their rejected source text can be checked in complete serialized events. Real filesystem obstructions stop each creation step in separate temporary homes; none replaces the scanner, copy, HTTP, record writer, or channel writer. Only an uncertain store save uses the storage adapter declared below, giving up proof of a real disk failure.

The [product proof](../../product/templates.md) walks CLI and browser success and refusal. [The CLI architecture proof](../cli/index.md) owns argument-to-client mapping. [Resource architecture](../resources/index.md) owns the first-write store mechanism; this proof crosses its handoff once. [Isolation](../artifact-frame/isolation.md) owns the shared control-route token and CORS rule. Image cropping and placeholder presentation belong to [the popover UI proof](../../ui/app/skill-selector/index.md).

## Test hooks

`ServerOptions.telemetry.sink` supplies a recording sink for malformed-request checks; production constructs the PostHog sink. This forfeits delivery to [the live sink proof](../telemetry/sink.md#^t-posthog-lands), not request validation or event construction.

The resource layer’s [storage-operations adapter](../resources/index.md#test-hooks) may fail the directory flush after a seed rename, leaving the save outcome uncertain. Production uses Node filesystem operations. This mock forfeits a real disk failure; the [resource proof](../resources/index.md#^rs-arch-t-uncertain-save) covers that write path. Other failure cases use real filesystem obstructions.

The destination suffix generator may supply a known sequence in the naming contract, including a repeated value that collides. Production draws random base-36 characters. The hook forfeits only randomness, which the assertion does not claim.

## Assertions

- **Contract** (installed folder → real scanner, server absent; authored valid and malformed folders): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-package), the scanner uses exact folder IDs; accepts required fields and Semantic Versions, ignores extra manifest fields, dot folders and top-level files, checks a readable root `index.html` and valid in-limit `data.json`, and reports every defect of one invalid folder in one error. It reports `hasData` by file presence and `hasThumbnail` only for a readable file inside the folder's real location. *(policy-grade test: `packages/server/test/templates-scanner.test.ts`, cases tagged `^templates-t-package`)* ^templates-t-package
- **Contract** (templates directory → real scanner): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-scan), each scan reads the current folders, returns valid templates ordered by English-locale name then ID and errors ordered by folder, and returns `folder: null` on directory-read failure. *(policy-grade test: `packages/server/test/templates-scanner.test.ts`, cases tagged `^templates-t-scan`)* ^templates-t-scan
- **Seam** (authenticated `GET /templates` → real scanner): Under [discovery](../../../specs/arch/templates/index.md#^artifact-template-scan) and [the route contract](../../../specs/arch/templates/index.md#^artifact-template-thumbnail-route), the response carries the current complete scan; a request without the token is refused. [Isolation](../artifact-frame/isolation.md#^iso-t-routes) owns CORS. *(policy-grade test: `packages/server/test/templates-routes.test.ts`, cases tagged `^templates-t-routes`)* ^templates-t-routes
- **Seam** (authenticated `POST /templates/artifacts` → fresh scanner; the outside sibling folder declared above is a fixture): Under [exact-ID resolution](../../../specs/arch/templates/index.md#discovery), the route refuses an invalid or missing folder by its current scan result, and reports a scan-wide directory-read failure. A request naming `../outside-template` is refused as not found even when `<home>/outside-template` has a valid manifest and page; it creates no copied folder or artifact record. A request without the token is refused. The complete successful create request is [#^templates-t-copy](#^templates-t-copy). *(policy-grade test: `packages/server/test/templates-routes.test.ts`, cases tagged `^templates-t-create-route`)* ^templates-t-create-route
- **Acceptance** (shared-client thumbnail request with token → running server over HTTP → fresh scan and real file bytes; temporary folder fixtures, including the outside sibling, no mocks): Under [thumbnail delivery](../../../specs/arch/templates/index.md#^artifact-template-thumbnail-route), a folder ID containing a space and `#` resolves through its URL-encoded form to exact-match thumbnail bytes served as `image/png`. An absent thumbnail, invalid template, unreadable file, or symbolic link escaping the folder returns not found. A request whose one URL-encoded ID segment decodes to `../outside-template` also returns not found, rather than the sibling folder's thumbnail bytes. The [popover browser proof](../../ui/app/skill-selector/index.md#^templates-ui-ac-open) checks that the app requests bytes only when `hasThumbnail` is true. *(policy-grade test: `packages/server/test/templates-routes.test.ts`, cases tagged `^templates-t-thumbnail-route`)* ^templates-t-thumbnail-route
- **Acceptance** (authenticated `POST /templates/artifacts` → running server, real store, and telemetry runtime; temporary home and template fixtures, recording sink as declared above): Under [runtime request validation](../../../specs/arch/templates/index.md#^artifact-template-request-validation), a request with an unknown string `source` containing an authored private marker, and requests with each missing required field, a wrong type for each string field, or starting data with an overlong object key, receive HTTP `400` with `{ error: string }`. None creates a copied folder, artifact record, or store. The recording sink contains no `artifact_created` or `artifact_template_used` from these requests, and no complete serialized event contains the marker. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-request-validation`)* ^templates-t-request-validation
- **Contract** (creation request → preflight; real scanner and store validator, no copy yet): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-preflight), invalid starting data, unusable channel or template, and invalid or conflicting placement are refused before any destination folder, artifact record, or store appears; a present `data: null` overrides `data.json`. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-preflight`)* ^templates-t-preflight
- **Acceptance** (authenticated HTTP create request → real scanner, copy, registry, channel layout, and resource store; temporary folder fixtures, no mocks): Under [the creation contract](../../../specs/arch/templates/index.md#^artifact-template-copy), creation excludes `manifest.json`, `data.json`, and `thumbnail.png`, copies `README.md` and supporting files, registers a normal path artifact with no origin field, and places it as requested. With starting data it durably seeds the artifact's own store before returning ID and path; supplied data replaces `data.json`, including with `null`. Without either source, the store remains unwritten. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-copy`)* ^templates-t-copy
- **Contract** (title → destination naming on real filesystem): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-copy-name), the specified ASCII slug rule, 60-character limit, empty-title fallback, five base-36 characters and collision retry produce distinct readable folders. [Product acceptance](../../product/templates.md#^templates-ac-cli-create) proves path stability after retitling. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-folder-name`)* ^templates-t-folder-name
- **Acceptance** (authenticated HTTP create requests → real files and store; no mocks): Under [failure after copying starts](../../../specs/arch/templates/index.md#^artifact-template-copy), separate temporary homes use deterministic obstructions: an unsupported socket entry among template support files stops a copy after its destination is created; a regular file at `<home>/state/artifacts` stops record writing; a directory at the target channel record path stops layout saving; and a regular file at `<home>/resources` stops the first store write. Each obstruction is installed after serving boot. Each failure returns no success, preserves all content already created, and names the destination and unconfirmed step; the error includes the generated ID once registration was attempted. *(policy-grade test: `packages/server/test/templates-failures.test.ts`, cases tagged `^templates-t-failure`)* ^templates-t-failure
- **Seam** (registered template artifact → resource first write, with the declared storage adapter failing the post-rename flush): Under [the uncertain-save rule](../../../specs/arch/templates/index.md#^artifact-template-copy), an uncertain seed returns failure naming the destination, generated ID, and unconfirmed store step. It leaves copied and registered content in place and never reports success; the [resource proof](../resources/index.md#^rs-arch-t-uncertain-save) owns the storage mechanism. *(policy-grade test: `packages/server/test/templates-failures.test.ts`, cases tagged `^templates-t-uncertain-seed`)* ^templates-t-uncertain-seed
