# Artifact template architecture — proof

Proves [specs/arch/templates/index.md](../../../specs/arch/templates/index.md).

## Coverage model

Scanner contracts use actual folders in a temporary home and exercise the real validator. A regular file at the templates-directory path causes scan-wide read failures; server cases place it after boot. A sibling folder outside that directory, with a valid manifest, page, and thumbnail, tests whether creation and thumbnail requests use only fresh scan IDs. Separate running-server checks cross list and thumbnail delivery over authenticated HTTP. A creation acceptance crosses HTTP, copying, artifact registration, channel placement, and the first store write with real files. Malformed HTTP requests cross validation and state boundaries; a recording telemetry sink replaces delivery so their rejected source text can be checked in complete serialized events. Real filesystem obstructions stop each creation step in separate temporary homes; none replaces the scanner, copy, HTTP, record writer, or channel writer. Only an uncertain store save uses the storage adapter declared below, giving up proof of a real disk failure.

The scanner contract validates manifest `display` and strips unknown fields from the returned template; the route seam below proves a fresh scan serves that validated record. Creation tests send authored request bodies over real HTTP, check each field's command, manifest, then default precedence, and check that invalid request display is refused before copying. They run the real scanner, copy, registry, and channel writer without mocks. [Layout creation](../layout/index.md#^ly-ac-create-display) covers path and URL HTTP requests and the shared page defaults; [product templates](../../product/templates.md#^templates-ac-display-cli) crosses the spawned CLI, and its [browser walk](../../product/templates.md#^templates-ac-display-ui) crosses the popover. This proof checks the template route's display handling without repeating the product journeys for every combination.

The [product proof](../../product/templates.md) walks CLI and browser success and refusal. [The CLI architecture proof](../cli/index.md) owns argument-to-client mapping. [Resource architecture](../resources/index.md) owns the first-write store mechanism; this proof crosses its handoff once. [Isolation](../artifact-frame/isolation.md) owns the shared control-route token and CORS rule. Image cropping and placeholder presentation belong to [the popover UI proof](../../ui/app/templates-popover/index.md), mirroring the single-file MDX spec. The scanner validates general JSON seed rules. [Checklist](./checklist.md) and [Sticky note](./sticky-note.md) architecture own their respective data shapes; [Checklist UI](../../ui/templates/checklist/index.md) and [Sticky note UI](../../ui/templates/sticky-note/index.md) own what the copied pages do with them.

Transparency follows the same manifest/request contract as the other display values. Scanner cases retain true and false as valid manifest inputs and check omission and type errors. Real HTTP creation checks per-field precedence, stores only true on the artifact record, and checks that false or a default opaque result leaves the field absent through the initial store write and restart. A list read in that walk proves that the validated manifest field crosses the scanner-to-route handoff. [CLI creation](../../product/templates.md#^templates-ac-transparent-cli) and [popover creation](../../product/templates.md#^templates-ac-transparent-ui) supply the outer command and browser paths. Existing size/full-screen assertions keep their evidence; the transparency assertions extend those fixtures without duplicating their whole matrices.

## Test hooks

`ServerOptions.telemetry.sink` supplies a recording sink for malformed-request checks; production constructs the PostHog sink. This forfeits delivery to [the live sink proof](../telemetry/sink.md#^t-posthog-lands), not request validation or event construction.

The resource layer’s [storage-operations adapter](../resources/index.md#test-hooks) may fail the directory flush after a seed rename, leaving the save outcome uncertain. Production uses Node filesystem operations. This mock forfeits a real disk failure; the [resource proof](../resources/index.md#^rs-arch-t-uncertain-save) covers that write path. Other failure cases use real filesystem obstructions.

The destination suffix generator may supply a known sequence in the naming contract, including a repeated value that collides. Production draws random base-36 characters. The hook forfeits only randomness, which the assertion does not claim.

## Assertions

- **Contract** (installed folder → real scanner, server absent; authored valid and malformed folders): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-package), the scanner uses exact folder IDs; accepts required fields and Semantic Versions, ignores extra manifest fields, dot folders and top-level files, checks a readable root `index.html` and valid in-limit `data.json`, and reports every defect of one invalid folder in one error. It reports `hasData` by file presence and `hasThumbnail` only for a readable file inside the folder's real location. *(policy-grade test: `packages/server/test/templates-scanner.test.ts`, cases tagged `^templates-t-package`)* ^templates-t-package
- **Contract** (authored `manifest.json` files → real scanner over a temporary templates directory; no mocks or test hooks): Under [manifest display validation](../../../specs/arch/templates/index.md#^artifact-template-package), omitted `display` is absent in the validated record; a valid partial object retains its known fields, including `fullScreen: false`, while unknown root and inner fields are omitted. A non-object `display`, nonpositive or nonfinite width or height, and nonboolean `fullScreen` each invalidate the folder with an error naming `display` or the offending field. *(policy-grade tests: `packages/server/test/templates-scanner.test.ts` “keeps validated display fields and omits unknown manifest fields” and “rejects invalid … in a manifest and names its field”)* ^templates-t-display-scan
- **Contract** (templates directory → real scanner): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-scan), each scan reads the current folders, returns valid templates ordered by English-locale name then ID and errors ordered by folder, and returns `folder: null` on directory-read failure. *(policy-grade test: `packages/server/test/templates-scanner.test.ts`, cases tagged `^templates-t-scan`)* ^templates-t-scan
- **Seam** (authenticated `GET /templates` → real scanner): Under [discovery](../../../specs/arch/templates/index.md#^artifact-template-scan) and [the route contract](../../../specs/arch/templates/index.md#^artifact-template-thumbnail-route), the response carries the current complete scan; a request without the token is refused. [Isolation](../artifact-frame/isolation.md#^iso-t-routes) owns CORS. *(policy-grade test: `packages/server/test/templates-routes.test.ts`, cases tagged `^templates-t-routes`)* ^templates-t-routes
- **Seam** (authenticated `POST /templates/artifacts` → fresh scanner; the outside sibling folder declared above is a fixture): Under [exact-ID resolution](../../../specs/arch/templates/index.md#discovery), the route refuses an invalid or missing folder by its current scan result, and reports a scan-wide directory-read failure. A request naming `../outside-template` is refused as not found even when `<home>/outside-template` has a valid manifest and page; it creates no copied folder or artifact record. A request without the token is refused. The complete successful create request is [#^templates-t-copy](#^templates-t-copy). *(policy-grade test: `packages/server/test/templates-routes.test.ts`, cases tagged `^templates-t-create-route`)* ^templates-t-create-route
- **Acceptance** (shared-client thumbnail request with token → running server over HTTP → fresh scan and real file bytes; temporary folder fixtures, including the outside sibling, no mocks): Under [thumbnail delivery](../../../specs/arch/templates/index.md#^artifact-template-thumbnail-route), a folder ID containing a space and `#` resolves through its URL-encoded form to exact-match thumbnail bytes served as `image/png`. An absent thumbnail, invalid template, unreadable file, or symbolic link escaping the folder returns not found. A request whose one URL-encoded ID segment decodes to `../outside-template` also returns not found, rather than the sibling folder's thumbnail bytes. The [popover browser proof](../../ui/app/templates-popover/index.md#^templates-ui-ac-open) checks that the app requests bytes only when `hasThumbnail` is true. *(policy-grade test: `packages/server/test/templates-routes.test.ts`, cases tagged `^templates-t-thumbnail-route`)* ^templates-t-thumbnail-route
- **Acceptance** (authenticated `POST /templates/artifacts` → running server, real store, and telemetry runtime; temporary home and template fixtures, recording sink as declared above): Under [runtime request validation](../../../specs/arch/templates/index.md#^artifact-template-request-validation), a request with an unknown string `source` containing an authored private marker, and requests with each missing required field, a wrong type for each string field, or starting data with an overlong object key, receive HTTP `400` with `{ error: string }`. None creates a copied folder, artifact record, or store. The recording sink contains no `artifact_created` or `artifact_template_used` from these requests, and no complete serialized event contains the marker. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-request-validation`)* ^templates-t-request-validation
- **Contract** (creation request → preflight; real scanner and store validator, no copy yet): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-preflight), invalid starting data, unusable channel or template, and invalid or conflicting placement are refused before any destination folder, artifact record, or store appears; a present `data: null` overrides `data.json`. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-preflight`)* ^templates-t-preflight
- **Acceptance** (authenticated real HTTP client → running server with a temporary home and authored valid template folders; no mocks or test hooks): Under [display precedence](../../../specs/product/templates.md#^artifact-template-display-options) and [the creation request](../../../specs/arch/templates/index.md#creating-an-artifact), creation through `POST /templates/artifacts` chooses width, height, and full-screen values from the request, then the template, then the shared defaults, and stores the resolved values on the page. Cases include a request width overriding a different template width while template height and `fullScreen: true` remain, explicit request `fullScreen: false` overriding true, and a partial manifest supplying one dimension while the other comes from the shared default. A real channel read and restart retain the selected page values. *(policy-grade test: `packages/server/test/templates-create.test.ts` “chooses request, manifest, then default display values independently and keeps them after restart”)* ^templates-t-display-resolution
- **Acceptance** (authenticated real HTTP client → running server and temporary home; authored valid template folder and malformed request bodies, no mocks or test hooks): Under [request preflight](../../../specs/arch/templates/index.md#^artifact-template-preflight) and [creation display validation](../../../specs/arch/layout/index.md#^ly-creation-display), a malformed `display` or invalid width, height, or `fullScreen` is refused before any destination folder, artifact record, page, or store is created. *(policy-grade test: `packages/server/test/templates-create.test.ts` “rejects malformed request display before copying or registering”)* ^templates-t-display-request-invalid
- **Acceptance** (authenticated HTTP create request → real scanner, copy, registry, channel layout, and resource store; temporary folder fixtures, no mocks): Under [the creation contract](../../../specs/arch/templates/index.md#^artifact-template-copy), creation excludes `manifest.json`, `data.json`, and `thumbnail.png`, copies `README.md` and supporting files, registers a normal path artifact with no origin field, and places it as requested. With starting data it durably seeds the artifact's own store before returning ID and path; supplied data replaces `data.json`, including with `null`. Without either source, the store remains unwritten. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-copy`)* ^templates-t-copy
- **Contract** (title → destination naming on real filesystem): Under [the specified behavior](../../../specs/arch/templates/index.md#^artifact-template-copy-name), the specified ASCII slug rule, 60-character limit, empty-title fallback, five base-36 characters and collision retry produce distinct readable folders. [Product acceptance](../../product/templates.md#^templates-ac-cli-create) proves path stability after retitling. *(policy-grade test: `packages/server/test/templates-create.test.ts`, cases tagged `^templates-t-folder-name`)* ^templates-t-folder-name
- **Acceptance** (authenticated HTTP create requests → real files and store; no mocks): Under [failure after copying starts](../../../specs/arch/templates/index.md#^artifact-template-copy), separate temporary homes use deterministic obstructions: an unsupported socket entry among template support files stops a copy after its destination is created; a regular file at `<home>/state/artifacts` stops record writing; a directory at the target channel record path stops layout saving; and a regular file at `<home>/resources` stops the first store write. Each obstruction is installed after serving boot. Each failure returns no success, preserves all content already created, and names the destination and unconfirmed step; the error includes the generated ID once registration was attempted. *(policy-grade test: `packages/server/test/templates-failures.test.ts`, cases tagged `^templates-t-failure`)* ^templates-t-failure
- **Seam** (registered template artifact → resource first write, with the declared storage adapter failing the post-rename flush): Under [the uncertain-save rule](../../../specs/arch/templates/index.md#^artifact-template-copy), an uncertain seed returns failure naming the destination, generated ID, and unconfirmed store step. It leaves copied and registered content in place and never reports success; the [resource proof](../resources/index.md#^rs-arch-t-uncertain-save) owns the storage mechanism. *(policy-grade test: `packages/server/test/templates-failures.test.ts`, cases tagged `^templates-t-uncertain-seed`)* ^templates-t-uncertain-seed

## Transparency display values

- **Contract** (authored manifests → real scanner over temporary folders, server absent; no mocks or hooks): under [the manifest contract](../../../specs/arch/templates/index.md#^artifact-template-package) and [display value rules](../../../specs/arch/layout/index.md#^ly-creation-display), true and false `display.transparent` values survive validation, an omitted field remains absent, and unrelated valid display values are retained. A string, number, or null invalidates the folder with an error naming the field. Extend [the existing display scanner cases](#^templates-t-display-scan). *(policy-grade tests: `packages/server/test/templates-scanner.test.ts`, “keeps validated display fields and omits unknown manifest fields” and “rejects invalid %s in a manifest and names its field”)* ^templates-t-transparent-scan
- **Acceptance** (authenticated HTTP client → running server, real scanner, copying, registry, channel writer, and resource layer; temporary template folders with authored manifests and valid `data.json`, no mocks or hooks): under [template creation](../../../specs/arch/templates/index.md#creating-an-artifact) and [field precedence](../../../specs/product/templates.md#^artifact-template-display-options), `GET /templates` carries validated true and false transparency values. Creation without a request override uses the manifest value; explicit request false overrides manifest true, request true overrides manifest false, and omission from both is opaque. Mix a request width with manifest height/full-screen/transparency to prove field-by-field selection without enumerating every combination. Under [the stored transparency rule](../../../specs/arch/artifacts/index.md#^ar-transparent), a successful seeded artifact carries top-level `transparent: true` when enabled; when resolution yields false or the opaque default, its saved record and individual/list/channel API records omit `transparent`. In each case it retains its store pointer and independently resolved page values. A restart exposes the same true-or-absent record shape and page settings. Extend [display resolution](#^templates-t-display-resolution). *(policy-grade tests: `packages/server/test/templates-create.test.ts`, “chooses request, manifest, then default display values independently and keeps them after restart”)* ^templates-t-transparent-resolution
- **Acceptance** (authenticated HTTP client → running server and temporary home; otherwise valid template request and folder, malformed transparency values as fixtures; no mocks or hooks): under [display preflight](../../../specs/arch/templates/index.md#creating-an-artifact), a string, number, or null request `display.transparent` is rejected before any copied destination, artifact record, page, or store is created, even when the manifest supplies a valid boolean. Extend [invalid request display](#^templates-t-display-request-invalid). *(policy-grade tests: `packages/server/test/templates-create.test.ts`, “rejects malformed request display before copying or registering”)* ^templates-t-transparent-request-invalid
