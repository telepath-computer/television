# Artifact template architecture — proof

Proves [specs/arch/templates/index.md](../../../specs/arch/templates/index.md).

## Coverage model

Scanner contracts read authored manifests and real files in temporary homes; they carry schema, icon-selection, ordering and display breadth without a browser.
Creation contracts carry request validation; HTTP seams cross the real scanner, registry, placement and store writers for each distinct creation branch.
The [product proof](../../product/templates.md) walks linked creation, copying, detaching, URL creation and principal refusals through the built CLI and browser.
The [CLI proof](../cli/index.md) owns flat list/show projection, argv parsing and output; those projections are not app records.
Server cache contracts control scan completion and watcher notifications; real filesystem and WebSocket seams prove observation and publication.
Client cache contracts control list/icon responses and events; browser seams prove the real shared client, authentication, image decoding and reconnection.
These controlled peers are mocks: they forfeit native watching, transport and browser behavior to the real seams named below.
Fixtures include readable SVG/PNG files, broken image bytes, escaping symlinks, schema documents, URL addresses and filesystem obstructions.
CSS-motion disablement in browser cases forfeits motion only; no template-cache promise depends on motion.
[Reload/navigation](../artifact-frame/reload-navigation.md) owns watcher mechanics and artifact-content events; template pushes do not replace those events.
[Resources](../resources/index.md) owns durable first writes and uncertain saves; [artifact records](../artifacts/index.md) owns ordinary record shapes.
[Isolation](../artifact-frame/isolation.md) owns route-wide CORS; [Toolbox](../../ui/app/toolbox.md) owns accessible interaction, default icons and appearance.
Schema compatibility across authored versions is assessed in template-content review, not by a runtime schema-diff or migration mechanism.
Evidence below covers creation, discovery and icons; browser cache evidence is recorded separately from its controlled-peer contracts.

## Test hooks

- `ServerOptions.telemetry.sink` may record complete events instead of sending them to PostHog; real delivery belongs to [the sink proof](../telemetry/sink.md#^t-posthog-lands).
- The [resource storage adapter](../resources/index.md#test-hooks) may fail the directory flush after a first-write rename; production uses Node filesystem operations. This forfeits a real failing disk, which cannot be induced deterministically; the resource proof carries normal real I/O.
- `generateTemplateSuffix` may return a known sequence to force a collision; production generates random base-36 suffixes. Randomness itself is not claimed.
- Cache contracts may inject a scan function, the shared watcher factory and debounce scheduler; production uses the real scanner, shared content watcher and timers. These are planned test affordances, not claims that those hooks already exist.
- Client-cache contracts may supply a recording shared client and event source with controlled completion order; production uses the authenticated connection. A transport gate in browser seams may delay real HTTP responses without changing their bytes; it forfeits ordinary timing only. The fallback acceptance may abort one list request and make the server watcher factory fail; these exceptional mocks forfeit actual network/kernel failure generation, not the real retry and refresh paths.

## Validation and discovery

Unless stated otherwise, these are **contract** assertions at the scanner output boundary, with authored folder trees on a real temporary filesystem, no mocks and no server.

- Under [the folder contract](../../../specs/arch/templates/index.md#^artifact-template-package), preserve exact IDs, required non-empty metadata and Semantic Versions, omit unknown root/display fields, require a readable root page only without `url`, trim absolute HTTP(S) URLs, and treat a URL as authoritative even with a page present. Reject other URL forms and any URL-template `dataSchema`. Return flat validated records and aggregate defects by folder. A supporting file named `data.json` is not interpreted as template metadata or validated as starting data. *(policy-grade tests: `packages/server/test/templates-scanner.test.ts`, “preserves exact IDs, validates package files, and reports every defect in an invalid folder”, “treats supporting data.json as ordinary content regardless of its bytes or readability”, and “uses a trimmed HTTP(S) URL even without a page and rejects other URL forms or URL schemas”)* ^templates-t-package
- Under [schema validation](../../../specs/arch/templates/index.md#^artifact-template-schema), accept boolean schemas and the specified draft with implicit or explicit dialect; reject invalid schemas, other dialects, and evaluated references that are unresolved or point outside the schema, including into the surrounding manifest. Local references work without external loads. Errors identify the schema field or root and direct the caller to `tv templates show <id>`. *(policy-grade tests: `packages/server/test/templates-scanner.test.ts`, “accepts a self-contained Draft 2020-12 schema: %j” and “rejects an invalid or escaping schema with an inspection hint: %j”; `packages/server/test/templates-schema.test.ts`, “compiles valid schemas without inspecting unused references: %j” and “rejects invalid schemas, wrong dialects and unresolved references: %j”)* ^templates-t-schema
- Under [display validation](../../../specs/arch/templates/index.md#^artifact-template-package), retain omitted or valid partial `display`, strip unknown fields, preserve explicit false, and report invalid dimensions or booleans by field. *(policy-grade tests: `packages/server/test/templates-scanner.test.ts`, “keeps validated display fields and omits unknown manifest fields” and “rejects invalid %s in a manifest and names its field”)* ^templates-t-display-scan
- Under the same [display contract](../../../specs/arch/templates/index.md#^artifact-template-package), true and false transparency survive validation, omission stays absent, and string, numeric and null values fail. This is part of the preceding table, not another suite. *(policy-grade tests: the same two `packages/server/test/templates-scanner.test.ts` cases)* ^templates-t-transparent-scan
- Under [scanning](../../../specs/arch/templates/index.md#^artifact-template-scan), ignore dot folders and ordinary top-level files, read current folders, sort records by English-locale name then exact ID and errors by folder, and return a directory error with `folder: null` when it cannot be read. *(policy-grade tests: `packages/server/test/templates-scanner.test.ts`, “preserves exact IDs, validates package files, and reports every defect in an invalid folder” for ignored entries only, and “rescans current folders, sorts names and IDs in English, and reports a directory read failure” for rescanning, record ordering and directory-read failure)*. Folder-error ordering across multiple invalid folders: *(policy-grade tests: `packages/server/test/templates-scanner.test.ts`, “rescans current folders, sorts names and IDs in English, and reports a directory read failure”)*. ^templates-t-scan
- Under [icon delivery](../../../specs/arch/templates/index.md#icon-delivery), ignore unusable entries or a non-array without invalidating the template; enforce local readable files within the real folder, including symlinks. Validate/infer supported types, sizes and `any` purpose, strip unknown fields and preserve usable manifest order. Selection uses SVG/`any` preference, the smallest PNG meeting 40px on both axes or largest available, shorter-dimension comparison, best declared size or PNG dimensions, unsized-last ranking and manifest-order ties. `hasIcon` reflects selection, not browser decoding. *(policy-grade tests: `packages/server/test/templates-scanner.test.ts`, “ignores unusable icons without invalidating the package and preserves usable manifest order” and “selects icons by %s”)* ^templates-t-icons

## Server cache and transport

- **Contract** (cache owner at scanner/watcher boundaries; controlled scan completions, notifications and debounce as declared above): under [cache ordering](../../../specs/arch/templates/index.md#^artifact-template-cache) and [fallback](../../../specs/arch/templates/index.md#^artifact-template-watch-fallback), initial watch/scan setup misses no intervening edit; a write burst yields one refresh; older work cannot replace a newer scan. Every added/changed/removed ID invalidates bytes even if its manifest and selected filename stay unchanged. Watch start/runtime failures warn, set `watching: false`, and publish; recovery publishes a full scan with true. Dispose closes owned observation. Native watching and transport are forfeited to the next seam and [watcher mechanics](../artifact-frame/reload-navigation.md#^rn-ac-shared-watcher-native). *(policy-grade tests: `packages/server/test/templates-cache.test.ts`, “watches before the initial scan and folds intervening edits and bursts into a current full scan”, “fresh scans cancel queued work and invalidate bytes even when records and filenames are unchanged”, “warns and publishes failure, scans on fallback reads, and publishes full recovery”, “retains missing-root observation and scans on rearm”, and “ignores callbacks from a failed watcher after observation has been replaced”)* ^templates-t-cache-order
- **Seam** (real shared content watcher → template cache → authenticated `/events` socket over native filesystem observation and WebSocket; temporary home, no mocks): under [cache updates](../../../specs/arch/templates/index.md#^artifact-template-cache) and [events](../../../specs/arch/templates/index.md#^artifact-template-events), editing a nested support/icon file and adding, renaming or removing a folder publishes the complete current scan and required invalidated IDs after the first `server-status`. A connection gets no replayed template event. Editing a folder used by an artifact also produces its separate artifact-content event. Closing the server releases observation. Use readiness/events rather than sleeps. *(policy-grade tests: `packages/server/test/templates-routes.test.ts`, “publishes native nested edits and folder additions renames removals without replay and keeps linked-content events”)* ^templates-t-cache-events
- **Seam** (authenticated shared client → server cache and scanner over HTTP; authored valid/invalid folders, only the watcher-failure mock described below): under [app routes and fresh scans](../../../specs/arch/templates/index.md#app-route-and-fresh-scans), list returns the flat `ArtifactTemplateScan`, `fresh: true` reaches `?fresh=true`, immediately reflects edits, replaces the cache and publishes the scan. Default reads use the cache when watching and scan when not. Missing credentials are refused. A watcher-factory failure may pose the fallback state; it forfeits native failure detection to [watcher mechanics](../artifact-frame/reload-navigation.md#^rn-ac-shared-watcher-native), while HTTP and scanning remain real. *(policy-grade tests: `packages/server/test/templates-routes.test.ts`, “authenticates cached lists and publishes immediate fresh shared-client scans” and “fallback list scans publish but icon-only validation changes neither cache nor events”; cache-read ordering in `packages/server/test/templates-cache.test.ts`, “fresh scans cancel queued work and invalidate bytes even when records and filenames are unchanged”)* ^templates-t-routes
- **Seam** (authenticated creation route → fresh scanner over HTTP; outside sibling folder, malformed folder and unreadable-directory fixtures; no mocks): under [lookup](../../../specs/arch/templates/index.md#discovery), edits are visible immediately; invalid, missing and unreadable-root lookups report their specified errors. Exact-ID resolution refuses `../outside-template` despite a valid sibling. Missing credentials are refused before creation. *(policy-grade test: `packages/server/test/templates-routes.test.ts`, “refuses missing, invalid, outside, and scan-wide-failed IDs from a fresh scan”, for existing lookup/refusal cases; immediate edited-record creation is covered below)*. *(policy-grade tests: `packages/server/test/templates-routes.test.ts`, “creates from an immediately edited manifest through a fresh exact-ID lookup” and “refuses missing, invalid, outside, and scan-wide-failed IDs from a fresh scan”)* ^templates-t-create-route
- **Seam** (shared-client icon call → authenticated route → real file over HTTP; SVG/PNG files, IDs with space and `#`, escaping and subsequently retargeted symlinks; no mocks except watcher failure to select fallback): under [icon delivery](../../../specs/arch/templates/index.md#^artifact-template-icon-route), URL encoding preserves exact IDs; selection and containment are repeated, correct bytes/type and `Cache-Control: no-store` are returned, and unavailable/invalid/escaping targets return not found. A request without the token is refused. With watching false, direct validation changes neither cache nor event stream. The watcher mock forfeits detection only to the shared-watcher proof. *(policy-grade tests: `packages/server/test/templates-routes.test.ts`, “serves authenticated exact-ID icons with media type and no-store and rechecks symlink containment” and “fallback list scans publish but icon-only validation changes neither cache nor events”)* ^templates-t-icon-route

## App cache

- **Contract** (app cache consumer at shared-client/event boundaries; authored scans, bytes and controlled response order through the declared peers): under [app cache consumption](../../../specs/arch/templates/index.md#^artifact-template-events), subscribe before loading on startup/reconnect; retain state per connection while closed; replace scans on pushes; invalidate all icons on full fetch and the named IDs on pushes. Removed IDs lose bytes. Stale lists/icons cannot overwrite newer pushes. A successful load allows request-free openings while watching; a failed startup/reconnect load retries next opening and retains any prior list. Watch failure requests fresh on every opening and once when learned while open, without loops from repeated false pushes; recovery resumes cached opening. Real connection, image rendering and UI opening are forfeited to the following seam and [Toolbox](../../ui/app/toolbox.md). *(policy-grade tests: `packages/web/test/template-cache.test.ts`, “preloads icons, retains them while closed, and applies only named push invalidations”, “rejects delayed lists and icons superseded by a push or a connection attempt”, “reloads every icon after reconnect when a partial push supersedes the list response”, “retries failed loads on opening, keeps previous rows, and refreshes once per watcher-failure transition”, and “keeps connections separate and discards completions after disposal”; `packages/web/test/server-connection.test.ts`, “subscribes to template pushes before bootstrap loads and retries a failed load without failing the connection” and “keeps template loading behind the desktop boot barrier”)* ^templates-t-app-cache
- **Seam** (real app connection → template cache over HTTP/WebSocket in a real browser; temporary templates and local icon files, no mocks except response-delay gates and CSS-motion disablement): under [app consumption](../../../specs/arch/templates/index.md#^artifact-template-events), startup preloads authenticated icon bytes, opening after load makes no list/icon request, a disk edit while closed updates the next opening, and reconnect reloads list and icon bytes after missed edits. A delayed old list or icon response cannot restore an earlier version. Requests never fetch site favicons, and an SVG is displayed as an image rather than inserted markup. *(policy-grade tests: `packages/web/test/e2e/template-cache.test.ts`, “preloads authenticated icons, opens from cache, observes closed edits and reloads after missed events (^templates-t-app-cache-seam)” and “discards delayed real list and icon responses after newer pushes (^templates-t-app-cache-seam)”)* ^templates-t-app-cache-seam

- **Acceptance** (real browser → running authenticated server and filesystem; temporary templates, one aborted initial list request and controlled server watcher-factory failure, CSS-motion override): under [load retry](../../../specs/arch/templates/index.md#^artifact-template-events) and [watcher fallback](../../../specs/arch/templates/index.md#^artifact-template-watch-fallback), opening after the failed initial load retries the cached server route and displays the list. With observation unavailable, each opening fetches a fresh scan and sees preceding edits; learning of failure while already open refreshes once, keeps prior rows until completion and adds no watcher warning in Toolbox. A later working watcher resumes cached opening. The exceptional mocks make these failure exits deterministic; [the successful transport seam](#^templates-t-app-cache-seam) and [shared native watcher contract](../artifact-frame/reload-navigation.md#^rn-ac-shared-watcher-native) own their forfeited mechanisms. *(policy-grade tests: `packages/web/test/e2e/template-cache.test.ts`, “retries initial load and refreshes on watcher failure without clearing prior rows or looping (^templates-ac-cache-fallback)”)* ^templates-ac-cache-fallback

## Creation

- **Contract** (request/data validator at the creation boundary; authored requests, schemas and store values, no mocks): under [runtime validation](../../../specs/arch/templates/index.md#^artifact-template-request-validation), [preflight](../../../specs/arch/templates/index.md#^artifact-template-preflight) and [schemas](../../../specs/arch/templates/index.md#^artifact-template-schema), reject malformed fields including nonboolean `copy`; distinguish omitted data from null. URL templates reject the presence of either data or copy, even null/false. Folder data meets store limits and schema before side effects. Local references and validation vocabulary work; format/content annotations do not reject, defaults do not seed, and values are neither coerced nor stripped. Required-field errors name the missing field and `show` command. No-data creation remains allowed even by a schema requiring data. *(policy-grade tests: `packages/server/test/templates-schema.test.ts`, “validates %j without changing %j”; `packages/server/test/templates-create.test.ts`, “rejects malformed HTTP fields before it creates files, records, or stores”, “validates caller data against the fresh schema before effects and leaves later resource writes unrestricted”, and “creates an ordinary URL record and rejects even null data or false copy before effects”)* ^templates-t-preflight

Live telemetry delivery is forfeited to the sink proof. *(policy-grade test: `packages/server/test/templates-create.test.ts`, “rejects malformed HTTP fields before it creates files, records, or stores”)* ^templates-t-request-validation
- **Seam** (creation route → preflight over real HTTP and filesystem; schema-invalid caller data, unusable channel, conflicting placement and wrong-channel neighbor fixtures; no mocks): under [preflight](../../../specs/arch/templates/index.md#^artifact-template-preflight), failures return bad requests before a folder, record, page or store is created; omitted and explicit-null data take their distinct valid paths.
