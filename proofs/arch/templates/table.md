# Table artifact template — proof

Proves [specs/arch/templates/table.md](../../../specs/arch/templates/table.md).

## Coverage model

Package contracts read the real bundled files. Pure model contracts exercise the same reading, ordering, drawn-position and write-planning functions used by the copied page, with authored store values and no replacement SDK. They cover value and action variations without paying for a browser run for each one.

Browser seams create a copied Table artifact in a temporary serving home. The page loads the served resource SDK and writes to the real JSON store. Tests observe outgoing operations and read persisted results through the administrative API. A forwarding proxy may record an operation or hold a real transaction attempt while an agent command changes the store; it fabricates no request or response.

The [Table UI proof](../../ui/templates/table.md) owns pointer and keyboard interaction, selection, resizing, live editing, access changes, failures, recovery and rendered conformance. Its new-Table, resizing and live-editing walks cross the package and model contracts into the running page. [JSON store coverage](../resources/json-store.md) owns generated push keys, atomic updates, compare-and-set retry, last-write-wins ordering and durability; the seams below prove that Table uses those mechanisms with the stated paths and scope.

[Template architecture](./index.md) owns copying and creation from the seed. [Bundled installation](./bundled-installation.md) owns build membership and installed-copy replacement. [Bundled inventory](./bundled-templates.md) owns the ID, name, description and versions. README meaning also requires agent review; file checks alone cannot prove that the guidance teaches the contract correctly.

## Test hooks

The production Table model exposes pure reading, ordering and write-planning functions consumed by the page. Tests call those same exports; no test-only branch or replacement dependency is used.

Browser cases use the served SDK path and forwarding proxy declared in the [Table UI proof](../../ui/templates/table.md#test-hooks). The proxy may record or hold an ordinary SDK write or its acknowledgement, and may hold one compare-and-set attempt until an administrative write completes. Production forwards each message immediately. Held messages remain unchanged, so these controls change timing without replacing write, acknowledgement or transaction behavior.

- **Seam** (copied page → served canonical stylesheet, components, resource SDK and copied supporting files over real HTTP; no mocks beyond the standing CSS-motion override): Under [packaged page requirements](../../../specs/arch/templates/table.md#^bundled-artifact-template-table-page), a created Table loads each dependency and its copied local modules and stylesheet. Move the installed template out of discovery after creation, reload the copy, edit a cell and read the saved value: the copied artifact remains independent. CSS motion is forfeited, not delivery or saving. *(real-stack test: `packages/web/test/e2e/template-table-real-stack.test.ts`, “a new Table draws four by four without writing, then its independent copy edits”)* ^templates-table-t-assets
- **Contract** (real bundled folder → production template scanner; no mocks): Under [icon requirements](../../../specs/arch/templates/table.md#^bundled-artifact-template-table-page), the only icon entry is `icon.svg`, and the scanner selects that readable SVG for Toolbox. [Table UI review](../../ui/templates/table.md#^table-review-icon) covers how the icon looks. *(policy-grade test: `packages/server/test/table-template.test.ts`, “supplies its SVG icon to the Toolbox”)* ^templates-table-t-icon
- **Contract** (real bundled README; no mocks): Under [agent guidance](../../../specs/arch/templates/table.md#^bundled-artifact-template-table-readme), content checks keep the `headerRow`, `columns`, `rows`, `width`, `height` and `cells` guidance; opaque-key rules; size defaults and limits; empty-cell omission; display-position mapping; ordering; tolerant-reading warnings; and every required whole-table or path command present. Review confirms that the header row is row 1 rather than separate structure, and that agents keep its title row first when sorting, reordering or inserting. It also confirms that `cells` is an object; edited numbers and booleans become strings; insertion may renumber an axis; column deletion leaves row cells in place; examples use fresh random keys or `push`; and unreadable data is not repaired. The README says never to write a cell below a missing row or repair an entry without `order`; warns that people can edit the page concurrently and recommends path updates; says copied artifacts are independent; and points an adapting agent to the copied local modules and foundation-token stylesheet. ## Store contracts

- **Contract** (authored store values → production Table reader; transport absent, no mocks): Under [store ordering](../../../specs/arch/templates/table.md#store) and [runtime reading](../../../specs/arch/templates/table.md#runtime-reading), distinguish an absent root and absent or partial axes, which are readable, from explicit `null` roots or axes and other non-object roots or axes, which are unreadable. Drop malformed entries and entries without finite numeric orders; order the rest by numeric `order` and then JSON-store key order. Treat `headerRow` only as a boolean; ignore obsolete or extra fields. With `headerRow: true`, mark the first displayed row after filtering and ordering as the header row, including when that position is drawn. Read strings, numbers, booleans, empty values and absent-column cells as specified. Clamp positive finite widths and heights at the stated boundaries, and use the defaults for other saved values, without changing the input. Exercise missing and non-object `cells`, numeric-looking keys and equal orders. The [UI unreadable acceptance](../../ui/templates/table.md#^table-ac-unreadable) crosses the result into the running page. *(policy-grade test: `packages/server/test/table-model.test.ts`, “Table tolerant reading, stored sizes and order”)* ^templates-table-t-model
- **Contract** (authored readable axes and successive snapshots → production display model; transport absent, no mocks): Under [drawn-position identity](../../../specs/arch/templates/table.md#^bundled-artifact-template-table-drawn-identity), each axis consists of displayed stored entries followed by enough drawn positions to reach four. Drawn positions retain identity while the displayed stored count stays fixed, including after a cell, width, height or finite-order change; changing that count invalidates the earlier identities. Include the accepted concurrent outcome where two writers store separate key sets for the same formerly drawn positions. The [selection contract](../../ui/templates/table.md#^table-t-selection-model) proves that a selection using an invalid identity clears, and [live acceptance](../../ui/templates/table.md#^table-ac-live) proves that the page suppresses its pending edit or resize. *(policy-grade test: `packages/server/test/table-model.test.ts`, “Table drawn axes”)* ^templates-table-t-drawn
- **Contract** (authored axes, selected keys and insertion sides → production order and transaction callbacks; transaction transport absent, no mocks): Under [ordering](../../../specs/arch/templates/table.md#store), ordinary insertion chooses a strict numeric position between or beyond neighbours. When no representable order exists, each callback reads its current axis, validates any selected contiguous keys, adds the needed entries, assigns consecutive orders from 0 to displayed stored entries, and preserves all other fields and ignored entries. Cover insert, add-at-end, cell commit and resize through a drawn position, including their pending `cells`, `width` or `height`; abort invalid input; and reinvoke after concurrent membership, order, size, cell and extra-field changes. [The transaction seam](#^templates-table-t-transaction) crosses the real compare-and-set retry. *(policy-grade tests: `packages/server/test/table-model.test.ts`, “Table ordering and renumbering” and the renumbering cases in “Table write planning”)* ^templates-table-t-order
- **Contract** (authored table snapshots and logical edit, resize or structure actions → production write planner; SDK absent, no mocks): Under [drawn storage](../../../specs/arch/templates/table.md#drawn-rows-and-columns) and [page writes](../../../specs/arch/templates/table.md#page-writes), distinguish plain operations, a retry-safe renumbering request with any deferred path operations, and no-write reasons. Plan only the specified cell, `headerRow`, `width`, `height`, row or column paths. Cover stored and drawn cell commits and resizes, including one-axis and rejected two-axis renumbering; header-row toggles, including a toggle with row 1 drawn that stores no row entry; add, insert, delete and multi-cell clear; whitespace-only empty text; numbers and booleans edited back as strings; unchanged and cancelled actions; exact text preservation; and the rule that a resize compares with the size shown when it began. A planned pointer resize beyond a limit commits the limit, while a keyboard resize already at a limit plans no write. Multi-path actions contain distinct paths in one update and never replace the root or an axis. *(policy-grade test: `packages/server/test/table-model.test.ts`, “Table write planning”)* ^templates-table-t-write-plan

## Store crossings

These seams use a copied page, real browser input, the served SDK and the real store. Store values and agent commands are fixtures. No mechanism is mocked beyond the standard CSS-motion override, which forfeits motion.

- **Seam** (page action handlers → resource SDK operations → persisted JSON paths): Under [page writes](../../../specs/arch/templates/table.md#page-writes), edit and clear ordinary and header-row cells; set `headerRow` explicitly; resize stored and drawn rows and columns by pointer and keyboard; add, insert and delete entries; and clear selected rows and columns. Observe operation paths and atomic update boundaries, then read the result. Generated keys are opaque and fresh. Unrelated entries and extra fields survive except where the spec removes a selected path or renumbering rewrites orders. Hold a cell or size write, delete its parent through an agent command, then release it: the recreated entry lacks `order`, is ignored and does not make the Table unreadable. *(test to be written: real-stack cases in `packages/web/test/e2e/template-table-real-stack.test.ts`, “stored values, header row and resizing write only their owned paths” and “late descendant writes stay ignored and renumbering retries before deferred writes”)* ^templates-table-t-write-scope
- **Seam** (page action → SDK transaction on one axis → real compare-and-set retry and persisted result): Under [renumbering](../../../specs/arch/templates/table.md#store), exhaust a numeric gap and begin an insert or drawn-cell commit. Hold the first real transaction attempt, make an agent write on that axis, then release it. Observe a retry from current data, preservation of the agent change and one atomic persisted result. Independently cross the same handoff with a resize through a drawn position and observe its committed size in the atomic result. Any ordinary writes on the other axis begin only after the transaction commits and never begin when it aborts. The proxy changes timing only. *(test to be written: real-stack case in `packages/web/test/e2e/template-table-real-stack.test.ts`, “late descendant writes stay ignored and renumbering retries before deferred writes”)* ^templates-table-t-transaction
- **Seam** (whole-store subscription → page write guard → real store): Under [runtime write suppression](../../../specs/arch/templates/table.md#runtime-reading), hold a renumbering transaction, make the other axis unreadable and release it. After the transaction reaches the store, repair the axis and wait for the grid. The recorded page writes contain only the axis transaction: the held-back edit or resize did not start. Repairing restores fresh actions without replay. Separately release a write already sent before invalidation and observe ordinary store ordering. [UI unreadable acceptance](../../ui/templates/table.md#^table-ac-unreadable) owns the alert and active-control response. *(test to be written: real-stack cases in `packages/web/test/e2e/template-table-real-stack.test.ts`, “late descendant writes stay ignored and renumbering retries before deferred writes” and “unreadable data closes active UI, guards actions and recovers without replay”)* ^templates-table-t-invalid-guard
