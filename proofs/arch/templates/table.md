# Table artifact template — proof

Proves [specs/arch/templates/table.md](../../../specs/arch/templates/table.md).

## Coverage model

Package contracts read the real bundled files. Pure model contracts exercise the same reading, ordering, drawn-position and write-planning functions used by the copied page, with authored store values and no replacement SDK. They cover input and action variations without paying for a browser run for each one.

Browser seams create a copied Table artifact in a temporary serving home. The page loads the served resource SDK and writes to the real JSON store. The tests observe outgoing operations and read persisted results through the administrative API. A forwarding proxy may record operations or hold a real transaction attempt while an agent command changes the store; no request or response is fabricated.

The [Table UI proof](../../ui/templates/table.md) owns pointer and keyboard interaction, selection, live editing, access changes, failures, recovery and rendered conformance. Its new-Table and live-editing walks cross the package and model contracts into the running page. [JSON store coverage](../resources/json-store.md) owns generated push keys, atomic updates, compare-and-set retry, last-write-wins ordering and durability; the seams below prove that Table uses those mechanisms with the stated paths and scope.

[Template architecture](./index.md) owns copying and creation from the seed. [Bundled installation](./bundled-installation.md) owns build membership and installed-copy replacement. [Bundled inventory](./bundled-templates.md) owns the ID, name, description and versions. README meaning also requires agent review; file checks alone cannot prove that the guidance teaches the contract correctly.

## Test hooks

The production Table model exposes pure reading, ordering and write-planning functions consumed by the page. Tests call those same exports; no test-only branch or replacement dependency is used.

Browser cases use the served SDK path and forwarding proxy declared in the [Table UI proof](../../ui/templates/table.md#test-hooks).

The shared forwarding proxy may record or hold an ordinary SDK write or its acknowledgement, and may hold one compare-and-set attempt until an administrative write completes. Production forwards each message immediately. Held messages remain unchanged, so the controls change timing without replacing write, acknowledgement or transaction behavior.

## Store contracts

- **Contract** (authored store values → production Table reader; transport absent, no mocks): Under [store ordering](../../../specs/arch/templates/table.md#store) and [runtime reading](../../../specs/arch/templates/table.md#runtime-reading), distinguish an absent root and absent or partial axes, which are readable, from explicit `null` roots or axes and other non-object roots or axes, which are unreadable. Drop malformed entries and entries without finite numeric orders; order the rest by numeric `order` and then JSON-store key order. Treat names, row cells, strings, number and boolean JSON text, empty values, absent-column cells, `showHeader` and extra fields exactly as specified without changing the input. Exercise missing and non-object `cells`, numeric-looking keys and equal orders. Include the accepted concurrent outcome where two writers created separate key sets and cells for the same formerly drawn positions: every valid entry remains readable and appears in stored order. The [UI unreadable acceptance](../../ui/templates/table.md#^table-ac-unreadable) crosses the result into the running page. *(policy-grade test: `packages/server/test/table-model.test.ts`, “Table tolerant reading and stored order”)* ^templates-table-t-model
- **Contract** (authored readable axes and successive snapshots → production display model; transport absent, no mocks): Under [drawn-position identity](../../../specs/arch/templates/table.md#^bundled-artifact-template-table-drawn-identity), each axis consists of displayed stored entries followed by enough drawn positions to reach four. Drawn positions retain identity while the displayed stored count stays fixed, including after cell, name or finite-order changes; changing that count invalidates the earlier positions and suppresses any pending write aimed at them. *(policy-grade test: `packages/server/test/table-model.test.ts`, “Table drawn axes”)* ^templates-table-t-drawn
- **Contract** (authored axes, selected keys and insertion sides → production order and transaction callbacks; transaction transport absent, no mocks): Under [ordering](../../../specs/arch/templates/table.md#store), ordinary insertion chooses a strict numeric position between or beyond neighbours. When an insert has no representable order, each transaction callback reads its current axis, verifies the selected contiguous keys, adds the needed entries, assigns consecutive orders from 0 to displayed stored entries, and preserves other fields and ignored entries. An invalid axis, missing selected key or split range aborts that insert without a proposed write. Reinvoke the callback after concurrent membership, order, cell, name and extra-field changes to prove it derives from current input. In one cheap table-driven, single-axis case, put the last displayed entry at `Number.MAX_VALUE` and exercise adding at the end and storing through a drawn position. For each action, the callback appends its needed entries after the current displayed entries and preserves other fields and ignored entries. [The transaction seam](#^templates-table-t-transaction) crosses the real compare-and-set retry. *(policy-grade test: `packages/server/test/table-model.test.ts`, “Table ordering and renumbering”)* ^templates-table-t-order
- **Contract** (authored table snapshots and logical edit or structure actions → production write planner; SDK absent, no mocks): Under [drawn storage](../../../specs/arch/templates/table.md#drawn-rows-and-columns) and [page writes](../../../specs/arch/templates/table.md#page-writes), plan only the specified cell, name, `showHeader`, row or column paths. Cover commits into every stored/drawn-axis combination, header naming, add, insert, delete and multi-cell clear. Drawn entries are stored only through the required position; inserting beside a multi-entry selection adds exactly one entry and omits later drawn positions; a stored row receives only its cell path. An empty or whitespace-only commit removes a stored cell or name path, while the same edit on a drawn position, an unchanged or cancelled edit, clearing a drawn position, and deleting an entirely drawn selection make no write. Editing a number or boolean stores the changed text as a string. Other changed text remains exact, including surrounding whitespace and line breaks. Multi-path actions contain distinct paths in one update and never replace the root or an axis. *(policy-grade test: `packages/server/test/table-model.test.ts`, “Table write planning”)* ^templates-table-t-write-plan

## Store crossings

These seams use a copied page, real browser input, the served SDK and the real store. Store values and agent commands are fixtures. No mechanism is mocked beyond the standard CSS-motion override, which forfeits motion.

- **Seam** (page action handlers → resource SDK operations → persisted JSON paths): Under [page writes](../../../specs/arch/templates/table.md#page-writes), edit and clear stored body and header cells, toggle the header, add and insert rows and columns, delete them, and clear selected rows and columns. Observe the operation paths and atomic update boundaries, then read the result. Generated keys are opaque, fresh after deletion and unrelated to column names. Unrelated entries and extra fields survive except where the spec explicitly removes a selected path or the renumbering transaction rewrites orders. Hold a cell or name write, delete its parent entry through an agent command, then release it: the recreated entry has no order, is ignored, and does not make the Table unreadable. The UI editing and structure assertions may carry the browser actions rather than duplicate them. *(test to be written)* ^templates-table-t-write-scope
- **Seam** (page insertion → SDK transaction on one axis → real compare-and-set retry and persisted result): Under [renumbering](../../../specs/arch/templates/table.md#store), exhaust a numeric gap, begin insertion, hold the first real transaction attempt, and make an agent write on that axis. Release it and observe retry from current data, preservation of the agent change and one atomic persisted result. The proxy changes timing only. The [UI save-failure acceptance](../../ui/templates/table.md#^table-ac-save-failure) crosses an aborted transaction into the page message. *(test to be written)* ^templates-table-t-transaction
- **Seam** (whole-store subscription → page write guard → real store): Under [runtime write suppression](../../../specs/arch/templates/table.md#runtime-reading), make the value unreadable while an edit or structure action is pending. Once the page receives that value, commit, clear, add and menu actions start no write. Repairing the value restores fresh actions without replaying the suppressed one. Separately release a write already sent before invalidation and observe ordinary store ordering. [UI unreadable acceptance](../../ui/templates/table.md#^table-ac-unreadable) owns the alert and editor response. *(test to be written)* ^templates-table-t-invalid-guard
