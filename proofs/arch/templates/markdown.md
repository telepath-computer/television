# Markdown artifact template — proof

Proves [specs/arch/templates/markdown.md](../../../specs/arch/templates/markdown.md).

## Coverage model

Package contracts read the actual bundled manifest, seed, page, icon, and README. The Markdown-view build contract reads its real output and establishes that the file editor and template adapter use one compiled editor implementation. Browser seams use a copied artifact, the served shared editor and resource SDK, a running server, and its real JSON store. They create the artifact through Toolbox, drive the editor through its public document surface, observe writes through the forwarding proxy, and make agent writes through the built CLI.

The [Markdown editor UI proof](../../ui/markdown-editor/index.md) retains the colour and table-interaction assertions, and existing editor browser tests retain tables, gestures and the file-host binding. Their link cases run in the trusted file editor, so they do not prove the template's HTML-artifact link route; relative and application-link handling in the copied sandbox remains a gap for the next proof stage. This proof adds no duplicate UI stories or byte-for-byte stylesheet assertion. [Template architecture](./index.md) owns general copying and seed creation; [bundled installation](./bundled-installation.md) owns build membership and boot replacement; [resource SDK](../resources/sdk.md) and [JSON store](../resources/json-store.md) own transport, optimistic values, rollback and write ordering.

## Test hooks

Browser cases use the real store and the shared forwarding proxy used by the other template acceptances. The proxy records real subscription and write messages and can delay their unchanged delivery; it does not fabricate content or access. Template cases use DOM selection and keyboard input, not an editor-library handle. Editor-only browser tests expose `window.__cmView` only when `import.meta.env.DEV` is true and the hosted source page carries `data-television-markdown-test-hook`; the development Vite transform and the editor-integration fixture opt into that path. The production build and the template's shared v1 mount omit the hook.

- **Contract** (real source folder, manifest, and seed; no mocks): Under [the store contract](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-store), the manifest omits `display`, declares the specified schema, and its `data.json` parses to exactly `{"markdown":""}`. The source contains the page and first-party icon. [Inventory coverage](./bundled-templates.md#^templates-bundled-t-inventory) owns identity and versions. *(policy-grade test: `packages/server/test/markdown-template.test.ts`, “provides the page, exact store schema and exact blank seed using the shared display default”)*. ^templates-markdown-t-package
- **Contract** (real package and built Markdown view; no mocks): Under [the shared-asset contract](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-shared-asset), the page refers to `/views/markdown/v1/editor.js` and `.css`; the built view contains those files and a self-contained `index.html`; the template mounts in its `#editor` element. Loading the classic v1 script does nothing except add `window.TelevisionMarkdownEditor`, and its handle exposes no editor-library object or production test hook. Every selector in the v1 stylesheet is scoped below `#editor`, leaving page layout to the file view or copied template, while retaining canonical-v2 compatibility. The browser contract covers authoritative values, editable state, focus, disposal and callback termination. The v1 build verifies its emitted packages against the one `view:markdown` inventory without writing another inventory or notices file. Existing recursive view-copy assertions establish CLI delivery. *(policy-grade tests: `packages/server/test/markdown-template.test.ts`, “loads canonical and one versioned shared Markdown editor”; `packages/web/test/e2e/markdown-editor-integration.test.ts`, “the v1 files add only the editor API and editor-scoped styles” and “the v1 mount exposes only document controls and no production editor test hook”; `test/repo/licensing-generator.test.ts`, “verifies a secondary Vite build without writing over its surface inventory”; `test/node/cli-assets.test.ts`, Markdown view asset copy case; `packages/view-markdown` build and type-check)*. ^templates-markdown-t-shared-assets
- **Contract** (real bundled folder through production scanner; no mocks): Under [page requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-page), the manifest's only icon entry is the readable first-party `icon.svg`, and the scanner selects it for Toolbox. *(policy-grade test: `packages/server/test/markdown-template.test.ts`, “supplies its SVG icon to the Toolbox”)*. ^templates-markdown-t-icon
- **Contract** (real bundled README; no mocks): Under [adapting-agent guidance](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-readme), the README teaches the `markdown` field, blank seed, whitespace, extra fields, full-string saves, live changes, last-write-wins and offline limits; tells an agent to read again immediately before replacement; gives file-based replace and clear commands; warns that a replacement discards both saves made since that read and unsaved typing; retains the `#editor` adaptation boundary; and distinguishes independent copied page files from the compatible v1 editor Television serves. ## Store crossings

- **Seam** (Toolbox → copied page → shared editor and resource SDK → real store): Under [blank-start and binding requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-binding), a new Markdown artifact persists exactly `{"markdown":""}`, loads the copied page and versioned editor assets, presents a blank document, and writes nothing on opening. Typing Markdown produces one scoped write at `markdown` and persists the complete string. The copied artifact continues to work after its installed template is moved outside discovery. *(policy-grade test: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “new Markdown from Toolbox starts blank, then saves through the shared editor”)*. ^templates-markdown-t-blank-save
- **Seam** (CLI agent write → real store subscription → open shared editor): Under [live binding requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-binding), an agent command replacing `markdown` updates the open editor without a page reload and without producing a page write. An agent replacement before the person's save pause cancels that unsent save. A confirmed local save leaves the editor state in place while establishing the saved string as the rollback baseline, including when its acknowledgement is lost; an older confirmation also leaves a newer local edit pending. An SDK optimistic copy of a page write and an agent change to another root field leave an in-progress local draft alone. Later agent saves replace the complete text according to last-write-wins ordering, while the page's scoped save leaves extra root fields unchanged. *(policy-grade tests: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “agent writes update the open editor and local save echoes preserve the caret”, “an agent write to another field preserves in-progress typing”, and “a confirmed save survives a lost acknowledgement”; `packages/web/test/e2e/markdown-editor-integration.test.ts`, “an older save confirmation preserves a newer local edit”)*. ^templates-markdown-t-live
- **Seam** (real access and connection changes → page state → editor write guard): Under [access requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-access), read access and revocation retain the latest delivered document without permitting a write; changing the same share from read back to read-write resumes editing from the stored string; a disconnect discards an unsent draft and prevents new saves; reconnection resumes editing even when the value did not change; and another stored value received through the ordinary subscription replaces the document without replaying that draft. The code-authoritative status shell shows `Saving…` while a page write awaits confirmation. Missing, invalid and unavailable data discard unsent typing, prevent editing and recover without a repair write under [error requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-errors). A refused save restores the latest stored string unless a newer stored value arrived while the save was pending. *(policy-grade tests: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “read access blocks changes and a same-share upgrade resumes editing”, “access, connection and unreadable data keep the editor from writing and recover live”, “a pending page write shows its saving status until confirmation”, “damaged saved bytes recover after repair and restart”, and “a refused save restores the stored document and reports the failure”; `packages/web/test/e2e/markdown-editor-integration.test.ts`, “a matching authoritative value remains after its save promise rejects”)*. ^templates-markdown-t-states
