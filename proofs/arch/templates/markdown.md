# Markdown artifact template — proof

Proves [specs/arch/templates/markdown.md](../../../specs/arch/templates/markdown.md).

## Coverage model

Package contracts read the actual bundled manifest, seed, page, icon, and README. A source contract checks the shared implementation boundary, build seams inspect fresh Markdown-view output, and browser contracts load its public v1 files in Chromium. The browser fixture delegates `trustedTypes.createPolicy` through a recording wrapper before bundle load; it preserves the native result and behavior while forfeiting only the function's identity and ordinary call timing. The ordinary-document interface contract forfeits the artifact sandbox to the real-stack acceptances, which load the same built files in a copied page whose opaque origin and insecure context are checked before the editor is used.

The store acceptances run Chromium against a spawned production CLI server, its installed and copied Markdown package, the served shared editor and resource SDK, and a real JSON store. Authored initial store values are fixtures. A forwarding proxy carries the real protocol bytes and can record, delay, refuse, or sever their delivery; this replaces only uncontrolled network timing and failure, forfeiting natural transport failure while retaining the production SDK, server, messages, and persistence. The [resource SDK proof](../resources/sdk.md) carries direct browser-to-server transport. The default CSS-motion override forfeits only motion, which no assertion claims.

Link coverage composes across clean shared boundaries. The shared [link-classifier contract](../artifact-frame/artifact-bridge.md#^ab-ac-link-classifier) proves the target dispositions, while the Markdown editor's inherited link tests prove its gestures. The real-stack link acceptance crosses a relative-navigation message from the sandboxed copied page into the host. The same page's checked opaque origin composes with [the browser application-link acceptance](../../product/artifact-navigation.md#^ac-application-links-browser), which proves Chromium's repeated prompt for application links in sandboxed HTML artifacts. No test repeats operating-system protocol registration solely for this template.

The [Markdown editor UI proof](../../ui/markdown-editor/index.md) owns colour delivery and table interactions. Existing editor browser suites retain the shared implementation's tables, task lists, Markdown gestures, undo history, punctuation treatment, and file-host binding; the source/build contract below proves both adapters use that implementation. [Template architecture](./index.md) owns general copying and seed creation, and [bundled installation](./bundled-installation.md#^templates-install-t-copied-artifacts) owns copied artifacts surviving installed-template changes. [Resource SDK](../resources/sdk.md) and [JSON store](../resources/json-store.md) own transport, optimistic values, rollback, and write ordering. [Licensing](../licensing.md#^licensing-t-vite-seam) owns the v1 build's verification against the single `view:markdown` inventory, and [CLI architecture](../cli/index.md#^cli-build-markdown-view-copy) owns the complete view-directory copy into the CLI. The code-authoritative status shell's `Saving…` regression test is intentionally not a policy assertion here.

## Test hooks

The editor's source page exposes `window.__cmView` only when `import.meta.env.DEV` is true and the hosted page carries `data-television-markdown-test-hook`; the development Vite transform and editor fixtures opt into it. Production builds and the shared v1 mount omit the hook. The v1 browser fixture's delegated trusted-types recorder is the only wrapper used by its delivery and interface contracts. Real-stack cases use no editor-library hook and drive the public document surface.

## Store and browser acceptances

The declarations below use the real-browser, CLI-server, copied-package, store, proxy, fixtures, and motion conditions in the coverage model.

- **Acceptance** (outer boundary: Chromium creates the template from the real Toolbox and edits its sandboxed artifact frame): Under [the store contract](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-store), [blank-start and binding requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-binding), and [shared-asset contract](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-shared-asset), a new Markdown artifact persists exactly `{"markdown":""}`, subscribes at the store root, loads the copied page and v1 editor in its opaque-origin sandbox, presents a focused blank document, and writes nothing on opening. Typing Markdown persists one complete string at `markdown`; clearing persists `""` without removing the field. *(policy-grade test: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “new Markdown from Toolbox starts blank, then saves and clears through the shared editor”)*. ^templates-markdown-t-blank-save
- **Acceptance** (outer boundary: Chromium edits an open copied page while a spawned CLI and administrative client edit its real store): Under [the live binding requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-binding), an agent replacement updates the editor without reload or a page write; a replacement before the person's save pause cancels that unsent save; and later replacements obey last-write-wins. A confirmed page save leaves the caret and newer local typing in place; a confirmed save also survives a lost acknowledgement. An SDK optimistic copy and an agent change to another root field leave an in-progress draft alone. Page saves are scoped to `markdown` and preserve extra root fields. *(policy-grade tests: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “agent writes update the open editor and local save echoes preserve the caret”, “an agent write to another field preserves in-progress typing”, and “a confirmed save survives a lost acknowledgement”; plus the v1 confirmation cases under [#^templates-markdown-t-v1-interface](#^templates-markdown-t-v1-interface))*. ^templates-markdown-t-live
- **Acceptance** (outer boundary: Chromium observes and edits the copied page through real access, connection, saved-data, and page-lifecycle changes): Under [the binding rules](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-binding), [access rules](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-access), [error rules](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-errors), and [v1 meanings](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-shared-asset), read access and revocation retain the latest delivered document without permitting a write; the same share's return to read-write resumes editing from stored text. A disconnect discards an unsent draft and blocks saves; reconnecting resumes editing whether or not the value changed, and a changed value arrives through the subscription. Missing and invalid data use the common unreadable path, discard an unsent draft, block writes, make no repair, and recover from a later valid value; a process restart onto unavailable damaged bytes exercises that path and recovery without claiming a separate draft observation. A refused save restores the latest stored string unless a newer value arrived. Closing the page before its save pause discards the pending draft. *(policy-grade tests: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “read access blocks changes and a same-share upgrade resumes editing”, “access, connection and unreadable data keep the editor from writing and recover live”, “reconnection with unchanged data resumes editing”, “damaged saved bytes recover after repair and restart”, “a refused save restores the stored document and reports the failure”, and “closing the page discards typing before its save pause”; plus the refusal cases under [#^templates-markdown-t-v1-interface](#^templates-markdown-t-v1-interface))*. ^templates-markdown-t-states
- **Acceptance** (outer boundary: Chromium clicks a rendered link in the copied page's sandboxed editor, crossing the production bridge into artifact navigation): Under [the editor link requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-editor), a relative Markdown link resolves against the copied template folder and navigates that artifact frame there.
