# Markdown artifact template — proof

Proves [specs/arch/templates/markdown.md](../../../specs/arch/templates/markdown.md).

## Coverage model

Package contracts read the actual bundled manifest, seed, page, icon, and README. The Markdown-view build contract reads its real output and establishes that the file editor and template adapter use one compiled editor implementation. Browser seams use a copied artifact, the served shared editor and resource SDK, a running server, and its real JSON store. They create the artifact through Toolbox, drive the real CodeMirror editor, observe writes through the forwarding proxy, and make agent writes through the built CLI.

The [Markdown editor UI proof](../../ui/markdown-editor/index.md) retains the colour and table-interaction assertions, and existing editor browser tests retain tables, links, gestures and the file-host binding. This proof adds no duplicate UI stories or byte-for-byte stylesheet assertion. [Template architecture](./index.md) owns general copying and seed creation; [bundled installation](./bundled-installation.md) owns build membership and boot replacement; [resource SDK](../resources/sdk.md) and [JSON store](../resources/json-store.md) own transport, optimistic values, rollback and write ordering.

## Test hooks

Browser cases use the real store and the shared forwarding proxy used by the other template acceptances. The proxy records real subscription and write messages and can delay their unchanged delivery; it does not fabricate content or access. The editor exposes its existing test-only `EditorView` handle so a caret position can be observed precisely.

The source contains the page and first-party icon. [Inventory coverage](./bundled-templates.md#^templates-bundled-t-inventory) owns identity and versions. *(policy-grade test: `packages/server/test/markdown-template.test.ts`, “provides the page, exact store schema and exact blank seed using the shared display default”)*. ^templates-markdown-t-package
- **Contract** (real package and built Markdown view; no mocks): Under [the shared-asset contract](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-shared-asset), the page refers to `/views/markdown/v1/editor.js` and `.css`; the built view contains those files and a self-contained `index.html`; the shared script carries the store-neutral mount entry used by the page. Existing recursive view-copy assertions establish CLI delivery. *(policy-grade tests: `packages/server/test/markdown-template.test.ts`, “loads canonical and one versioned shared Markdown editor”; `test/node/cli-assets.test.ts`, Markdown view asset copy case)*. ^templates-markdown-t-shared-assets
- **Contract** (real bundled folder through production scanner; no mocks): Under [page requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-page), the manifest's only icon entry is the readable first-party `icon.svg`, and the scanner selects it for Toolbox. *(policy-grade test: `packages/server/test/markdown-template.test.ts`, “supplies its SVG icon to the Toolbox”)*. ^templates-markdown-t-icon
- **Contract** (real bundled README; no mocks): Under [adapting-agent guidance](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-readme), the README teaches the `markdown` field, blank seed, whitespace, extra fields, full-string saves, live changes, last-write-wins and offline limits; gives replace and clear commands; covers invalid data, the shared editor and independent copies. Review establishes its meaning while bounded checks retain the concrete commands. *(policy-grade test: `packages/server/test/markdown-template.test.ts`, “documents the shared Markdown, replacement rules, errors and shared editor”)*. ^templates-markdown-t-readme

## Store crossings

- **Seam** (Toolbox → copied page → shared editor and resource SDK → real store): Under [blank-start and binding requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-binding), a new Markdown artifact persists exactly `{"markdown":""}`, loads the copied page and versioned editor assets, presents an empty focused CodeMirror editor, and writes nothing on opening. Typing Markdown including a link produces one scoped write at `markdown` and persists the complete string. The copied artifact continues to work after its installed template is moved outside discovery. *(policy-grade test: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “new Markdown from Toolbox starts blank and focused, then saves through the shared editor”)*. ^templates-markdown-t-blank-save
- **Seam** (CLI agent write → real store subscription → open shared editor): Under [live binding requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-binding), an agent command replacing `markdown` updates the open editor without a page reload and without producing a page write. An agent replacement before the person's save pause cancels that unsent save. A local save echo leaves the caret at its current position; after that echo is complete, an agent can return the document to the same string and the editor still applies it. Later agent saves replace the complete text according to last-write-wins ordering, while the page's scoped save leaves an extra root field unchanged. *(policy-grade test: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “agent writes update the open editor and local save echoes preserve the caret”)*. ^templates-markdown-t-live
- **Seam** (real access and connection changes → page state → editor write guard): Under [access requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-access), loading keeps the editor hidden and read-only; read access and revocation retain the latest stored document in a read-only editor, including task checkboxes and table cells; a disconnect reports reconnection, discards an unsent draft and prevents new saves; and a restored current valid value re-enables editing without replaying that draft. Clearing an existing document remotely does not steal focus. Missing and invalid saved data use the alert and recover without a repair write; real unreadable saved bytes use the same alert and recover after repair and restart under [error requirements](../../../specs/arch/templates/markdown.md#^bundled-artifact-template-markdown-errors). A save refused by real access control rolls the editor back to the latest stored string, reports the failure and clears the message after its interval. *(policy-grade tests: `packages/web/test/e2e/template-markdown-real-stack.test.ts`, “read access blocks task, table and document changes”, “access, connection and unreadable data keep the editor from writing and recover live”, “damaged saved bytes recover after repair and restart”, and “a refused save restores the stored document and reports the failure”)*. ^templates-markdown-t-states
