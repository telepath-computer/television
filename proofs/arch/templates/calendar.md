# Calendar artifact template — proof

Proves [specs/arch/templates/calendar.md](../../../specs/arch/templates/calendar.md).

## Coverage model

The package checks read the real Calendar source: its manifest, empty starting store, README guidance, linked stylesheets, and icon. The [Calendar UI proof](../../ui/templates/calendar.md#^calendar-ac-conformance) holds the page's appearance to the [Calendar UI spec](../../../specs/ui/templates/calendar.mdx) stories by conformance. A browser opens a Calendar artifact against a running server and real store, and a spawned `tv resource json` write adds an event to the open page. The no-write check records every message the page's resource SDK sends over its WebSocket, and every request other than GET, while the page opens, shows events, follows an agent write and reloads. The dependency check runs on a server of its own, because it moves the installed template out of discovery; it reads the served responses for the page's shared and copied files, then reloads the copy. The [Calendar UI proof](../../ui/templates/calendar.md) covers that page's layout, live updates, and the store contract's rules that invalid events are not shown and that a `startDate`, `days` or `visibleHours` that breaks the contract is treated as absent ([`visibleHours`](../../ui/templates/calendar.md#^calendar-ac-visible-hours-invalid)). The ordinary copy, seed, and default display rules are covered by [template architecture](./index.md) and [layout creation](../layout/index.md#^ly-ac-create-appends); build membership and minimum versions are covered by [bundled installation](./bundled-installation.md). Visual polish is judged in browser review.

No production test hook is needed.
