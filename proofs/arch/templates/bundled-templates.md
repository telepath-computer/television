# Bundled artifact templates — proof

Proves [specs/arch/templates/bundled-templates.md](../../../specs/arch/templates/bundled-templates.md).

## Coverage model

The package check reads the real Example source, including its manifest's absence of `display`. A browser opens an artifact created from it against a running server and real resource store, then an agent-style `tv resource json` write changes the visible text. This walks the Example page's main use without mocking its resource connection. The Calendar package check reads the real Calendar source: its manifest, empty starting store, README guidance, linked stylesheets, thumbnail size, and a byte comparison of its `styles.css` with the stylesheet of the [Calendar UI spec](../../../specs/ui/templates/calendar.mdx) stories. A browser opens a Calendar artifact against a running server and real store, and a spawned `tv resource json` write adds an event to the open page. The [Calendar UI proof](../../ui/templates/calendar/index.md) covers that page's layout, live updates, and the store contract's rule that invalid events are not shown. The ordinary copy, seed, and default display rules are covered by [template architecture](./index.md) and [layout creation](../layout/index.md#^ly-ac-create-appends); build membership and minimum versions are covered by [bundled installation](./bundled-installation.md). Visual polish is judged in browser review.

## Test hooks

No production test hook is needed.

- **Contract** (real bundled Example manifest on disk; no mocks or test hooks): Under [the bundled template spec](../../../specs/arch/templates/bundled-templates.md#bundled-artifact-template), the source manifest has no `display` property. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts` “declares the sole Example with its minimum version, manifest, starting data, and adapting guidance”)* ^templates-example-t-no-display
