# Bundled artifact template installation — proof

Proves [specs/arch/templates/bundled-installation.md](../../../specs/arch/templates/bundled-installation.md).

## Coverage model

Build evidence reads the real bundled source and package output. Validation failures use temporary source trees passed to the production validation command through its source-directory argument. Boot cases construct a serving store over temporary homes with authored installed folders and state files; they use the real validator and filesystem. A token-only construction shows that serving is the installation boundary. Socket entries in fixture folders obstruct backup or replacement copies through the real filesystem. A recording adapter delegates state writes to Node filesystem operations so the test can observe the temporary write and rename; a directory placed at the temporary path makes one write fail through the real filesystem.

The scanner and installed-folder validity live in [template architecture](./index.md). [The CLI architecture proof](../cli/index.md) proves that the built package path reaches the serving store. [Bundled content](./bundled-templates.md) covers the bundled pages and starting values. We do not test routine source-version increases as a new behavior: the minimum-version rule below covers whether an installed copy stays. The boot cases use the real two-ID inventory: when the Example folder fails backup or replacement, the same boot still installs and records Calendar. A future removal from the bundled set is not exercised; a former bundled folder would continue to appear through the ordinary scanner, which has no bundle membership filter.

## Test hooks

The bundled-template validation command accepts an optional source-directory argument for temporary fixture trees; the server build supplies the real `packages/server/assets/templates` directory. The argument changes only the input tree and forfeits no validation behavior.

The bundled-state writer accepts a filesystem-operations adapter for temporary-file write and rename. Production uses Node filesystem operations. A test adapter records the paths and delegates to those same operations; it may create a directory at the chosen temporary path just before delegating the write. This changes only the timing of that real filesystem obstruction and forfeits no filesystem behavior. Temporary source trees, installed folders, and state files are fixtures.

## Assertions

- **Contract** (temporary source trees → production bundled-template validation command; source-directory argument as declared above, no mocks): Under [the bundled package rule](../../../specs/arch/templates/bundled-installation.md#bundled-packages), an absent or extra folder, an invalid folder, and an Example manifest below its minimum version fail validation with a useful diagnostic; the exact valid two-template inventory passes. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-validate`)* ^templates-install-t-validate
- **Seam** (real source tree → production server build → packaged tree; no mocks): Under [the bundled package rule](../../../specs/arch/templates/bundled-installation.md#bundled-packages), the build runs bundled-template validation on the real bundled source and copies the complete tree, with matching relative paths and bytes, into `packages/server/dist/templates/`. *(policy-grade test: `test/node/cli-assets.test.ts`, cases tagged `^templates-install-t-build`)* ^templates-install-t-build
- **Contract** (state file → serving installer and recorded state-file operations delegated to the real filesystem): Under [the state contract](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-state), valid version-1 state keeps unique exact IDs in English-locale order. The operation record shows, for each handled ID, a write to a temporary file in the state directory followed by a rename from that file onto `bundled-templates.json`; a hard link to the former state retains its old bytes. Missing state means unhandled IDs; malformed, unsorted, duplicate, or unreadable state (the last posed as a directory at the state-file path) warns and leaves both template handling and state untouched for that boot, with no write or rename call. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-state`)* ^templates-install-t-state
- **Seam** (serving boot → installed folder and state file, real filesystem): Under [the specified behavior](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-replacement), an unhandled absent ID installs; a handled absent ID remains absent; a valid existing folder at or above the minimum remains byte-for-byte intact and becomes handled; an invalid or below-minimum occupant is replaced only after a hidden timestamped backup succeeds. A token-only construction installs nothing. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-boot`)* ^templates-install-t-boot
- **Seam** (failed backup or replacement → next serving boot, real filesystem): Under [backup and replacement failure](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-backup), an invalid installed folder containing a Unix-domain socket makes the real backup copy fail; a separate otherwise valid bundled source containing such a socket makes replacement copying fail after backup. Each boot warns and leaves a complete prior folder or complete replacement at the destination, records only the other bundled ID that it handled, and leaves the failed ID unrecorded. Removing the obstruction lets the next boot apply the rule. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-retry`)* ^templates-install-t-retry
- **Seam** (state-write failure → next serving boot, real filesystem): Under [the state and retry rules](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-state), start with valid state that has handled no ID. After boot installs the complete folders, each delegated write meets a directory created at its chosen temporary-file path and fails. The warning leaves the prior state file byte-identical and the complete bundled folders at their destinations. With the obstruction removed, the next boot keeps those valid folders and records both IDs through the observed temporary writes and renames. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-state-retry`)* ^templates-install-t-state-retry
