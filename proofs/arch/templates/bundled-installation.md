# Bundled artifact template installation — proof

Proves [specs/arch/templates/bundled-installation.md](../../../specs/arch/templates/bundled-installation.md).

## Coverage model

Build evidence reads the real bundled source and package output. Validation failures use temporary source trees passed to the production validation command through its source-directory argument. Boot cases construct a serving store over temporary homes with authored installed folders and state files; they use the real validator and filesystem. A token-only construction shows that serving is the installation boundary. Socket entries in fixture folders obstruct backup or replacement copies through the real filesystem. A recording adapter delegates state writes to Node filesystem operations so the test can observe the temporary write and rename; a directory placed at the temporary path makes one write fail through the real filesystem.

The scanner and installed-folder validity live in [template architecture](./index.md). [The CLI architecture proof](../cli/index.md) proves that the built package path reaches the serving store. [Bundled content](./bundled-templates.md) covers the Example page, schema and empty-store default. We do not test routine source-version increases as a new behavior: the minimum-version rule below covers whether an installed copy stays. A small installer-contract fixture may supply two bundled IDs to prove failure containment and removal from the bundled set; it does not change the shipped inventory, which remains covered by the real build.

## Test hooks

The bundled-template validation command accepts an optional source-directory argument for temporary fixture trees; the server build supplies the real `packages/server/assets/templates` directory. The argument changes only the input tree and forfeits no validation behavior.

The bundled-state writer accepts a filesystem-operations adapter for temporary-file write and rename. Production uses Node filesystem operations. A test adapter records the paths and delegates to those same operations; it may create a directory at the chosen temporary path just before delegating the write. This changes only the timing of that real filesystem obstruction and forfeits no filesystem behavior. Temporary source trees, installed folders, and state files are fixtures.

A warning recorder replaces `console.warn` in failure contracts; it forfeits process-stream formatting, which this proof does not claim. A contract may supply an authored bundled-ID/minimum list to the installation loop; production uses the shipped inventory. This planned affordance forfeits inventory wiring to the real build and boot seams, not installer behavior.

Replacement-order tests may observe filesystem/state operations while delegating them to Node, and obstruct the temporary state path just before a write. They may inject a stop after destination removal to pose an interruption; this mock forfeits operating-system process termination, while the subsequent boot and all saved files remain real. It does not prove power-loss durability.

## Assertions

- **Contract** (temporary source trees → production bundled-template validation command; source-directory argument as declared above, no mocks): Under [the bundled package rule](../../../specs/arch/templates/bundled-installation.md#bundled-packages), an absent or extra folder, an invalid folder, and an Example manifest below its minimum version fail validation with a useful diagnostic; the exact valid Example inventory passes. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-validate`)* ^templates-install-t-validate
- **Seam** (real source tree → production server build → packaged tree; no mocks): Under [the bundled package rule](../../../specs/arch/templates/bundled-installation.md#bundled-packages), the build runs bundled-template validation on the real Example source and copies the complete tree, with matching relative paths and bytes, into `packages/server/dist/templates/`. *(policy-grade test: `test/node/cli-assets.test.ts`, cases tagged `^templates-install-t-build`)* ^templates-install-t-build
- **Contract** (state file → serving installer and recorded state-file operations delegated to the real filesystem): Under [the state contract](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-state), valid version-1 state keeps unique exact IDs in English-locale order. The operation record shows a write to a temporary file in the state directory followed by a rename from that file onto `bundled-templates.json`; a hard link to the former state retains its old bytes. Missing state means unhandled IDs; malformed, unsorted, duplicate, or unreadable state (the last posed as a directory at the state-file path) warns and leaves both template handling and state untouched for that boot, with no write or rename call. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-state`)* ^templates-install-t-state
- **Seam** (serving boot → installed folder and state file, real filesystem): Under [the specified behavior](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-replacement), an unhandled absent ID installs; a handled absent ID remains absent; a valid existing folder at or above the minimum remains byte-for-byte intact and becomes handled; an invalid or below-minimum occupant is replaced only after a hidden timestamped backup succeeds. A token-only construction installs nothing. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-boot`)* ^templates-install-t-boot
- **Seam** (failed/interrupted replacement → real serving boot over the filesystem; prior installed folder, hidden backup and saved-state fixtures): under [replacement recovery](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-backup), an absent destination with its ID durably removed is reinstalled on the next boot and recorded as handled. A backup failure leaves the destination intact; a state-removal write failure also leaves it intact. Observe backup completion before durable state removal, destination removal afterward, and handled recording only after complete replacement. The declared stop/failure controls forfeit actual crash/disk-failure generation, not recovery. No assertion requires a complete destination during interruption. *(policy-grade tests: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-retry`)* ^templates-install-t-retry
- **Seam** (state-write failure → next serving boot, real filesystem): Under [the state and retry rules](../../../specs/arch/templates/bundled-installation.md#^bundled-artifact-template-state), start with valid state that has not handled `example`. After boot installs the complete folder, the delegated write meets a directory created at its chosen temporary-file path and fails. The warning leaves the prior state file byte-identical and the complete Example folder at its destination. With the obstruction removed, the next boot keeps that valid folder and records `example` through the observed temporary write and rename. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-state-retry`)* ^templates-install-t-state-retry

- **Contract** (installation loop at the shipped-inventory boundary; authored two-ID bundle list, real directories/state and a socket obstructing one backup, warning recorder): under [failure containment and bundle removal](../../../specs/arch/templates/bundled-installation.md#serving-boot), one failed ID warns while the other is handled; dropping an ID from the supplied list leaves its installed folder and contents available to the ordinary scanner. The inventory mock forfeits real membership to the build seam. *(policy-grade test: `packages/server/test/bundled-template-installation.test.ts`, case tagged `^templates-install-t-containment`)* ^templates-install-t-containment
- **Seam** (bundled replacement → existing linked artifact records/stores over real boot/filesystem; artifacts and stores established through production operations before making the installed template invalid/below minimum, no mocks): under [same-path replacement](../../../specs/arch/templates/bundled-installation.md#serving-boot), replacement retains the installed path and every linked artifact record/store byte while preserving prior content in its hidden backup. A valid edited folder at/above minimum survives even with a newer bundled source. Deleting a handled folder leaves it absent on reboot despite linked dependents; their records/stores remain. The [product linked walk](../../product/templates.md#^templates-ac-cli-create) owns visible breakage and restoration. *(policy-grade tests: `packages/server/test/bundled-template-installation.test.ts`, cases tagged `^templates-install-t-linked-records`)* ^templates-install-t-linked-records
