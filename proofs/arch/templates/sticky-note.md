# Sticky note artifact template — proof

Proves [specs/arch/templates/sticky-note.md](../../../specs/arch/templates/sticky-note.md).

## Coverage model

Package contracts read the actual bundled manifest, seed, stylesheet, font, thumbnail, and README. Store contracts exercise the validation and save decisions used by the copied page with authored values and event sequences. A controlled clock covers the exact 400 ms delay without a browser case for every timing variation; it does not prove browser timer delivery or SDK behavior.

Browser seams use a copied artifact, the served resource SDK, a running server, and its real JSON store. They observe operations through the shared forwarding proxy and read persisted results through the administrative API. Holding unchanged messages controls confirmation and disconnect timing without replacing authorization, rollback, or storage. These cases establish particular orderings, not every possible network schedule.

The [Sticky note UI proof](../../ui/templates/sticky-note/index.md) owns real input, save-on-pause and blur outcomes, concurrent viewers, access changes, offline drafts, failures, and recovery. Its [conformance assertion](../../ui/templates/sticky-note/index.md#^sticky-note-ui-ac-conformance) compares every story with the copied page after its font loads. The delivery seam below establishes that the independent copy loads its own assets. Thumbnail composition and README meaning also require review; file checks cannot establish either on their own.

[Template architecture](./index.md) owns general copying and seed creation; [bundled installation](./bundled-installation.md) owns build membership and boot replacement. [Resource SDK](../resources/sdk.md) and [JSON store](../resources/json-store.md) proofs own transport, rollback, write ordering, and durability. The assertions here establish how the page uses them, including retaining a draft outside the SDK. [Licensing](../licensing.md) owns inventory and generated notices. The Sticky note tests below are obligations to be implemented, not existing evidence.

## Test hooks

Pure contracts call the validation and save-decision logic used by the shipped page; a controlled clock advances its timer and a recorder observes proposed operations, while production uses browser timers and the resource SDK. This substitutes time and operation delivery at the contract boundary; the browser seams and UI acceptance supply real timer, SDK, and persistence coverage.

Browser cases use the served SDK and forwarding proxy declared in the [UI proof](../../ui/templates/sticky-note/index.md#test-hooks). The proxy may record whole-store reads, subscriptions, and writes and hold a real request or confirmation; production delivers those messages normally. It fabricates no request, reply, or access state.

## Store contracts

- **Contract** (authored values → production whole-value validator; transport absent, no mocks): Under [validity](../../../specs/arch/templates/sticky-note.md#^bundled-artifact-template-sticky-note-store), accept the seed, empty and whitespace-only strings, line breaks, and extra root fields without changing the input. Reject an absent value, null, arrays, scalar roots, missing `text`, and non-string `text`. [Invalid-data acceptance](../../ui/templates/sticky-note/index.md#^sticky-note-ui-ac-invalid) crosses the result into the real page. *(test to be written)*: `packages/server/test/sticky-note-model.test.ts`, “Sticky note whole-value validation”. ^templates-sticky-note-t-validity
- **Contract** (authored inputs, SDK events and controlled time → production save decisions; clock and operation recorder as declared above): Under [saving and concurrent changes](../../../specs/arch/templates/sticky-note.md#saving-and-concurrent-changes), every input restarts the 400 ms delay: no save before expiry, a save of the complete latest string at expiry, and an immediate save on leaving the field with an unsent change. Confirmation clears only the draft it acknowledges, preserving newer typing. Pending unsent text blocks replacement by incoming valid text; after sending, SDK values apply unless newer typing is unsent, and previously suppressed values are not replayed. An unchanged value requests no selection change. A non-`disconnected` rejection clears all retained typing, including newer unsent text, and uses the SDK rollback value, even when that value includes an uncertain write. These fixtures prove decisions, not SDK event generation; [the confirmation seam](#^templates-sticky-note-t-confirmation) and UI saving, concurrency and refusal walks cross the real path. *(test to be written)*: `packages/server/test/sticky-note-model.test.ts`, “Sticky note save timing and confirmation ownership”. ^templates-sticky-note-t-saving
- **Contract** (authored connection, access, data and timer events → production draft decisions; the same controlled clock and recorder): Under [offline retention and reconnect](../../../specs/arch/templates/sticky-note.md#saving-and-concurrent-changes), established write access and valid data permit offline typing, but no write call starts while disconnected. Keep only the latest draft, including an in-flight save rejected as `disconnected`, through rollback. Reconnection checks current access and gets the whole store before a draft can be sent. Valid writable data permits an immediate save if the pause or blur condition was already met; otherwise the normal input delay still applies. Incoming stored text does not replace the retained draft first. Without a draft, current stored text is displayed. Confirmed loss of access or unreadable data discards the draft and prevents its later replay; a disconnect before access/data were established permits no editing. Real reconnect and access delivery live in [the reconnect seam](#^templates-sticky-note-t-reconnect) and [UI acceptance](../../ui/templates/sticky-note/index.md#^sticky-note-ui-ac-offline). *(test to be written)*: `packages/server/test/sticky-note-model.test.ts`, “Sticky note offline draft and reconnect decisions”. ^templates-sticky-note-t-offline

## Store crossings

These seams drive real input on the copied page and read the real store. Fixtures include extra root fields, multiline strings, and missing or invalid values supplied through the administrative API. The standard CSS-motion override forfeits motion. Only the declared forwarding proxy controls message timing.

- **Seam** (whole-store subscription and page edit handlers → SDK → real store): Under [store access and write scope](../../../specs/arch/templates/sticky-note.md#store), observe subscription at the root, no writes on opening or displaying values, and `set` at `text` with the complete string on a save. Other root fields survive. Clearing writes `""`, never removes `text` or persists the hint. The UI creation, editing and agent-change walks carry these observations without repeating their input. *(test to be written)*: `packages/web/test/e2e/template-sticky-note-real-stack.test.ts`, “new Sticky note from the popover persists its seed, display, edits and independent assets”; “real editing preserves line breaks, spaces, copying and native undo”; “agent commands and two viewers preserve active typing and follow the latest stored write”. ^templates-sticky-note-t-write-scope
- **Seam** (real write confirmation → page draft retention → next SDK save): Under [confirmation ownership](../../../specs/arch/templates/sticky-note.md#saving-and-concurrent-changes), hold the confirmation of a sent save while the person types a newer string. Release the confirmation: newer text and its selection remain, and its subsequent pause or blur saves the newer complete value. Read the store to establish both writes. This tests actual SDK confirmation delivery, not a fabricated successful callback. *(test to be written)*: `packages/web/test/e2e/template-sticky-note-real-stack.test.ts`, “an older save confirmation leaves newer typing pending”. ^templates-sticky-note-t-confirmation
- **Seam** (real disconnect and reconnect → page access/root read → SDK write): Under [reconnection](../../../specs/arch/templates/sticky-note.md#saving-and-concurrent-changes), hold a sent write then sever the connection so it rejects as `disconnected`. The latest text stays visible through rollback. While offline, make a real remote edit; after reconnect, observe the page check access and read the whole store before saving its retained text. The old stored text never replaces the draft first. Cover a pause already completed offline and typing whose pause has not completed. With a real permission downgrade or invalid root while offline, reconnection starts no draft write; restoring valid writable data does not replay the discarded edit. The UI offline/access/invalid-data walks can carry these observations. The [store proof](../resources/json-store.md) retains the uncertain-outcome guarantee for a write the server received before disconnection; no test assumes such a write was cancelled. *(test to be written)*: `packages/web/test/e2e/template-sticky-note-real-stack.test.ts`, “offline typing survives rollback and saves after reconnect checks”; “reconnect discards a draft when access or readable data is lost”. ^templates-sticky-note-t-reconnect
- **Seam** (whole-value subscription → page write guard → real store): Under [invalid-data write suppression](../../../specs/arch/templates/sticky-note.md#store), invalidate the root while input is unsent. Once delivered, further input, blur, and expiry of its delay start no write. Repair through the API restores editing without replaying that draft. Separately, hold a write already sent before invalidation and release it afterwards: it follows ordinary last-write-wins ordering; the test does not require its cancellation. [UI invalid-data acceptance](../../ui/templates/sticky-note/index.md#^sticky-note-ui-ac-invalid) owns the alert and recovery. *(test to be written)*: `packages/web/test/e2e/template-sticky-note-real-stack.test.ts`, “unreadable data discards pending typing and recovers without reopening”; “invalid subscriptions prevent new writes while an already-sent write remains last-write-wins”. ^templates-sticky-note-t-invalid-guard
