# Map artifact template — proof

Proves [specs/arch/templates/map.md](../../../specs/arch/templates/map.md).

## Coverage model

Package contracts read the real Map source: its manifest, empty starting store, README guidance, canonical and local assets, vendored dependencies, and icon. README meaning also requires review; file checks cannot prove that the prose teaches an agent correctly. A pure contract drives the same media-value parser the page imports, covering the safe local-path and HTTPS breadth without making browser requests for every string. Browser acceptance opens a copied Map against a running server and real store. It covers creation, live values, local interaction, connection and access loss, unreadable data, and recovery without page writes.

The browser aborts requests to the configured Esri tile host, as the testing guidance requires. That mock forfeits the external service and rendered tile images, but leaves the copied page, Leaflet runtime, resource SDK, server, and store real. A forwarding proxy records messages and, in the disconnection case, refuses and severs the real browser connection without fabricating messages. The access-loss case adds a second resource-SDK listener inside the page to observe the real `no-store` result; it does not replace the Map listener or access control. Real share revocation produces that result. A real server restart over an authored damaged store file produces the other terminal error; another restart over the restored file exercises resubscription.

The ordinary copy and default-display rules are covered by [template architecture](./index.md) and [layout creation](../layout/index.md#^ly-ac-create-appends); build membership and minimum versions are covered by [bundled installation](./bundled-installation.md). The [licensing architecture proof](../licensing.md#^licensing-t-map-assets) covers the vendored records and generated folder notice, and [product licensing acceptance](../../product/licensing.md#^licensing-ac-map-assets) covers the packed assets and notices. This proof covers what the store means and what the page shows, omits, falls back to, or reports. Presentation remains code-authoritative under the [Map authority boundary](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-ui-boundary), so it makes no appearance or conformance claim.

## Test hooks

No production test hook is needed. The forwarding proxy and Esri request interception are test-harness controls declared in the affected assertions below.

## Assertions

- **Contract** (real bundled Map source on disk; no mocks): Under [the Map store](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-store) and [packaged page](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-page), the manifest matches the [inventory](./bundled-templates.md#^templates-bundled-t-inventory), declares no `display`, and carries the exact specified schema; `data.json` is `{}`; the required page files and vendored libraries are present; the Lucide module exposes exactly the schema icon enum; the production automatic-category-colour sequence equals the schema colour enum; and the page loads the canonical stylesheet before `map.css`, loads its local Leaflet and Lucide files, loads the resource SDK, and names the configured Esri tile host. *(policy-grade test: `packages/server/test/map-template.test.ts`, “ships the exact Map package contract”)* ^templates-map-t-package
- **Contract** (real bundled README; no mocks): Under [README guidance](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-readme), content checks and guidance review establish that the README covers every store field, the empty seed, JSON-store key ordering, schema and later-read key rules, sorting and fallbacks, icon and colour names, safe photos and credits, viewer-local interaction, the external tile requirement, and live read-only behavior. It includes the short inline example, gives scoped `set` and `remove` examples, tells agents to choose schema-valid keys explicitly, explains why push IDs do not fit the starting-data schema, and explains that later places still appear under any key while badly keyed categories do not. *(policy-grade test: `packages/server/test/map-template.test.ts`, “documents Map data and scoped agent writes”; guidance reviewed against the Map store and command requirements)* ^templates-map-t-readme
- **Contract** (authored media strings → production Map media-value parser; browser and HTTP delivery absent, no mocks): Under [the photo and credit schema](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-store) and [later-value handling](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-later-values), accept HTTPS URLs without whitespace or control characters U+0000–U+001F and local photo paths with optional `./` and internal spaces. Reject HTTPS values with whitespace, control characters U+0000–U+001F, another scheme, or no address, and reject local paths with edge whitespace, an absolute root, empty or dot segments, a backslash, colon, percent escape, query, fragment, or control character U+0000–U+001F. This covers parser breadth; the live acceptance observes an accepted local photo and credit and an omitted unsafe photo and credit URL through the copied page. *(policy-grade test: `packages/server/test/map-template.test.ts`, “accepts only safe local photos and HTTPS media links”)* ^templates-map-t-media-values
- **Contract** (real bundled folder → production template scanner; no mocks): Under [the Map icon requirement](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-page), the manifest's only icon entry is `icon.svg`, its SVG view box is square, and the scanner selects it as a readable SVG for the Toolbox slot. *(policy-grade test: `packages/server/test/map-template.test.ts`, “supplies its square SVG icon to the Toolbox”)* ^templates-map-t-icon
- **Acceptance** (real browser → Toolbox → running server → copied Map and real JSON store; the bundled empty seed is the fixture; Esri requests are aborted locally, forfeiting the external service and rendered tile images): Under [the empty store](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-store) and [packaged page](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-page), Toolbox creates an empty Map with the shared display default. The copy loads the canonical stylesheet, local assets, and resource SDK, subscribes to its root store, makes no write, and remains usable after the installed template is moved outside discovery. *(policy-grade test: `packages/web/test/e2e/template-map-real-stack.test.ts`, “new Map from Toolbox has the empty seed, shared display and independent packaged assets”)* ^templates-map-ac-create
- **Acceptance** (real browser → running server → copied Map and real JSON store; authored valid and malformed later values plus real administrative and spawned-CLI writes; Esri requests are aborted with the same forfeit): Under [later-value handling](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-later-values), the open page applies the stored fields and their fallbacks, including JSON-store key order for tied places and automatic category colours. A valid explicit category colour between two automatic categories does not consume an automatic colour slot. The page treats unusable named values and non-object category or place maps as absent, ignores unnamed properties and badly keyed or nameless categories, accepts places under every store key, and omits places without usable coordinates. Filter, details, basemap, and sidebar choices make no store writes. Unrelated store changes preserve the basemap and sidebar choices, while later stored basemap and sidebar values override them. *(policy-grade test: `packages/web/test/e2e/template-map-real-stack.test.ts`, “live store values and tolerant later reads stay read-only”)* ^templates-map-ac-live
- **Acceptance** (real browser → forwarding proxy → running server and real JSON store; populated store fixture; the proxy refuses and severs the connection without fabricating messages, and real share revocation supplies `no-store`; Esri requests are aborted with the same forfeit): Under [runtime behavior](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-runtime), a normal disconnection keeps the last good map without an alert, and a later connection catches up. Revoking the active read share ends the listener with `no-store` and also keeps the last good map. Neither path makes a store write. *(policy-grade test: `packages/web/test/e2e/template-map-real-stack.test.ts`, “read-only access loss and disconnection retain the last map and reconnect live”)* ^templates-map-ac-connection
- **Acceptance** (real browser → running server and real JSON store; unreadable-root fixture plus real server restarts over authored damaged and restored store files; Esri requests are aborted with the same forfeit): Under [runtime behavior](../../../specs/arch/templates/map.md#^bundled-artifact-template-map-runtime), an unreadable root shows the unreadable-data state without repair, and a later readable root restores the map. A terminal SDK error other than `no-store` produces the same state; after the connection returns, the page starts a new subscription and recovers from the restored store. *(policy-grade test: `packages/web/test/e2e/template-map-real-stack.test.ts`, “unreadable roots and terminal errors recover without repair”)* ^templates-map-ac-recovery
