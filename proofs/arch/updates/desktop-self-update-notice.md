# Desktop self-update notice — proof

Proves [specs/arch/updates/desktop-self-update-notice.md](../../../specs/arch/updates/desktop-self-update-notice.md).

## Coverage model

The web client holds one desktop update state per page. It subscribes to the bridge's `onDesktopUpdateDownloaded` the first time the notice surface or the gate asks, keeps the reported version and asks the bridge to restart. A contract covers that state with a stand-in bridge. A second contract covers the shared notice controller with the same stand-in, as the spec's Testing section allows. It covers everything the Testing section lists: which clients get no notice; the notice presenting for a reported version, including one reported after the surface mounts; the server notice's precedence, dismissed or not; the desktop self-update notice presenting once the server notice stops applying; dismissal by equal version; the independence of the three dismissal keys; and a single restart call. The stand-in gives up real IPC, which the product acceptance crosses.

The body is a source constant with a `{version}` placeholder. A contract compares it with the authored `desktop_self_update_notice` copy and checks the placeholder's replacement. A real-browser seam renders the body through the standard markdown pipeline with a reported version in place, as the Testing section requires.

The real Electron path, from the runtime's report through the bridge to the notice and its restart request, is the product's [desktop self-update notice acceptance](../../product/update-notifications.md#^ac-desktop-self-update-notice). The gate's suppression of this notice is [the gate proof's precedence contract](./desktop-upgrade-gate.md#^t-gate-precedence). The notice's markup, restart button and closing controls are [the update-notification surface's](../../ui/app/update-notification/index.md).

## Test hooks

This module adds no test hook. Its tests hand the controller a desktop update state built on a stand-in bridge, the same configuration seam production uses, and an in-memory dismissal store.

## Assertions

- **Contract** (the page's desktop update state with a stand-in bridge that records subscriptions and restarts and reports authored versions; forfeits real IPC to [product acceptance](../../product/update-notifications.md#^ac-desktop-self-update-notice)): the state subscribes to `onDesktopUpdateDownloaded` once, on the first request, and only in Electron context with the operation present, so a browser or a bridge without the operation never reports a version. It keeps the latest non-empty reported version and notifies only when the version changes. Its restart calls `restartToInstallUpdate()` exactly once, marks the state restarting and does nothing before a version has been reported. This proves the bridge side of [when the notice applies](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-condition) and [the restart](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-restart) — *(covered by tests: `packages/web/test/desktop-update.test.ts` “the page's desktop update state (^desktop-self-update-notice-t-state)”)*. ^desktop-self-update-notice-t-state
- **Contract** (the production notice controller and view in a mocked DOM, with the desktop update state on a stand-in bridge, retained update state injected through the fake connection owner and an in-memory dismissal store, all greenlit; forfeits real relay to [update-channel.md#^t-relay-on-connect](./update-channel.md#^t-relay-on-connect), real IPC to product acceptance and native popover behavior to [the surface's closing contract](../../ui/app/update-notification/index.md#^un-ac-closing)): a browser, a flipped gate suppression switch, a bridge without the operation and a bridge that has reported nothing produce no desktop self-update notice and no bell. A reported version presents the notice with the bell, whether it arrives before or after the surface mounts. An applying server notice, dismissed or not, keeps the desktop self-update notice from presenting, and the bell presents the server notice. When the server notice stops applying, a desktop self-update notice that has not been dismissed presents in the same session. Dismissing writes the reported version under `tv-desktop-self-update-dismissed` and nothing else. An equal stored version suppresses automatic presentation while the bell remains and presents the notice again. A different stored version, including a higher one, presents it. Each of the three dismissal keys leaves the other notice kinds unaffected. When a recommendation would also apply, the desktop self-update notice is the one shown. The restart button calls `restartToInstallUpdate()` exactly once and leaves the notice open and restarting. Presenting, dismissing and restarting send no telemetry signal. This proves [when the notice applies](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-condition), [its evaluation](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-evaluation), [precedence](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-precedence) in [the shared order](../../../specs/product/update-notifications.md#^notice-precedence), [restart](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-restart), [dismissal](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-dismissal), [bell](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-bell) and [absence of telemetry](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-no-telemetry) — *(covered by tests: `packages/web/test/update-notification.test.ts` “desktop self-update notice presentation (^desktop-self-update-notice-t-presentation)”)*. ^desktop-self-update-notice-t-presentation
- **Contract** (the source constant and the authored content file read directly; no mocks): `DESKTOP_SELF_UPDATE_NOTICE_MARKDOWN` equals the authored [`desktop_self_update_notice`](../../../specs/ui/app/update-notification/content.yml#desktop_self_update_notice) copy, and the notice body replaces its `{version}` placeholder with the reported version. This proves the constant half of [the body](../../../specs/arch/updates/desktop-self-update-notice.md#^desktop-self-update-notice-render) — *(covered by test: `packages/web/test/desktop-update.test.ts` “conforms the notice body to its authored copy and fills in the version”)*. ^desktop-self-update-notice-t-body
- **Seam** (reported version → standard markdown pipeline → shared update-notification DOM, crossed in a real browser loaded with Electron-mode parameters; the fixture's stand-in bridge reports a version and is a declared mock that forfeits real IPC to product acceptance; popover and markdown behavior are real): the notice presents with the authored heading and the reported version in its sentence, the rendered body equals the pipeline's output for the filled-in constant, and its actions are Later and **Restart to update** — *(covered by test: `packages/web/test/e2e/update-notification.01.spec.ts` “desktop self-update notice rendering seam (^desktop-self-update-notice-t-render) > renders the downloaded version through markdown with Later and the restart button”)*. ^desktop-self-update-notice-t-render
