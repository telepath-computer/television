## Test hooks


Per [the domain's test-hook posture](./index.md#^updates-test-hooks):

- **`UpdateChannelPollerOptions.serverVersion` and `UpdateChannelPollerOptions.env`** — expose the production inputs that decide whether polling is enabled and which operational overrides apply. `Server` supplies the release version from `resolveUpdateReleaseVersion()`, and the poller defaults `env` to `process.env`; tests may supply both without replacing the gating decision.
- **`UpdateChannelPollerOptions.fetchImpl`** — substitutes the channel HTTP transport so contract coverage can exercise response and failure handling. Production uses global `fetch`; coverage using this hook does not cover real HTTP.
- **`UpdateChannelPollerOptions.setTimeoutImpl`, `UpdateChannelPollerOptions.clearTimeoutImpl`, `UpdateChannelPollerOptions.random`, and `UpdateChannelPollerOptions.nowSeconds`** — control the poll cadence, timeout, jitter, and cache-busting timestamp. Production uses global timers, `Math.random`, and epoch seconds from `Date.now()`; tests may control those inputs without replacing the polling loop or state adoption.
- **`PRODUCTION_POLL_INTERVAL_MS` and `POLL_JITTER_MAX_MS`** — expose the production timing thresholds that the poller itself uses, allowing contract coverage to check the same values without replacing them.
- **`UpdateChannelPollerOptions.onStateChange`** — reports adoption of the first or a different valid document. Production `Server` uses it to broadcast `server-status`; contract coverage may record the callback, which does not cover that websocket broadcast.
- **`TV_UPDATE_CHANNEL_URL`** — tests use [the operational override](../../../specs/arch/updates/update-channel.md#Server-side polling) to point the server at a locally served fixture `update-channel.json` they author; every channel-driven acceptance criterion (toast, bell, gate instructions, toast telemetry) presupposes it. An env var requires host control and the channel is first-party content, so this adds no security surface. ^hook-channel-url
- **`TV_UPDATE_CHANNEL_POLL_INTERVAL_MS`** — tests use [the interval override, which applies when the URL override is set](../../../specs/arch/updates/update-channel.md#^hook-poll-interval) to disable jitter and drive a state change in [the relay](../../../specs/arch/updates/update-channel.md#Relay to clients) mid-run — including the bell disappearing when an update stops applying — without waiting out the production cadence. An interval override is chosen over a force-repoll trigger because it needs no extra server surface (no test-only route) and the polling loop under test is the production loop.

## Assertions

### Test assertions

Shapes declared per [the declaration schema](../../../specs/arch/testing-policy.md#^declaration-schema). Versions named in `toast.markdown` and `desktop.upgradeMarkdown` are authored content, which the channel mechanism passes on unchanged: [product update acceptance](../../product/update-notifications.md#^ac-toast-release-label) proves that the real relay and renderer keep the announced release's exact version in authored details, and the gate's selected-markdown seam proves that desktop instructions render verbatim. Which desktop version the instructions name is the author's choice under [Operations](../../../specs/arch/updates/update-channel.md#Operations) and the [channel deployment runbook](../../../specs/arch/updates/runbook-channel-deploy.md): the required desktop version or the version of the desktop release that meets it, neither of which need equal the announced release. Deploying only after that desktop release is out and the release is on npm is a maintainer procedure that nothing checks ([release order](../../../specs/arch/updates/desktop-upgrade-gate.md#^ops-release-order)). Keeping the `desktop` block current ([^ops-author](../../../specs/arch/updates/update-channel.md#^ops-author)) and updating the master copy in the pull request that changes what it repeats ([^channel-master-copy](../../../specs/arch/updates/update-channel.md#^channel-master-copy)) are authoring rules that review enforces. None of these orders a test here, and no duplicate validator or formatter test is ordered.

The spine is owned by the product acceptance criteria: [product/update-notifications.md#^ac-toast-shows](../../product/update-notifications.md#^ac-toast-shows), [product/update-notifications.md#^ac-toast-not-newer](../../product/update-notifications.md#^ac-toast-not-newer), [product/update-notifications.md#^ac-toast-copy](../../product/update-notifications.md#^ac-toast-copy), [product/update-notifications.md#^ac-toast-dismiss](../../product/update-notifications.md#^ac-toast-dismiss), [product/update-notifications.md#^ac-bell-visible](../../product/update-notifications.md#^ac-bell-visible), [product/update-notifications.md#^ac-bell-refires](../../product/update-notifications.md#^ac-bell-refires), [product/update-notifications.md#^ac-toast-desktop](../../product/update-notifications.md#^ac-toast-desktop), [product/update-notifications.md#^ac-toast-silent-failure](../../product/update-notifications.md#^ac-toast-silent-failure), [product/update-notifications.md#^ac-toast-dev-host](../../product/update-notifications.md#^ac-toast-dev-host).

- **Contract** (the document validator; pure logic over test-authored documents): validation accepts the documented shape with and without each optional field and rejects missing or mistyped required fields and invalid release versions; unknown fields and a higher `schemaVersion` are read, not rejected. - **Contract** (the master copy, producer side of the published document; the server's production validator reads the file directly, so no copy of the validation rules can disagree with the fleet — forfeits publication and the HTTP fetch, which the [runbook](../../../specs/arch/updates/runbook-channel-deploy.md)'s byte comparison and [#^t-poll-fetch](#^t-poll-fetch) cover): the [master copy](../../../specs/arch/updates/update-channel.md#^channel-master-copy) parses as JSON, passes [shape validation](../../../specs/arch/updates/update-channel.md#^channel-validation), and has no field at any level that the validator does not read, shown by the validator's normalized result equaling the file, which needs no separate list of known fields; this honors the spec's testing directives — *covered by `test/repo/update-channel-master-copy.test.ts` “passes the server's shape validation and has no field the server does not read”*. ^updates-t-channel-master-copy
- **Contract** (poll schedule and request builder; fake scheduler, clock, and random source — greenlit, forfeiting real time to the HTTP seam below): polling starts at boot, follows the five-minute-plus-jitter cadence, honors a URL-scoped fast interval without jitter, and adds the cache-busting query and no-cache request header — *covered by all four cases under `packages/server/src/updates/update-channel.test.ts` “poll schedule and request shape”*. ^updates-t-poll-schedule
