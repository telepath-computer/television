## Test hooks


Per [the domain's test-hook posture](./index.md#^updates-test-hooks):

- **`resolveUpdateReleaseVersion(env, stamp)`** — exposes the two production version sources. Production defaults `env` to `process.env` and `stamp` to `readVersionStamp()`; tests may supply both to prove that a build stamp takes precedence and that the test override is consulted only without one.
- **`resolveBundleVersion(stamp)`** — exposes the web bundle's resolved build constant. Production defaults to the module's `__TV_VERSION__` value; tests may supply a stamp without claiming coverage of the Vite build boundary.
- **`UpdateReloadAgentOptions.owner`** — identifies the production connection event source. The web entrypoint supplies its `ServerConnectionOwner`; contract coverage may substitute it without claiming the real websocket crossing.
- **`UpdateReloadAgentOptions.bundleVersion`, `UpdateReloadAgentOptions.storage`, and `UpdateReloadAgentOptions.reload`** — expose the reload decision's local inputs and effects. Production defaults them to `resolveBundleVersion()`, browser `sessionStorage`, and `location.reload()`; tests may control them without claiming real browser storage or navigation.
- **`UpdateReloadAgentOptions.navigationLatch`** — supplies the page-wide navigation latch that makes the dying page inert. The web entrypoint passes the latch shared with the gate and boot pipeline, while standalone construction defaults to a private latch; tests may supply a controlled latch to prove that a pending navigation blocks later actions.
- **`TV_TEST_VERSION`** (server) — overrides the update-domain release version, consulted **exactly when the stamp is absent** (`__TV_VERSION__` undefined — that is, only when running from source, because `packages/cli/build.mjs` always defines it in a published build and the define short-circuits before any env read; without the hook an unstamped run resolves `0.0.0` per the stamp-only rule). Release builds are therefore inert to it by construction, with no runtime build-type check to maintain. ^hook-server-version
- **`TV_TEST_WEB_VERSION`** (web bundle, build-time) — when set in the environment of a `vite build`, the version define stamps this value instead of the workspace `package.json` version. Production publishing never sets it, so the default is the finalized workspace version; tests use it to control the stamp at the real build boundary. ^hook-web-version

## Assertions

### Test assertions

Shapes declared per [the declaration schema](../../../specs/arch/testing-policy.md#^declaration-schema); the end-to-end spine is owned by the product acceptance criteria: [product/update-notifications.md#^ac-reload-heals](../../product/update-notifications.md#^ac-reload-heals), [product/update-notifications.md#^ac-reload-fresh](../../product/update-notifications.md#^ac-reload-fresh), [product/update-notifications.md#^ac-reload-guard](../../product/update-notifications.md#^ac-reload-guard), [product/update-notifications.md#^ac-reload-dev](../../product/update-notifications.md#^ac-reload-dev).

- **Seam** (version source → `/health` payload, crossed over real HTTP against a running server): `GET /health` includes the server's release version — *covered by both cases under `packages/server/test/version-advertisement.test.ts` “GET /health version”*. ^t-version-surfaces
- **Seam** (global version middleware → HTTP response, crossed over real HTTP): every response carries `X-TV-Version` — *covered by `packages/server/test/version-advertisement.test.ts` “X-TV-Version response header”*. ^t-version-header
- **Seam** (connection establishment → `server-status` delivery, crossed over a real `/events` websocket): a new connection receives exactly one `server-status` with the server version as the **first message on the connection**, before any broadcast event ([#^events-version](../../../specs/arch/updates/version-advertisement.md#^events-version) — the ordering the boot barrier depends on), its update field reflecting current update state — *covered by both cases under `packages/server/test/version-advertisement.test.ts` “server-status on connect” and the status-message slice of `packages/server/test/events.test.ts` “sends exactly one server-status message on connect and replays no domain events”*. ^t-server-status-on-connect
- **Seam** (the build boundary: version input → stamped bundle, on real `vite build` output): a production build stamps the workspace version — or `TV_TEST_WEB_VERSION` when set ([#^hook-web-version](#^hook-web-version)) — into the bundle — *covered by the first two cases under `test/repo/build-config-integrity.test.ts` “web bundle version stamp”*. ^t-web-stamp
- **Contract** (consumer of the build define; the define's value substituted in unit tests — greenlit, forfeiting real-build coverage, which [#^t-web-stamp](#^t-web-stamp) carries): an absent or empty constant resolves the bundle version to `0.0.0`, while a stamp is returned unchanged — *covered by all four cases in `packages/web/test/update-version.test.ts`*. ^t-version-resolution
- **Seam** (the GUI web bundle's `express.static` mount → response headers, crossed over real HTTP): the GUI's entry document (`index.html`, and any other `.html` the bundle mount serves) carries `Cache-Control: no-cache`; the bundle's hashed assets may carry immutable caching. HTML served by other code paths (the artifact proxy, the `/views/*` mounts) is out of scope ([#^cache-headers](../../../specs/arch/updates/version-advertisement.md#^cache-headers)) — *covered by both cases under `packages/server/test/version-advertisement.test.ts` “GUI bundle cache headers”*. ^t-cache-headers
- **Contract** (the client's `/events` message routing; messages injected — greenlit): messages with an unrecognized or invalid `type` are ignored without throwing or disabling later known events, and a `server-status` message reaches its own handler rather than the domain-event path — *covered by the first three cases under `packages/web/test/server-connection.test.ts` “ServerConnection /events message routing”*. ^t-unknown-message
- **Contract** (consumer side of the `server-status` seam; messages and marker storage injected — greenlit, the real crossing owned by [#^t-reload-wiring](#^t-reload-wiring)): the reload decision, given bundle version, server version, and guard marker, reloads only on a true mismatch with no matching marker; `0.0.0` on either side never reloads; a matching marker never reloads; a new server version gets one attempt; and malformed stored markers read as absent. Permutation breadth lives here — *covered by the `reload decision` and `reload marker storage` groups in `packages/web/test/update-reload.test.ts`*. ^t-reload-decision
- **Seam** (`server-status` → reload decision, crossed in a real browser over a real websocket; two crossings, one per detection point — initial connect and reconnect): a mismatching message actually triggers the reload path at each detection point — *covered by both cases in `packages/web/test/e2e/update-reload.spec.ts`*. ^t-reload-wiring
- **Contract** (producer side of the telemetry client signal; the socket transport is not asserted here — that crossing is owned by [client-signals.md#^t-signal-forwarding](../telemetry/client-signals.md#^t-signal-forwarding)): on post-reload startup with a satisfied marker, the client clears it and signals `client_autoreloaded` exactly once with the marker's from/to versions as soon as the primary connection can carry it; a marker whose mismatch persists signals nothing — *covered by `packages/web/test/update-reload.test.ts` “satisfied marker: signals client_autoreloaded exactly once with the marker's versions and clears it”, “persisting mismatch: signals nothing, reloads nothing, and leaves the marker for the guard”, and “defers the autoreloaded signal until the connection is connected (server-status precedes bootstrap)”*. ^t-autoreload-signal
