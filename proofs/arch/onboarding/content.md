# Onboarding content & server packaging — proof

Proves [specs/arch/onboarding/content.md](../../../specs/arch/onboarding/content.md).

## Coverage model

Contract tests drive the real content-tree validator, runtime schema loader, and source resolver over temporary filesystem trees without mocks. Their authored fixtures cover schema and source-shape breadth; the CLI and installer proofs carry packaging, runtime installation, and failure-containment crossings.

A separate production-tree contract reads the committed onboarding package. It covers the configured shipped set, source resolution, focus channel, and the canonical v2 dependencies of the single-file welcome document. The [bake proof](bake.md#^t-baked-content) owns conversion from flat frames and Markdown into packaged content; this proof covers the committed package that ships, without comparing it to a fresh bake.

## Test hooks

The content validator, runtime config loader, and source resolver accept content roots as ordinary inputs. Fixtures use that public interface; no additional test hook is required.

## Assertions

### Test assertions

CLI packaging and runtime resolution are asserted by [arch/cli/index.md#^t-valid-tree-ships](../cli/index.md#^t-valid-tree-ships), [arch/cli/index.md#^cli-resolve-onboarding-success](../cli/index.md#^cli-resolve-onboarding-success), and [arch/cli/index.md#^t-resolution](../cli/index.md#^t-resolution). The product fresh-install assertion [onboarding-channels.md#^ac-fresh-install](../../product/onboarding/onboarding-channels.md#^ac-fresh-install) proves that each source shape from the actual packaged bundle reaches a running installation. This section owns source/config validation and production-tree integrity rather than duplicating those crossings.

- **Contract.** The real full content-tree validation entry point receives authored fixture trees over the real filesystem, with no mocks or test hooks. A fully valid version-3 tree with all three source shapes, several ordered artifacts, and optional page layout passes. Full-tree validation rejects an unparseable or schema-invalid config (including an earlier version, empty channels or artifacts, and blank names or titles), invalid or duplicate slugs, a missing channel folder, an unknown focus channel, a missing or ambiguous artifact source (all three source-shape pairs), a directory artifact without root `index.html`, and unreferenced content. The real runtime schema loader receives one-file temporary content roots whose config is copied from the valid fixture and has one artifact entry replaced; it rejects unknown artifact keys and every invalid shared size or geometry branch — *(policy-grade tests: `packages/server/test/onboarding-content.test.ts` "passes a fully valid fixture tree with artifact order and optional page layout", the generated "fails %s with a useful error" matrix, and the generated cases "rejects unknown artifact key", "rejects non-object size", "rejects unknown size key", "rejects missing size width", "rejects missing size height", "rejects non-numeric size axis", "rejects non-finite size axis", "rejects zero size axis", "rejects negative size axis", "rejects non-object geometry", "rejects unknown geometry key", "rejects unknown geometry kind", "rejects missing full-screen flag", and "rejects non-boolean full-screen flag"; `test/node/onboarding-packaging.test.ts` "Broken onboarding tree fails the real build validation step with a non-zero exit")*. ^t-validation-matrix
- **Contract.** On the runtime-config and artifact-source side of the installer handoff, the real schema loader accepts a schema-valid config when a source is missing or unreferenced on disk, still rejects schema and slug defects, and the real resolver distinguishes HTML files, markdown files, and indexed directories while rejecting missing, ambiguous, and unindexed sources. Fixture trees use the real filesystem; no mocks or test hooks are used. The installer crossing and failure containment are [installer.md#^t-per-channel-persistence](./installer.md#^t-per-channel-persistence) — *(policy-grade tests: all cases under `packages/server/test/onboarding-content.test.ts` "Runtime validation allows lazy source failures" and "Artifact source resolution")*. ^t-runtime-source-resolution
- **Contract.** The real production content tree passes full validation, its configured channel list equals the shared shipped-set pin, `tv-guide` is the focus channel, and every configured artifact resolves to a real source. No mocks are used — *(policy-grade tests: both cases under `packages/server/test/onboarding-content.test.ts` “production onboarding tree”)*. The welcome case requires `tv-guide/welcome.html` as a single-file HTML source, its `/canonical/v2/styles.css` and `/canonical/v2/components.js` dependencies, and custom-property references from the live canonical v2 public vocabulary. The inline logo retains the brand artwork allowed by the [UI design](../../../specs/ui/onboarding-artifacts/index.md#^respect-theme). This proves the [welcome-document contract](../../../specs/arch/onboarding/content.md#^welcome-document) without a separate sibling-image requirement — *(policy-grade test: `packages/server/test/onboarding-content.test.ts` “ships the tv-guide welcome channel and the pinned channel set”)*. ^t-production-tree
