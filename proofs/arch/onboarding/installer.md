## Assertions

### Test assertions

Unless an assertion states otherwise, everything below is **contract** shape ([testing-policy.md](../../../specs/arch/testing-policy.md)) on the store side of the serve → store bootstrap seam. Tests construct the real server store against a real filesystem and temporary storage; the CLI side is absent, not mocked. Product acceptance crosses that side for real. Fixtures are small version-3 onboarding trees — except where a source-invalid tree is named — and pre-seeded storage directories generated by real installer boots wherever possible and hand-authored only for crash and legacy states. The filesystem is never mocked. Assertions that require a warning replace `console.warn` with a recording function; that mock forfeits only Node's process-stream formatting, which no assertion claims.

- **Exactly-once per slug.** Two boots against the same storage install each configured channel once with slug-only markers and its artifacts' content at their copy names; the second boot creates nothing and modifies nothing. This proves [marked-slug skipping](../../../specs/arch/onboarding/installer.md#^marked-not-inspected) and [copy names](../../../specs/arch/onboarding/installer.md#^artifact-ids) — *(policy-grade tests: `packages/server/test/onboarding-installer.test.ts` "installs each configured channel once with slug-only markers and its artifacts' content at their copy names" and "a second boot against the same storage creates and modifies nothing")*. ^t-exactly-once
- **Initial page order and layout.** A bundle with several ordered artifacts installs one tab page per artifact in exactly that order, each carrying its installed artifact's ID and its configured-or-default `size` and `geometry` ([layout write](../../../specs/arch/onboarding/installer.md#^layout-write-unmarked)). The fixture includes size-only, full-screen-only, both-authored, and default entries — *(policy-grade test: `packages/server/test/onboarding-installer.test.ts` “Configured artifact order” / “installs each configured artifact as one configured-or-default page in authored order”, whose pages name the installed artifacts, in configured title order)*. ^t-layout-install
- **v1 migration.** A legacy sentinel with a v1 payload yields `onboarding.json` v3 with `tv-guide` marked and the original `installedAt` preserved — or migration time when the timestamp is unusable; the legacy file, artifact, content, and channel remain untouched — *(policy-grade tests: `packages/server/test/onboarding-installer.test.ts` "migrates a v1 sentinel to v3 with tv-guide marked and the timestamp preserved" and "uses migration time when the v1 timestamp is unusable", with the first minimally extended to seed and inspect the legacy artifact and channel)*. ^t-migrate-v1
- **Authoritative v2 field migration.** Shape **seam** on the state-file load → onboarding migration handoff, crossed through the real filesystem: an `onboarding.json` v2 fixture becomes v3 with only `version` and `screens`/`channels` changed; every slug, record, and timestamp is unchanged, no marked channel reinstalls, and a second boot changes no byte. A mixed-name fixture is rejected without a write — *(covered by inherited tests: `packages/server/test/onboarding-installer.test.ts` "migrates authoritative v2 screens to v3 channels and makes the second boot byte-stable" and "a mixed screens/channels onboarding.json is rejected without a write", with parser corroboration in `packages/server/test/onboarding-state.test.ts` "reports v2 state as a migration input")*. ^t-migrate-v2-field
- **Legacy v2 adoption.** A legacy sentinel holding a valid v2 payload produces `onboarding.json` v3 with its records unchanged; the legacy file remains byte-identical, and no marked channel reinstalls — *(covered by inherited tests: `packages/server/test/onboarding-installer.test.ts` "adopts a valid v2 payload held at the legacy path with records unchanged" and `packages/server/test/onboarding-state.test.ts` "reads a valid v2 payload held at the legacy path")*. ^t-migrate-legacy-v2
- **Legacy-artifact migration.** No state file at either path plus a stored `television-onboarding` artifact yields `onboarding.json` v3 with `tv-guide` marked and no duplicate or changed TV Guide content — *(policy-grade test: `packages/server/test/onboarding-installer.test.ts` "marks tv-guide when only the legacy artifact exists, without duplicating its content")*. ^t-migrate-artifact
- **Migration needs no bundle.** With a legacy v1 sentinel or authoritative v2 state and no content root supplied, the boot still writes `onboarding.json` v3 ([decoupled migration](../../../specs/arch/onboarding/installer.md#^migration-decoupled)) — *(policy-grade test: `packages/server/test/onboarding-installer.test.ts` "migrates without a bundle", minimally table-driven across v1 and authoritative v2 inputs)*. ^t-migrate-no-bundle
- **Crash retry converges without artifact recovery.** From marker-carrying, unmarked crash states holding none, some, or all of an interrupted attempt's artifacts, with a missing or partial page list, the next boot reuses the channel, creates every configured artifact again with a new generated ID, writes the complete configured artifact-order and configured-or-default page layout over those new artifacts, and marks the slug. The interrupted attempt's artifacts remain on the channel without pages, untouched: no duplicate channel or page appears, and duplicate artifacts are accepted ([no artifact recovery](../../../specs/arch/onboarding/installer.md#^artifact-ids)). One crash state holds an artifact with an earlier release's predictable ID for a slug that declares a store; the retry neither reuses it nor writes to any store for it, and the retry's own artifact's store holds the declared starting value — *(policy-grade tests: all five cases under `packages/server/test/onboarding-installer.test.ts` "Crash retry converges", among them "neither reuses nor writes to the store of an earlier release's predictable-ID artifact for a slug that declares a store", and the completion mark's order in `packages/server/test/onboarding-installer-state-write.test.ts` "attempts a slug's completion mark only after all artifact metadata and pages are persisted", whose retry writes its pages over generated IDs)*. ^t-crash-retry
- **Unmarked content is copied fresh.** A damaged occupant of an unmarked slug's copy-name destination is fully replaced on the next boot: truncated HTML and markdown files, a directory at a file destination, and a file at a directory destination. The marked complement belongs to [#^t-fire-forget](#^t-fire-forget). This proves [unmarked overwrite](../../../specs/arch/onboarding/installer.md#^copy-overwrite-unmarked) — *(policy-grade tests: all four cases under `packages/server/test/onboarding-installer.test.ts` "Unmarked content is copied fresh")*. ^t-overwrite-unmarked
- **Fire-and-forget.** For a marked slug whose channel, artifacts, pages, or copied files were deleted or modified, or whose artifact's store was changed or had its value removed, a boot recreates, repairs, rewrites, and overwrites nothing. This proves that [a marked slug is not inspected](../../../specs/arch/onboarding/installer.md#^marked-not-inspected), including its stores — *(policy-grade test: `packages/server/test/onboarding-installer.test.ts` "recreates, repairs, and overwrites nothing for marked slugs", minimally extended with an authored page-order edit, and "writes nothing to a marked slug's store that was changed or emptied" under "Fire-and-forget for declared stores")*. ^t-fire-forget
- **Generated artifact IDs.** Installing the same bundle into two fresh storage directories gives every installed artifact an ID in the generated form, different between the two installations and different from its copy name, while each artifact's content lives at its copy-name path ([generated artifact IDs and copy names](../../../specs/arch/onboarding/installer.md#^artifact-ids)) — *(policy-grade test: `packages/server/test/onboarding-installer.test.ts` "gives each installed artifact a generated ID, different across installations and from its copy name, with its content at the copy name")*. ^t-generated-ids
- **Declared stores.** A fixture bundle whose HTML artifact declares a store installs on a fresh boot with the declared starting value in that artifact's store, written as the store's first write: the artifact's record points to the store, whose manifest names the artifact. A declaration with `shiftDatesFrom` installs, on a boot whose local day Vitest's fake clock sets, a starting value whose calendar-date strings, at every depth and inside arrays, have moved by the whole days from that date to the boot's local day, across a month boundary, while a date-like string with a time, a string that is not a valid date, and every other value are unchanged. When the starting value cannot be written, because `<home>/resources/json` is a file where the store's directory must go, the channel still installs and is marked, the artifact's store has no value, and a warning naming the artifact is recorded. The occupied path is a real storage state, not a mock; the fake clock forfeits only reading the real clock. A write that fails after saving the starting value leaves the store with what was saved; the installer handles it as any failed write, and what the store then holds is [the JSON store's uncertain-write contract](../resources/json-store.md#^js-arch-t-uncertain), whose content step a first write shares. This proves [declared stores](../../../specs/arch/onboarding/installer.md#^onboarding-store-install) and [their shifted dates](../../../specs/arch/onboarding/installer.md#^onboarding-store-dates) — *(policy-grade tests: all three cases under `packages/server/test/onboarding-installer.test.ts` "Declared stores")*. ^t-onboarding-stores

**Marker contracts** are **contract** shape on the producer side of the marker wire surface. A really-running server and store are driven by real HTTP or websocket clients; the browser consumer is absent, not mocked. Temporary storage and an installer fixture bundle are the fixtures. No mocks or test hooks are used.

- **Marker in HTTP responses.** Channel list and get return installer-created channels with exactly `{ slug }`; ordinary channels carry no marker — *(policy-grade test: `packages/server/test/onboarding-marker-transport.test.ts` "returns installer-created markers from channel list and get; ordinary channels carry none")*. ^t-marker-roundtrip
- **Marker on channel events.** A `channel-updated` event for a marked channel carries exactly `{ slug }` over the real websocket; events for ordinary channels carry none — *(policy-grade test: `packages/server/test/onboarding-marker-transport.test.ts` "channel-updated for a marked channel carries the marker over the real websocket")*. ^t-marker-events
- **Marker is ignored on create.** A public channel-create request carrying `onboarding` succeeds and creates an unmarked channel — *(policy-grade test: `packages/server/test/onboarding-marker-transport.test.ts` "a create request carrying onboarding succeeds and creates an unmarked channel")*. ^t-marker-api-ro
- **Marker is ignored on update.** A public channel update carrying `onboarding` succeeds and leaves marker state unchanged for marked and unmarked channels, including attempts to alter or remove the slug — *(policy-grade test: `packages/server/test/onboarding-marker-transport.test.ts` "updates carrying onboarding succeed and leave marker state exactly as installed")*. ^t-marker-api-ro-update
- **Marker persistence.** Shape **contract** at channel-record persistence over the real filesystem, with routes absent: a slug-only marker survives raw JSON persistence, restart, and a user rename — *(policy-grade test: `packages/server/test/onboarding-marker-transport.test.ts` "survives raw channel JSON and a store restart")*. ^t-marker-persistence
- **Per-channel persistence and failure containment.** A schema-valid fixture whose later channel has a missing source marks only completed slugs; a failed channel does not block later channels or startup and converges on the next boot after its source appears. No mechanism is mocked — *(policy-grade tests: all three cases under `packages/server/test/onboarding-installer.test.ts` "Per-channel persistence and failure containment", minimally updated to version 3)*. ^t-per-channel-persistence
- **Transient mark-write failure.** Shape **contract** on the installer-loop side of the installer → state-writer seam. A one-shot failing writer double is a greenlit mock because real filesystem state cannot fail exactly one write; it forfeits real writer atomicity to [#^t-state-writer](#^t-state-writer). The real installer, store, and filesystem prove that a failed slug does not leak into a later successful write and converges on retry — *(policy-grade tests: both transient-failure cases in `packages/server/test/onboarding-installer-state-write.test.ts`)*. ^t-transient-state-write
- **Focus rule matrix.** Focus moves to the designated channel when the pre-install store has zero artifacts and zero channels, and when it has only empty channels including an earlier "Default"; focus is unchanged when content exists or the designated channel fails — *(policy-grade tests: all four cases under `packages/server/test/onboarding-installer.test.ts` "Focus rule matrix", plus the focus check in `packages/server/test/onboarding-installer-state-write.test.ts` "a failed mark write is not persisted by a later channel's successful write")*. ^t-focus-matrix
- **Invalid state file.** Unparseable, truncated, schema-invalid, and mixed-name authoritative or legacy state disables installation for that boot, records a warning, installs nothing, and leaves the file untouched — *(policy-grade tests: all five cases under `packages/server/test/onboarding-installer.test.ts` "Invalid state file" and the invalid parsing cases in `packages/server/test/onboarding-state.test.ts`)*. ^t-invalid-state
- **State-file writer.** Shape **contract** at the state-writer boundary over the real filesystem. Successful rewrites leave complete parseable v3 JSON, preserve the legacy file byte-for-byte, and leave no temporary file. A recoverable failure induced by occupying the real temp path surfaces and leaves the prior authoritative file intact. The unmockable instant between temp write and rename remains the explicit testing exception under [spec-policy.md](../../../specs/spec-policy.md), with [#^t-invalid-state](#^t-invalid-state) covering a torn downstream file — *(policy-grade tests: all four cases under `packages/server/test/onboarding-state.test.ts` "State-file writer")*. ^t-state-writer
- **Default-channel invariant.** A serving boot with no content root and zero channels creates one empty, unmarked "Default"; existing channels suppress another default, and deleting all installed channels yields "Default" on the next boot without reinstall — *(policy-grade tests: all three cases under `packages/server/test/onboarding-installer.test.ts` "Default-channel invariant")*. ^t-default-invariant
- **Token-only construction is inert.** A non-serving construction against an empty directory creates storage and a token but no channels, display state, onboarding state, or content; a serving boot immediately afterward treats the directory as no-content — *(policy-grade tests: both cases under `packages/server/test/onboarding-installer.test.ts` "Token-only construction is inert")*. ^t-token-only
- **No telemetry from install.** Shape **contract** on the store side of the store → telemetry-hooks seam. A recording hook double is greenlit and forfeits the real telemetry pipeline to [arch/telemetry/index.md](../../../specs/arch/telemetry/index.md). Attached at the production point after construction, it receives no channel, artifact, or layout CRUD call for installer-created entities and does receive the next ordinary user action — *(policy-grade test: `packages/server/test/onboarding-installer.test.ts` "produces zero CRUD hook invocations for installer-created entities")*. ^t-no-telemetry
- **`dataDirCreated` capture unchanged.** A boot that installs onboarding captures the same value as one without a bundle: true on a fresh directory and false on the next boot — *(policy-grade test: `packages/server/test/onboarding-installer.test.ts` "captures the same values with and without a bundle")*. ^t-datadir-capture
- **Relative storage path.** Shape **contract** at direct `ServerStore` construction, the only way a relative `storagePath` reaches the store: a store constructed with a relative `storagePath` beside a fixture bundle installs onboarding, persists absolute artifact paths, and writes onboarding state under the resolved absolute directory; no mocks or test hooks are used. The CLI resolves a relative `--home` before it constructs the store, and [the CLI's relative-home seam](../cli/index.md#^cli-relative-home-seam) crosses that path through a built process. This proves [absolute storage paths](../../../specs/arch/onboarding/installer.md#^storage-path-absolute) — *(covered by `packages/server/test/onboarding-installer.test.ts` "installs onboarding against a relative storage path")*. ^t-storage-path-absolute
- **Watchers start after install.** Shape **contract** at the store → content-watcher handoff. A recording watcher factory is a greenlit mock used only to observe start calls; it forfeits actual watcher behavior to the server's code-authoritative watcher suites. A serving install starts exactly one watcher per artifact after bootstrap, while token-only construction starts none even over existing artifacts — *(policy-grade tests: both cases under `packages/server/test/onboarding-installer.test.ts` "Watchers start last")*. ^t-watchers-last

Coverage relationship: [bootstrap-sequence](../../../specs/arch/onboarding/installer.md#^bootstrap-sequence) step 6 and its handoff into step 7's initial-theme decision are carried by [the bundled-theme initial-selection seam](../themes/bundled-installation.md#^bundled-t-initial-selection). That real serving-store and filesystem seam runs minimum-version handling before registry construction, then loads display state and applies the default-theme decision across fresh installation, sufficient existing content, below-minimum replacement, handled deletion, and handling-failure fixtures. This proof orders no duplicate assertion.
