*How the ToDesktop build's promises are proven: repository checks of the desktop workspace, its ToDesktop configuration, a generated upload directory, the build script's exit status and the real ToDesktop CLI's dry run, and the product's real-host checks for everything ToDesktop does.*

# ToDesktop build — proof

Proves [specs/arch/desktop/distribution.md](../../../specs/arch/desktop/distribution.md).

## Coverage model

Everything Television sends to ToDesktop is checked in the repository, with no call to ToDesktop's service. Contract tests read the desktop workspace manifest directly. They also run the real build script after a real desktop build, stopping before `todesktop build`, and inspect the upload directory it generates: its contents, the generated manifest and lockfile, the ToDesktop configuration it carries, and whether the bundled code needs any module the built app will lack. Two more contracts run the script through to the ToDesktop command, with that command replaced by a local stand-in. They show that the script waits on the build and exits nonzero when the command does, and that it passes on the option that makes an unsigned test build. The stand-in forfeits the real CLI, so one more contract runs the script's dry run with the workspace's real CLI. It shows that the CLI loads as the script runs it and that the upload directory passes every check the CLI makes before an upload. A dry run calls no ToDesktop service. [Licensing acceptance](../../product/licensing.md#^licensing-ac-desktop-upload) checks the license and notices files in the same directory.

The runtime's start is [desktop updates](./updates.md#^desktop-updates-t-start)'s. This proof covers only the runtime's place among the packages ToDesktop installs, in the workspace contract.

What ToDesktop does with the upload directory is carried by the product's real-host checks, the testing-policy exception the product spec declares. When the product spec calls for the [Mac install check](../../product/desktop-app.md#^desktop-ac-mac-install), it runs on an unreleased build of the candidate commit that the build script makes, as a candidate build or a test build, covering signing and notarization and the application name the configuration sets. No check starts the built app with `ELECTRON_RUN_AS_NODE` set, so the `runAsNode` fuse is covered only as a configuration value, by the [configuration contract](#^desktop-dist-t-config); that ToDesktop applies it when packaging is its documented behavior, which no test observes. The [license-file check](../../product/desktop-app.md#^desktop-ac-electron-license-files) reads the same build's Mac zip, and the [update check](../../product/desktop-app.md#^desktop-ac-updates) presses the restart in it with the runtime's simulated update. ToDesktop's smoke tests launch a build and update to and from it before it is released.

Some promises order no test, because they are settings or procedures outside the repository's code ([spec purposes](../../../specs/arch/testing-policy.md#^spec-purposes)): the build target and the **Allow releases without a security token** setting in the ToDesktop dashboard, the accounts and credentials under Setup, the commits a maintainer starts the two build workflows on, the version of the [first desktop release](../../../specs/arch/desktop/distribution.md#^desktop-dist-first-release), and candidate and test builds apart from the option the build script passes on for test builds. Review and first use check them. The download link is administrator-guide content, which [the guide's spec](../../../specs/arch/cli/admin-guide.md#Testing) leaves to review. Comparing the upload directory's release version with the CLI package's is [product versioning's acceptance](../../../specs/product/versioning.md#Testing), and the [runtime proof](./runtime.md) owns the workspace's Electron declaration.

The desktop workflows’ repository conditions and action pins are checked as parsed YAML contracts. These tests do not dispatch builds or prove GitHub authorization, and do not change the real-host coverage above. GitHub first evaluates each workflow’s changed configuration on its next dispatch after merge; a maintainer checks that run. SHA syntax tests do not establish that an action commit exists upstream. CI builds the local desktop bundle without supplying ToDesktop credentials; the upload tests consume that bundle, and the dry-run test clears those credentials before running the real ToDesktop CLI.

## Test hooks

The build script accepts an option that generates the upload directory at a path the test supplies and stops before running `todesktop build`. The build workflows and test builds run the script without it, so their runs always continue to the ToDesktop build.

The build script accepts an environment variable naming the command it runs in place of the ToDesktop CLI. A test sets it to a local stand-in; production leaves it unset, and the script runs the workspace's `@todesktop/cli`.

## Assertions

- **Contract** (the desktop workspace manifest read directly; no mocks or test hooks): `packages/desktop/package.json` sets `"private": true` and has no `bin`, `files` or `engines` field. Every entry in its `dependencies` is an exact version, and `@todesktop/runtime` is one of them. `@todesktop/cli` is a development dependency at an exact version. This proves [the desktop workspace](../../../specs/arch/desktop/distribution.md#The desktop workspace), the runtime's place among the packages ToDesktop installs ([updates](../../../specs/arch/desktop/distribution.md#^desktop-dist-updates)), and the build script's CLI dependency — *(covered by test: `test/repo/desktop-workspace.test.ts` “is private and declares the packages ToDesktop installs at exact versions”)*. ^desktop-dist-t-workspace
- **Contract** (the real build script, run with the upload-only hook after a real desktop build over the real repository; the temporary output directory is a fixture; no mocks): the upload directory contains `dist/`, `assets/`, `LICENSE`, `package.json`, `package-lock.json` and the ToDesktop configuration file, and nothing else; its `assets/` is byte-for-byte the workspace's, and so is its `dist/`, except that the workspace's `dist/electron.cjs` is `dist/electron.js` there. The generated `package.json` carries the workspace manifest's version, `main: "dist/electron.js"`, a nonempty `homepage`, an `author` with an email address, `dependencies` equal to the workspace's, `electron` under `devDependencies` at the [runtime version](../../../specs/arch/desktop/runtime.md#^desktop-runtime-version), and no `type` field. The generated `package-lock.json` is a lockfile for that manifest: its root entry lists the same `dependencies` and `devDependencies`. This proves [the upload directory](../../../specs/arch/desktop/distribution.md#^desktop-dist-upload) and that the build takes its version from the workspace manifest ([the build script](../../../specs/arch/desktop/distribution.md#The build script)) — *(covered by tests: `test/node/desktop-upload.test.ts` “holds the built app, the license, a generated manifest and lockfile, and the configuration” and “names an author with an email address, as ToDesktop requires”)*. ^desktop-dist-t-upload
- **Contract** (the ToDesktop configuration in that upload directory, read directly; no mocks): the configuration sets a nonempty `id`, `appId: "computer.telepath.television"`, `productName: "Television"`, `icon: "assets/icon.icns"` naming a file in the upload directory, `buildVersion` equal to the generated manifest's version, `nodeVersion` naming the Node version `.nvmrc` selects, `appBuilderLibVersion: "26.16.1"` and `fuses.runAsNode: false`. This proves [the configuration](../../../specs/arch/desktop/distribution.md#^desktop-dist-config) — *(covered by test: `test/node/desktop-upload.test.ts` “carries the ToDesktop configuration values that other specs rely on”)*. ^desktop-dist-t-config
- **Contract** (the files in that upload directory's `dist/`; no mocks): every module that code in `dist/` loads from outside `dist/` is a Node built-in module, `electron`, or a package the generated manifest lists in `dependencies`. The built app, which has only the packages ToDesktop installs, can therefore load everything the bundle needs, because [`dist/` bundles every workspace package the app uses](../../../specs/arch/desktop/distribution.md#^desktop-dist-upload) — *(covered by test: `test/node/desktop-upload.test.ts` “loads nothing from outside dist/ but Node built-ins, Electron and declared dependencies”)*. ^desktop-dist-t-bundle-imports
- **Contract** (the real build script, run after a real desktop build over the real repository; the ToDesktop CLI is a declared mock, a local stand-in named through the command hook that records its arguments and working directory and exits with a status the test chooses, forfeiting the real CLI's upload, build and log following to the product's real-host run): the script runs the stand-in as `todesktop build` from the upload directory, with the option that follows the build log until the build finishes, and exits nonzero when the stand-in exits nonzero. This proves that [the build script](../../../specs/arch/desktop/distribution.md#The build script) follows ToDesktop's build log and exits with a nonzero status when the build fails. That the real CLI exits nonzero for a failed build is ToDesktop's documented behavior, which no test observes — *(covered by test: `test/node/desktop-upload.test.ts` “runs todesktop build from the upload directory following the build log, and fails when it fails”)*. ^desktop-dist-t-build-exit
- **Contract** (the real build script, run after a real desktop build over the real repository; the ToDesktop CLI is the same declared mock as in the previous assertion, forfeiting what the real CLI does with the option): run with `--code-sign=false`, the script runs the stand-in as `todesktop build` with the option that follows the build log and then `--code-sign=false`. This proves that a developer can make [a test build](../../../specs/arch/desktop/distribution.md#The build script) without signing and notarization by passing that option to the build script. That the real CLI then skips signing and notarization is ToDesktop's documented behavior, which no test observes — *(covered by test: `test/node/desktop-upload.test.ts` “passes --code-sign=false to todesktop build for an unsigned test build”)*. ^desktop-dist-t-unsigned
- **Contract** (the real build script, run with `--dry-run` after a real desktop build over the real repository, running the workspace's real `@todesktop/cli` with no ToDesktop credentials in its environment or configuration; no mocks or test hooks): the script exits with status 0, and the CLI prints its dry-run report of the upload. This proves that the CLI loads as [the build script](../../../specs/arch/desktop/distribution.md#The build script) runs it, with its own React 17, and that the generated upload directory passes the checks ToDesktop's CLI makes before an upload. Those checks include the configuration's `schemaVersion` ([the configuration](../../../specs/arch/desktop/distribution.md#^desktop-dist-config)), the generated manifest's author email and a `.js` main file ([the upload directory](../../../specs/arch/desktop/distribution.md#^desktop-dist-upload)). That a dry run signs in to nothing and uploads nothing is ToDesktop's documented behavior, which no test observes — *(covered by test: `test/node/desktop-upload.test.ts` “passes the ToDesktop CLI's own checks in a dry run”)*. ^desktop-dist-t-dry-run
- **Contract** (both committed desktop workflow files parsed directly; no mocks or hooks): each build job has exactly the official-repository comparison at job level, so the condition applies before checkout and credential-bearing steps, and every external action is pinned to a full commit SHA. This proves the declared [workflow origin restriction](../../../specs/arch/desktop/distribution.md#^desktop-dist-workflow-origin); GitHub execution and company credential configuration remain outside this repository test — *(covered by tests: `test/repo/public-workflow-boundaries.test.ts` “restricts %s at job level to the official repository” and “pins external actions in %s to full commit SHAs”, for both desktop workflows)*. ^desktop-dist-t-workflow-origin
