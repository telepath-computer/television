*How the promises in Desktop appearance are proven across renderer composition, Electron IPC, and the real desktop application.*

# Desktop appearance — proof

Proves [specs/arch/desktop/appearance.md](../../../specs/arch/desktop/appearance.md).

## Coverage model

The IPC contract uses recording Electron mocks to cover validation and assignment breadth on both sides of the channel. Those mocks forfeit real IPC and native-theme behavior to the real Electron acceptance path.

A web-composition contract supplies confirmed display snapshots and events and records the optional native bridge. It proves the appearance-input rule, ordering before connected mount, changed-value delivery, disconnect retention, reconnect replacement, and browser/older-shell guards. The application and bridge boundaries are mocks: real display and event transport lives in [theme architecture](../themes/index.md#^themes-t-active-color-scheme-state), while real IPC and rendering live in the assertions on either side.

The real Electron/server/webview acceptance path proves that adaptive and fixed theme inputs reach `nativeTheme`, existing webviews, their root markers, and rendered styling. It also proves that a stored preference can change under a fixed theme without changing presentation and becomes effective after returning to an adaptive theme. The theming release blocks incompatible shells before connected rendering; that requirement is covered by [desktop upgrade acceptance](../../product/update-notifications.md#^ac-themes-desktop-required), not by weakening the defensive missing-operation test.

The local page keeps the last native appearance input and uses Clouds independently of the server theme. Its seam below observes native appearance and the local document together; [local asset delivery](./connect-flow.md#^desktop-t-local-assets) proves packaged resources. This extends lifecycle evidence without duplicating the existing webview/theme matrix.

## Test hooks

The local-page seam uses the [desktop harness hooks](./connect-flow.md#test-hooks). Its saved record is a fixture; appearance changes use the real server display API and existing native bridge, not a test-written renderer marker.

## Assertions

### Test assertions

- **Contract** (preload and main sides of the IPC boundary with Electron APIs replaced by recording mocks, forfeiting real IPC and native-theme behavior to the Electron assertion below): the shared predicate accepts exactly the three appearance inputs; preload sends each valid value and rejects unknown input; main starts at `system`, assigns each valid message, and ignores unknown input — *(covered by tests: `packages/desktop/test/connect-preload.test.ts` and `packages/desktop/test/main.test.ts` “starts native appearance at system and accepts only valid IPC values”)*. ^desktop-appearance-t-contract
- **Contract** (web composition with confirmed display snapshots and events as fixtures and the native bridge supplied as a recording boundary mock or as an older-shell fixture lacking the appearance operation; this forfeits real server transport to [theme architecture](../themes/index.md#^themes-t-active-color-scheme-state) and IPC to [the IPC contract](#^desktop-appearance-t-contract)): the null and adaptive schemes send the stored `system`, `light`, or `dark` preference, while fixed-light and fixed-dark schemes send their fixed value. Electron sends the initial appearance input before connected content mounts, sends only changed inputs after confirmed theme or preference events, retains the last input across disconnect, and replaces it from the next server's display state on reconnect. Browser mode never calls the bridge. When the bridge operation is absent, confirmed state still reaches the document and startup continues — *(covered by `packages/web/test/renderer.test.ts` “sends resolved Electron appearance before mount and only when effective input changes”, “keeps Electron startup running when the shell lacks the appearance bridge operation”, and “never calls the native appearance bridge in browser mode”)*. ^desktop-appearance-t-renderer
- **Acceptance** (outer boundary: the real Electron app at the [declared runtime version](../../../specs/arch/desktop/runtime.md#^desktop-runtime-version) connected to a really-running server with adaptive and fixed installed themes and media-query, `[data-theme]`, and computed-style probe artifacts; the harness fixture URL bypasses the saved-connection flow, and `TV_TEST_MODE=true` with the default shell-version override `9.9.9` substitutes version provenance. Those forfeits are covered by [gate acceptance](../../product/update-notifications.md#^ac-themes-desktop-required) and the [unhooked version seam](../updates/desktop-upgrade-gate.md#^t-shell-version-param); native appearance IPC, media queries, webview retention, and rendering remain real): main applies the initial appearance input before the first artifact webview attaches. Under the adaptive theme, `light`, `dark`, and `system` update `nativeTheme.themeSource`, the same loaded webview's media-query result, resolver-owned root marker, and exact computed probe color without replacing its document. Under the fixed theme, an opposing stored preference persists without changing those results; returning to the adaptive theme applies that latest preference — *(covered by `packages/desktop/test/e2e/webview-event-parity.test.ts` “applies manifest-resolved appearance to Electron and retained webviews”)*. ^desktop-appearance-t-electron

- **Seam — retained appearance to local page.** Cross real Electron `nativeTheme` into the packaged local renderer, using a running Television server, a saved connection fixture and the hooks above. Set the connected server's appearance through its production display API, disconnect through the menu, and observe that native appearance is retained while setup uses Clouds and its matching application root marker. Exercise light and dark retained inputs; also observe initial `system` against Electron's effective appearance. For a local page following system changes, a test may change `nativeTheme.themeSource` to generate real native-theme updates: this is a mock of the operating-system preference source, forfeiting that source to the real-Mac product checks, but it replaces neither Electron notification nor renderer adaptation. The local marker follows the new effective value without changing Clouds. This proves [appearance lifecycle](../../../specs/arch/desktop/appearance.md#^desktop-appearance-lifecycle) together with [the local-page rule](../../../specs/arch/desktop/connect-flow.md#^desktop-local-page). *(test to be written)* ^desktop-appearance-t-local
