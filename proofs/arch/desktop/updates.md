*How desktop updates are proven: main-process and preload contracts with Electron and the update runtime replaced by recording mocks, the real Electron app with the runtime in its simulation mode, and the desktop product's update check, which presses the restart in a candidate build on a real Mac.*

# Desktop updates — proof

Proves [specs/arch/desktop/updates.md](../../../specs/arch/desktop/updates.md).

## Coverage model

Two contracts cover each side of the update operations with recording mocks. The main-process contract replaces Electron and `@todesktop/runtime` with mocks, then checks four things: how the runtime starts, how the main process records a downloaded update, how it reports the update to the window, and how it handles a restart request. The preload contract replaces `contextBridge` and `ipcRenderer`. It pins the two operations' names on the native preload bridge, the argument each takes and the version string its callback receives. Renaming an operation or changing what it passes fails that contract, which is how the [frozen contract](../../../specs/arch/desktop/updates.md#^desktop-updates-frozen) is held. The mocks give up real IPC and the real runtime. The Electron path below covers both.

Real Electron coverage, as the spec's Testing section directs, launches the repository's desktop package with `--runtime-simulate-updates=update-available`. In that mode the real runtime reports a downloaded update a few seconds after launch, with the version `<app version>-simulated`, and needs no network or ToDesktop build. The version reaches the page loaded at launch, before the report, and a page loaded after it by a reload. A restart pressed after the report reaches the main process's restart. That path is the product's [desktop self-update notice acceptance](../../product/update-notifications.md#^ac-desktop-self-update-notice), and this proof cites it rather than repeating it.

As the spec's Testing section also directs, `TV_TEST_MODE=true` makes the main process record a restart request for the test instead of calling `restartAndInstall()`. On a real Mac, the desktop product's [update check](../../product/desktop-app.md#^desktop-ac-updates) presses **Restart to update** in a candidate build running the runtime's simulated update, which crosses the main process's real call into the runtime; the simulated restart quits the app and opens it again without installing anything. Installing a real update through electron-updater and Squirrel.Mac on that call is left to ToDesktop's smoke tests, which update to and from a build before it is released ([releases](../../../specs/arch/desktop/distribution.md#^desktop-dist-release)); no Television check observes it. The time between the request and the quit is not measured, as the spec says.

Some promises order no test ([spec purposes](../../../specs/arch/testing-policy.md#^spec-purposes)). The runtime's defaults (checking at launch and every ten minutes, downloading, installing on quit), its re-emitting `update-downloaded` after each check, and its making no network request outside a released build are ToDesktop's documented behavior. No Television test observes them.

## Test hooks

- **The restart log.** With `TV_TEST_MODE=true`, the main process appends the recorded version to `globalThis.__televisionRestartToInstallLog` instead of calling `restartAndInstall()`, and a test reads the log through Playwright's `ElectronApplication`. Production runs without `TV_TEST_MODE`, and the main process calls the runtime. This follows the external-open log the same variable already controls.
- **Extra launch arguments.** The [`e2e:desktop` harness](../../../specs/arch/desktop/e2e-harness.md#^desktop-e2e-launch-contract) lets a test append arguments to the Electron command line, which is how a test passes the runtime's simulation flag. The flag is the runtime's own; production launches carry no such argument.

## Assertions

- **Contract** (the production main-process module; Electron's `app` and `@todesktop/runtime` are declared mocks that record their calls, forfeiting what the runtime does to the Electron path and the [update check](../../product/desktop-app.md#^desktop-ac-updates)): loading the main process calls the runtime's `init()` exactly once, with `{ updateReadyAction: { showNotification: "never" } }` as its only argument, and the call directly follows `app.setName("Television")` with no other `app` call between them. This proves [the runtime's start](../../../specs/arch/desktop/updates.md#^desktop-updates-start) — *(covered by test: `packages/desktop/test/main.test.ts` “starts the update runtime once, with only its notification turned off, straight after naming the app”)*. ^desktop-updates-t-start
- **Contract** (the production main-process module with Electron, `BrowserWindow` and the runtime's `autoUpdater` as the same declared mocks, and `update-downloaded` events authored as fixtures; forfeits real IPC to the Electron path): before any event the recorded version is `null` and a restart request does not reach `restartAndInstall()`. An event records the version from its `updateInfo` and sends it to the window once. A repeat of the same version sends nothing. A different version replaces the record and is sent. An event without a version changes nothing. With a record, a restart request calls `restartAndInstall()` once; with `TV_TEST_MODE=true` it appends the version to the restart log and does not call the runtime. This proves [the downloaded update](../../../specs/arch/desktop/updates.md#^desktop-updates-record) and the main process's side of [the update operations](../../../specs/arch/desktop/updates.md#^desktop-updates-ops) — *(covered by tests: `packages/desktop/test/main.test.ts` “records the runtime's downloaded update, reports each new version to the window, and restarts only with a record” and “records a restart for the test instead of calling the runtime in test mode”)*. ^desktop-updates-t-record
- **Contract** (the production preload with `contextBridge` and `ipcRenderer` as declared recording mocks, forfeiting real IPC to the Electron path): the native preload bridge exposes `onDesktopUpdateDownloaded` and `restartToInstallUpdate`. A subscription calls its callback at once with the version the main process holds, and again for each different version the main process sends. It passes only non-empty strings, never repeats a version and reports nothing while there is no record. `restartToInstallUpdate()` sends the restart request with no payload. This proves the preload's side of [the update operations](../../../specs/arch/desktop/updates.md#^desktop-updates-ops) and pins the names and payload that [stay fixed across releases](../../../specs/arch/desktop/updates.md#^desktop-updates-frozen) — *(covered by tests: `packages/desktop/test/connect-preload.test.ts` “connect preload desktop update operations”)*. ^desktop-updates-t-preload
- **Acceptance** (the real Electron app with the real runtime in its simulation mode, connected to a really-running server; `TV_TEST_MODE=true` records the restart as declared above): the simulated version reaches the page loaded before the report and, after a reload, the page loaded after it, and a restart pressed after the report reaches the main process's restart — *(covered by the product's [desktop self-update notice acceptance](../../product/update-notifications.md#^ac-desktop-self-update-notice))*. ^desktop-updates-t-electron
- **Acceptance** (a candidate build on a real Mac, opened with the runtime's simulated update): pressing **Restart to update** reaches the runtime's restart through the main process's real call, and the app quits and opens again. The simulated restart installs nothing; installing through electron-updater and Squirrel.Mac is left to ToDesktop's smoke tests before a release. This proves the part of [restarting on a Mac](../../../specs/arch/desktop/updates.md#^desktop-updates-restart) that an unreleased build can show — *(manual: the desktop product's [update check](../../product/desktop-app.md#^desktop-ac-updates))*. ^desktop-updates-t-restart
