*How the Electron runtime's promises are proven: exact-version declarations, runtime validity over authored package and runtime trees, and a real cold installation on a Node release known to truncate one.*

# Electron runtime — proof

Proves [specs/arch/desktop/runtime.md](../../../specs/arch/desktop/runtime.md).

## Coverage model

Repository checks read the root and desktop workspace manifests, the lockfile and the installed `electron` package, and prove one exact Electron version with no extractor chain. The ToDesktop build's generated manifest carries the same version, which the [upload-directory contract](./distribution.md#^desktop-dist-t-upload) proves.

Runtime validity is proven at the contract tier. The runtime inspection that the e2e harness and preflight share classifies authored package and runtime trees, with the platform supplied as an input. Supplying the platform forfeits real host detection, which the [harness's runtime-setup seam](./e2e-harness.md#^desktop-t-e2e-runtime-handoff) crosses on the CI host; that seam also hands Playwright the executable path that validation builds. [Preflight's planner seam](../test-runner/preflight.md#^preflight-t-electron-planner-handoff) shows that classifying the real installed package leaves the runtime tree unchanged, so validation does not start an installation.

A real cold installation under the affected Node 26 release proves that Electron's installer leaves a runtime satisfying the validity predicate, which the extractor boundary protects. Global setup's use of the installer is crossed by the harness seam above, and Blaxel's repair path by [Blaxel shards](../test-runner/blaxel-testshards.md). A development run's installation through Electron's resolver, the browser build target, and the major-upgrade procedure order no test; the procedure's real-host step points to the [product's checks](../../product/desktop-app.md).

## Assertions

Shapes follow [testing-policy.md](../../../specs/arch/testing-policy.md).

- **Contract — declarations and installed tree** (repository manifests and lockfile read directly, plus the real installed package; no mocks): the root development dependency and the desktop workspace's development dependency both declare the [target version](../../../specs/arch/desktop/runtime.md#^desktop-runtime-version) without a range, the installed `electron` package and its lockfile entry have that version, and `yauzl` and `fd-slicer` are absent from the lockfile ([extractor boundary](../../../specs/arch/desktop/runtime.md#^desktop-runtime-extractor-boundary)) — *(covered by test: `test/repo/electron-runtime.test.ts` “keeps both development declarations and the installed package on one exact version”)*. ^desktop-t-runtime-declarations
- **Contract — runtime validity** (the shared runtime inspection over temporary package and runtime trees; the platform is supplied as an input, a declared mock that forfeits host detection to the [runtime-setup seam](./e2e-harness.md#^desktop-t-e2e-runtime-handoff)): a runtime with no `path.txt`, no `dist/version`, and no `dist/` or an empty one is [absent](../../../specs/arch/desktop/runtime.md#^desktop-runtime-absence). The exact [Linux layout](../../../specs/arch/desktop/runtime.md#^desktop-runtime-native-validity) and the exact [macOS layout](../../../specs/arch/desktop/runtime.md#^desktop-runtime-macos-validity) are valid and return the absolute executable path built from the package root. Each of these is invalid: a package or `dist/version` version other than the target, a `dist/version` or `path.txt` that is not a regular file, a `path.txt` whose content is not exactly the layout's relative path (including surrounding whitespace), a missing or non-executable executable, a macOS `Info.plist` whose `CFBundleExecutable` is not `Electron`, an empty macOS `Frameworks/` directory, and any other partial layout ([common predicate](../../../specs/arch/desktop/runtime.md#^desktop-runtime-common-validity)) — *(covered by tests: the “Electron runtime inspection” cases in `test/repo/electron-e2e-env.test.ts`)*. ^desktop-t-runtime-validity
- **Seam — cold runtime installation under Node 26** (the `e2e:node` surface, which discovers `test/node/`; real npm registry, the published `node@26.7.0` binary, the declared Electron package and installer, archive download, extraction, and temporary filesystem; no mocks): Node 26.7.0 is the Node 26 release directly confirmed to make Electron 35's installer exit `0` after silently truncating extraction. The test creates separate temporary tool and runtime prefixes, obtains that Node without changing the test process's own Node, installs Electron's JavaScript package with lifecycle scripts disabled, and spawns the obtained Node binary on that package's `install.js` with an empty case-local Electron archive cache. It first proves the spawned binary matches the pinned Node package version, then requires installer exit `0` and the resulting host-platform files to satisfy the exact [runtime validity predicate](../../../specs/arch/desktop/runtime.md#runtime-location-and-validation). It changes no repository runtime. — *(covered by test: `test/node/electron-installer.test.ts` “Electron installs a complete runtime under the affected Node 26 release”)*. ^desktop-t-node26-install
