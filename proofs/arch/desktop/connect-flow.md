# Desktop connection flow — proof

Proves [specs/arch/desktop/connect-flow.md](../../../specs/arch/desktop/connect-flow.md).

## Coverage model

The [desktop product proof](../../product/desktop-app.md#^desktop-ac-connect-link) carries the real-Electron walk from setup through a token-requiring Television server to its served page, honoring this spec's Testing directive. It also carries saved startup, the principal failure outcomes, and Disconnect from Server. This proof composes that evidence with cheaper contracts for parsing, persistence, retries and cancellation.

Main-process contracts replace Electron, the connect-check peer, and scheduling. They prove decisions and side effects, not real HTTP, IPC, rendering, or native menus. The product walks cross HTTP, IPC, disk and navigation, invoking installed menu callbacks; native Mac menu and accelerator input remain unobserved. The navigation-failure seam below covers Electron's actual failed-load event. Identity-response permutations and success-only save/navigation remain with the [connect-check proof](../updates/desktop-upgrade-gate.md#^updates-t-preflight-desktop-contract), rather than being repeated here.

The [setup proof](../../ui/setup/index.md) owns link entry, inline errors, Copy composition, and the Connected presentation. The [system-modal proof](../../ui/app/system-modal/index.md) owns dialog contents, non-dismissal, and dragging. Local assets cross the real desktop build and `file:` loader below; that does not prove visual conformance. The [appearance proof](./appearance.md#^desktop-appearance-t-local) crosses retained native appearance into the local page. Exact styling stays with its UI owners and active stylesheet-copy checks.

Under [the local bridge](../../../specs/arch/desktop/connect-flow.md#^desktop-connect-local-bridge), [product connection acceptance](../../product/desktop-app.md#^desktop-ac-connect-link) crosses the packaged local page's connect operation through real preload and IPC, then observes that the served page has neither connection control. [Local-button acceptance](../../product/desktop-app.md#^desktop-ac-saved-auth) crosses disconnect through the same local bridge. These walks also prove [server page entry](../../../specs/arch/desktop/connect-flow.md#^shell-page-entry); no separate bridge launch is needed.

## Test hooks

The desktop harness supplies an isolated Electron `userData` directory and may seed a saved `connection.json`; production uses the ordinary application data directory and the record saved by a successful connection. Seeding is a stored-data fixture, not evidence of the save path.

The [shell-version hook](../updates/desktop-upgrade-gate.md#^hook-shell-version) may represent a compatible shell in the Electron assertions; it forfeits the real version source to the [unhooked version seam](../updates/desktop-upgrade-gate.md#^t-shell-version-param). Tests enter through the packaged local page, not the harness's direct remote-URL shortcut.

## Assertions

- **Contract — entry and retries.** Exercise the production main-process connection owner with recording Electron/window and connect-check peers and a controlled scheduler. Authored fixtures are absent, valid, and malformed saved records and successful, `401`, and other failed check results. These mocks forfeit real startup, HTTP and timers to [saved-startup acceptance](../../product/desktop-app.md#^desktop-ac-saved-recovery). Under [local entry](../../../specs/arch/desktop/connect-flow.md#^desktop-connect-entry), no record selects setup; a valid saved record selects Connecting without selecting setup. A tokenless submission uses no token from an earlier input or saved connection. Failed setup submission returns its message to setup, including link-oriented missing/rejected-token guidance, without selecting a system modal. Saved `401` selects Access token required and schedules nothing further; other failures select Can't connect with server and retry with backoff, supplying a deadline between attempts and an in-flight state during a check. Later success navigates; later `401` stops. A gate-requiring but valid server identity still passes to the served page. Identity-body breadth remains with the connect-check owner. *(covered by `packages/desktop/test/connect-flow.test.ts` “starts without a record in setup and saves a checked link before the Connected handoff”, “keeps rejected setup links inline and a tokenless retry carries no previous token”, “starts saved records with Connecting then retries failures with backoff and stops on 401”, and “reconnects saved records automatically and treats malformed records as setup”)* ^desktop-t-connect-entry
- **Contract — link normalization.** At the link-reader boundary, authored HTTP, HTTPS, bare-host, host-and-port, path/query, encoded-token, tokenless, invalid and unsupported-scheme strings are fixtures; no mechanisms are mocked. Under [normalization](../../../specs/arch/desktop/connect-flow.md#^desktop-connect-normalization), the result is the normalized origin and the link's token, discarding path and other query parameters. A tokenless link yields no token. Invalid inputs fail. Real consumption is covered by [product connection acceptance](../../product/desktop-app.md#^desktop-ac-connect-link). *(covered by `packages/desktop/test/connect-url.test.ts` “reads one link as an HTTP origin and its decoded token”)* ^desktop-t-connect-link
- **Contract — stored records.** The storage owner runs with recording Electron data-directory and filesystem peers and authored records. The filesystem mock forfeits real disk operations to [product connection acceptance](../../product/desktop-app.md#^desktop-ac-connect-link). Under [persistence](../../../specs/arch/desktop/connect-flow.md#^desktop-connect-persistence), supported records round-trip with normalized `serverURL` and token, including an empty token; a missing or malformed record means no connection. *(covered by inherited tests: `packages/desktop/test/connection-store.test.ts`, all cases under “connection-store”; these use a filesystem mock, not a real temporary filesystem)* ^desktop-t-connect-storage
- **Contract — atomic save and deletion.** Exercise the production storage owner with recording filesystem and Electron data-directory peers. Under [persistence](../../../specs/arch/desktop/connect-flow.md#^desktop-connect-persistence), saving writes the complete record to a temporary sibling before renaming it over `connection.json`; deleting removes the saved record. Record operations, not just the final in-memory map. These mocks forfeit actual filesystem behavior to [product connection acceptance](../../product/desktop-app.md#^desktop-ac-connect-link). *(covered by `packages/desktop/test/connection-store.test.ts` “writes connection.json atomically via a temp file and deletes the record”)* ^desktop-t-store-writes
- **Contract — disconnect and pending work.** Exercise the production main process with recording Electron/menu, storage and check peers, a controlled scheduler, and deferred check/navigation-completion results. These mocks forfeit installed-menu wiring, real IPC, disk and navigation to [product acceptance](../../product/desktop-app.md#^desktop-ac-connect-link) and [local-button acceptance](../../product/desktop-app.md#^desktop-ac-saved-auth). Under [Disconnect from Server](../../../specs/arch/desktop/connect-flow.md#^desktop-disconnect-server), the application menu always contains that item with `CmdOrCtrl+,`, enabled exactly while a valid record is saved, including immediately after setup success and before remote navigation. Menu and local-button requests stop pending attempts and retries, delete the record, and select setup without confirmation. Completing a check or setup-success handoff after disconnect cannot save again or navigate; advancing a previously scheduled retry makes no request. Cover disconnect during a pending check and after success while navigation is pending, while local or served pages are displayed. The served gate uses the same main-process operation; its real crossing is [product-owned](../../product/desktop-app.md#^desktop-ac-gate-disconnect). *(covered by `packages/desktop/test/connect-flow.test.ts` “disconnect cancels pending checks, retries and a successful setup handoff” and “starts without a record in setup and saves a checked link before the Connected handoff”)* ^desktop-t-disconnect
- **Contract — load recovery.** The production main process receives failed-navigation event fixtures through a recording `BrowserWindow`, forfeiting native event delivery to the next seam. Under [load recovery](../../../specs/arch/desktop/connect-flow.md#^desktop-connect-load-recovery), a genuine top-level remote failure re-enters saved startup; aborted navigation, subframe failure, and local-page failure do not. *(covered by `packages/desktop/test/connect-flow.test.ts` “only a genuine top-level remote load failure re-enters saved startup”)* ^desktop-t-connect-load-recovery
- **Seam — failed remote navigation.** Cross Electron's real failed top-level HTTP load into the production recovery handler. A controlled HTTP peer passes the identity check and then breaks the page load; this peer mocks Television's response, forfeiting real server behavior to the [connect-check contracts](../updates/desktop-upgrade-gate.md#^updates-t-preflight-server-contract) and [product success](../../product/desktop-app.md#^desktop-ac-connect-link). Electron, local assets, preload, main process and native navigation events remain real; use the hooks above. Under [load recovery](../../../specs/arch/desktop/connect-flow.md#^desktop-connect-load-recovery), failure returns to the local page with the saved connection and its retry presentation, without setup or a setup-field error. *(covered by `packages/desktop/test/e2e/local-page.test.ts` “a real failed remote page load returns to saved-connection recovery”)* ^desktop-t-load-recovery-seam
- **Seam — packaged local assets.** Cross the real desktop build's packaged files into Electron's `file:` loader, with isolated user data and the version hook above; no builder, filesystem, asset-response or renderer mocks. Under [the local-page contract](../../../specs/arch/desktop/connect-flow.md#^desktop-local-page), setup and a saved-startup dialog run from the built package without a server stylesheet available. Their application-document marker, foundation, surface styles, icons, fonts, Clouds stylesheet and both referenced wallpapers resolve from packaged files. Observe actual resource loading and font readiness. The [foundation crossing](../ui/foundation.md#^ui-t-foundation-copy) owns byte equality; [local appearance](./appearance.md#^desktop-appearance-t-local) owns mode selection. *(covered by `packages/desktop/test/e2e/local-page.test.ts` “the built local page loads foundation, Clouds, fonts and icons for setup and saved dialogs”)* ^desktop-t-local-assets
