## Assertions

### Test assertions

Plain markers below are policy-grade to be written; inherited evidence is labeled separately. Shapes are declared per assertion ([arch/testing-policy.md#^declaration-schema](../../../specs/arch/testing-policy.md#^declaration-schema)). Fixtures are hand-authored only where the pre-migration or interrupted state cannot be produced by current code, and are reviewed against the shipping version-1 format. Across the server-side assertions, the filesystem is real throughout, the conflict seam's declared watcher recorder is the only mock, and no test hook is used. The browser acceptance declares its hooks and standing motion override inline.

- **Contract** (the layout-conversion routine, with the store absent): authored version-1 trees — a single card, a row, a stack, mixed nesting, numeric and `"auto"` sizes, and an empty layout — map to version-2 layouts with `layoutVersion: 2` and one default-geometry, one-artifact page per artifact in traversal order; any stored onboarding marker narrows to its slug, including on a version-2-layout intermediate record, while a version-2 record with no legacy marker returns unchanged — *(policy-grade tests: cases under `packages/server/src/redesign-record-migration.test.ts` “redesign record conversion” / “stored channel records”)*. ^ly-ac-migrate-contract
- **Acceptance.** Booting over a data directory holding a version-2 channel record whose pages lack `size` serves and persists every such page at the shared default size, leaves a page already carrying a size untouched, and a second boot changes nothing — *(policy-grade test: `packages/server/test/storage-name-migration.test.ts` “serves and persists missing page sizes, preserves authored sizes, and makes the second boot byte-stable”, with conversion corroboration in `packages/server/src/redesign-record-migration.test.ts` “backfills missing sizes without replacing pages that already carry one”)*. ^t-size-backfill
- **Seam** (serving-store boot through the final display migration operation over a real temporary data directory; no mocks or test hooks): an otherwise-valid current display record without `appearanceMode` gains `system` while preserving focus, pins, active theme, and sibling fields; a second boot leaves its bytes unchanged. A real same-directory replacement obstruction stops every boot while present without changing the authoritative input, and removing it lets the next boot converge. A present invalid mode bypasses migration and follows strict-loader initialization of the whole display record — *(covered by `packages/server/test/storage-name-migration.test.ts` “migrates appearance atomically, retries while blocked, and leaves completed bytes stable” and “leaves an invalid appearance mode to strict display initialization”)*. ^mig-t-appearance

### Test assertions: storage-name migration

These assertions own the shipped name step's routine breadth and refusal. Successful whole-boot output belongs to the one migration below, so the old name-only process walk is partial evidence rather than a second acceptance assertion.

- **Contract** (directory migrator with the store absent, over real temporary directories): all six cases above are covered — legacy-only empty and populated, current-only, populated legacy plus empty current, both non-empty conflict, empty legacy plus populated current, and both empty. Successful moves preserve the complete recursive entry set and every file byte; successful non-conflict cases leave no legacy directory; the conflict writes nothing; every successful result selects `state/channels/` for current writes — *(covered by inherited tests: all six cases under `packages/server/test/storage-name-migration.test.ts` “channel metadata directory contract”)*. ^rn-t-directory-contract
- **Contract** (display-field migrator with the store absent, over real files): legacy-only and equal-dual-key records become current-key records with the active value and every sibling unchanged; a current-only record is byte-stable; differing dual keys fail without changing the file. Failure before atomic replacement leaves the prior complete file, and retry converges to the same current bytes — *(covered by inherited tests: all five cases under `packages/server/test/storage-name-migration.test.ts` “display document contract”)*. ^rn-t-display-contract
- **Seam** (serving-store boot into the directory migrator, crossed through the real filesystem; a real onboarding bundle is supplied, and a recording watcher factory is a minimally added mock that observes start calls while forfeiting watcher behavior to the server's code-authoritative watcher suites): both non-empty metadata directories stop construction before token, display, onboarding, artifact-directory, or watcher work, and the conflict names both paths — *(covered by inherited test: `packages/server/test/storage-name-migration.test.ts` “stops a directory conflict before token, display, onboarding, or current-state writes”, minimally extended with that bundle and recorder)*. ^rn-t-server-boot-seam

### Test assertions: the one migration

These assertions prove the server buffer: boot invokes the single pass, resumes every ordered intermediate state, refuses to serve partial output, and crosses the complete upgrade spine.

- **Seam** (serving-store loading persisted records through the one migration, crossed through the real filesystem): authored intermediate directories cover current names with all old record shapes, a partial channel batch containing complete version-1 and version-2 records together, and completed channel conversion with the old display shape. Boot completes every remaining step; version-2 layouts preserve channel `id`, `name`, and each onboarding marker's slug while dropping `order`; display becomes `focusedChannelId` plus an empty pinned list; and a second boot changes no byte — *(covered by authored tests in `packages/server/test/storage-name-migration.test.ts`: “leaves legacy names intact during token-only construction and migrates them on the later serving boot”, “migrates legacy metadata and display names before loading, preserving values and second-boot bytes”, and “resumes a partial batch of version-1, intermediate, and current channel records before display conversion”)*. ^mig-t-intermediate-state
- **Seam** (the one migration's channel and display record writers crossing into the filesystem during a real serving-store boot): related channel-record and final display-record cases induce a recoverable replacement failure through real filesystem state, never a mocked writer. Boot stops; every authoritative record is complete input or complete output; removing the obstruction and booting again completes the pass without rolling back already-current records — *(covered by authored tests in `packages/server/test/storage-name-migration.test.ts`: “stops at a channel replacement obstruction and resumes without rolling back completed records” and “stops at the final display replacement obstruction and resumes without rolling back channels”)*. ^mig-t-atomic-resume
- **Acceptance** (outer boundary: a built `tv serve` process over a real authored pre-rename home given with `--home`, driven through authenticated HTTP and websocket clients; no mocks or test hooks): one boot leaves channel-named storage; every channel record carries `layoutVersion: 2`, one default-geometry page per artifact in traversal order (left to right and vertical containers top to bottom), its original id and name, and a slug-only onboarding marker; display carries `focusedChannelId`, an empty pinned list, its preserved theme, and `appearanceMode: "system"`. Artifact registry records, artifact content, and theme files are byte-identical. HTTP exposes the migrated channels, artifacts, and display, and a subsequent ordinary channel event carries the same current channel shape. A second boot changes no migrated record byte. The fixture contains rows, stacks, marker order, an active screen field, opaque ids, non-default sibling values, artifacts, content, and a theme so every ordered step and preservation boundary is exercised together — *(covered by authored test: `test/node/storage-name-migration.test.ts` “boots a pre-redesign directory through current HTTP and websocket contracts, then restarts byte-stably”)*. ^mig-ac-full-upgrade
- **Acceptance** (outer boundary: a real browser loading the production web bundle served by a built authenticated `tv serve` process over a real authored pre-redesign server directory and a complete authored pre-redesign browser-local record; the browser init-script writes that input before boot and replaces no production mechanism; the read-only `window.__telepath.connectionOwner.storedAuthToken` e2e observation hook exposes the real production connection owner and replaces no production mechanism; the standing motion override is the only mock): one boot signs in with the carried token, renders the migrated server focus as the selected channel rather than the retired local pointer, renders the flattened migrated artifacts as ordered tabs with the first selected, loads both artifact documents through production frames, and persists the version-2 page records — *(covered by authored test: `packages/web/test/e2e/path-artifact-real-stack-coverage.test.ts` “pre-redesign server and browser records upgrade together into the rendered application”)*. ^mig-ac-browser-crossing
