## Assertions

### Test assertions

The redesign's page model is greenfield. Plain markers below are policy-grade to be written; inherited evidence is labeled separately. The migration contract, boot seams, and upgrade acceptance spine live with [arch/layout/migration.md](../../../specs/arch/layout/migration.md).

Shared acceptance declaration ([arch/testing-policy.md#^declaration-schema](../../../specs/arch/testing-policy.md#^declaration-schema)): unless an assertion says otherwise, the boundary is a really-running server over a real temporary data directory, driven through a real HTTP client and, where the assertion claims an event, a real websocket client; no mocks or test hooks are used. Ordinary channels and one-artifact pages are created through the production API. The valid-update and membership matrices additionally use an authored version-2 channel record containing a multi-artifact page, so the test proves each page remains a unit and exercises the split branch from a format-valid state that stage 1 does not create through its UI; the real server loads that fixture before the HTTP update.

- **Acceptance.** In one server fixture, reordering pages on both an API-created channel and an authored version-2 channel containing a page whose ordered `artifactIds` has several entries is accepted without changing any page's membership. Changing only a page's `full_screen` value is likewise accepted. Each HTTP response and resulting channel event carries the submitted order and `full_screen` state, each stored channel record carries `layoutVersion: 2`, and a server restart exposes the same pages, order, and `full_screen` state — *(policy-grade test: `packages/server/test/page-layout.test.ts` “persists page reorder and full-screen state without narrowing multi-artifact membership”)*. ^ly-ac-update-valid
- **Acceptance.** An update that duplicates or drops an artifact id, names an unknown one, or regroups artifacts by splitting or merging a page's `artifactIds` is rejected; the exposed layout and stored channel bytes remain unchanged — *(policy-grade tests: the duplicate, dropped, unknown, split, merged, and internally reordered generated cases under `packages/server/test/page-layout.test.ts` “rejects an update that … without changing exposed or stored state”)*. ^ly-ac-membership
- **Acceptance.** An update containing an empty `artifactIds` list or an unknown geometry `kind` is rejected; the exposed layout and stored channel bytes remain unchanged — *(policy-grade tests: `packages/server/test/page-layout.test.ts` “rejects an update that contains empty membership without changing exposed or stored state” and “rejects an update that contains an unknown geometry kind without changing exposed or stored state”)*. ^ly-ac-shape-invalid
- **Acceptance.** An update setting a page's `size` — a fractional pair included — is accepted; the HTTP response and resulting channel event carry it, a second connected client observes it, and a server restart exposes the same size — *(policy-grade test: `packages/server/test/page-layout.test.ts` “persists a fractional page size through HTTP, two websocket clients, and restart”)*. ^ly-ac-size-persists
- **Acceptance.** An update whose page lacks `size`, or whose `size` is half-shaped (one axis missing), non-numeric, non-finite, zero, or negative, is rejected; the exposed layout and stored channel bytes remain unchanged — *(policy-grade tests: the invalid-size generated cases under `packages/server/test/page-layout.test.ts` “rejects an update that … without changing exposed or stored state” and “rejects a non-finite JSON size without changing exposed or stored state”, with contract breadth under `packages/shared/test/layout.test.ts` “stored page size (^ly-ac-size-invalid)”)*. ^ly-ac-size-invalid
- **Acceptance.** Creating an artifact appends a page whose `artifactIds` contains exactly that artifact and whose geometry is the shared default — *(covered by inherited tests: `packages/server/test/endpoints.test.ts` “POST /artifacts requires channelID and appends one default page”, minimally updated to assert the page shape, default geometry, and shared default size)*. ^ly-ac-create-appends
- **Acceptance.** Deleting a page's only artifact removes that page from the layout — *(covered by inherited tests: `packages/server/test/endpoints.test.ts` “DELETE /artifacts/:id deletes metadata and does not touch the target” and `packages/server/test/server-store-attach-detach-delete.test.ts` “persists the stripped layout to disk”, minimally updated from card removal to page removal)*. ^ly-ac-delete-removes


#### Moving an artifact between channels

Shared declaration: same boundary as above — a really-running server over a real temporary data directory, driven through a real HTTP client and, where an assertion claims events, a real websocket client — with no mocks or test hooks. Channels and one-artifact pages are created through the production store's own methods before the server under test starts, with the moved page between other pages so that a change to the remaining order is visible; the multi-artifact case uses an authored version-2 record whose page holds three artifacts. The save-failure cases make one channel's stored file unwritable by replacing it on disk with a directory of the same name, a filesystem fixture that every user, including root, fails to write as a file; the server's own save runs unchanged against it. Each save goes through the store's atomic file writer, whose write order (temporary file, flush, rename, directory flush) is proven once by the resource architecture's storage contracts ([resources/index.md#^rs-arch-t-write-order](../resources/index.md#^rs-arch-t-write-order)); the move tests check only that the move uses it, by the replaced file. A server stop during either save leaves that channel's old or new record, by the writer's contract; a stop between the two saves is not staged, because it leaves the same state as a failed target save, which [#^ly-ac-move-target-fails](#^ly-ac-move-target-fails) checks, including across a restart.

- **Acceptance.** Under [the move contract](../../../specs/arch/layout/index.md#^ly-move), Moving a one-artifact page's artifact from channel A to channel B removes that page from A and appends to B a page holding only that artifact, with the `full_screen` value and `size` the page had on A, while the other pages of both channels keep their order. The HTTP response reports the move, a websocket client observes both channels' new layouts, the artifact's ID and record are unchanged, each channel's stored record is a new file that replaced the old one (its inode changed) rather than the old file rewritten in place, and a server restart exposes the same two layouts — *(policy-grade test: `packages/server/test/artifact-move.test.ts` “moves a page's artifact to the end of another channel with its size and full-screen state, replacing each channel's record, through HTTP, websocket, and restart”)*. ^ly-ac-move
- **Acceptance.** Under [the move contract](../../../specs/arch/layout/index.md#^ly-move), Moving one artifact out of the authored multi-artifact page leaves that page on the source channel holding its remaining artifacts in their order, and appends the moved artifact on the target channel as a one-artifact page with the source page's geometry and size — *(policy-grade test: `packages/server/test/artifact-move.test.ts` “moves one artifact out of a multi-artifact page, leaving the rest of the page in place”)*. ^ly-ac-move-multi
- **Acceptance.** Under [the move contract](../../../specs/arch/layout/index.md#^ly-move), Moving an artifact to the channel that already holds it reports that nothing changed; the exposed layout and stored channel bytes are unchanged — *(policy-grade test: `packages/server/test/artifact-move.test.ts` “reports that nothing changed when the artifact is already on the channel”)*. ^ly-ac-move-same
- **Acceptance.** Under [the move contract](../../../specs/arch/layout/index.md#^ly-move), A move naming an unknown artifact or an unknown target channel is rejected with a not-found response; every exposed layout and stored channel byte is unchanged — *(policy-grade tests: the two cases of `packages/server/test/artifact-move.test.ts` “rejects a move naming … without changing any layout”)*. ^ly-ac-move-unknown
- **Acceptance.** Under [the move contract](../../../specs/arch/layout/index.md#^ly-move), a move whose source channel cannot be saved, staged with the unwritable-file fixture above on the source channel's file, is rejected and changes nothing: both channels' served layouts and the target's stored bytes are unchanged, and after the fixture is removed a restart exposes the original layouts — *(policy-grade test: `packages/server/test/artifact-move.test.ts` “rejects a move whose source channel cannot be saved and changes nothing”)*. ^ly-ac-move-source-fails
- **Acceptance.** Under [the move contract](../../../specs/arch/layout/index.md#^ly-move), a move whose target channel cannot be saved, staged with the unwritable-file fixture above on the target channel's file, is rejected after the source save: the source's served and stored layouts no longer hold the artifact, the target's served layout is unchanged, and after the fixture is removed a restart exposes the artifact on neither channel while its record is still served unchanged by ID, and moving it again is refused with `Artifact not found: <artifact-id>`, as for an artifact no channel holds — *(policy-grade test: `packages/server/test/artifact-move.test.ts` “leaves the artifact on no channel, with its record kept, when the target channel cannot be saved”)*. ^ly-ac-move-target-fails
