*How the promises in Reload and navigation are proven.*

# Reload and navigation — proof

Proves [specs/arch/artifact-frame/reload-navigation.md](../../../specs/arch/artifact-frame/reload-navigation.md).

## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below.

The shared content watcher is proven directly over real temporary file and folder trees for ordinary delivery, exact-file filtering, ancestor/root loss, polling recovery, re-arm, and close. Recursive operation breadth also crosses it through the serving-store folder-artifact seam. Native runtime errors have no reliable filesystem trigger, so one contract test substitutes controllable `fs.watch` handles; that mock forfeits kernel error generation and event semantics to the real-filesystem cases while proving the production module's native-watch topology, error handoff, and idempotent close.

The sibling-filtering and recovery cases separate setup, replacement, and re-arm notifications from measured operations with bounded quiet-period baselines. The sibling phase still requires no additional callback and then proves a watched-file write is observed; recovery cases retain their disappearance and re-arm or fresh replacement assertions, followed by an observed later write for each watcher. These waits establish test-phase separation, not a native watcher readiness or latency guarantee.

Path-artifact consumer tests cross the production watcher for content, loss, and recovery events. A narrow injected-watcher contract covers the owner's error and cleanup branches and forfeits shared watcher behavior to the direct assertions. [Theme architecture](../themes/index.md#^themes-t-shared-watcher-targets) proves that file artifacts and both recursive consumers select this same injected constructor with their intended modes; its real serving-store seam carries the separate theme domain event. The product artifact and theme proofs carry the browser/Electron spines.

These assertions live in this spec's declared server-integration buffer. They can move with the shared watcher if server architecture gains spec authority; no parallel watcher proof surface or migration machinery is introduced here.

## Test hooks

`WatchContentFileOptions.rearmIntervalMs` may shorten missing-root polling in watcher tests; production uses the module's default interval.

`ServerStoreOptions.watchContentFile` may supply a recording or controllable shared watcher constructor; production uses `defaultWatchContentFile`.

## Assertions

### Acceptance criteria

The assertions use five declared harnesses:

- The **server watcher harness** invokes the real path-artifact watch-mode selector, calls the production shared watcher directly over temporary source trees, and runs a real serving `ServerStore` over those trees. Call-through filesystem metadata spies may observe target selection but replace no behavior. The designated native-boundary contract substitutes controllable `fs.watch` handles and forfeits kernel delivery to the harness's real-filesystem cases; injected serving-store watchers are used only for owner error and cleanup contracts and forfeit shared mechanics to the direct watcher assertions.
- The **navigation-state contract harness** runs the real `ArtifactNavigationState` under jsdom. Stored records and artifact ids are authored fixtures; jsdom supplies `location` and `localStorage`, and timestamp cases replace the clock. It covers the history module but forfeits real browser storage and application wiring to the browser and Electron assertions below.
- The **host contract harness** mounts the real artifact-frame view under jsdom with authored artifacts and stored history, then injects channel events, bridge messages, and webview events. Frame peers and browser/Electron delivery are mocked; the harness covers host decisions but forfeits those handoffs to the seam and acceptance assertions below and to [artifact-bridge.md](../../../specs/arch/artifact-frame/artifact-bridge.md)'s bridge assertions.
- The **browser acceptance harness** drives a real browser against running Television servers with temporary artifact and theme files. Unless an assertion says otherwise, it uses no mechanism mock or test hook on the path under test.
- The **Electron acceptance harness** drives the real Electron app against running servers with temporary artifact and theme files. Its fixture-launch hook selects the app URL but replaces no reload, navigation, storage, IPC, or webview mechanism.
