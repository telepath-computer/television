# Theme authoring — proof

Proves [specs/arch/themes/authoring.md](../../../specs/arch/themes/authoring.md).

## Coverage model

The real Television builder crosses fixture inputs and committed production token sheets into temporary outputs. The manifest-driven build crosses the complete authored guidance, generated vocabulary and authored component reference into the shipped document. No builder or filesystem is mocked.

The reference freshness seam enumerates every application frame and stylesheet, includes the application index that owns the document-root marker, and compares recorded source fingerprints. Bounded automated checks cover classes, IDs, custom elements, attribute names and literal values in authored outlines and inline-code references. Independent review covers full selector composition and meaning, template-derived states, and component coverage. Source changes require reviewing the reference before updating its fingerprints; fingerprints do not generate documentation.

Independent guidance review checks that the document identifies the four semantic colors that establish a readable scheme and distinguishes a fixed theme from an adaptive theme with a one-mode customization. It says plainly that accent, wallpaper and the eight base hues are optional overrides that retain foundation defaults, identifies what accent and wallpaper control, and explains that each base hue regenerates its scale. It explains automatic active and hover derivation, distinguishes filled-control and wallpaper-overlay active treatments, and requires local resting and active pairs for per-control colors. It directs coordinated navbar treatments through the shared wallpaper-overlay background with no tab override, and reserves tab tokens for an independent treatment that states resting and active backgrounds while hover remains derived and selection remains separate. The dedicated image-background section teaches packaged relative URLs, app scoping, optional appearance-specific images, paired fill/text choices, optional blur and edges, and review over actual image crops and interaction states. The interaction contrast advice agrees with the shared foundation interaction policy, including perceptible feedback, readable labels and evaluation over actual translucent backdrops. Review also confirms that the manifest is the sole theme appearance declaration, that theme CSS leaves `color-scheme` to the foundation, and that the workflow evaluates a fixed theme under both matching and opposing stored preferences.

The executable-theme guidance seam also checks the frame appearance contract at the shipped-document boundary. It requires startup-only use of the baked root `data-theme`, explains appearance-driven reruns and the host/document scheme match that preserves transparency, warns against changing the frame root scheme, and keeps theme CSS outside the child document. This is guidance-content coverage, not a claim that the skill build exercises browser frame behavior; [theme delivery](./delivery.md#^theme-delivery-t-frame-appearance-browser) owns that crossing.

The bundled-upgrade guidance is checked at the same real build seam. A focused assertion covers the dot-prefixed-ID restriction, the exact backup notice, and the Clouds example's status as a potentially edited structural reference. It adds no agent policy about bundled IDs.
