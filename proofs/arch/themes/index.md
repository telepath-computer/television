*How the promises in Theme architecture are proven.*

# Theme architecture — proof

Proves [specs/arch/themes/index.md](../../../specs/arch/themes/index.md).

## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below. Package and scan contracts exercise real temporary package trees through the production validator and registry scanner. Color-scheme breadth stays at this cheapest honest boundary: real manifest files cover normalization to the three canonical values and useful rejection of every invalid class without paying for server or browser setup. Scan fixtures include valid and invalid dot-prefixed folders, proving that the candidate filter excludes the entire namespace before validation. The package-root `README.md` contract uses that same real-filesystem boundary: one test calls both production paths over one package and rereads its distinctive file bytes.

JavaScript-manifest breadth stays at that same real-filesystem validator contract: all three declaration/entry pairs are exercised independently and together across literal `true`, literal `false`, absence, invalid property types, missing or non-file entries, readability, and arbitrary script bytes, with no server or browser. A serving-store seam then changes each selected package declaration through real manifest writes and registry refreshes, observing snapshot replacement and same-ID events for every declared-value change. Its no-op injected active-package watcher isolates registry-refresh events and forfeits live filesystem notification only to the existing active-package watcher seam. A narrow real-HTTP seam proves all optional values survive registry serialization. Exact public script responses are [theme delivery](./delivery.md#^theme-delivery-t-script-route), and execution is the [product browser spine](../../product/themes-and-appearance.md#^theme-ac-executable-browser).

Display-state coverage crosses a real serving store, temporary `state/display.json`, authenticated display HTTP, and the real event stream. It proves that `activeThemeColorScheme` is derived rather than persisted or patchable and remains paired with the current theme ID through null, adaptive, fixed, missing-root, declaration-refresh, fallback, and restart states. The same crossing starts with the optional consent field absent, proves the required empty wire value, exact-ID set validation and replacement, persistence across restart, explicit removal, non-pruning lifecycle, and fresh consent payloads. Shared-client and application-service contracts use boundary mocks for request shape and confirmed-state handling; they forfeit real transport to that server seam. Telemetry's recording sink replaces only PostHog delivery while real store mutation and runtime paths prove that declared/consented state becomes the permitted booleans while consent lists and user-authored IDs remain private. Telemetry-owned assertions carry those tests, avoiding a second set of theme-package tests for the same payloads.

Active-package coverage has one real seam from a temporary package tree through the production shared watcher into a serving store. It changes a nested file, observes debounce and the theme domain event, moves the package root away and back, and verifies selection and registry continuity without a refresh. The shared watcher's operation breadth and native recovery mechanics compose from [the recursive-operation seam](../artifact-frame/reload-navigation.md#^rn-ac-recursive-watch) and [shared recovery contract](../artifact-frame/reload-navigation.md#^rn-ac-shared-watcher-recovery): active-theme code supplies one unfiltered callback after selecting recursive mode, so it cannot branch on descendant path or operation.

Target selection, superseded-target suppression, cleanup, and runtime errors are cheaper and deterministic at the injected watcher boundary. Those contract tests replace filesystem observation with controllable watchers and forfeit native delivery and error generation to the reload proof's shared-watcher assertions. A call-through warning observer replaces no reporting behavior. The product browser spine is [themes and appearance](../../product/themes-and-appearance.md#^theme-ac-active-package), and missing-root HTTP bytes and validators are [theme delivery](./delivery.md#^theme-delivery-t-route-recovery).

The existing scanner and registry-lifecycle contracts compose with the display-state crossing for explicit refresh or boot while a package is absent: the scanner omits the absent ID and the one fallback handoff produces the paired null theme ID and color scheme. Live missing-root recovery retains the registered scheme and is exercised once through the production watcher; no second package-loss acceptance walk is ordered.

## Test hooks

`ServerStoreOptions.watchContentFile` may supply a recording or controllable shared watcher constructor; production uses `defaultWatchContentFile` from `packages/server/src/file-watcher.ts`.

## Assertions

### Test assertions

The package and scan contract tests use real temporary directory trees as fixtures and call the production validator and scanner. They replace no filesystem mechanism and use no test hooks.

- **Contract** (package validator over real package folders): a valid package returns its exact filesystem-derived `id`, `name`, and `version`, includes a valid optional `authoredForAppVersion`, and omits unknown manifest properties. Missing, non-string, and unparseable authored-against values remain valid and are omitted. Uppercase, spaces, punctuation, and Unicode in real immediate directory names are preserved as valid IDs, while empty names, invalid package Semantic Versions, malformed or unreadable manifests, and missing or non-file `theme.css` entries fail with useful messages. Several fatal defects in one folder produce one combined error — *(covered by `packages/server/test/themes.test.ts` “returns the exact theme ID and supported metadata from a valid package”, “omits missing or unparseable authored-against metadata and accepts unrestricted filesystem theme IDs”, “rejects a manifest with empty name”, “rejects malformed and non-file manifests”, “rejects a missing or non-file theme.css”, and “reports several package defects in one folder error”)*. ^themes-t-package-validation
- **Contract** (production package validator over real package folders; manifests are fixtures and no mocks or test hooks are used): canonical, padded, mixed-case, repeated-whitespace, and reversed-word-order values resolve only to `light`, `dark`, or `light dark` in validated manifests and registry records. A missing, non-string, empty, or unrecognized `colorScheme` rejects the package with an error naming the field and all accepted values; no raw spelling survives validation — *(covered by `packages/server/test/themes.test.ts` “normalizes theme color schemes and rejects every invalid class”, `packages/server/test/theme-registry.test.ts` “publishes a selected color scheme change only after normalized refresh”, and `packages/server/test/themes-routes.test.ts` “returns only normalized color schemes through list and refresh”)*. ^themes-t-color-scheme-package
- **Contract** (production package validator over real package folders; no mocks or test hooks): `enableMainJS` governs only root `main.js`, `enableIframeBackgroundJS` only root `iframe-background.js`, and `enableIframeOverlayJS` only root `iframe-overlay.js`. Independently and with all three present, literal `true` and `false` are preserved only with their matching readable regular entry; absent declarations ignore matching present or absent scripts; arbitrary bytes, including invalid syntax, are not inspected; and each non-boolean declaration or missing, unreadable, or non-file matching entry yields a useful validation error alongside any other defects — *(covered by `packages/server/test/themes.test.ts` “preserves all JavaScript declaration values and ignores unflagged or invalid script bytes” and “rejects every invalid JavaScript declaration and matching missing, non-file, or unreadable entry”)*. ^themes-t-javascript-package
