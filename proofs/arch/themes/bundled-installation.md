*How the promises in Bundled theme installation are proven.*

# Bundled theme installation — proof

Proves [specs/arch/themes/bundled-installation.md](../../../specs/arch/themes/bundled-installation.md).

## Coverage model

Installer contract tests construct the production serving store over real temporary bundled-source and data-directory trees. They use the production package validator and real filesystem operations; package trees, existing installed content, persisted state, and filesystem obstructions are fixtures. No filesystem mechanism or serving-store dependency is replaced. A recording warning function forfeits only Node process-stream formatting, which no assertion claims.

The decision matrix covers absent handled and unhandled IDs, invalid and below-minimum destinations, and valid destinations at or above their minimum. A retained installed-package fixture proves that removing an ID from the bundled set preserves its files, registry entry, and selection. It checks complete recursive paths and bytes where preservation is promised. Replacement checks the backup and final package as complete trees, including removal of prior extra files, while repeated replacements establish that earlier backups are retained rather than overwritten.

Real failure paths cover backup and replacement errors, per-theme continuation, state-write retry, and the required destination outcome. The suite does not terminate a process at an arbitrary machine instruction: deterministic filesystem failures prove the same observable destination states without adding a crash-injection hook or timing-sensitive kill harness. Review of the replacement boundary remains responsible for confirming that an uncatchable interruption cannot leave the destination as anything other than the prior content or the complete bundled package.

A serving-store seam composes handling, registry construction, display loading, the one-time Clouds decision, invalid-theme fallback, and persisted exact-ID JavaScript consent. The product proof carries the built-CLI spine for first installation and an upgrade of packaged Clouds. State parsing and atomic state-file writes remain narrower real-filesystem contracts.

Build coverage separates the YAML-to-runtime derivation from source-tree validation and distribution copies. A focused real-source contract reads all bundled packages through the production validator to pin their exact versions and normalized color schemes against the inventory minimums. The validation command is spawned over real trees for exact inventory, package validity, and minimum-version failures. Existing package-copy seams compare complete source, server, and CLI trees byte for byte. CLI resolver and serving-store wiring are crossed by [CLI architecture](../cli/index.md#^cli-bundled-theme-resolution).

## Test hooks

The build helper accepts manifest and generated-output paths so tests can use temporary filesystem trees; production uses the repository inventory and committed runtime module.

Tests replace `console.warn` with a recording function while exercising warning paths. Production uses Node's console implementation, so those assertions forfeit only process-stream formatting.

## Assertions

- **Contract** (exported bundled-theme declarations read from the production source module; no mocks or test hooks): the ordered IDs and minimums match [the YAML inventory](../../../specs/ui/themes/bundled.yml); the production Semantic Version parser accepts every minimum; and the default ID is Clouds — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “declares the exact bundled theme IDs, minimums, and default”)*. ^bundled-t-version-table
- **Contract** (production validator over the committed bundled source folders and authoritative inventory; no mocks or test hooks): Aquarium is version `1.0.2` with `light dark`; Blueprint and CRT Phosphor are version `1.0.0` with `dark`; Clouds is version `2.1.0` with `light dark`; Swiss is version `1.1.1` with `light dark`; Nord and Tokyo Night are version `1.1.1` with `dark`. Inventory minimums remain `1.0.2` for Aquarium, `1.0.0` for Blueprint and CRT Phosphor, `2.1.0` for Clouds, and `1.1.0` for Nord, Swiss, and Tokyo Night, so every source version meets its minimum without requiring replacement of valid installed `1.1.0` copies — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “declares the exact bundled source versions, minimums, and color schemes”)*. ^bundled-t-color-scheme-versions
- **Seam** (spawned bundled-theme validation command → production package validator and YAML-derived minimums over real source trees; no mocks or test hooks): the committed tree passes, while fixture trees fail with useful output when an expected ID is missing, an extra ID exists, a package is invalid, or a valid source version is below its minimum. The build script's real invocation of this command is proven by [theme architecture](./index.md#^themes-t-build-validation) — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “validates exact bundled inventory, package shape, and minimum versions”)*. ^bundled-t-build-validation
- **Contract** (production serving store over real source, state, and destination trees; no mocks or test hooks): an absent unhandled ID installs the complete bundle, while an absent handled ID remains absent. Existing invalid directory or non-directory content and valid versions below the minimum are replaced whether or not the ID was already recorded; below-minimum fixtures include Semantic Version prerelease precedence. Valid versions equal to or above the minimum remain byte-for-byte unchanged, including a numerically higher version, a pre-existing unrecorded package, and a package whose bundled source is newer. Every successful install, replacement, or preservation records the exact ID once in sorted state without package version or provenance — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “installs, preserves, and replaces from the minimum-version decision matrix”)*. ^bundled-t-install-preserve-replace
- **Contract** (real serving store, temporary source and installed package trees, and persisted display state; no mocks or hooks): for an installed theme whose ID is no longer in the bundled set, a later boot preserves its files byte-for-byte, keeps it in the valid registry, and preserves its active selection — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “preserves an installed theme removed from the bundled source”)*. This proves the retained user-owned package promise in [the product spec](../../../specs/product/themes-and-appearance.md#bundled-themes). ^bundled-t-retired-package
- **Contract** (the same real serving-store and filesystem boundary; existing package trees and repeated below-minimum boots are fixtures; no mocks or test hooks): before each replacement, Television copies the complete prior tree to a sibling whose name matches `.<theme-id>.backup.YYYY-MM-DD-HH-MM-SS`; the destination becomes exactly the complete bundled tree with prior edits and extra files absent; a later replacement creates another unused backup while every earlier backup remains byte-identical; and no backup appears in the resulting registry snapshot or errors — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “copies complete unused backups before repeated replacement and keeps selection and consent”)*. ^bundled-t-backup-replacement
- **Contract** (production serving store over real filesystem obstructions at backup, replacement, and state-write paths; a recording warning function replaces only process-stream formatting): an observed backup or replacement failure warns, leaves the destination as either the complete prior tree or complete bundled tree, does not prevent another theme from completing, and converges on a later unobstructed boot. State advances only after a complete install, replacement, or preservation; a failed state write leaves the complete destination for the next boot to evaluate again — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “warns on replacement failure, continues other themes, and converges on retry”, “warns on backup failure, preserves the destination, and converges on retry”, “recovers a prior destination before retrying an interrupted replacement”, and “keeps a completed install pending when its state write fails, then converges”)*. ^bundled-t-failures

- **Contract** (state parser and atomic writer over a real temporary state directory; no mocks or test hooks): an absent file returns `absent`; the sole version-2 shape accepts unique exact IDs in ascending `en` order and no version or provenance fields; invalid shapes return `invalid`; and a failed replacement leaves the prior complete state intact — *(covered by `packages/server/test/bundled-theme-installation.test.ts` “reads absent, current, and invalid bundled-theme state” and “leaves the previous complete state intact when replacement fails”)*. ^bundled-t-state
