## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below. The active-route acceptance crosses a really-running server and real package folders for ordinary files, escapes, and validators. JavaScript-route breadth covers all three reserved entries at that same public HTTP boundary: main-entry consent matches and mismatches exact IDs, each manifest declaration is independently enabled, disabled, or absent, and invalid syntax remains fixture bytes rather than being executed. A sibling JavaScript file remains an ordinary static asset. One missing-root recovery walk removes a package with every entry enabled and main consent granted, then proves empty CSS and JavaScript entries, unavailable ordinary assets, and exact restored bytes and validators. The package-root `README.md` exclusion retains its own assertion.

Main-script coverage composes a mocked-DOM contract for the resource owner's element mechanics with application-composition contracts for confirmed consent, connection and event wiring, forced reload, and one-shot Settings restoration. DOM, service, history, and navigation mocks forfeit loading, execution, transport, and actual browser reload to [the product executable-theme browser acceptance](../../product/themes-and-appearance.md#^theme-ac-executable-browser) and [reset acceptance](../../product/themes-and-appearance.md#^theme-ac-executable-reset); they buy deterministic lifecycle breadth only. The reset contract deliberately follows installed include presence rather than inferred execution, so it also covers the harmless conservative reload when consent installed an include whose server-side manifest gate returned empty JavaScript. A same-ID manifest refresh remains an in-place include replacement even when it closes that gate. The same product proof carries the required real-Electron execution path. Static ownership and exclusion from standalone entry graphs live in [UI architecture](../ui/index.md#^ui-t-theme-resources).

Sandboxed-frame coverage splits deterministic host lifecycle from browser mechanisms. Mocked-DOM contracts exercise independent declarations, exact generated documents, connection and event handling, registry lookup failures, stale asynchronous results, pointer normalization, focus-target selection, and cleanup without pretending to load an iframe. The registry mock forfeits real HTTP and manifest serialization to [theme architecture](./index.md#^themes-t-javascript-http); the DOM and authored-event mocks forfeit sandboxing, opaque origins, browsing-context destruction, native focus transfer, browser trust generation, and hit testing to the real-browser seam and product acceptance. On initial or replacement lookup failure, the contract requires both frames absent: a prior frame is destroyed before lookup and is never retained under uncertain registry state, while the stylesheet, main script, and application continue and reconnect or a later frame-recreation trigger retries from confirmed state. Superseded failures cannot remove frames installed by a newer lookup. This is the fail-safe consequence of the spec's destroy-before-resolve order.

Shell appearance breadth is a contract around the production resolver-input owner: confirmed display snapshots and events cover null, adaptive, fixed-light, and fixed-dark schemes against all stored preferences, with the real resolver and cache still on the path. The application-state boundary is controlled, forfeiting real display and event transport to [theme architecture](./index.md#^themes-t-active-color-scheme-state). This is also the cheapest boundary for proving that appearance needs no registry lookup. The built-shell seam separately proves resolver-first paint and replacement by confirmed display state before connected mount.

The frame appearance contracts pass light and dark root values through the real frame-document builder, then drive the production composition path with controllable registry outcomes in a mocked DOM. They prove exact document output, synchronous removal in the appearance observer's callback turn before a fresh lookup begins, failure-closed retries, and superseded-operation handling. Those mocks buy deterministic lifecycle breadth but forfeit script execution, iframe canvas composition, and real browsing-context replacement to one real Chromium acceptance.

That Chromium acceptance crosses current registry state, public entry routes, production appearance controls and host elements, the artifact bridge, and both theme iframe windows. It composes opaque-origin isolation, script execution and failure containment, appearance-driven replacement with matched host and document schemes, transparent iframe composition, all five pointer events across application and artifact documents, continued input and clicks in both, focus restoration, usability of the ordinary document-layer Settings popover, and browser-top-layer modal usability. The product assertion carries the same browser walk as a user-visible spine rather than ordering a second launch. Exact host markup belongs to [the app UI proof](../../ui/app/index.md#^ap-ac-theme-layers), and its appearance-keyed styling reaches production through [the UI stylesheet crossing](../ui/foundation.md#^ui-t-foundation-copy).

Artifact contexts that produce no qualifying pointer notification are outside this proof. The [artifact bridge proof](../artifact-frame/artifact-bridge.md) owns the tested producer boundaries and the explicit non-goals for bridgeless documents, nested frames, possible content interference, and Electron raw/plugin content.

The active-package browser path is shared with the product spine at [themes and appearance](../../product/themes-and-appearance.md#^theme-ac-active-package). One real Chromium walk changes a nested imported stylesheet while the entry stays byte-identical, crosses the production server event and application-link path, and observes computed presentation in the application and a live-canonical artifact. Shared watcher breadth remains in [reload and navigation](../artifact-frame/reload-navigation.md#^rn-ac-shared-watcher-recovery), while [theme architecture](./index.md#^themes-t-active-package-watch) owns the serving-store event producer.

Canonical wrapper query propagation is proven at the real HTTP seam for marked frozen and unmarked live version directories. Query-free, advisory, and encoded multi-parameter requests cross the production request handler; the responses establish exact query copying on every import without decoding or reserialization. Public-route acceptance separately establishes that the imported canonical base and active theme retain their resource-derived bytes and validators under those queries. No browser behavior or display state is inferred from either server check.

The foundation-owned `color-scheme` cascade composes the application's complete-foundation ownership seam at [ui/app/index.md#^ap-ac-foundation-color-scheme](../../ui/app/index.md#^ap-ac-foundation-color-scheme), the production-copy distribution seam at [arch/ui/foundation.md#^ui-t-foundation-copy](../ui/foundation.md#^ui-t-foundation-copy), [canonical's live-build seam](../canonical.md#^cn-t-authored-build), the live wrapper seam below, and real-browser acceptance across the application and a live-canonical artifact. Fixed-light, fixed-dark, and adaptive fixtures declare their mode only in the manifest; their CSS uses tokens and mode selectors without declaring `color-scheme`. Cross-context fixed-theme behavior is carried by the [product browser](../../product/themes-and-appearance.md#^theme-ac-appearance) and [Electron](../../product/themes-and-appearance.md#^theme-ac-appearance-electron) spines rather than duplicated here.

The Firefox Markdown directive is carried by [#^theme-delivery-t-markdown-refresh-firefox](#^theme-delivery-t-markdown-refresh-firefox). That acceptance keeps the built application, production Markdown document, real Settings selection, event transport, canonical wrapper, nested theme route, and Firefox stylesheet loading on one unmocked path. It is the same browser walk as [product acceptance](../../product/themes-and-appearance.md#^theme-ac-markdown-refresh-firefox), not a second launch.

The authored-against instruction's exact release-version pass-through is proven in the built skill by [making skills](../making-skills.md#^making-skills-t-authored-app-version). Canonical query propagation is proven by [#^theme-delivery-t-wrapper-query](#^theme-delivery-t-wrapper-query), and imported-route query neutrality by [#^theme-delivery-t-import-query](#^theme-delivery-t-import-query), with query-free frozen and live composition covered separately by the adjacent canonical assertions.

The first-frame directive is carried by [shell first paint](#^theme-delivery-t-first-paint) and [standalone documents](#^theme-delivery-t-standalone). Built error documents are exercised directly. Markdown composes [built-HTML ordering](#^theme-delivery-t-markdown-build-order) with [first-frame observation of the Vite-served source document](#^theme-delivery-t-markdown-source-first-frame) using intercepted stylesheet responses; it does not establish the built Markdown document’s first frame or its real stylesheet delivery. [Artifact colors](#^theme-delivery-t-artifact-colors) crosses the real proxy and built Markdown document in an un-emulated Chromium context; it observes resolver-owned root state, computed colors, and document retention/replacement, but does not measure proxy first paint. [Chromium frame coverage](#^theme-delivery-t-chromium-frame) observes explicit appearance in the same cross-origin frame without media emulation. [Firefox frame coverage](#^theme-delivery-t-firefox-frame) observes system preference using browser media emulation; it makes no explicit-mode or Safari claim. [Desktop appearance](../desktop/appearance.md#^desktop-appearance-t-electron) owns the real Electron webview crossing. These are distinct tested boundaries, not temporary exemptions.

The [visible application-theme seam](#^theme-delivery-t-visible-app) is covered by the selection/clear and repeated-file-edit cases in `theme.test.ts`. It observes a real application surface rather than a test-only color probe. Its entry-file edit check complements the product's nested-import/package-recovery acceptance above; it does not replace that broader spine.
