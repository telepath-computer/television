# CLI architecture — proof

Proves [specs/arch/cli/index.md](../../../specs/arch/cli/index.md).

## Coverage model

The product spine and its spawned-process acceptance tests are owned by [product/cli.md#Acceptance criteria: CLI spine](../../product/cli.md#Acceptance criteria: CLI spine). This architecture spec owns command breadth through contract tests and proves composition through these named handoffs:

- The **argument tokens → command dispatch → command action** seam is Commander's single handoff from parsed process arguments to one registered action. Spawned acceptance tests prove that the executable reaches this dispatcher; in-process `runCLI` contract tests cover command and option variations through the same dispatcher.
- The **home selection ↔ process environment and filesystem** handoff gives `resolveTelevisionHome` the parsed `--home`, the operating-system home directory, and the working directory. Resolver contracts use real temporary directories and `.tv-home` files supplied through the injected `resolveHomeDir`. The product [default-home acceptance](../../product/cli.md#^cli-ac-default-home) crosses production `os.homedir()` and a real `.tv-home` with the built CLI, and [the relative-home seam](#^cli-relative-home-seam) crosses the process working directory.
- The **config file ↔ command** handoffs run the reader and writer contracts over real temporary files. The CLI's use of the file crosses real boundaries three times: [the config-port client seam](#^cli-config-port-client-seam) reaches a real server through a port read from the home's file; the product [multi-listener acceptance](../../product/cli.md#^cli-ac-multi-listener-success) runs `tv config set` and then `tv serve` over one file; and the [persisted install](../../product/cli.md#^cli-ac-persist-home-install) reads the port from the file for both the service and `tv status`.
- The **CLI command action ↔ Television server** seam crosses real HTTP and WebSocket transports. `test/node/cli-integration.test.ts` proves representative artifact, channel, display, auth, health, and event paths, while the product acceptance file proves representative success and failure outcomes through a spawned CLI. The `update-channel` acceptances cross both its successful mutation and unknown-channel HTTP failure through separate built CLI and server processes.
- The **CLI token lookup ↔ token file** seam crosses real filesystem reads of `<home>/state/token`. Temporary-file tests prove trimming and missing files; the unauthorized acceptance path proves that the resulting token reaches a real server.
- The **build user's developer marker → Git `HEAD` → esbuild define → version output** path is crossed by the product's [developer-version acceptance](../../product/cli.md#^cli-ac-developer-version) using actual builds and spawned binaries. The architecture seam separately proves that an unmarked build does not require Git and a marked build fails when Git provenance is unavailable.
- The **foreground serve action ↔ Television server lifecycle** seam crosses the production server adapter, real TCP listener, and signal disposal path in spawned serve tests. The product [multi-listener Acceptance assertion](../../product/cli.md#^cli-ac-multi-listener-success) crosses production construction and real TCP listeners for a config file's `listen` naming an assigned non-loopback IPv4, with loopback added.
- The **persist action's `daemon.install()` call ↔ real `Daemon` service-manager operation** handoff is crossed inside the [persisted-install](../../product/cli.md#^cli-ac-persist-install) and [live reinstall](../../product/cli.md#^cli-ac-persist-reinstall) Acceptance assertions. The dedicated `daemon-acceptance` surface reaches it through the freshly packed and globally installed `tv` binary, production daemon construction, literal service identity and arguments, real service manager, and successful `/health` responses from the resulting daemon boots.
- The **persist action's health check ↔ the service's real server** handoff crosses real HTTP inside the product [persisted-install](../../product/cli.md#^cli-ac-persist-home-install) and [unanswered-install](../../product/cli.md#^cli-ac-persist-unanswered) Acceptance assertions. The first command exits `0` only after its request to the server the service manager launched succeeds; the second meets real refused connections until its deadline passes.
- The **stop and persist-uninstall actions' `daemon.uninstall()` calls ↔ real `Daemon` service-manager operation** handoff is crossed inside the product [product/cli.md#^cli-ac-persist-stop](../../product/cli.md#^cli-ac-persist-stop) and [persist-uninstall](../../product/cli.md#^cli-ac-persist-uninstall-alias) Acceptance assertions. Both enter through the installed binary and observe the production service absent and inactive.
- The **direct skills action ↔ packaged skills and destination directories** seam crosses real filesystem operations. The built-CLI package-copy and stale-cleanup acceptances both resolve the production package tree; temporary-root tests carry copy, replacement, and stale standalone-theme cleanup breadth.
- The **skills action ↔ telemetry emitter** seam calls the real server telemetry emitter in `test/node/telemetry-cli.test.ts`. Injected-emitter contracts carry success, failure, timeout, and payload breadth.
- The **validated source assets ↔ packaged CLI assets** seams cross the production build and real filesystem output. Full-build packaging tests prove every declared copy byte-for-byte, and resolver tests prove the supported built and development lookup layouts.
- The **served home and port ↔ ACP agent prompt** handoff is the [home-context buffer](../../../specs/arch/cli/index.md#^cli-acp-home-context). [Its seam](#^cli-acp-home-context-seam) runs the web package's real `ACPClient` against a spawned `tv serve` whose ACP agent is a stub executable, and reads the prompt the stub receives.

Connect-link contracts exercise `runCLI` with recording output streams and client/server/daemon peers. They forfeit real process streams and HTTP to [product links acceptance](../../product/cli.md#^cli-ac-links). Link inclusion follows the running server's responses, including when its home's configuration has since changed. The default environment passes `process.stdout` directly; spawned acceptance crosses that handoff with a pipe, and the formatter contract covers true, false and absent `isTTY` values. Native terminal detection and hyperlink activation are not observed; they are Node and terminal behavior, so this change adds no pseudo-terminal harness. The existing [persisted-install acceptance](../../product/cli.md#^cli-ac-persist-home-install) crosses plain piped output in its designated-host suite; no second service-manager journey is needed.

Each assertion below declares whether it is a contract or seam test. A contract that replaces a peer states what that replacement leaves unproved and points to the real crossing or explicit exception that owns the gap.

### Remaining coverage decisions and owned exception

Implemented assertions live in the sections above. This section records one bounded coverage extension and three deliberate omissions.

- **No generated-help sweep.** Top-level help and the key `create-path-artifact`, `list-artifacts`, `update-channel`, and `set-theme` pages pin agent-note placement and important option text. Generating every other visible subcommand page would buy exhaustive repetition at permanent runtime and maintenance cost, not another plausible consequential failure.
- **Contract.** At the pure `resolveBindAddresses` boundary, authored repeated and comma-separated IPv4 inputs are flattened and deduplicated with loopback present, `0.0.0.0` collapses the set to the wildcard alone, and non-IPv4 values are rejected; no mocks or test hooks are used — *(covered by inherited tests: all three cases in `packages/server/test/bind-addresses.test.ts`)*. ^cli-listener-resolution-contract

Coverage relationship: [product/cli.md#^cli-ac-multi-listener-success](../../product/cli.md#^cli-ac-multi-listener-success) crosses built CLI dispatch, production server construction, and real specific-address listeners. `packages/server/test/server-listeners.test.ts` "reports raw bind addresses and the listening port from /health" crosses the wildcard branch through a real `Server` and TCP listener. Because the CLI hands the config file's `listen` array to that same constructor without transforming it, these tests compose with [#^cli-listener-resolution-contract](#^cli-listener-resolution-contract) to cover wildcard foreground serve without another spawned variant. Failure behavior belongs to [arch/cli/startup-bind-failure.md#Test assertions](./startup-bind-failure.md#Test assertions).

- **No supported ACP-success assertion.** ACP is not currently a supported product feature. `test/agent/acp-bridge.test.ts` exercises the real bridge, protocol, and agent behavior downstream of the CLI handoff under code authority, while [#^cli-acp-missing-command](#^cli-acp-missing-command) covers the CLI's missing-command exit. The [home-context assertions](#Architecture test assertions: ACP agent home context) prove only the buffer's context, with a stub agent. A CLI-side success crossing with a real agent becomes warranted only if ACP enters the supported product surface.
- **No staged failure between the config writer's temporary write and its rename.** [The writer contract](#^cli-config-writer-contract) observes that a successful update replaces `config.json` by a rename and that every refused update leaves the file and home unchanged. No test fails a write after the temporary file exists: the real filesystem cannot stage that fault deterministically, and its worst outcome is a leftover temporary file, not a changed config file.

#### Owned exception: external skills installer

The CLI claims no real crossing of the `tv skills install -i` seam into the [external skills installer](#^cli-external-skills-installer). Vercel's third-party terminal interface can prompt and select agent skill directories outside Television's control, so exercising it could mutate the developer's real agent configuration. The injected-installer contract pins Television's executable arguments and failure handling; behavior after the handoff belongs to the `skills` package.

> **Coverage ownership.** Home, config, command, parser, client, foreground process, persisted daemon, skills, asset, ACP home-context, and real-server assertions use the standing boundaries named above. Layout-persistence behavior belongs to [arch/layout/index.md](../../../specs/arch/layout/index.md) and [arch/channel-state/index.md](../../../specs/arch/channel-state/index.md); onboarding outcomes belong to [product/onboarding/onboarding-channels.md](../../../specs/product/onboarding/onboarding-channels.md) and [arch/onboarding/index.md](../../../specs/arch/onboarding/index.md); telemetry event meaning and analytics delivery belong to the telemetry authorities; bind-failure details belong to [startup-bind-failure.md](../../../specs/arch/cli/startup-bind-failure.md); and test-runner infrastructure belongs to [arch/test-runner/test-runner.md](../../../specs/arch/test-runner/test-runner.md). Browser presentation is downstream of the CLI handoff.
>
> The spawned product spine proves principal process outcomes, while in-process contracts carry command permutations and the real seams cross storage, HTTP, WebSocket, filesystem, build, and service-manager boundaries. The listener-resolution contract, real wildcard-server case, and built specific-listener acceptance compose across the untransformed `listen` argument, so no duplicate spawned wildcard case is required. The interactive installer and ACP success remain the explicit exceptions above.
>
> **Focus boundary.** CLI focus tests prove transient request and delivery only. [product/cli.md](../../../specs/product/cli.md) and the tab-page authorities own rendered tab selection and channel switching. Opaque fixture values such as `screen-1` are identifiers rather than user-facing vocabulary. The recording telemetry sink proves CLI/server and CLI/emitter handoffs, not outbound analytics delivery. The designated-host daemon workflow is manually selected and carries the service-definition evidence owned by [startup-bind-failure.md](../../../specs/arch/cli/startup-bind-failure.md).

## Test hooks

`runCLI` accepts a partial `CLIEnvironment`, the spec's dependency boundary; a test may supply any subset, and production fills the rest with the defaults listed under [contract types](#Architecture test assertion: contract types). Recording `stdout` and `stderr` writers may set `isTTY` to true, false, or leave it absent; production uses the real process streams. In particular, `resolveHomeDir` lets a test supply a temporary operating-system home directory, which holds `.tv-home` and the built-in default `.television`; production returns `os.homedir()`.

The web package's `ACPClient` accepts `createSocket`, which lets a Node test give it a real `ws` WebSocket; production uses the browser `WebSocket`. Only [the ACP home-context seam](#^cli-acp-home-context-seam) uses it in this proof.

### Architecture test assertions: module boundary

The contract boundary in this block is the exported source module called in process with authored argv. Injected output writers and, for help, a client-constructor spy replace the process streams and production client construction; they forfeit the executable process boundary, which [the product spine](../../product/cli.md#^cli-ac-help-version) crosses. The version contract also injects the operating-system home-directory resolver, replacing production `os.homedir()` and forfeiting that resolution to the [developer-version acceptance](../../product/cli.md#^cli-ac-developer-version). The standalone-build seam instead writes a real bundle to a temporary directory and spawns it with no mock or test hook on the handoff.

- **Contract.** `listVisibleCLICommandNames()` returns the current visible top-level command names, including `config` and `themes-path`, and omits the historical command names that the product spec pins absent, including `storage-path` — *(policy-grade test: `packages/cli/test/cli.test.ts` "keeps the visible command list aligned with the live CLI surface")*. ^e8a5216c
- **Contract.** `runCLI([])`, `runCLI(["help"])`, `runCLI(["-h"])`, and `runCLI(["--help"])` return `0`, write identical top-level help, include the documented command names and agent note, and do not instantiate a client. Help omits `tv skills show`, internal markdown references such as `cli-capabilities.md`, the heading `## User intent`, and the pinned historical command names — *(covered by inherited tests: `packages/cli/test/cli.test.ts` "prints top-level help with the pointer command surface", minimally extended across the complete pinned historical-name list, and "renders the same normal help for bare tv, tv help, tv -h, and tv --help")*. ^723f3673
- **Contract.** Top-level help shows the global `--home <path>` option and lists `config` and `themes-path`. `storage-path` is absent from help and rejected as an unknown command: `runCLI(["storage-path"])` returns `1` and writes nothing to stdout — *(policy-grade tests: `packages/cli/test/cli.test.ts` "prints top-level help with the pointer command surface" and "does not expose the old storage-path command name")*. ^cli-home-command-surface
- **Contract.** The visible command inventory and top-level help list `update-channel`. Both `runCLI(["help", "update-channel"])` and `runCLI(["update-channel", "--help"])` return `0`, describe channel renaming, list required `--channel <id>` and `--name <name>` options and no `--storage-path` option, write nothing to stderr, and do not instantiate a client — *(policy-grade test: `packages/cli/test/cli.test.ts` "update-channel help exposes the command and required options")*. ^cli-update-channel-help
- **Contract.** Under the [developer build-stamp contract](../../../specs/arch/cli/index.md#^cli-developer-build-stamp), source execution has no baked developer commit, so `runCLI(["--version"])`, `runCLI(["-V"])`, and `runCLI(["-v"])` return `0` and print the CLI package's exact release version unchanged under both marked and unmarked temporary operating-system home directories. They leave stderr empty. Injected writers and the operating-system home resolver replace process streams and `os.homedir()`; they forfeit the executable, build-stamp, and real process-home boundaries to [developer-version acceptance](../../product/cli.md#^cli-ac-developer-version) — *covered by `packages/cli/test/cli.test.ts` “supports version output”*. ^99e06341
- **Seam.** The handoff is the standalone `build.mjs --outfile` output to the Node process entrypoint through a real bundle file and spawned process. The binary prints normal help outside the repository tree — *(covered by inherited test: `packages/cli/test/cli.test.ts` "prints normal help from an executable built CLI binary outside the repo tree")*. ^3ac55abd
- **Contract.** Reading the real `packages/cli/package.json`, with no mocks or hooks, shows `bin.tv: "dist/cli.cjs"` and `files: ["dist/**"]` without `main` or `exports` — *(policy-grade test: `packages/cli/test/cli.test.ts` "declares the published package as executable-only")*. ^cli-package-metadata-contract

### Architecture test assertion: contract types

The contract boundary is the exported TypeScript declaration surface. The fixture is an independently written literal copy of the spec-owned types; no declaration is derived from production, and no mock or test hook is used.

- **Contract.** The compile-time fixture declares the spec-owned `Writable` including optional `isTTY?: boolean`, server adapter, daemon adapter, option, and `CLIEnvironment` shapes independently, then requires exact type equality with every exported source declaration. It likewise declares the [home and config types and functions](../../../specs/arch/cli/index.md#Home and config resolution) that `@telepath-computer/television-server` exports for the CLI — `TelevisionConfigFile`, `TelevisionSettings`, `TelevisionConfig`, `TelevisionConfigError`, `resolveTelevisionHome`, `readTelevisionConfig`, and `updateTelevisionConfig` — and requires exact type equality with those exports. It lives on the normal `unit:cli` surface; `npm run type-check` fails if either side drifts — *(policy-grade tests: `packages/cli/test/contract-types.test.ts` “keeps exported CLIEnvironment and adapter declarations exact” and “keeps the server package's home and config declarations exact”)*. ^cli-contract-type-drift

The production default environment is:

- `stdout` / `stderr` → `process.stdout` / `process.stderr`.
- `createClient(serverURL, token)` → `new TelevisionClient(serverURL, { token })`.
- `createServer(options)` → a new `Server` backed by a `ServerStore` whose `storagePath` is `options.home`; it always sets `installOnboardingChannels: true`, passes `onboardingContentPath` and `bundledThemesPath` when they resolve, passes `auth` explicitly, and passes `{ launchMode, installedByAgent }` into the server telemetry options alongside the static, canonical, bundled-view, listen, port, and ACP options.
- `createDaemon(options)` → a new `Daemon` named `com.television.server`, running `process.execPath` with the home-only serve arguments `[process.argv[1] ?? "tv", "--home", options.home, "serve"]` and the persisted environment.
- asset resolvers → the exported resolver functions in this module.
- `resolveHomeDir()` → `os.homedir()`, the operating-system home directory.
- `runSkillsInstaller(args)` → resolves `skills/bin/cli.mjs` from Vercel's third-party `skills` package and spawns it with `process.execPath` and inherited stdio. The package provides a terminal interface that Television neither designs nor controls; the CLI uses it only to let users browse and install the bundled collection interactively. This is the *external skills installer* referenced below. ^cli-external-skills-installer
- `emitSkillInstalledTelemetry(options)` → the server package's telemetry emitter.
- `onSignal(signal, handler)` → `process.on(signal, handler)`.

### Architecture test assertions: home and config resolution

The contract boundary in this block is the server package's exported home and config functions, called in process. Temporary operating-system home directories, `.tv-home` files, homes, and config files are real filesystem fixtures; no filesystem or path mechanism is mocked. The process-level crossings of these functions are named in the coverage model.

- **Contract.** When `homeOption` is present, `resolveTelevisionHome` returns it resolved against `cwd` when relative and unchanged when absolute, gives `~` no special meaning (`~/x` resolves to `<cwd>/~/x`), and does not read `.tv-home`, even when that file is invalid. An empty or whitespace-only `homeOption` throws an `Error` that names `--home` — *(policy-grade tests: `packages/server/test/home-config.test.ts` "resolves a relative --home against cwd and returns an absolute one unchanged", "gives ~ no special meaning in --home", "does not read .tv-home when --home is given, even when the file is invalid", and "rejects an empty or whitespace-only --home with an error naming --home")*. ^cli-home-option-contract
- **Contract.** When `homeOption` is absent and `<os-home>/.tv-home` is missing, `resolveTelevisionHome` returns `<os-home>/.television`. When the file exists, it resolves each [pointer form](../../../specs/product/cli.md#^cli-home-pointer): a path beginning with `/` unchanged, `~` alone as the operating-system home directory, `~/x` as `<os-home>/x`, and `x/y` or `.television` relative to the operating-system home directory. A trailing `/`, surrounding whitespace, and a final newline do not change the result, and a symbolic link in the path is returned unresolved — *(policy-grade tests: `packages/server/test/home-config.test.ts` "selects .television in the operating-system home when .tv-home is missing", "resolves each .tv-home pointer form against the operating-system home", "ignores a trailing slash, surrounding whitespace, and a final newline", and "returns a symbolic link in the pointer path unresolved")*. ^cli-home-pointer-contract
- **Contract.** When `homeOption` is absent, `resolveTelevisionHome` throws an `Error` that names `<os-home>/.tv-home` and the problem when that path cannot be read as a file (fixture: a directory at that path), holds only whitespace, or holds two non-empty lines. It also throws when the path begins with `~` followed by anything other than `/`, as in `~otheruser/tv` and `~x`; that message says that `~` followed by a user name is not supported and suggests an absolute path — *(policy-grade tests: `packages/server/test/home-config.test.ts` "names the file and the problem when .tv-home cannot be read as a file", "names the file and the problem when .tv-home holds no path", "names the file and the problem when .tv-home holds more than one line", and "rejects ~ followed by a user name and suggests an absolute path")*. ^cli-home-pointer-errors
- **Contract.** `readTelevisionConfig` over real temporary homes returns `configFileExists: false` and the defaults (port `32848`, an empty `listen`, `auth: true`, no `installedByAgent`) when the file is missing, and `configFileExists: true` with the same settings for `{}`. It fills absent keys of a partial file and returns every value of a complete valid file, including port `0` and `65535` and `listen` items such as `0.0.0.0`; `configPath` is `<home>/config.json` — *(policy-grade tests: `packages/server/test/home-config.test.ts` "returns the defaults for a missing file and for {}", "fills absent keys of a partial file", and "returns every value of a complete valid file")*. ^cli-config-reader-defaults
- **Contract.** `readTelevisionConfig` throws a `TelevisionConfigError` whose `configPath` is the file and whose message names that path and the problem, and returns no partial result, for: a directory at `config.json`; malformed JSON; a top level that is an array, `null`, or a number; an unknown key; `port` as a string, `1.5`, `-1`, or `65536`; `listen` that is not an array or holds a non-string, a hostname, `*`, or an IPv6 address; a non-boolean `auth`; and a non-string `installedByAgent`, including `null`. Results do not change when `TELEVISION_PORT` and `TELEVISION_STORAGE_PATH` hold valid or invalid values — *(policy-grade tests: `packages/server/test/home-config.test.ts` "rejects a config.json that cannot be read as a file", "rejects malformed JSON and a top level that is not an object", "rejects an unknown key and names it", "rejects each invalid value and names its key", and "ignores TELEVISION_PORT and TELEVISION_STORAGE_PATH")*. ^cli-config-reader-errors
- **Contract.** `updateTelevisionConfig` over real temporary homes creates a missing home and its parents and writes the changes; with an existing file, it replaces only the keys in `changes` and preserves the others, including replacing a stored invalid value of a known key with a valid one. The written bytes are JSON with two-space indentation and a trailing newline, the file is replaced by a rename (the `config.json` inode changes), no other new file remains in the home, and the return value equals what `readTelevisionConfig` then reads. An unknown stored key, malformed stored JSON, a stored top level that is not an object, and an invalid complete result each throw `TelevisionConfigError` and leave `config.json` byte-identical, or absent without creating the home, with no new file — *(policy-grade tests: `packages/server/test/home-config.test.ts` "creates a missing home and its parents and writes the changes", "replaces only the changed keys, preserves the others, and replaces the file by rename", "replaces a stored invalid value of a known key with a valid one", "refuses unusable stored files and invalid results, leaving config.json unchanged", and "refuses an invalid result for a missing file without creating the home")*. ^cli-config-writer-contract

### Architecture test assertions: parser and errors

The contract boundary in this block is authored argv entering the in-process dispatcher and reaching either validation or error formatting. Injected output writers replace process streams. Where named below, fake clients or an authored `fetch` response replace the server peer and forfeit HTTP; the directive, connection, unauthorized, and channel-selection acceptance paths in [product/cli.md#Acceptance criteria: CLI spine](../../product/cli.md#Acceptance criteria: CLI spine) cross the real process and network boundaries. No other mock or test hook is used.

- **Contract.** Commander errors for unsupported commands/options, missing required inputs, invalid arguments, focus-directive violations, and command-specific validation return `1`, write to stderr, and avoid constructing clients when validation fails before the client boundary — *(covered by inherited tests: the directive-error cases in `packages/cli/test/cli.test.ts`, including "prints command help and rejects unsupported options", "requires exactly one focus directive for create-path-artifact, create-url-artifact, and create-channel" minimally extended across missing and conflicting directives, "update-artifact requires at least one of --title, --path, --url", "update-artifact rejects --path and --url together without contacting the server", and the command-specific required-input and strict-port cases for `invalidArgument`)*. ^37bb8262
- **Contract.** When a directive error repeats an invocation, its formatter preserves the entered argument tokens, including option names and values — *(policy-grade test: the unknown-option phase of `packages/cli/test/cli.test.ts` "skills install reports missing destination, conflicting interactive destination, and unknown options")*. ^cf207a25
- **Contract.** At the authored-argv dispatcher boundary, `update-channel` rejects either missing required option and rejects `--id` as unsupported, returning `1`, preserving the entered invocation and option values in the standard directive error, appending the bundled-skills recovery pointer, and avoiding client construction — *(policy-grade test: `packages/cli/test/cli.test.ts` "update-channel rejects missing required options and --id without constructing a client")*. ^cli-update-channel-directives
- **Contract.** With fake clients throwing authored shared `RequestError` instances, formatter logic turns `401` into the token-file hint naming `<home>/state/token` for the home given with `--home`, and appends the help pointer for other HTTP-status errors; the fake forfeits the HTTP response to [product/cli.md#^cli-ac-unauthorized](../../product/cli.md#^cli-ac-unauthorized) and [#^bd409c7e](#^bd409c7e) — *(covered by inherited tests: `packages/cli/test/cli.test.ts` "update-artifact prints a token-file hint instead of a raw 401" and "update-artifact appends the stable help pointer when server refusals do not include it yet")*. ^26872411
- **Contract.** With a real shared client consuming authored mocked `fetch` responses, `get-channel` auto-selection failures are not formatted as server reachability failures; the response mock forfeits real HTTP to [product/cli.md#^cli-ac-channel-selection](../../product/cli.md#^cli-ac-channel-selection) — *(policy-grade test: `packages/cli/test/cli.test.ts` "get-channel reports auto-selection failures as channel-selection problems")*. ^47e6c375
- **Contract.** At the dispatcher boundary, with a home whose config file sets port `0`, client `--port` accepts whole decimal integers from `1` through `65535`, and `tv config set port` accepts them from `0` through `65535`. Both reject trailing text (`123abc`), no digits, a sign (`+1`, `-1`), a decimal (`1.5`), and an out-of-range value (`70000`, and `0` for client `--port`) as directive errors, before any client is constructed or file written. The client is a call-recording fake and forfeits network behavior to the product spine — *(policy-grade test: `packages/cli/test/cli.test.ts` "rejects port option values that are not whole decimal integers in range")*. ^cli-port-parsing
- **Contract.** For a command that uses the home, an empty or whitespace-only `--home` returns `1` with an error naming `--home` followed by the help pointer. An injected operating-system home whose `.tv-home` is invalid makes a command given no `--home` return `1` with that file's error and the help pointer, while the same command given `--home` succeeds. A `TelevisionConfigError` prints its message and the help pointer. No client is constructed on these paths — *(policy-grade test: `packages/cli/test/cli.test.ts` "reports home selection and config errors with the help pointer before constructing a client")*. ^cli-home-errors-formatting
- **Contract.** Help and version resolve no home: `tv --home "" --help` and `--help` under an injected operating-system home whose `.tv-home` is invalid return `0` with help on stdout and empty stderr. Each of `--version`, `-V`, and `-v` returns `0` with the version on stdout and empty stderr in four positions: after `--home ""`, after `--home` naming a missing directory, before `--home` naming that directory, and alone under the invalid `.tv-home` — *(policy-grade test: `packages/cli/test/cli.test.ts` "prints help and version without resolving a home")*. ^cli-help-without-home
- **Contract.** The global `--home` is accepted before and after the command name: `tv --home <home> list-channels` and `tv list-channels --home <home>` construct the fake client from the same home's config port and token — *(policy-grade test: `packages/cli/test/cli.test.ts` "accepts --home before and after the command name")*. ^cli-home-position

### Architecture test assertions: client boundary

The command-breadth and daemon assertions below jointly prove every row of the client-call table; no aggregate assertion duplicates those permanent obligations.
