# Startup bind failure — proof

Proves [specs/arch/cli/startup-bind-failure.md](../../../specs/arch/cli/startup-bind-failure.md).

## Coverage model

Coverage declarations are carried inside the migrated assertion blocks below.

Listener addresses come from the config file's `listen` setting in the [Television home](../../../specs/product/cli.md#^cli-home) the server serves, and the fatal record goes to that home's `logs/tv.log`. The Tailscale-aware hint depends on the server's launch mode: [the daemon hint contract](#^t-hint) and [the foreground hint contract](#^t-hint-foreground) run `Server.start()` with launch mode `daemon` and `cli`, the same launch-mode value the server's telemetry receives. The CLI's choice of launch mode, `daemon` only under `TELEVISION_LAUNCH_MODE=daemon`, is proven by [the CLI serve contract](../cli/index.md#^cli-serve-config-options).

## Assertions

### Test assertions

Shapes declared per [the declaration schema](../../../specs/arch/testing-policy.md#^declaration-schema). The successful-startup spine (all listeners bind, server serves) is already carried by the existing listener coverage in `packages/server/test/server-listeners.test.ts` and the CLI serve tests; the failure exit's spine acceptance is owned by [the product CLI spine](../../product/cli.md#^cli-ac-bind-failure), and this spec owns its detailed observable contract and breadth. Techniques available to assertions below: an address in TEST-NET-1 (`192.0.2.1`) reliably produces `EADDRNOTAVAIL` on Linux and macOS without any Tailscale dependency; an occupied port produces `EADDRINUSE`; and a capability probe gates the privileged-port branch when the host cannot stage `EACCES` or `EPERM` honestly.

**Coverage dependency.** The failure exit's single acceptance declaration is [the product CLI spine](../../product/cli.md#^cli-ac-bind-failure); this spec declares no duplicate assertion for that path. The product-declared test also carries this spec's architectural detail, anchored here for citation: with `tv --home <tmp> serve` over a home whose config file sets port `0` and `listen` to `["192.0.2.1"]`, the process exits with status `69`; after exit, `<tmp>/logs/tv.log` contains a fatal record naming `192.0.2.1` as `failed` with code `EADDRNOTAVAIL` and a bound loopback outcome carrying its resolved ephemeral port, and a connection to that loopback port is refused. The temporary home, its config file, and TEST-NET-1 are fixtures; the test spawns the built CLI with no mocks or test hooks — *(policy-grade test: `test/node/cli-integration.test.ts` "tv serve exits with status 69 and closes all listeners after a bind failure")*. ^t-spine-fatal-exit

- **Contract** (`Server.start()` in process with real sockets and temporary storage; TEST-NET-1 is the failing-address fixture; no mocks or test hooks, while the process boundary is owned by [#^t-spine-fatal-exit](#^t-spine-fatal-exit)): with one failed address alongside loopback, `start()` rejects with an error carrying exit status 69, and every listener that did bind during the attempt is closed by the time the rejection is observable — asserted by connection-refused on the previously bound address and clean teardown — *(policy-grade test: `packages/server/test/server-listeners.test.ts` "rejects startup and closes bound listeners when any required address fails")*. ^t-all-or-nothing
- **Contract** (same real-socket harness, with two TEST-NET addresses as fixtures and no mocks or hooks): all binds are attempted before rejection — the single fatal record lists both failures with their codes; `start()` does not stop at the first — *(policy-grade tests: `packages/server/test/server-listeners.test.ts` "attempts every required address before rejecting startup" and `packages/server/test/logging.test.ts` "records every bind outcome in one fatal startup record")*. ^t-attempt-all
- **Contract** (same real-socket harness; TEST-NET-1, a real occupied loopback port, and an available privileged-port failure are fixtures; no mocks or hooks): `EADDRNOTAVAIL` and `EADDRINUSE` both reject with status 69 and produce a fatal record, with no behavior difference by class ([#^all-errors-fatal](../../../specs/arch/cli/startup-bind-failure.md#^all-errors-fatal)). `EACCES` or `EPERM` is exercised where the host can stage it predictably and skipped otherwise — *(policy-grade tests: `packages/server/test/server-listeners.test.ts` "rejects startup and closes bound listeners when any required address fails", "rejects startup with status 69 when a listener port is in use", and the host-gated "rejects startup when the process lacks permission to bind a privileged port")*. ^t-error-classes
- **Contract** (fatal-record content read from the real tv.log written over temporary storage by failed `Server.start()`; two TEST-NET addresses are fixtures; no mocks or hooks): the record carries every resolved address with per-address outcome, errno `code` and `syscall` on failures, exit status 69, and a timestamp; a bound-then-closed address appears as `bound` — *(policy-grade test: `packages/server/test/logging.test.ts` "records every bind outcome in one fatal startup record")*. ^t-record-schema
- **Contract** (same real logging harness, with the server's launch mode supplied as its constructor option, as production supplies it; one dynamically chosen unassigned CGNAT address is the fixture; no mocks or hooks): under launch mode `daemon`, CGNAT `EADDRNOTAVAIL` produces the [Tailscale-aware hint](../../../specs/arch/cli/startup-bind-failure.md#^record-hint): the address is not assigned to any interface; if it is a Tailscale IP, tailscaled may not be up yet (transient at boot) or the tailnet IP may have changed (permanent until the config file's `listen` setting is corrected); and the service manager will retry — *(policy-grade test: `packages/server/test/logging.test.ts` "writes Tailscale recovery guidance for an unassigned CGNAT address under launch mode daemon")*. ^t-hint
- **Contract** (same real logging harness; TEST-NET-1 is the fixture; no mocks or hooks): non-CGNAT `EADDRNOTAVAIL` produces the generic cause with no Tailscale wording — *(policy-grade test: `packages/server/test/logging.test.ts` "keeps generic address failures free of Tailscale wording")*. ^t-hint-generic
- **Contract** (same real logging harness and fixtures, with launch mode `cli`; no mocks or hooks): the unassigned CGNAT `EADDRNOTAVAIL` failure records a plain one-line cause with no Tailscale wording, and its record otherwise carries the same fields as under launch mode `daemon`, as [foreground semantics](../../../specs/arch/cli/startup-bind-failure.md#^foreground) require — *(policy-grade test: `packages/server/test/logging.test.ts` "records a plain cause without Tailscale wording for an unassigned CGNAT address under launch mode cli")*. ^t-hint-foreground
- **Contract** (a real occupied loopback port and temporary tv.log are fixtures; no mocks or hooks): the fatal record is present on disk at the moment `start()`'s rejection is observable, proven by reading tv.log synchronously in the rejection handler — *(policy-grade test: `packages/server/test/logging.test.ts` "writes the fatal bind record before startup rejection is observable")*. ^t-record-before-exit
- **Contract** (same in-process real-socket harness; port `0` and TEST-NET-1 are fixtures; no mocks or hooks): with port `0` and a failing second address, the ephemeral-port loopback listener is closed like any other — connection is refused on the resolved port after rejection ([#^port-zero](../../../specs/arch/cli/startup-bind-failure.md#^port-zero)) — *(policy-grade test: `packages/server/test/server-listeners.test.ts` "rejects startup and closes bound listeners when any required address fails")*. ^t-port-zero
- **Seam** (thrown bind error → process exit status, crossed at `runCLI` through production `Server` construction and a real TEST-NET-1 bind failure over a temporary home whose config file names that address in `listen`; injected output writers replace process streams but not the handoff, and the outer shell crossing is [#^t-spine-fatal-exit](#^t-spine-fatal-exit)): bind failure resolves to exit code 69 and an ordinary validation failure to 1 — *(policy-grade test: `packages/cli/test/cli.test.ts` "propagates bind failure exit status while ordinary serve errors remain status 1")*. ^t-exit-propagation
- **Seam** (persist action → production daemon renderer → real host service-definition file, crossed by the packed and globally installed CLI in the designated-host daemon suite; a temporary home whose config file holds a released stable port is the fixture, with no mocks or test hooks): the generated Linux unit carries `Restart=always`, `RestartSec=5`, and `WantedBy=default.target` with no backoff keys; the generated macOS LaunchAgent carries boolean `KeepAlive` and `RunAtLoad` with no `StandardErrorPath`. This is platform breadth run on the actual supported designated-host platform, outside ordinary CI; changes to either branch require the suite on that platform — *(policy-grade test: the service-definition checks in `test/node/daemon-acceptance.test.ts` "installs, refreshes, boots, stops, and persist-uninstalls the production service", minimally extended with these retry-related fields)*. ^t-current-service-definition
- **Contract** (Linear TV-507; rendered service-definition content over a real temporary filesystem; `systemctl` execution may be stubbed, forfeiting live service-manager coverage, which no CI environment provides): once the daemon package exposes the start-limit option, installing the daemon renders a unit containing `Restart=always`, `RestartSec=5`, `StartLimitIntervalSec=0`, and `WantedBy=default.target`, with no `RestartSteps=`/`RestartMaxDelaySec=` — *(test to be written)*. ^t-unit-content

Coverage relationship: [#^t-current-service-definition](#^t-current-service-definition) crosses normal installation into a real `systemctl --user` or `launchctl` manager and inspects the installed definition. No automated test stages a missing address, waits for that real manager to restart exit-69 processes, then makes the address available; that restart-after-bind-failure outcome remains manual-verification territory alongside the agent-harness integrations described in [testing-policy.md](../../../specs/arch/testing-policy.md)'s paid-services section. The success spine and listener-resolution breadth this spec composes with live in the existing server listener tests.
