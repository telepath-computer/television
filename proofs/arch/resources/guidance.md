# Resource guidance — proof

Proves [specs/arch/resources/guidance.md](../../../specs/arch/resources/guidance.md).

## Coverage model

The guidance is hand-authored prose, so tests check it where agents receive it: in the skills that the real manifest-driven build emits. Bounded automated checks confirm that each taught item is present in recognizable form: the pointer from `SKILL.md`, `getStore()` and the comment that documents the data, the commands addressed by artifact, the share commands, the SDK functions the example must show, the differences from Firebase, and the APIs that do not exist; that nothing the bindings flag hides ships; and that no passage claims the store's API is Firebase's. Independent guidance review, in the manner of [theme authoring](../themes/authoring.md), judges what the checks cannot: that each item is taught correctly and that the document states nothing the [resource specs](../../../specs/product/resources/resources.md) do not promise, apart from the simpler account of browser storage the spec chooses. That account, that browser storage does not work in artifacts in either runtime although it works in the desktop app, is held by [#^rg-t-purpose](#^rg-t-purpose): its check that every sentence naming browser storage says it does not work, or how to catch the exception, also fails a sentence saying that it works in the desktop app. That it does work there is [artifact isolation's storage-visibility matrix](../artifact-frame/isolation.md#^iso-t-desktop-storage). No builder or filesystem is mocked.

The spec's testing directive is honored by the example acceptance. The test extracts the document's complete artifact example from the built `resources.md` without editing it, registers it as an artifact through the built CLI, and runs it in a real browser against the running server, using its own store, so the guidance cannot teach code that does not work. The browser loads the page from a plain-HTTP host name that is not `localhost`, through [the resources proof's host-name mapping](../../product/resources/resources.md#Test hooks), which is how many people reach their server; a second page of the example, opened on its own through a network proxy, lets the walk cut that page's connection.

Bundle membership, the three-file shape of the `television` skill and delivery to consumers are [making skills](../making-skills.md#^making-skills-t-theming-bundle)'s, and the CLI's packaged copy is [the CLI architecture proof](../cli/index.md#^cli-build-skills-copy)'s.

## Test hooks

The browser acceptance uses [the resources proof's host-name mapping](../../product/resources/resources.md#Test hooks), and [the SDK proof's network proxy](./sdk.md#Test hooks) between the browser and the server for a page of the example opened on its own, which forwards traffic unchanged until the walk cuts that page's connection and refuses new ones, standing in for a network that drops. The skills build runs with its supported output redirection for repository tests, as in [theme authoring](../themes/authoring.md#Test hooks).
