*How the promises in Canonical are proven.*

# Canonical — proof

Proves [specs/arch/canonical.md](../../specs/arch/canonical.md).

## Coverage model

Fresh-build seam tests cross both canonical input classes through the real production builder and filesystem. The committed `packages/canonical/frozen/v1/` tree is the frozen fixture: the test compares its complete recursive file set and every byte with fresh output. The live-v2 test crosses the complete foundation authority and its production copies through CSS resolution, font content-addressing, icon extraction, and component bundling. No filesystem or builder mechanism is mocked or replaced.

The independent public-name fixture proves released v1's additive vocabulary and checks v2's current transitional inventory without turning it into a shipped compatibility promise. V1 extraction reads the committed built CSS and JavaScript; v2 extraction reads live sources and fresh output. Running-server and browser assertions carry the build through real HTTP, marker-based wrapper classification, caching, font loading, and custom-element registration. Theme delivery owns the wrapper and browser seams for the shared foundation-owned `color-scheme` cascade; canonical's live-build seam proves that the complete live foundation reaches `base.css`. The skill-build seam proves current Television authoring guidance exposes live canonical v2. Element behavior stays with the element owners, and the complete canonical-package → server-package → CLI-package byte-copy chain stays with the CLI proof.

The icon-extraction contract cases exercise mixed top-level selector lists and nested rules through the production extractor. They verify that only matching placeholder selectors survive, their declarations remain unchanged, and nested rules are not lifted. The existing fresh-build icon seam then compares the authoritative placeholder declarations with real canonical output.

## Assertions

### Test assertions

The public-name fixture is separate and committed: it records only names an artifact can write or reference and is never generated from the current implementation. After a version is released, its entries grow only by addition while it is live and remain the compatibility record after freezing. That separation lets generated internals change while removal or renaming fails against the recorded inventory. Frozen bytes themselves are compared only at real copy crossings; there is deliberately no digest fixture or test that declares an edit legitimate.


- **Seam** (the handoff is the complete committed `packages/canonical/frozen/v1/` directory to a fresh canonical output root, crossed through the real repository filesystem and production builder; no mocks or test hooks): the builder discovers v1 as frozen, emits exactly its recursive file set including `frozen.json`, and copies every file byte-for-byte without resolving CSS, renaming its font, or bundling its components; a version present in both the live and frozen roots is rejected rather than overwritten — *(covered by tests: `packages/canonical/test/build-canonical.test.ts` "copies every frozen canonical version byte-for-byte into fresh production output" and "rejects a version present in both live and frozen roots")*. ^cn-t-frozen-copy
- **Seam** (the handoff is the complete live foundation and committed v2 production copies to fresh canonical output, crossed through the real repository filesystem and production builder; no mocks or test hooks): every complete-sheet production input conforms to the foundation authority in the same order; the sole partial input is the icon placeholder set selected from the live icon sheet; `styles.css` resolves to the complete foundation with only the builder's URL transformations; every referenced font is copied byte-for-byte under the content-addressed name defined by [#^cn-cache-policy](../../specs/arch/canonical.md#^cn-cache-policy), and changing font bytes changes that name; `components.js` carries the live public elements and complete icon stylesheet; and no production input imports from `specs/` — *(covered by tests: `packages/canonical/test/build-canonical.test.ts` "builds live canonical v2 from its authoritative sources into fresh production output", "changes the published font name when the font bytes change", and "extracts exactly the authoritative pre-upgrade icon rules into canonical document scope")*. ^cn-t-authored-build
- **Contract** (the public-name checker over the committed per-version fixture, frozen v1 CSS/JavaScript, and real live-v2 sources and fresh output; no mocks or test hooks): public token names, element tag names, attributes and public values, documented custom properties, and icon names include every fixture entry for the corresponding version; v1 checks use precise extraction from the built payload, while v2 checks use the live owners and output. Removing or renaming a recorded name fails; for v1 that enforces its released compatibility contract, while v2 checks the current live inventory. The fixture records no CSS value, class, shadow part, or internal markup — *(covered by test: `packages/canonical/test/build-canonical.test.ts` "keeps every recorded canonical public name per version and rejects a recorded removal")*. ^cn-t-v1-additive
- **Seam** (production canonical build output → canonical HTTP response caching, crossed over real HTTP against a running production `Server`; the fresh canonical tree supplies marked frozen v1 and unmarked live v2 fixtures; no mocks or test hooks): for each class, a font response under `/canonical/v<n>/fonts/` carries `Cache-Control: public, max-age=31536000, immutable`; `base.css`, the server-owned `styles.css` wrapper, and `components.js` each carry `Cache-Control: no-cache` and an `ETag`; and a matching `If-None-Match` for `components.js` returns `304` — *(covered by test: `packages/server/test/canonical-cache.test.ts` “serves both canonical cache classes over real HTTP”)*. ^cn-t-cache-headers
- **Acceptance** (outer boundary: for each built version, a real browser loads two authored artifact documents from a really running production `Server` supplied the canonical tree from a fresh production server build; temporary storage and the documents are fixtures; no mocks; synchronization waits for stylesheet load, `document.fonts.ready`, and `customElements.whenDefined()` for every public tag): each document receives the public `styles.css` wrapper, canonical-built `base.css`, and `components.js` from its `/canonical/v<n>` mount; the first receives every referenced font; the components register exactly the public elements; and the served base, font, and component bytes equal the fresh build's files. Frozen v1's wrapper is its base import alone and requests no theme; live v2's wrapper imports and requests the theme. While the second document loads, the running server receives no request for any font, and that document renders in Hind — *(covered by tests: `packages/server/test/e2e/canonical.spec.ts` “an artifact loads the fresh canonical v1 tree through the production server” and “an artifact loads the fresh canonical v2 tree through the production server”)*. ^cn-t-server-mount
- **Seam** (canonical-owned version base and frozen marker → server-owned wrapper class, crossed through a really running production `Server` and real HTTP; marked v1 and unmarked v2 directories plus an installed theme are authored filesystem fixtures; no mocks or test hooks): frozen v1 receives the exact base-only wrapper, while live v2 receives its base and the stable active theme without a wrapper-owned `color-scheme` declaration; the theme remains a separate resource — *(covered by tests: `packages/server/test/canonical-styles.test.ts` “serves frozen versions with only their base import”, “serves live versions with base then theme and nothing after”, and “keeps each base separate from the live version's active theme resource”)*. ^cn-t-theme-layer
- **Seam** (the handoff is this spec's public live-v2 vocabulary to the built Television and artifact-authoring skills, crossed through the real skill build and their real sources; the canonical manifests and source guidance are repository inputs, not mocks; no test hooks): the built HTML guidance carries canonical v2's mount addresses, every public token and icon name, each public element's author markup, attributes, and documented custom properties, while exposing no class, shadow part, internal structure, numeric icon-size API, or unknown-name fallback; each built artifact-authoring skill's guidance links canonical v2 and names no retired token, each stylesheet those skills ship executes no retired token, and the unbundled sidebar's source guidance and carried stylesheet are checked on the same terms, with historical token names in comments outside the executable vocabulary. The check samples these salient contract facts rather than comparing the guidance character for character — *(covered by test: `test/repo/skills-build.test.ts` “builds one bundle per renamed skill without stamping shared house style into per-artifact bundles”)*. ^cn-t-skill-guidance

The app foundation-copy seam at [arch/ui/foundation.md#^ui-t-foundation-copy](./ui/foundation.md#^ui-t-foundation-copy) governs only foundation sheets delivered by the app; [#^cn-t-authored-build](#^cn-t-authored-build), [#^cn-t-frozen-copy](#^cn-t-frozen-copy), and [#^cn-t-server-mount](#^cn-t-server-mount) govern the sheets delivered through canonical.
