*How the promises in Telemetry identity and control are proven.*

# Telemetry identity and control — proof

Proves [specs/arch/telemetry/identity.md](../../../specs/arch/telemetry/identity.md).

## Coverage model

Pure decision matrices cover all control inputs, filesystem contracts cover identity persistence, and real authenticated HTTP covers state transitions. Transport and compiled-build evidence compose from the sink proof.

## Assertions

### Test assertions

The identity contract harness uses the real state reader/writer over temporary data directories, standing in for [Television homes](../../../specs/product/cli.md#^cli-home), with authored versions, data-directory classification inputs, malformed files, and environments. It has no filesystem mock; the optional user-id factory is not used by the cited cases. The runtime seam harness starts a real `Server` and store, drives authenticated HTTP where applicable, and observes a recording sink. That sink mocks analytics delivery, which [sink.md#^t-posthog-lands](./sink.md#^t-posthog-lands) crosses for real. The persisted-daemon acceptance harness is declared by [product/telemetry.md#^ac-persist-auth-install](../../product/telemetry.md#^ac-persist-auth-install).

- **Contract** (identity state file): first load without state mints and persists a GUID, and a second load from the same real data directory returns that exact GUID — *(covered by inherited test: `packages/server/src/telemetry/identity.test.ts` “mints a telemetry GUID once and reuses it across a real filesystem restart”)*. ^t-guid-stable
- **Contract** (identity state parser over a real file): missing, malformed-JSON, and schema-invalid telemetry state are treated as absent and mint valid fresh state without throwing — *(covered by inherited tests: `packages/server/src/telemetry/identity.test.ts` “mints a telemetry GUID once and reuses it across a real filesystem restart”, “recovers from malformed JSON telemetry state by minting fresh boot state”, and “recovers from schema-invalid JSON telemetry state by minting fresh boot state”)*. ^tel-t-state-recovery
- **Contract** (boot derivation and real state file): fresh, same-version, pre-telemetry adoption, semantic-version upgrade, prerelease-to-release, downgrade, and unparseable-version fallback derive the documented lifecycle events and persist the running `lastVersion`; pre-telemetry cohort properties appear only on install or adoption as specified — *(covered by inherited tests: `packages/server/src/telemetry/identity.test.ts` “derives install, start, upgrade, and downgrade events across real boot state”, “treats a newly minted telemetry state on an existing data dir as an upgrade”, and “uses semantic version order instead of string inequality for upgrade detection”, with the version-order case minimally extended to the documented non-equal unparseable fallback)*. ^t-boot-derivation
- **Contract** (pure decision with authored environments and baked-global fixtures): a matrix covers ordinary/production builds, marker absence/presence, test mode, stored opt-out, DNT, and CI. Destination, enabled state, and status must agree with all four product rules. Each absolute suppression input wins in test mode; ordinary and marked production builds are silent without test mode. Explicit status rows also prove DNT/CI/development/developer-host suppression precedes stored opt-out, DNT precedes CI, marked production reports developer-host, and test mode reports active under [status contract](../../../specs/product/telemetry.md#^status-visible). Flag spelling/whitespace and ignored NODE_ENV, runtime TV_NPM_RELEASE, TELEVISION_TELEMETRY_BUILD and TV_TELEMETRY_DEV are covered — policy-grade tests: `packages/server/src/telemetry/identity.test.ts`. Baked globals are restored after each case; compiled evidence belongs to the sink proof. ^t-suppression
- **Seam** (real authenticated control routes → identity state and capture): disabling records exactly one final opt-out event, persists the flag, and closes the gate; enabling preserves the GUID, emits no standalone event, and reopens the gate with the false person-property correction attached to the next event or restart — *(covered by inherited tests: both cases in `packages/server/test/telemetry-control.test.ts`)*. ^t-optout-event
- **Seam** (telemetry initialization failure → status route): unexpected state I/O leaves the server running with no event and makes the real status endpoint return `unavailable`, no GUID, and US region — *(covered by inherited test: `packages/server/test/telemetry-lifecycle.test.ts` “disables telemetry instead of crashing boot when state I/O unexpectedly fails”, minimally extended to query the endpoint)*. ^tel-t-unavailable

The real persisted-daemon ordering proof is [product/telemetry.md#^ac-persist-auth-install](../../product/telemetry.md#^ac-persist-auth-install) and [sink.md#^t-persist-auth-install](./sink.md#^t-persist-auth-install); [product/telemetry.md#^tel-ac-persist-config-home](../../product/telemetry.md#^tel-ac-persist-config-home) runs those installs from homes that hold a config file before the first serving boot. The served-evidence input to boot derivation, including that a config file is not evidence of a serving boot, is proven by [server-telemetry-buffer.md#^tel-t-data-dir-created](./server-telemetry-buffer.md#^tel-t-data-dir-created) and [server-telemetry-buffer.md#^tel-t-config-not-evidence](./server-telemetry-buffer.md#^tel-t-config-not-evidence). That a skill install records under the identity of the home its command selects is proven by [the CLI's skills emitter seam](../cli/index.md#^cli-skill-real-emitter-seam), which gives the command its home with `--home`. CLI dispatch and output remain [arch/cli/index.md#^cli-telemetry-http-seam](../cli/index.md#^cli-telemetry-http-seam)'s. Product outcomes are [product/telemetry.md#^ac-install-once](../../product/telemetry.md#^ac-install-once), [product/telemetry.md#^ac-upgrade](../../product/telemetry.md#^ac-upgrade), [product/telemetry.md#^ac-opt-out](../../product/telemetry.md#^ac-opt-out), [product/telemetry.md#^ac-do-not-track](../../product/telemetry.md#^ac-do-not-track), [product/telemetry.md#^ac-dev-ci](../../product/telemetry.md#^ac-dev-ci), and [product/telemetry.md#^ac-developer-host](../../product/telemetry.md#^ac-developer-host).
