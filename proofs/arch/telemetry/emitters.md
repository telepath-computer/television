*How the promises in Telemetry emitters are proven.*

# Telemetry emitters — proof

Proves [specs/arch/telemetry/emitters.md](../../../specs/arch/telemetry/emitters.md).

## Coverage model

Real store, HTTP, websocket, and boot seams prove production state reaches the telemetry runtime and its complete payloads. Temporary data, themes, and metadata are fixtures. A recording sink replaces analytics delivery only, covered by the live PostHog proof below. Pure classifiers supply value breadth; session and identity proofs supply attribution and suppression breadth. For theme/appearance telemetry, a small set of existing harness extensions covers committed action origins and reading fresh settings after consent, registry, boot, and re-enablement. Product acceptance composes those seams into the server settings workflow. This honors the emitter spec's real-mutation directive; no theme execution or additional client test machinery is needed for configured-use fields.

## Test hooks

`ServerOptions.telemetry.sink` supplies the recording sink; production constructs the PostHog sink. Existing CLI flush coverage uses its injected sink and fake clock as declared below. Theme snapshot tests use the real store reader wired by server bootstrap, not an injected replacement snapshot.

## Assertions

### Test assertions

The server-emitter seam harness constructs a real `Server` and `ServerStore` over temporary data and invokes the production store or HTTP mutation path. A recording sink replaces PostHog delivery, so these assertions prove the store/runtime handoffs and payloads but forfeit the sink transport, covered by [sink.md#^t-posthog-lands](./sink.md#^t-posthog-lands). Authored artifacts, channels, layouts, themes, client metadata, and files are fixtures; no server-store or telemetry hook is replaced. The CLI emitter contract calls the real emitter over a temporary home's telemetry state with the same recording-sink mock; [the CLI-owned seam](../cli/index.md#^cli-skill-real-emitter-seam) proves the successful CLI action reaches it.

These seams compose with [derivation.md](../../../specs/arch/telemetry/derivation.md), [sessions.md](../../../specs/arch/telemetry/sessions.md), and [identity.md](../../../specs/arch/telemetry/identity.md) without enumerating event×property combinations ([testing-policy.md#Compositional coverage across clean seams](../../../specs/arch/testing-policy.md#Compositional coverage across clean seams)).

- **Seam** (store mutation → telemetry runtime): committed artifact/channel CRUD, tab reorder, pin-list, and full-screen hooks emit exactly the expected event with derived properties; same-value metadata/display patches, page-size-only replacements, artifact-membership layout side effects, and deletion pin pruning emit nothing beyond their owning mutation event — *(covered by the artifact, channel, layout, pins, full-screen, and no-op cases in `packages/server/test/telemetry-emitters.test.ts`; classifier breadth composes from [derivation.md#^t-layout-classify](./derivation.md#^t-layout-classify), [derivation.md#^t-full-screen-classify](./derivation.md#^t-full-screen-classify), and [derivation.md#^t-pin-classify](./derivation.md#^t-pin-classify))*. ^t-emit-hooks
- **Seam** (committed display/registry mutation → runtime capture, through the real store and recording sink): a combined theme/appearance patch emits exactly one event per changed field with complete committed person settings; a custom-to-custom selection emits despite equal classification; explicit None carries `selection`, and invalid-theme refresh carries `fallback`. Repeated values, consent-only changes, and same-selection registry refresh emit no action; a rejected display patch emits nothing and leaves the next snapshot unchanged. Proves [action hooks](../../../specs/arch/telemetry/emitters.md#behavior) and [transition origins](../../../specs/arch/telemetry/emitters.md#^theme-settings-transitions), composed with the existing active-package watcher seam for rendering-only reloads — *(covered by tests: `packages/server/test/telemetry-emitters.test.ts` “TV-755 emits theme changes with registry count but no theme package data”, “TV-755 emits each committed setting once and ignores unchanged or rejected patches”, and “TV-755 distinguishes custom switches, explicit None, and registry fallback”; product HTTP crossings are [ac-theme](../../product/telemetry.md#^ac-theme) and [ac-theme-adoption](../../product/telemetry.md#^ac-theme-adoption))*. ^t-theme-settings-actions
- **Seam** (real store snapshot → server runtime → event properties and `$set`): fresh-default and persisted/restarted boots initialize all six fields, including normalized invalid-theme fallback without a synthetic switch. After consent grant/revocation or selected-manifest refresh, the next unrelated server event updates `$set` and real websocket activity copies the same current settings into event properties; false/None clears prior enabled flags. Opt-out suppresses setting/activity telemetry; changing settings while opted out and re-enabling produces no catch-up actions, and the next event carries fresh settings under the same GUID. Proves [publication](../../../specs/arch/telemetry/emitters.md#^theme-settings-publication) and [history](../../../specs/arch/telemetry/emitters.md#^theme-settings-history). The recording sink forfeits only delivery to [sink.md#^t-posthog-lands](./sink.md#^t-posthog-lands); pure value combinations compose from [derivation.md#^t-theme-settings](./derivation.md#^t-theme-settings) — *(covered by tests: `packages/server/test/telemetry-lifecycle.test.ts` “TV-755 initializes default, persisted, and normalized fallback settings on boot”; `packages/server/test/telemetry-event-stream.test.ts` “TV-755 reads fresh consent and registry settings on activity without switch events”; `packages/server/test/telemetry-control.test.ts` “TV-755 publishes fresh settings after re-enable without replaying suppressed changes”; these cover distinct boot, activity, and control handoffs)*. ^t-theme-settings-refresh
- **Seam** (snapshot generator → event properties and `$set`): server config and version, including the installed-by agent the server receives as an option, are attached to `server_started`; upgrades carry new and prior versions; `session_activity` carries the current version; and content totals are attached and `$set` on artifact/channel add and delete — *(covered by inherited tests: `packages/server/test/telemetry-lifecycle.test.ts` “attaches config and version to server_started as event properties and $set person properties”; `packages/server/test/telemetry-emitters.test.ts` artifact, channel, and aggregate-total cases; and `packages/server/test/telemetry-event-stream.test.ts` “emits a content-free session_activity event from an activity signal”)*. ^t-config-attached
- **Seam** (client metadata → session manager → built event): a client-attributed emit carries the current `$session_id`, while a request without client metadata and the CLI `skill_installed` emit carry none — *(covered by inherited tests: both cases in `packages/server/test/telemetry-session-attachment.test.ts`, `packages/server/test/telemetry-event-stream.test.ts` “emits a content-free session_activity event from an activity signal”, and `packages/server/src/telemetry/skill-install.test.ts` “mints pre-first-boot identity and emits a session-less skill_installed event”)*. ^t-session-stamp
- **Contract** (CLI emitter side of the skills-action seam): with no running server, the real emitter mints or reuses telemetry identity, applies suppression, and builds a session-less `skill_installed` event with server version, inferred agent type, and the optional normalized self-identifier — *(covered by inherited tests: all three cases in `packages/server/src/telemetry/skill-install.test.ts`)*. ^t-skill-emit
- **Contract** (CLI emitter with an injected sink whose shutdown never settles; fake clock only, forfeiting delivery to [sink.md#^t-posthog-lands](./sink.md#^t-posthog-lands)): the emitter returns at its 500 ms bound without throwing — *(covered by `packages/server/src/telemetry/skill-install.test.ts` “returns at the 500ms bound when sink shutdown never settles”)*. ^tel-t-skill-flush-bound
