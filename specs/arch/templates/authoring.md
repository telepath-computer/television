*Artifact template guidance: linking, copying, detaching, and maintaining compatible templates through the bundled television skill.*

# Artifact template guidance

The `television` skill introduces artifact templates and carries a separate document for using and authoring them. This spec owns that guidance and its source-to-bundle placement. [Product behavior](../../product/templates.md) and the [folder contract](./index.md) own the facts it teaches; [making skills](../making-skills.md) owns general bundle and installation mechanics.

## Skill introduction

The primary `SKILL.md`, built from `packages/skills/skills/television/src/skill-intro.md`, names `tv templates list`, `tv templates show <id>`, `tv create-artifact --template`, and `tv templates path`. It tells agents to check the list when a person asks for an artifact, including a “macro” or “stock artifact,” and use `show` before writing data for the chosen template. It introduces linking as the default for folder templates and points to `templates.md` for using, detaching, creating, changing, or fixing templates. It retains guidance to use [display-option flags](../../product/cli.md#^cli-create-display) when the request calls for particular display settings. ^artifact-template-skill-intro

## Template document

The skill build copies `packages/skills/skills/television/src/templates.md` into the bundle beside `SKILL.md`, `theming.md`, and `resources.md`. It teaches the selected-home convention, the required manifest fields, optional display options, folder and URL templates, optional manifest `dataSchema`, and local icons. It uses `list` to choose from names, descriptions and optional URLs, then `show <id>` to inspect the installed folder path, version and optional `dataSchema` before preparing caller data. Both commands always scan again, so listing immediately after an edit checks the edited files. The app instead keeps a watched cache for instant Toolbox opening. It explains that templates carry no starting data and that caller data is validated and written within the server creation request. It also teaches agents how to inspect content left by a [failed creation](./index.md#^artifact-template-copy). ^artifact-template-authoring-doc

The introduction, template document, and CLI capabilities distinguish changing one artifact from changing a template. Link when only data needs changing. Before changing page files for one artifact, use `--copy` at creation or detach the existing artifact: inspect its path, copy that folder to a fresh location, then run `tv update-artifact --id <id> --path <copy>`. The artifact keeps its ID and store. An agent must never edit an installed template folder for a request about one artifact. When asked to change a template, it tells the person that every artifact using that folder receives the change.

The template document teaches [schema compatibility](./index.md#^artifact-template-schema): keep accepting and rendering previously accepted data. Pages render defaults for empty or partial stores without writing them on load, and schema defaults do not supply starting content. A `README.md` gives context about the data and page files, available both in the linked folder and in copies. The document points to `resources.md` for store operations rather than restating them. URL templates have no store and reject caller data, copying, and `dataSchema`.

Authors declare local SVG or PNG files using [manifest icons](./index.md#icon-delivery). For a URL template, the agent fetches the best site icon once: prefer SVG or a large PNG declared through `<link rel="icon">`, `apple-touch-icon`, or the site web app manifest; otherwise fetch `/favicon.ico` and convert it to PNG. Save the result in the template folder and list it in `icons`. Neither the app nor the server fetches favicons. Toolbox shows icons and names; the required description remains useful to agents. It explains the supplied and default icon presentation owned by [Toolbox](../../ui/app/toolbox.mdx#icons).

The document explains [bundled installation](./bundled-installation.md): valid installed versions at or above the minimum survive later boots; invalid or older folders are backed up and replaced at the same path. It warns that deleting or moving an installed folder breaks linked artifacts. For page authoring and template-folder naming, it refers to the Artifact workflow and HTML artifact style sections of `SKILL.md`.
