# Bundled artifact template

Television ships the Checklist [artifact template](../../product/templates.md#^artifact-template-bundled). It follows the ordinary [folder and copy contract](./index.md#^artifact-template-package); [bundled installation](./bundled-installation.md) owns when an installed copy is kept or replaced. The [Checklist UI spec](../../ui/templates/checklist.mdx) owns the page's interaction, markup, and styling.

| Folder ID | Manifest `name` | Manifest `description` | Initial `version` | Minimum installed version |
|---|---|---|---|---|
| `checklist` | Checklist | A list of items to tick off and edit. | `1.0.0` | `1.0.0` |

The bundled manifest declares `display: { "width": 640, "height": 800 }` in reference pixels. `fullScreen` uses the shared default. `BUNDLED_ARTIFACT_TEMPLATE_IDS` is the readonly tuple `['checklist']`; [telemetry](../telemetry/derivation.md#^artifact-template-telemetry-derivation) uses this closed vocabulary. ^bundled-artifact-template-inventory

## Store

The template's `data.json` seeds the artifact's [own JSON store](../../product/resources/resources.md#^rs-own-store) with `{"title":"Checklist","items":{}}`. The value has this contract because agents write it:

```ts
interface ChecklistData {
  title: string;
  items: Record<string, {
    order: number;
    text: string;
    done: boolean;
  }>;
}
```

Each item key is generated by [JSON store `push`](../resources/json-store.md#^js-arch-push-keys). The page displays items by ascending `order`, breaking ties by key. `order` permits insertion at the top or directly below an item without replacing the list. The page subscribes to the store through the [resource SDK](../resources/sdk.md). It writes title changes only at `title`. Each save of an item's text or done state sets the complete `{ order, text, done }` object at `items/<key>`; adding an item uses `push` under `items` with the same complete object, and deleting one removes only its key. The page uses the SDK's [`getAccess` and `onAccessChanged`](../resources/sdk.md#^sdk-access) to follow changes in write access. Concurrent editing follows the [Checklist pilot's Changes from elsewhere section](../../ui/templates/checklist.mdx#changes-from-elsewhere). ^bundled-artifact-template-checklist-store

## Packaged page and guidance

The page loads Television's canonical stylesheet and the resource SDK, and includes its other page dependencies inside the template folder so copied artifacts work independently. Its `thumbnail.png` is a 4:5 portrait screenshot, about 400 by 500 pixels, of the UI pilot's `WithItems` state. The [Templates popover UI spec](../../ui/app/templates-popover.mdx) owns how the image is displayed. ^bundled-artifact-template-checklist-page

The bundled `README.md` explains the `title` string and the `items` map, including each item's numeric `order`, `text` string and `done` boolean. It says that smaller `order` values appear first. It tells an adapting agent to change the title at `title`, add items with `tv resource json push` under `items` while supplying an `order`, change an item by writing its complete object at its key, and remove an item at that key. These writes leave other items alone. It explains that the page and agent share the artifact's own store and that changes appear live. ^bundled-artifact-template-checklist-readme
