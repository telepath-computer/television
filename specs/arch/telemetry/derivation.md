*Property derivation: the pure functions that turn server and request state into enumerated and integer telemetry properties — config, host binding, client/user-agent, artifact classification, tab-page order and presentation, channel pins, theme, agent type, and versions — emitting only classifications, never source strings.*

# Telemetry property derivation

## What this owns

This module owns the **pure functions** that compute telemetry properties from inputs. The property *types* (the enumerations) are defined once in [arch/telemetry/index.md](./index.md); this module owns the logic that produces values of those types. Every function emits only enumerated values, booleans, or numeric classifications — never the source string — which is the structural half of [no user-generated content](../../product/telemetry.md#^no-ugc) (the chokepoint types are the other half).

These are pure functions with typed inputs and outputs, which is what lets a small table-driven test per classifier cover its breadth, composed with the emitter seam ([emitters.md](./emitters.md)) that attaches the result to events ([testing-policy.md#Compositional coverage across clean seams](../testing-policy.md#Compositional coverage across clean seams)).

## Behavior

All derivations run server-side (CLI-side for agent-type at skill install).

- **Config: default-vs-custom port / home** — compare the effective port against `DEFAULT_SERVER_PORT` (32848), and the served home (the `ServerStore` storage path) against `.television` in the operating-system home directory, the [Television home](../../product/cli.md#^cli-home-selection) a command uses when nothing selects another. The home is `default` when the two absolute paths are equal and `custom` otherwise, whether `--home` or `~/.tv-home` selected it. The home classification is reported under the `storage_path` key. **Launch mode** (daemon via `--persist`/service vs. direct CLI) comes from the boot config.
- **Auth mode** — binary: `auth` (a bearer token is enforced) vs. `no-auth`. The server's internal `configurationSnapshot()` reports a third `none` state; for telemetry it collapses to `no-auth` (no token enforced), since the only question is whether auth is on.
- **Host binding booleans** — from the resolved bind-address set, mark `bindsLoopback` (`127.0.0.1`/`::1`), `bindsAllInterfaces` (`0.0.0.0`), `bindsTailnet` (`100.64.0.0/10`), `bindsOtherSpecific` (any remaining specific address). Multiple may be true.
- **Client app / platform / browser** — from the standard client metadata payload ([client.md](./client.md)): `clientApp` distinguishes browser vs. desktop directly, and `userAgent` is parsed for platform (`windows`/`macos`/`linux`/`ios`/`android`/`other` — spanning desktop and **mobile**), browser vendor, and browser major version; `HeadlessChrome` and `CriOS` classify as Chrome. `desktopAppVersion` is read directly for Electron. UA reduction makes the major version coarse and `other` expected for uncommon browsers. The raw `userAgent` is parsed here and never emitted.
- **Artifact classification** — `path` vs `url` from the artifact kind; for paths, `folder` is inferred from a trailing path separator and otherwise the path is classified as `file`; file extension then maps to `html`/`markdown`/`other`. For urls, two **independent** classifications — `urlHost` from the host (`localhost` = `127.0.0.1`/`localhost`/`::1`, `tailnet` = `100.64.0.0/10`, else `third-party`) and `isArtifactProxy` (boolean), which reuses the existing canonical `isTvArtifact(url)` helper (`packages/artifact/src/model.ts`) that already detects whether a URL addresses Television's own artifact-proxy endpoint. Only classifications are emitted, never the URL.
- **Layout-change classification** — compare the previous and committed ordered `TabPage` lists. Preserved page membership in a different order is `tab_reorder`; unchanged order, page-size-only changes, artifact add/remove, and regrouping return no classification. See [product/telemetry.md#^layout-classification](../../product/telemetry.md#^layout-classification).
- **Tab-page full-screen classification** — match retained pages by ordered artifact membership and return the committed `full_screen` boolean for each matched page whose value changed. Page additions and removals produce no presentation transition. This classifier is independent of page-order classification, so one replacement can produce both results. See [product/telemetry.md#^full-screen-classification](../../product/telemetry.md#^full-screen-classification).
- **Channel-pins classification** — compare previous and committed ordered `pinnedChannelIds`: additions only produce `pin_change_type: pin`, removals only produce `unpin`, unchanged membership in a new order produces `reorder`, and simultaneous additions and removals produce `replace`. Every result carries the committed pin count; unchanged lists return no classification. See [product/telemetry.md#^pin-classification](../../product/telemetry.md#^pin-classification).
- **Theme** — `activeThemeName` null ⇒ `none`; a non-null theme ID in `BUNDLED_THEME_IDS` ⇒ that bundled theme ID; every other non-null theme ID ⇒ `custom`. `themeCount` is the number of valid entries in the server's current theme registry. The classifier reads the runtime ID list derived from [the bundled theme inventory](../../ui/themes/bundled.yml), as owned by [bundled installation](../themes/bundled-installation.md). A user-edited or pre-existing package at a bundled theme ID therefore retains the bundled classification. User-authored folder names, raw manifest fields, theme IDs, and validation errors never enter the output.
- **Theme JavaScript and appearance** — find the active exact ID in the current validated registry. `theme_main_js_declared` is true only when its `enableMainJS` is literal `true`; `theme_main_js_enabled` additionally requires consent for that exact active ID. The background and overlay booleans are true only when the corresponding `enableIframeBackgroundJS` and `enableIframeOverlayJS` are literal `true`, independently of main consent. An absent declaration, literal `false`, or no active registered theme produces false. Preserved consent for an inactive theme has no effect. Return the stored `appearanceMode` as `appearance_mode`, without client-side system resolution. Together with `theme_state`, these are the complete six-field current-settings snapshot. Manifest names, raw manifest fields, and the consent ID list are inputs only; output contains the declared telemetry classifications. These are configured-use values, so script bytes, load success, runtime failures, and temporary package-root loss without registry refresh do not change the snapshot. ^theme-settings-derivation
- **Theme change reason** — the committed mutation's origin determines `selection` versus `fallback`. An explicit display selection is `selection`; clearing an invalid selected ID during registry refresh is `fallback`. The caller supplies this internal origin to the emitter; it cannot be inferred from the destination `none`, which is also a valid explicit selection. Startup reports normalized settings through lifecycle telemetry without replaying a theme transition. ^theme-change-reason
- **Installed-by agent** — not derived: the config file's `installedByAgent` setting for the server, or the `tv skills install --installed-by-agent` value, is lowercased and trimmed and passed through **as-is** (the one non-enumerated property; [product/telemetry.md#^installed-by-agent](../../product/telemetry.md#^installed-by-agent)). An absent value, or a value that is empty after trimming, is omitted.
- **Versions** — telemetry records numeric `major.minor.patch` only. For a strict Semantic Version (no leading `v` or surrounding whitespace), discard prerelease and build metadata; otherwise return `0.0.0`. The [chokepoint](./index.md#The event chokepoint) owns application to outbound properties. Product version comparison and advertisement retain their own contracts.
- **Agent type** — match the skills-install target directory against a fixed token set (`pi`, `opencode`, `claude`, `codex`, `hermes`, `openclaw`, `cursor`); a `.agents` directory matching none reports `dot-agents`; anything else reports `other`. Interactive target selection (`tv skills install -i`) reports `interactive-install` without deriving from a target path. Low-fidelity (see [product/telemetry.md#^agent-type](../../product/telemetry.md#^agent-type)); complemented by the self-reported `installed_by_agent` server property (above).
