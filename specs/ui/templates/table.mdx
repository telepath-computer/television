# Table template

The Table template makes an artifact that shows and edits data in rows and columns. Each story on this page is one state of the page, and the template page must pass a [UI conformance](../../spec-ui.md#conformance) check against every one. The prose states the behaviour the stories cannot show.

The architecture spec owns the [store schema and ordering](../../arch/templates/table.md#store), [runtime reading](../../arch/templates/table.md#runtime-reading), [drawn positions](../../arch/templates/table.md#drawn-rows-and-columns), and [paths each action writes](../../arch/templates/table.md#page-writes). The [resource SDK](../../arch/resources/sdk.md#^sdk-access) owns how the page learns its access level.

## A new table

A new Table draws four blank columns and four blank rows, with no header row. As entries are stored, blank positions remain after them until each axis has at least four positions. An axis with more stored entries grows beyond four. Drawing these positions makes no write.

## Rows, columns and cells

Rows and columns follow their stored order. String, number, and boolean cells appear as text; an empty cell is blank. Text stays on one line and ends in an ellipsis when it is wider than its cell. Stored line breaks appear as spaces in the grid. The grid scrolls in either direction when it is larger than the artifact; the header and reference strips stay with the visible grid while it scrolls.

There is no search or sorting. Stored entries always appear in stored order.

When the header row is on, its cells show the column names. When it is off, the row is absent. An unnamed column has a blank header cell.

## Selecting cells, rows and columns

Clicking a cell or header cell selects it. The selected cell gets a quiet accent outline and fill. Column letters and row numbers appear by position in two continuous, rounded strips outside the table. The strips use the page surface, a muted border, and dividers between items. They are hidden while nothing is selected.

For a selected body or header cell, its row number when it has one and its column letter receive a quiet emphasis. Clicking a letter selects that whole column; clicking a number selects that whole row. A whole-row or whole-column selection uses the accent colour on its strip item and a pale accent across the selected body cells. Shift-clicking another item in the same strip extends the selection from its anchor.

These stories show pointer selection at rest, without the keyboard-focus treatment.

## Keyboard and assistive technology

The table control is one Tab stop. Tab into it returns to the selected cell or selected strip item, or selects the first body cell when there is no selection. The selected cell has its quiet accent outline at rest; keyboard focus adds the inner surface-coloured ring shown below. A focused strip control uses the foundation focus outline.

<Artifact><Canvas of={Stories.KeyboardFocus} /></Artifact>

When a body or header cell is selected and not being edited, Left and Right move between columns. Up from the first body row selects the header cell when the header is shown; Down from a header selects the first body row. Other Up and Down presses move one row. Tab moves right and Shift-Tab moves left. Tab at the last displayed column and Shift-Tab at the first leave the table.

Shift-Space selects the current body row. Ctrl-Shift-Space selects the current column from a body or header cell; it avoids the macOS Ctrl-Space input-source shortcut. Up and Down move a whole-row selection, and Left and Right move a whole-column selection. An arrow without Shift collapses a range to its anchor and moves that single-row or single-column selection. Holding Shift moves the active end, extending or shrinking one contiguous range. Tab or Shift-Tab leaves the table from a whole-row or whole-column selection.

Only the strip item holding a whole-row or whole-column selection can receive focus. Enter or Space on it keeps that selection and does not open its menu. Hidden strip items and the plus controls are not focusable.

The table is a grid named “Table”. A body cell and its editor are named by position, such as “Row 4, column B”; a header cell and its editor are named by letter, such as “Column B name”. Strip buttons are named “Select row” followed by the number and “Select column” followed by the letter. Plus buttons are named “Add row at end” and “Add column at end”. Selection state is exposed through the grid and strip controls.

## Editing cells and headers

Typing while a cell is selected replaces its contents and starts editing in place. Double-clicking it, pressing Return, or pressing F2 starts editing with the existing text. The editor fills the cell and has the foundation focus outline. Arrow keys and the usual text-editing keys then work in the text.

Return commits and selects the cell below. From a header it selects the first body cell; at the last body row it stays at the last row and does not add one. Shift-Return moves in the opposite direction, including from the first body row to the header when it is shown. Tab commits and selects the cell to the right; Shift-Tab moves left. At the last displayed column, Tab commits and leaves the table; at the first, Shift-Tab does the same. Neither key adds an entry merely by reaching an edge.

Clicking another cell, a header, a strip item, or a plus control commits before acting on that target. Clicking elsewhere in the page or moving focus out of the artifact commits and clears the selection. Escape cancels the edit and restores the stored text. The sections below state the cases where an editor instead closes without writing.

<Artifact><Canvas of={Stories.EditingCell} /></Artifact>

Header cells use the same editing commands. The editor preserves stored and pasted line breaks, even though the grid displays them as spaces. Copying, pasting, text selection, and browser undo work inside the editor as in another text field. Whole-cell and range copy or paste are not supported. After an edit or structural action is committed, the page provides no undo.

The [page-write rules](../../arch/templates/table.md#page-writes) own empty and unchanged commits. In visible terms, clearing stored text leaves a blank cell or header; leaving unchanged text does not replace a newer stored value.

## Clearing contents

Delete or Backspace clears the selected cell or the body cells in selected rows or columns. It never removes a row or column. Clearing a column selection leaves the column name. When a header cell itself is selected, Delete or Backspace clears that name.

## Adding, inserting, and deleting structure

A plus sign at the end of each visible reference strip adds a row or column at the end. Right-clicking an item outside the current range selects only that row or column. Right-clicking inside a selected range keeps the range. Either action opens a canonical `<tv-menu>` below that strip item. Right-clicking a body or header cell does not open a Table menu, change the selection, or commit an edit.

The context-menu key or Shift-F10 opens the menu from the keyboard. For a whole-row or whole-column selection, it opens the corresponding menu at the range anchor. For a body cell, it selects the row containing that cell and opens the row menu; for a header cell, it selects that column and opens the column menu. Opening a menu commits an active edit first. The page creates the menu only while opening it, gives it the strip item as its trigger, and removes it after it closes. With no menu open, a normal press on a strip item therefore selects the row or column without opening one.

The row menu contains “Insert row above”, “Insert row below”, “Delete row” or “Delete rows”, and “Show header row” or “Hide header row”. The column menu has “Insert column left”, “Insert column right”, “Delete column” or “Delete columns”, followed by the same header action. Destructive actions use the canonical danger treatment.

Insert adds one row above or below the selected row range, or one column to the left or right of the selected column range. Insert and either plus control select the new whole row or column. After deleting selected rows or columns, one whole row or column stays selected at the same displayed position, or at the last position when the old position no longer exists. Clearing contents leaves the selection unchanged. The [store contract](../../arch/templates/table.md#page-writes) owns ordering, deletion, and header-setting writes.

## Changes from elsewhere

The page follows the whole store live. Changes outside the field currently being edited appear at once. A selected stored cell, header, row, column, or range follows the keys it selected when entries move. A range remains selected only while those keys occupy one contiguous range; otherwise the selection clears. If any selected stored entry is removed, the selection clears and an editor on it closes without writing.

A drawn position has no key to follow. If a change from another writer adds or reorders stored entries on an axis used by a selected drawn position, the selection clears and an editor on it closes without writing.

While a person is editing one field, an incoming change to that field does not replace the text or move the caret. A changed edit commits through the ordinary last-write-wins store rule. An unchanged edit closes without writing, so it reveals the current stored value. Cancelling also shows the current stored value. A late edit that races with deletion can be lost under the [runtime reading rules](../../arch/templates/table.md#runtime-reading).

## Read-only and access loss

When the page can only read its store, as through a read-only share, the table can still be selected and navigated. Cells and headers cannot enter editing, Delete does nothing, plus signs are absent, and the action menus do not open. The page switches between editable and read-only as access changes. If write access is removed while an editor is open, the editor closes without writing and shows the last confirmed value.

<Artifact><Canvas of={Stories.ReadOnly} /></Artifact>

When all access is lost, as after a share link is revoked, the page keeps the last table it received and becomes read-only. An active editor closes and shows the last confirmed value.

## Saving and disconnection

Each changed edit saves when committed. Normal saving shows no message. While the page cannot reach its server, the table keeps its last data, removes the plus signs and action menus, disables new editing, and shows “Reconnecting…” in muted text in a strip ruled off along the bottom. An editor already open keeps one draft and remains usable. Escape cancels it.

Return, Tab, or a click that ordinarily commits finishes the disconnected edit without making a store call. The page keeps that draft on screen, moves or clears the selection as the same gesture normally would, and saves the draft once after reconnecting with write access and readable data. Losing write access or receiving unreadable or unavailable data discards it. A draft aimed at a drawn position is also discarded if the stored entries on that axis change before it can save. Closing or reloading the page loses any retained draft.

A write sent before the connection drops is not turned back into a draft when the SDK rolls it back. That edit can be lost, although the server can still apply a write whose outcome is [uncertain after disconnection](../../product/resources/json-store.md#^js-disconnect). This is an accepted limitation.

If a save is refused, the affected path returns to its stored value and “Couldn't save that change.” appears in the same strip for a few seconds. “Reconnecting…” takes precedence. The strip is a status region, so a screen reader hears each message.

## Data the page cannot read

The page reads the table as one value, while deliberately tolerating bad entries under the [runtime reading rules](../../arch/templates/table.md#runtime-reading). No store value and a partial root object show the empty grid and are not repaired.

When the value is not a table at all, because the root is not an object or a present `columns` or `rows` value is not an object map, or when the server reports saved data unavailable, an error page replaces the table: centred in the page, a warning icon in a ruled circle, “This table can't be shown”, and below it in muted text, “Its saved data isn't in the form this page reads. Ask your agent to check it.” Nothing on it can be edited. An open editor closes without writing. The page starts no write until readable data returns. The error page is an alert, so a screen reader hears it when it replaces the table.

The error page follows data live. Once an agent supplies a readable table value, the grid returns. If all access is lost before the first readable value arrives, the error page replaces the loading state; after a readable table has arrived, total access loss keeps that last table as the read-only section describes. A disconnection leaves the loading or error state in place and adds “Reconnecting…” below it.
