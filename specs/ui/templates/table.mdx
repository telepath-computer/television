# Table template

The Table template makes an artifact that shows and edits data in rows and columns. Each story on this page is one state of the page, and the template page must pass a [UI conformance](../../spec-ui.md#conformance) check against every one. The prose states the behaviour the stories cannot show.

The architecture spec owns the [store schema and ordering](../../arch/templates/table.md#store), [runtime reading](../../arch/templates/table.md#runtime-reading), [drawn rows and columns](../../arch/templates/table.md#drawn-rows-and-columns), and [paths each action writes](../../arch/templates/table.md#page-writes). The [resource SDK](../../arch/resources/sdk.md#^sdk-access) owns how the page learns its access level.

## Rows, columns and cells

Rows and columns follow their stored order. Cell text is top-aligned, stays on one line, and ends in an ellipsis when it is wider than its cell; an empty cell is blank. Stored line breaks appear as spaces in the grid. Extra row height falls below the text, and a row at the 28-pixel minimum keeps its single line whole. The grid scrolls in either direction when it is larger than the artifact. When the header row is on, it and row number 1 stay with the visible grid while the table scrolls.

There is no search or sorting. Stored entries always appear in stored order.

When the header row is on, the first displayed row is still row 1 and is edited like every other row. Its cells use the canonical muted surface, and their values serve as column titles. When it is off, the same row appears as data. Every other row uses the canonical page surface.

## Selecting cells, rows and columns

Clicking a cell selects it. The selected cell gets a quiet accent outline and fill. Column letters and row numbers appear by position in two continuous, rounded strips outside the table. These are the *column strip* and *row strip*. They use the page surface, a muted border, and dividers between items, and stay visible whether or not anything is selected. Each “+” at the end of a strip is an *add control*. The grid, strips and add controls together are the *table control*.

The top strip is as tall as the side strip is wide for single-digit row numbers. The side strip grows only enough to fit additional digits with thin inline padding. Strip items contain only their letters or numbers, and there is a small gap between each strip and the table.

For a selected cell, its row number and column letter receive a quiet emphasis. Clicking a letter selects that whole column; clicking a number selects that whole row. A whole-row or whole-column selection uses the accent colour on its strip item and a pale accent across the selected cells. Shift-clicking another item in the same strip extends an existing row or column selection from its anchor. With a cell selected, or with the other strip selected, Shift-clicking selects only the row or column clicked.

## Keyboard and assistive technology

The table control is one Tab stop. Tab into it returns to the selected cell or the anchor item of a selected row or column range, or selects the first cell when there is no selection. The selected cell has its quiet accent outline at rest; keyboard focus adds the inner surface-coloured ring shown below. A focused strip control uses the foundation focus outline inside its edge, where the scrollport does not clip it. Selection remains when Tab moves focus out and is restored when Tab returns.

<Artifact><Canvas of={Stories.KeyboardFocus} /></Artifact>

This story shows keyboard focus on a selected row strip item.

<Artifact><Canvas of={Stories.KeyboardFocusRow} /></Artifact>

When a cell is selected and not being edited, Left and Right move between columns and Up and Down move between rows. Tab moves right and Shift-Tab moves left. Tab at the last displayed column and Shift-Tab at the first leave the table. Moving the selection scrolls the selected cell or strip item fully into view, clear of the strips and the header row.

Shift-Space selects the current row. Ctrl-Shift-Space selects the current column; it avoids the macOS Ctrl-Space input-source shortcut. In an open editor, Shift-Space and Ctrl-Shift-Space type normally. Up and Down move a whole-row selection, while Left and Right do nothing. Left and Right move a whole-column selection, while Up and Down do nothing. On a range, Up or Down for rows and Left or Right for columns first collapses the range to its anchor, then moves that single-row or single-column selection. Holding Shift instead moves the active end, extending or shrinking one contiguous range. Tab or Shift-Tab leaves the table from a whole-row or whole-column selection.

Only the strip item at the anchor of a whole-row or whole-column selection can receive focus. Return, F2, or typing other than the resizing keys while a whole row or column is selected does nothing. Space keeps the selection and does not open its menu. The add controls are not focusable.

The table is a grid named “Table”. Cells take their names from their displayed contents, while the grid's row and column positions convey position. When the header row is on, its cells are column headers in the accessibility tree; they keep the same editing and position names as other cells. An editor is named by position, such as “Row 4, column B”. Strip buttons are named “Select row” followed by the number and “Select column” followed by the letter. The add controls are named “Add row at end” and “Add column at end”. Selection state is exposed through the grid and strip controls.

## Resizing rows and columns

Dragging the divider after any column letter, including the last, resizes that column live. Dragging the divider below any row number, including the last, does the same for that row. Pressing a divider commits an open cell editor before resizing begins and leaves the selection unchanged. If another writer changes that saved size during the drag, the person's live preview holds in place. On release, a changed size saves through the ordinary last-write-wins rule; an unchanged size writes nothing and shows the current saved size. A resize ends without writing if its target disappears, a drawn target changes identity, or the page becomes unable to write before release. The architecture spec owns the [stored size and drawn-position writes](../../arch/templates/table.md#page-writes). A table wider or taller than the artifact scrolls rather than shrinking its saved sizes.

For keyboard and assistive-technology access, a person selects exactly one whole row or column, then presses plus to grow it or minus to shrink it. Each press commits one resize and announces the new size without adding a visible message. Plus and minus do nothing for a selection of several rows or columns. The focused strip button's accessible description gives its current size and, when resizing is available, these keys. The visible drag dividers are pointer targets, not additional Tab stops. The default sizes are the 160-pixel columns and 38-pixel rows shown in the stories; stored size limits follow the architecture [runtime reading rules](../../arch/templates/table.md#runtime-reading). Exact resize steps are code-governed.

## Editing cells

Typing a character while a cell is selected replaces its contents with that character and starts editing in place. Double-clicking it, pressing Return, or pressing F2 starts editing with the existing text and the caret at its end. The editor fills the cell and has the foundation focus outline. Arrow keys and the usual text-editing keys then work in the text.

Return commits and selects the cell below. At the last displayed row it stays at the last row and does not add one. Shift-Return moves in the opposite direction. Tab commits and selects the cell to the right; Shift-Tab moves left. At the last displayed column, Tab commits and leaves the table; at the first, Shift-Tab does the same. Neither key adds an entry merely by reaching an edge.

Clicking another cell, a strip item, or an add control commits before acting on that target. Clicking outside the table control and its open menu commits and clears the selection. Focus leaving the editor any other way commits and keeps the selection. Escape cancels the edit, restores the stored text, and returns focus to the selected cell. A second Escape clears the selection. The sections below state the cases where an editor instead closes without writing.

The editor preserves stored and pasted line breaks, even though the grid displays them as spaces. Copying, pasting, text selection, and browser undo work inside the editor as in another text field. Whole-cell and range copy or paste are not supported. After an edit or structural action is committed, the page provides no undo.

Empty and unchanged commits follow the architecture [page-write rules](../../arch/templates/table.md#page-writes).

## Clearing contents

Delete or Backspace clears the selected cell or the cells in selected rows or columns. It never removes a row or column.

## Adding, inserting, and deleting structure

The add control at the end of a row or column strip adds a row or column at the end. Right-clicking an item outside the current range selects only that row or column. Right-clicking inside a selected range keeps the range. Either action opens a canonical `<tv-menu>` below that strip item. Right-clicking a cell does not open a Table menu, change the selection, or commit an edit.

When no editor is open, the context-menu key or Shift-F10 opens the menu from the keyboard. For a whole-row or whole-column selection, it opens the corresponding menu below the range anchor. For a cell, it selects the row containing that cell and opens the row menu below that strip item. While an editor is open, right-clicking inside it, the context-menu key and Shift-F10 open no Table menu and do not commit. Opening a Table menu commits an active edit first. A normal press on a strip item selects the row or column without opening a menu.

The row menu contains “Insert row above” and “Insert row below”, followed by “Delete row” or “Delete rows” when the selection contains a stored row. A row menu opened from row 1 then contains “Make header row” when the header row is off, or “Remove header row” when it is on. No other row menu and no column menu contains that action. The column menu contains “Insert column left”, “Insert column right”, and “Delete column” or “Delete columns”. The Delete label is singular or plural according to the number of stored entries the action will delete, not the number of drawn positions in the selection. A selection made entirely of drawn positions has no Delete item. Destructive actions use the canonical danger treatment.

Insert adds one row above or below the selected row range, or one column to the left or right of the selected column range, and selects that whole new row or column. The row add control selects and focuses a cell in the new row at the previously selected cell's column, or in the first column when no cell was selected. The column add control does the same at the previously selected cell's row, or in the first row. After deleting selected rows or columns, one whole row or column stays selected at the first displayed position formerly occupied by the selection, or at the last position when the old position no longer exists. Clearing contents leaves the selection unchanged. The [store contract](../../arch/templates/table.md#page-writes) owns ordering, deletion, sizing, and header row writes.

When the header row is on, inserting a row above row 1 makes the inserted row the header row and turns the previous titles into data. Deleting row 1 makes the next row the header row. Clearing a selected column also clears its cell in the header row.

## Changes from elsewhere

The page follows the whole store live. Changes outside the field currently being edited appear at once. A selected stored cell, row, column, or range follows the keys it selected when entries move. A range remains selected only while those keys occupy one contiguous range; otherwise the selection clears. If any selected stored entry is removed or no longer displayed, the selection clears and an editor on it closes without writing.

Escape closes an open Table menu and keeps the selection. A Table menu also closes when its selection clears.

A selected drawn position follows the architecture [identity rule](../../arch/templates/table.md#^bundled-artifact-template-table-drawn-identity). When it changes identity under that rule, the selection clears and an editor on it closes, discarding the text being typed.

While a person is editing one field, an incoming change to that field does not replace the text or move the caret. A changed edit commits through the ordinary last-write-wins store rule. An unchanged edit closes without writing, so it reveals the current stored value. Cancelling also shows the current stored value. A late edit that races with deletion can be lost under the [runtime reading rules](../../arch/templates/table.md#runtime-reading).

## Read-only and access loss

When the page can only read its store, as through a read-only share, the table can still be selected and navigated. Cells cannot enter editing, Delete does nothing, add controls are absent, resize gestures, including plus and minus, do nothing, and the action menus do not open. The page switches between editable and read-only as access changes. If write access is removed while an editor is open, the editor closes without writing and shows the last confirmed value. An open menu closes.

<Artifact><Canvas of={Stories.ReadOnly} /></Artifact>

When all access is lost, as after a share link is revoked, the page keeps the last table it received and becomes read-only. An active editor closes and shows the last confirmed value.

## Saving and disconnection

Each changed edit saves when committed. Normal saving shows no message. While the page cannot reach its server, the table keeps its last data, removes the add controls and action menus, disables new editing, and shows “Reconnecting…” in muted text in a strip ruled off along the bottom. An editor already open stays open and remains usable. Escape cancels it and keeps the cell selected.

Any commit gesture has no effect while disconnected: it does not write, close the editor, move or clear the selection, or act on the click target. Resize gestures, including plus and minus, also do nothing; a drag preview ends without writing. Once the connection returns, commit and resize gestures work normally.

If the SDK rolls back a write sent before the connection drops, the page does not reopen the editor with that text. The edit can be lost, although the server can still apply a write whose outcome is [uncertain after disconnection](../../product/resources/json-store.md#^js-disconnect). This is an accepted limitation.

If a save is refused, the affected path returns to its stored value and “Couldn't save that change.” appears in the same strip for a few seconds. Any action whose renumbering transaction aborts or fails while connected shows the same message. If that transaction commits but a required follow-up write is refused, or not sent because the page can no longer write or the data became unreadable, the page also shows the message. A follow-up held back by disconnection shows only “Reconnecting…”. The strip is a status region, so a screen reader hears each message.

## Data the page cannot read

The page reads the table as one value, while deliberately tolerating bad entries under the [runtime reading rules](../../arch/templates/table.md#runtime-reading). No store value shows the empty grid. A partial root object shows any readable rows or columns it contains. The page does not repair either value.

When the value is not a table at all, because the root is not a JSON object or a present `columns` or `rows` value is not a JSON object, or when the server reports saved data unavailable, an error page replaces the table: centred in the page, a warning icon in a ruled circle, “This table can't be shown”, and below it in muted text, “Television can't read the saved table data. Ask your agent to check the data and access.” Nothing on it can be edited. An open editor closes without writing, and an open menu closes. The page starts no write until readable data returns. The error page is an alert, so a screen reader hears it when it replaces the table.

The error page follows data live. Once an agent supplies a readable table value, the grid returns. If all access is lost before the first readable value arrives, the error page replaces the loading state; after a readable table has arrived, total access loss keeps that last table as the read-only section describes. A disconnection leaves the loading or error state in place and adds “Reconnecting…” below it.

## Icon

In the Toolbox, the template icon is a pale teal table with a solid teal header and a teal grid.

## Appearance

The page uses only foundation tokens, so it follows the active theme and light or dark appearance. The scrollport reaches the card edges. The padding between the card edges and the strips and table belongs to the scrolled content, so it scrolls away at the leading edges and remains beyond the last row and column. The table has left and right borders as well as its top and bottom borders.
