# Weather template

The Weather template makes an artifact that shows a forecast an agent keeps up to date. The current condition fills a small floating card; more room reveals an hourly strip and then a multi-day forecast. Each story on this page is one state of the page, and the page in the template must pass a [UI conformance](../../spec-ui.md#conformance) check against every one. The prose states the behaviour the stories cannot show.

The [store contract](../../arch/templates/weather.md#^bundled-artifact-template-weather-store) owns the forecast data. The page reads that store and never fetches weather itself.

## Current conditions

The card names the place. Below it, the “Updated” label says how long ago the agent fetched the forecast, followed by the unit as `°C` or `°F`. The current temperature is the largest type on the card. Beside it, first-party weather artwork depicts the current condition. The short description and the high and low from the daily entry for the current date sit together below. When the stored daily forecast has no entry for the current date, the high-and-low line is absent. The high-and-low line updates within one minute after the current date changes while the page remains open.

Temperatures are rounded to the nearest whole degree for display, with halves rounded away from zero. A result of zero is shown as `0°`, never `−0°`. The age uses completed elapsed units: less than a minute is “Updated now”; less than an hour is “Updated 1 min ago” or “Updated N min ago”; less than a day is “Updated 1 hr ago” or “Updated N hrs ago”; and older fetches use “Updated 1 day ago” or “Updated N days ago”. A fetch time in the future because of clock skew also says “Updated now”. The age updates within one minute after its displayed value should change while the page is open.

The current condition chooses the sky. `isDay` changes the clear and partly cloudy skies and their sun-or-moon artwork. Clear daylight is saturated blue with a warm sun; clear night is deep indigo with a moon glow. Partial cloud softens either sky. Cloudy, rain, snow, thunderstorm, and fog use the same sky and artwork by day and night: cloudy uses a cool blue-grey gradient, rain darkens it to blue slate, snow cools it to icy blue-grey, a thunderstorm turns it ink-blue and violet, and fog mutes it to silver-blue. Skies are soft gradients only: no sky draws rain, snow or other weather across it, which is left to the condition artwork. Every sky uses white type with subtle text shadows and a local dark gradient behind the upper-left text. Condition artwork uses the same visual language at every size and stays clear of the summary and high-and-low line.

Across this page, the stories show every condition, both designs for clear and partly cloudy, a thunderstorm at night, and both unit systems.

## Size

The artifact document is transparent. The weather card sits inside it with rounded corners, a fine light rim, and a soft shadow, so it reads as one floating object in the transparent artifact frame.

The small layout is used below 600 pixels wide or below 480 pixels high. It shows current conditions only and is what a new artifact opens in at 340 by 340 reference pixels. The current temperature and artwork continue to scale down to the 230-by-230-pixel artifact-frame minimum so three-character readings fit without crowding. Their size is bounded by both width and height, so a wide, short artifact keeps the artwork clear of the text.

At least 600 pixels wide and 480 pixels high, the medium layout adds a translucent hourly panel for the [hourly display window](../../arch/templates/weather.md#^bundled-artifact-template-weather-hourly-window), independently of the daily window. It leaves out that panel when no stored entries remain after “Now”. Requiring both dimensions is intentional: a wide artifact below 480 pixels high keeps the balanced current-only layout instead of squeezing in a short forecast panel. The first cell is labelled “Now” and uses `temperature`, `condition`, and `isDay` from `current`. The following cells use the retained hourly entries. The window and labels update within one minute after the clock changes which entries or labels should appear. The strip scrolls horizontally when all entries do not fit.

<Artifact width="700px"><Canvas of={Stories.Medium} /></Artifact>

At least 760 pixels wide and 740 pixels high, the large layout also places a translucent daily panel after the hourly panel when the [daily display window](../../arch/templates/weather.md#^bundled-artifact-template-weather-daily-window) is not empty. Its presence depends only on the daily window. When the daily window is empty, the card uses the medium composition instead of leaving space for that panel. The heading says “N-day forecast”, where N is the number of displayed rows. Each row has “Today” for the entry whose date is the current date at `timeZone`, or otherwise its weekday, followed by a condition glyph, a low, a shared-scale temperature-range bar, and a high. The bars share the lowest low and highest high in the displayed daily forecast, so their positions can be compared. The window and “Today” label update within one minute after the clock changes which entries or labels should appear.

Generated hour and weekday labels use the `en-US` locale. Each hour label shows the entry instant as a clock time at `timeZone`; it includes minutes when the local time is not on the hour. “Now”, “Today”, the “Updated” forms, headings, and other page copy remain in English.

The hourly strip is named “Hourly forecast; scroll for later hours” and can receive keyboard focus, so left and right arrow keys can reach hours outside the visible area. Each hourly entry exposes its local time, condition name, and temperature to assistive technology. Each daily entry exposes its date label, condition name, low, and high; the range bar adds visual comparison but no separate meaning.

## Changes, access, and disconnection

When an agent replaces the forecast, the place, sky, current conditions, and visible forecast panels update together. Opening, reading, and displaying weather make no store writes.

A read-only share looks and behaves like any other Weather page. While the page cannot reach the server or its share access has been revoked, it keeps showing the last forecast without a message. When the connection returns, the page catches up by itself. If the first result had not arrived before the connection was lost or access was revoked, it keeps showing the loading state.

## Data the page cannot read

Agents write forecast data by hand, so it can break the [store contract](../../arch/templates/weather.md#^bundled-artifact-template-weather-store). The page never rewrites data it cannot read.

Any value other than the empty object or one complete forecast replaces the forecast with an alert: a warning icon in a softly ruled circle, “This forecast can't be shown”, and “Its saved data isn't in the form this page reads. Ask your agent to check it.” The same alert appears when the server reports the store's saved data unavailable. Once an agent fixes the value, the forecast returns without reopening the page.

## Icon

In the Toolbox, the template icon is a rounded blue sky tile with a small gold sun emerging from a white cloud.

## Appearance

The sky communicates the weather and time of day, so the active theme and light or dark appearance do not recolour a populated card. Typography and spacing still use the foundation. Empty, loading, and unreadable states use the same fixed sky treatment in any theme or appearance.
